# scripts/cerebro-zones.txt
#
# Source of truth for which paths are considered "upstream zone" — diffs in
# these paths require a CEREBRO-PATCH(<name>): marker. Used by:
#   - scripts/validate-cerebro-patches.sh
#   - future CODEOWNERS / sync-script reporting
#
# Format:
#   - One glob per line.
#   - Lines starting with `!` are exclusions (path is OUTSIDE the upstream zone).
#   - Lines starting with `#` are comments. Blank lines ignored.
#   - Globs are shell-style: `*` matches a single path segment, `**` matches
#     across segments. The validator translates them to regex (see
#     glob_to_regex in validate-cerebro-patches.sh).
#
# Order matters only for human readability; matching is "first include, then
# any exclude removes" — the script applies all includes then all excludes.

# --- Includes (upstream zone) ---
packages/views/**
packages/core/**
packages/ui/**
server/**

# --- Excludes (cerebro-only carve-outs) ---
!packages/cerebro-*/**
!server/internal/cerebro/**
!server/migrations/cerebro/**
# Cerebro docs namespace — own folder under Fumadocs auto-discovery, never
# touched by upstream. Listed even though apps/web/** is outside the include
# zone today, so the carve-out is already in place if upstream/web docs is
# ever added to the upstream zone.
!apps/web/content/docs/cerebro/**
# Cerebro 9NNN migrations are net-new files in the cerebro namespace,
# not modifications of upstream files. The 9000+ prefix is the namespace marker.
!server/migrations/9*.sql
# Auto-generated by sqlc — never hand-edited; regenerated whenever queries change.
!server/pkg/db/generated/**
# Test fixtures: golden files match generated output bit-for-bit; markers would break tests.
!**/testdata/**
# Go module checksums cannot carry comments.
!server/go.sum
# Cerebro-only Go files in otherwise-upstream server dirs (e.g. server/cmd/multica,
# server/internal/handler) are identified by a `cerebro_` prefix or `_cerebro`
# suffix. Upstream multica never uses these names, so they are net-new fork files
# that an upstream sync cannot overwrite — they belong to the cerebro zone exactly
# like packages/cerebro-*/ and server/internal/cerebro/. Carving them out here
# means editing a genuinely-cerebro CLI command or handler does not require a
# per-line CEREBRO-PATCH marker (which only makes sense for true upstream edits).
# This matches the "cerebro- filename prefix" convention in CLAUDE.md.
!server/**/cerebro_*.go
!server/**/*_cerebro.go
# Cerebro-only Go TEST files. Go test files use the `_test.go` suffix (underscore
# + .go), so the JS/TS-oriented `**/*.test.*` glob below never matches them. A
# `*_cerebro_test.go` (or `cerebro_*_test.go`) file is a net-new cerebro test for
# a cerebro fork file — it can never be a true upstream edit, so carve it out the
# same way as the `_cerebro.go` source files above.
!server/**/*_cerebro_test.go
!server/**/cerebro_*_test.go
# Net-new cerebro built-in agent skills are fork-only ADDITIONS (a whole new
# skill directory upstream never ships), not edits to an upstream skill — same
# philosophy as the _cerebro.go carve-outs above. A markdown SKILL.md cannot
# carry an inline CEREBRO-PATCH marker cleanly, so the directory is carved out.
# One explicit line per cerebro skill keeps edits to UPSTREAM skills still caught.
!server/internal/service/builtin_skills/multica-personal-browser/**
!**/*.test.*
!**/*.spec.*
