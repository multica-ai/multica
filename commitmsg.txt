feat(daemon): validate MULTICA_AGENT_TEMP_BASE is writable (#6475)

An existing directory the daemon cannot write to still failed task
startup, but as a bare mkdir error from deeper in the run. Probe
writability while resolving the base so the failure names the variable
the operator set. The probe runs only when the variable is set, leaving
the default /tmp path byte-for-byte unchanged.

Cover the contract at the level operators experience it: an unusable
base fails runTask with a message naming the variable, and the agent
never starts. Also restore the environment in the unset subtest, which
previously called os.Unsetenv without a matching restore and could leak
into later tests in the package.
