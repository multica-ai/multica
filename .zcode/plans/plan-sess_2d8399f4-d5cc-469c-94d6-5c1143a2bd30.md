# 鸿蒙移动端支持 — 第一阶段：apps/mobile-harmony 垂直切片

## 已确认决策
- 新建独立 RNOH 工作区 `apps/mobile-harmony`，与 `apps/mobile` 平行；复用 `@multica/core` 类型+纯函数（与 iOS 相同边界）；不改动今天跑通的 iOS 应用。
- 本阶段交付可验证垂直切片：本地鸿蒙手机模拟器（HarmonyOS 7.0 / API 26 镜像已就绪）上构建、安装、运行，走通 **staging 登录（邮箱验证码）→ 工作区选择 → 收件箱只读列表 + 实时 WS 更新**。
- 技术基线：RNOH 跟进 RN 0.82（本仓 iOS 在 0.83，差距可接受，依赖各自锁定）；DevEco 26 内置 hvigor 6.26.4 / ohpm / hdc / node 24。

## 任务分解

### 0. nativewind v4 on RNOH 验证闸门（最先执行）
用 RNOH CLI 生成最小工程 + nativewind v4（metro `withNativeWind`）+ 一个 className 测试屏，在模拟器上验证。生态调查表明 nativewind 鸿蒙移植停留在 v2，v4 大概率能跑但必须实证：
- **通过** → 屏幕移植沿用 className，效率最高；
- **不通过** → 切片屏幕改用 `lib/theme.ts` 的 THEME token 显式 StyleSheet 样式兜底，「样式体系适配」列为后续独立工作项。

### 1. 工作区脚手架
- `package.json`（`@multica/mobile-harmony`）：固定 RN 0.82.x、`react-native-harmony`、`@react-native-oh-tpl/*`（screens、safe-area-context、reanimated、gesture-handler、svg、netinfo、async-storage、flash-list）、react-navigation v7、`@multica/core: workspace:*`、zod/zustand/react-query。
- `metro.config.js`：参照 apps/mobile 的 monorepo watchFolders/symlink 配置，去掉 expo 部分。
- `harmony/` 原生壳（ArkTS EntryAbility + RNInstance + CMake + oh-package.json5），按 APP_ENV 切换应用名/bundle 变体（staging 与 prod 可共存）。
- env 文件三件套 + dotenv-cli/cross-env 脚本阶梯；`scripts/harmony-run.sh`（+ .test.sh，纳入 test 脚本）固化 DevEco 内置工具链 PATH 与「先 prebuild 再构建」守护，风格对齐 ios-run.sh。
- AGENTS.md / README.md / .gitignore（oh_modules/、.hvigor/、构建产物、`!data/` 覆盖根规则）。

### 2. 数据层移植（纯 JS 直搬 + 平台 shim）
- 移植 `data/api.ts`（zod+fetch+请求超时/中止）、auth query/mutation、workspace 列表、inbox 列表 + 未读 summary、realtime `ws-client` + inbox updaters、`query-client`（AppState+NetInfo）。保持 bearer auth、X-Workspace 头、401 清理、wsId query key 语义与 iOS 版一致。
- `secure-storage` 抽象：优先做 ArkTS 小模块走 **Asset Store Kit**（鸿蒙等价 Keychain）；若阻塞先用 async-storage 落地并明记债务。
- `src/platform/` shim：haptics（no-op）、clipboard（可空实现）、Image 用 RN core、图标用 react-native-vector-icons 的 Ionicons 字体。

### 3. 导航与切片屏幕
- react-navigation v7：root stack（Login/Verify → 工作区选择 → Inbox）。
- 屏幕参照 iOS 版移植：login、verify（input-otp-native 纯 JS 可直用）、工作区选择（首阶段合并 switch/select）、inbox 列表（FlashList）、inbox 详情（正文降级纯文本）。主题跟随系统 + THEME token。

### 4. 本地模拟器验证闭环
- 启动 DevEco 手机模拟器 → hvigor 构建 HAP → hdc 安装启动 → Metro 连接 → `hdc snapshot_display` 截图验证。
- 验收清单：真实 staging 登录、收件箱渲染、**web 端改数据模拟器无刷新同步**（跨端实时验证，仓库规则要求）、vitest/typecheck/lint 全绿。

### 5. 仓库集成
- 根 `package.json`：`harmony:mobile-harmony*` 脚本阶梯 + 四个 repo 级任务的 `--filter=!@multica/mobile-harmony`。
- `knip.jsonc` ignoreWorkspaces；根 `.gitignore` 白名单 env 文件；根 `AGENTS.md` 工作区表/阅读顺序/验证表加行。
- CI：新建 `harmony-verify.yml`（复制 mobile-verify.yml 模式）+ `ci.yml` 两处 filter + `ci-paths.json`。
- 文档：`apps/docs` 四语言新增 mobile-harmony-app 页并注册 meta；更新 `docs/zcode-harmony-support-report.md` 的鸿蒙结论。遵守 conventions（kebab-case、英文代码注释、中文全角标点等）。
