# AI 会话 UI 审查

范围为 iOS AI 会话：会话列表、消息、输入、引用、设置、用量、排队、附件、文件与 Side 工作区。
遵循移动端独立 UI、原生弹层、主题 token、44 pt 触控区和三语言文案规范。
按钮视觉尺寸、选择状态和输入区已按外部页面统一，依据及改动见[视觉规范对齐](style-alignment.md)。

## 问题与修复依据

| 证据 / 根因 | 用户影响 | 本次处理 |
| --- | --- | --- |
| 原有草稿、发送、队列和历史展示只有文本与附件 | iOS 无法携带结构化 @ 引用 | 补齐三个分类、独立分页、引用验证、上下文、调用和重试全流程 |
| 会话目录 HTTP 逐页循环全取，实时订阅又从序号 0 重放 | 主会话列表一次加载全部会话；只对 @ 结果切片不能解决请求量 | 数据库按目录游标分页，每个目录首次 8 条、独立加载更多；单独计数，实时订阅从当前序号开始 |
| 输入工具栏分散显示运行器和模型 | 长模型名称挤占输入操作空间 | 合并为一个设置入口；更换运行器明确为新建会话，并保留草稿 |
| iOS 26 为会话列表导航按钮自动添加共享玻璃背景 | 圆形和胶囊底色与页面分离 | 通过 Expo Router 的 Stack.Toolbar.View 关闭共享背景，保留原生导航和 44 pt 点击区 |
| 会话分组使用文本字符充当折叠箭头 | 收起、展开符号的大小与基线不一致 | 改为统一 14 pt 的 chevron 图标，数量与箭头独立对齐 |
| 原生模拟器长会话中，每个思考和工具项独占一行 | 消息被大量执行细节打断 | 连续细节按轮次合并，点击展开；失败仍独立显示 |
| 原摘要清理函数只处理链接等少数标记 | 列表露出粗体、代码和标题符号 | AI 会话使用现有 Markdown lexer 提取纯文本预览，保留代码标识符 |
| @ 半屏弹层空间不足 | 加载更多不容易发现 | 默认使用共享 formSheet 的较大停靠高度，首次展示最多 8 条并支持滚动 |
| 智能体引用行缺少身份头像 | 同名或相似名称不便辨识 | 复用移动端 ActorAvatar 展示配置的图片、emoji 或默认头像；会话、任务保留纯文本行 |
| 引用元数据直接展示完整工作目录 | 绝对路径和内部目录 ID 影响扫描 | 展示运行器和文件夹名，隐藏自动工作目录 ID |
| 辅助功能大字号下固定行高、按钮高度 | 标题、标签、按钮文字被裁切 | AI 范围内使用原生自然行高和自适应控件高度；@ 标题按字号换行布局 |
| 选择页数量栏处于键盘后方 | 搜索时看不到已选数量 | 复用现有 KeyboardStickyView，固定在键盘上方 |
| 多个设置弹层各自实现标题和底部 | 导航与安全区表现不一致 | 复用 AI 模块专用 AISheet，保留原生 formSheet |
| 附件名称点击同时承担移除动作 | 容易误删草稿中的附件 | 名称打开预览，移除使用独立按钮；附件条可横向滚动 |
| 空文件夹、搜索无结果缺少反馈 | 无法区分空数据和未完成加载 | 增加对应空态与失败重试 |
| Side 会话选择使用长原生操作菜单 | 会话变多后难以查找 | 改为可搜索的原生列表弹层 |
| 原 DOM WebView 没有网页加载/错误/导航回调 | 无法可靠展示失败、前进和后退 | 使用 Expo SDK 对齐的 react-native-webview；添加真实加载、错误、重试和导航状态 |

自然行高覆盖只应用于 AI 会话，避免扩大到全局 Text/Button 规范。
WebView 自定义错误占位由应用提供恢复提示，避免重复出现默认英文诊断页。

## 状态与数据流

选择页临时选择 → 完成写入隔离草稿 → 发送前验证并生成摘录 → 固定提交内容与请求 ID → 直接发送或入队 → 服务端确认 → 清理该提交。
取消选择页不改草稿。失败保留原提交供重试。晚到的确认不清除更新后的草稿。
会话和任务的摘录明确标识为引用数据，附带截断及未包含内容的说明。

根本方案是结构化引用贯穿整个发送链路；交互兼容方案采用现有原生输入框和上方标签。
本次组合采用两者，保留原有发送协议，也未引入新编辑器或迁移 Web 状态层。

会话列表另有独立数据流：当前序号握手 → 目录元数据和完整计数 → 已展开目录的 8 条首页 → 用户点击加载更多 → 读取下一游标页。
实时订阅只接收握手后的变化，合并刷新已加载的页；游标边界变化时，后续页跟随新游标重新读取。
Query 持有服务端页面，组件只保存请求页数、搜索和折叠状态。@ 会话引用与 Side 会话列表复用相同分页接口。
