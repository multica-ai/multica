Cerebro kører på vores egen Mac mini, ikke på Multica Cloud. For at agenterne kan udføre opgaver på din maskine, skal du installere `multica`-CLI'en, pege den på vores server, og starte daemonen.

Du skal **ikke** oprette dit eget workspace. Du bliver tilføjet til det eksisterende **Firtal**-workspace via en invitation — så snart du har accepteret den, springer du workspace-opretningen over.

<Callout type="info">
Du har brug for en invitation fra Jesper, før du kan logge ind. Bed ham sende et invite-link (Settings → Members → Invite) inden du går i gang.
</Callout>

## 1. Installér CLI'en

På macOS og Linux:

```bash
brew install multica-ai/tap/multica
```

Bekræft at den er installeret:

```bash
multica --version
```

## 2. Konfigurér CLI'en til Cerebro

Vores Cerebro-instans kører på `https://sara.tailbde0.ts.net` (frontend, backend og daemon-API ligger alle på samme host). Kør:

```bash
multica setup self-host \
  --server-url https://sara.tailbde0.ts.net \
  --app-url https://sara.tailbde0.ts.net
```

Hvad kommandoen gør:

1. Gemmer URL'erne i `~/.multica/config.json`.
2. Åbner din browser til Cerebro, så du kan logge ind via OAuth.
3. Starter daemonen i baggrunden.

<Callout type="warn">
Du vil se en advarsel som `⚠ Server at https://sara.tailbde0.ts.net is not reachable.` Det er kosmetisk — vores reverse proxy eksponerer ikke `/health` på roden. Fortsæt med næste trin; loginnet virker stadig.
</Callout>

Hvis advarslen forhindrer browseren i at åbne, kør login manuelt bagefter:

```bash
multica login
```

## 3. Acceptér invitationen til Firtal-workspacet

Når browseren åbner og du er logget ind:

1. Åbn invite-linket fra Jesper i **samme browser**.
2. Klik **Acceptér invitation**.
3. Du lander direkte i Firtal-workspacet — ingen onboarding-flow, ingen "create workspace"-skærm.

Hvis du allerede har klikket på linket før login, så loggede du ind først og er måske blevet vist en "opret workspace"-skærm. Luk fanen, åbn invite-linket igen, og acceptér derfra — det springer skærmen over.

<Callout type="warn">
Opretter du dit eget workspace ved en fejl, så fortæl Jesper med det samme. Han kan slette det og sende en ny invitation, så du lander det rigtige sted.
</Callout>

## 4. Verificér at daemonen kører

```bash
multica daemon status
```

Du skulle gerne se PID, uptime og at `Firtal`-workspacet er watched. Hvis ikke:

```bash
multica daemon start
multica workspace list
```

`multica workspace list` markerer watched workspaces med `*`. Hvis Firtal ikke har en stjerne:

```bash
multica workspace watch <workspace-id>
```

## 5. Tjek hvilke agent-CLI'er daemonen har fundet

Daemonen kører kun de AI-CLI'er, du allerede har installeret. Kør:

```bash
multica daemon status --output json
```

Kig under `runtimes`. Mangler den agent, du forventer, så installér den lokalt (fx `claude`, `codex`, `gemini`) og genstart daemonen:

```bash
multica daemon stop
multica daemon start
```

## 6. Opret en agent

Daemonen er kun runtimen — den udfører ikke noget før der findes en **agent** der peger på den. En agent binder din runtime sammen med et navn, en system-prompt og evt. en model, og kan tildeles issues præcis som en kollega.

### Via UI'et (anbefalet)

1. Åbn `https://sara.tailbde0.ts.net` i din browser og vælg Firtal-workspacet.
2. Gå til **Agents** i sidemenuen og klik **New agent**.
3. Udfyld:
   - **Name** — fx `Mia - CEO EA`. Det er det navn issues bliver assigned med.
   - **Runtime** — vælg din lokale daemons runtime (typisk `Local Agent — claude`). Det er denne kobling der gør at opgaver havner på din maskine.
   - **Model** — fx `claude-opus-4-7`. Lader du den stå tom, bruger daemonen CLI'ens default.
   - **Instructions** — agentens system-prompt. Hold den specifik: rolle, opgaver der er i scope, kommunikationsregler.
   - **Visibility** — `private` (kun dig) eller `workspace` (hele teamet kan tildele opgaver).
4. Gem. Agenten dukker op i Agents-listen og kan nu vælges som assignee på issues.

### Via CLI

Find først runtime-ID'et:

```bash
multica daemon status --output json
```

Notér `runtime_id` for den runtime du vil bruge, og opret agenten:

```bash
multica agent create \
  --name "Min agent" \
  --runtime-id <runtime-uuid> \
  --model claude-opus-4-7 \
  --instructions "Du er ..." \
  --visibility workspace
```

Se alle flags med `multica agent create --help`. API-nøgler i `--custom-env` bør altid sendes via `--custom-env-stdin` eller `--custom-env-file`, aldrig inline på kommandolinjen — så røber de sig ikke i shell-historik eller `ps`.

### Test agenten

```bash
multica issue create \
  --title "Test opgave" \
  --description "Sig hej og bekræft du kører lokalt på min maskine." \
  --assignee "Min agent"
```

Følg daemon-loggen mens den eksekverer:

```bash
multica daemon logs -f
```

Daemonen skal claime opgaven, spawne din AI-CLI, og afslutte med en kommentar på issuet.

## 7. Gør daemonen persistent (macOS, launchd)

`multica daemon start` kører kun indtil næste reboot. For at daemonen automatisk starter igen efter reboot — og respawner hvis den crasher — registrér den som en launchd-agent.

1. Find stien til din `multica`-binær:

   ```bash
   which multica
   # fx /opt/homebrew/bin/multica  (Apple Silicon)
   #    /usr/local/bin/multica     (Intel)
   ```

2. Opret `~/Library/LaunchAgents/com.multica.daemon.plist` med følgende indhold — udskift `/opt/homebrew/bin/multica` og `<DIT-BRUGERNAVN>` med dine egne værdier:

   ```xml
   <?xml version="1.0" encoding="UTF-8"?>
   <!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
     "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
   <plist version="1.0">
   <dict>
     <key>Label</key>
     <string>com.multica.daemon</string>
     <key>ProgramArguments</key>
     <array>
       <string>/opt/homebrew/bin/multica</string>
       <string>daemon</string>
       <string>start</string>
       <string>--foreground</string>
     </array>
     <key>EnvironmentVariables</key>
     <dict>
       <key>PATH</key>
       <string>/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin</string>
     </dict>
     <key>RunAtLoad</key>
     <true/>
     <key>KeepAlive</key>
     <true/>
     <key>StandardOutPath</key>
     <string>/Users/<DIT-BRUGERNAVN>/Library/Logs/multica-daemon.out.log</string>
     <key>StandardErrorPath</key>
     <string>/Users/<DIT-BRUGERNAVN>/Library/Logs/multica-daemon.err.log</string>
     <key>ProcessType</key>
     <string>Background</string>
   </dict>
   </plist>
   ```

3. Stop en evt. allerede kørende daemon og indlæs agenten:

   ```bash
   multica daemon stop
   launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.multica.daemon.plist
   launchctl kickstart -k gui/$(id -u)/com.multica.daemon
   ```

4. Verificér:

   ```bash
   launchctl print gui/$(id -u)/com.multica.daemon | grep -E 'state|last exit'
   multica daemon status
   ```

   `state = running` og en runtime-liste fra `daemon status` betyder du er kørende.

<Callout type="info">
**Stop / fjern agenten** med `launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/com.multica.daemon.plist`. Slet evt. `.plist`-filen bagefter hvis du ikke vil have den aktiveret automatisk igen.
</Callout>

Kræver din AI-CLI login (fx `claude /login`), så kør det login-flow i din normale brugersession **én gang** — credentials gemmes i din hjemmemappe og bruges også af daemonen når den kører via launchd.

## Færdig

Du har nu en kørende daemon, en agent på din egen runtime og en persistent setup der overlever reboots. Tildel agenten et issue og se den arbejde.

## Almindelige problemer

**"Server at … is not reachable" — men loginnet virker.** Kosmetisk. Vores reverse proxy svarer ikke på `/health`. Ignorér.

**Login åbner `multica.ai` i stedet for Cerebro.** Du har en gammel cloud-konfiguration. Kør `multica setup self-host …` igen, og svar `y` til at overskrive.

**Daemonen starter ikke fordi porten er optaget.** En anden daemon-instans kører allerede. `multica daemon stop` og prøv igen, eller tjek `~/.multica/daemon.log`.

**Jeg har klikket Opret workspace og lavet et "Mit Workspace".** Bed Jesper slette det og sende en ny invitation. Du vil ikke have to workspaces — alt arbejde foregår i Firtal.

**Daemonen er nede efter genstart.** Du har ikke gjort den persistent endnu. Følg trin 7 ovenfor for at registrere `com.multica.daemon` som en launchd-agent der starter ved login og respawner ved crash.

**`multica daemon status` viser runtimes, men ingen agent kan claime opgaven.** Opret en agent (trin 6) der peger på den runtime — uden agent forbliver runtimes blot tilgængelige uden ejer.
