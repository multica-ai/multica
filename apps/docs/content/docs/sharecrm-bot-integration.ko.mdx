import { Callout } from "fumadocs-ui/components/callout";

임의의 [에이전트](/agents)를 ShareCRM 봇에 연결하면 팀은 ShareCRM 안에서 바로 사용할 수 있습니다 — 봇에 DM하거나, 그룹에서 @멘션하거나, `/issue`를 입력해 앱을 열지 않고 [Multica 이슈](/issues)를 만들 수 있습니다.

ShareCRM 연동은 커뮤니티에서 유지 관리합니다. 모든 릴리스에 포함되지만 공식 지원 SLA는 없습니다. 문제는 [GitHub issues](https://github.com/multica-ai/multica/issues)에 알려주세요.

ShareCRM은 **직접 앱을 가져오는(BYO: bring-your-own-app)** 모델을 사용합니다. 워크스페이스 관리자가 ShareCRM 오픈 플랫폼에서 봇 자격 증명을 만든 뒤 Multica에 붙여넣습니다. 에이전트마다 **자체** ShareCRM 봇을 가지므로 같은 조직에서 여러 에이전트가 각각 별도로 @멘션할 수 있는 봇을 가질 수 있습니다. (스캔 후 설치하는 흐름인 [Lark](/lark-bot-integration)와는 다릅니다.)

전체 설정은 아래에 있으며 약 5분 걸립니다. 최종적으로 Multica에 붙여넣을 두 자격 증명을 얻습니다.

- **App ID** — 봇 애플리케이션의 client id
- **App Secret** — 봇 애플리케이션의 client secret

프라이빗 클라우드에서는 선택적으로 **API base URL**도 설정할 수 있습니다(기본값 `https://open.fxiaoke.com`).

## ShareCRM 봇 설정

### 1. ShareCRM 오픈 플랫폼에서 봇 자격 증명 만들기

1. 관리자 계정으로 [ShareCRM 오픈 플랫폼](https://open.fxiaoke.com)(또는 프라이빗 클라우드 콘솔)을 엽니다.
2. Multica가 연결할 봇 애플리케이션을 만들거나 엽니다.
3. 해당 애플리케이션의 **App ID**와 **App Secret**을 복사합니다.
4. 봇이 메시지(DM 및 그룹 @멘션)를 수신하고 답장을 보낼 수 있는지 확인합니다. Multica는 장시간 SSE 세션으로 **밖으로** 연결하므로 채팅용 공개 webhook URL은 **필요 없습니다**.

이것이 플랫폼 계층에서 Multica가 필요로 하는 전부입니다.

| 설정 | 있는 이유 |
|---|---|
| **봇 애플리케이션** | Multica 인증에 쓰는 App ID / App Secret을 발급합니다. |
| **메시지 수신** | 봇이 1:1 메시지와 자신을 @멘션한 그룹 메시지를 받도록 합니다(그룹 전달은 Multica가 이벤트를 보기 전에 ShareCRM 측에서 필터링됩니다). |
| **메시지 전송** | 봇이 에이전트 답장과 안내를 같은 채팅에 게시할 수 있게 합니다. |
| **SSE 장기 연결** | Multica가 밖으로 연결해 push 연결을 유지합니다 — 수신 채팅에 **공개 webhook / URL이 필요 없습니다**. |

**Multica 측 webhook URL과 OAuth 리다이렉트 URL은 없습니다.** 봇은 SSE 장기 연결로 동작하고 BYO는 OAuth를 사용하지 않기 때문입니다.

<Callout type="info">
ShareCRM에는 네이티브 입력 중 표시가 없으므로 — DingTalk와 같이 — 봇은 처리를 시작할 때 짧은 "처리 중" 확인을 먼저 보내고, 전체 답장은 에이전트가 끝난 뒤에 도착합니다. 짧은 시간에 연속으로 보낸 메시지는 하나의 확인으로 합쳐집니다.
</Callout>

### 2. Multica에서 연결하기

1. **Agents → _에이전트_**에서 에이전트를 연 다음 **Integrations** 탭(또는 왼쪽 사이드바 **Integrations** 섹션)을 엽니다.
2. **Connect ShareCRM**을 클릭합니다.
3. **App ID**와 **App Secret**을 붙여넣습니다. 퍼블릭 클라우드에서는 **API base URL**을 비우고, 프라이빗 클라우드에서는 호스트를 지정합니다.
4. **Connect**를 클릭합니다. Multica는 API base URL에 대해 토큰을 발급받아 자격 증명을 검증합니다.
5. 에이전트에 **Connected to ShareCRM**이 표시됩니다. 봇은 자체 SSE 연결로 수신 대기합니다.

<Callout type="warning">
두 자격 증명은 **같은** ShareCRM 봇 애플리케이션에서 와야 하며, 그 애플리케이션은 정확히 **하나의** 에이전트에 대응합니다. 다른 에이전트나 워크스페이스에 이미 연결된 App ID 연결은 거부됩니다. 봇을 다른 에이전트로 옮기려면 먼저 연결을 해제하세요. 에이전트를 **새** App ID로 다시 연결하면 해당 에이전트의 봇이 그 자리에서 업데이트됩니다.
</Callout>

<Callout type="info">
**여러 에이전트**에 설정하나요? 에이전트당 전체 과정을 한 번씩 반복하세요 — 각 에이전트가 자체 App ID / App Secret을 가지며 별개의 봇으로 나타납니다.
</Callout>

## 연동이 하는 일

| 화면 | 동작 |
|---|---|
| **에이전트 → Integrations** | owner와 admin에게 **Connect ShareCRM**이 보이며, 연결 후에는 **Connected to ShareCRM** 배지와 **Disconnect** 컨트롤로 바뀝니다. |
| **봇에 DM** | 워크스페이스 멤버가 1:1 채팅에서 봇에 메시지를 보냅니다. 대화는 해당 에이전트의 Multica [chat](/chat) 세션이 되며 모든 메시지가 읽힙니다. |
| **그룹에서 @멘션** | 봇을 그룹에 추가한 뒤 @멘션합니다. ShareCRM이 봇에 전달하는 메시지만 읽히며, 봇은 전체 그룹을 듣지 않습니다. |
| **텍스트만** | 현재 텍스트 메시지만 처리합니다. 이미지, 파일, 음성은 에이전트로 전달되지 않습니다. |
| **`/issue` 명령** | 메시지를 `/issue <제목>`으로 시작하면 입력 내용으로 Multica 이슈를 당신 명의로 바로 만들고, 같은 대화에 이슈 ID와 제목을 돌려줍니다. 설명은 이어지는 줄에 적습니다. 명령 자체는 Multica Chat에 나타나지 않으며, 생성된 이슈가 Multica에 기록되는 결과입니다. |
| **`/new` 명령** | 메시지를 `/new <메시지>`로 시작하면 이전 대화 컨텍스트 없이 그 메시지를 실행합니다. `/new`만 보내면 같은 fresh 의도를 다음 비어 있지 않은 메시지에 적용하며 빈 turn은 만들지 않고, 봇이 의도가 준비됐음을 확인합니다. pending 의도는 이후 채팅 작업이 큐에 들어갈 때까지 유지됩니다. 대화 기록은 그대로 유지됩니다. |
| **답장** | 에이전트 답변은 같은 1:1 채팅 또는 그룹에 일반 텍스트로 게시됩니다(전달 시 Markdown은 제거됩니다). |

## 봇 사용(멤버)

### 첫 메시지: 계정 연결

처음 봇에 **DM**하면 제품 내 **/sharecrm/bind** 페이지를 가리키는 **계정 연결** 안내가 옵니다. 링크를 열고 Multica에 로그인하면 ShareCRM 신원이 Multica 멤버십에 연결됩니다 — 이 단계 덕분에 에이전트가 당신으로 행동할 수 있습니다(예: `/issue`가 당신 명의로 만들어짐). 링크는 일회용이며 약 15분 후 만료됩니다. 약 1분 안에 다시 메시지를 보내면 이미 보낸 링크를 가리킬 뿐 새 링크를 만들지 않습니다. 창이 지난 뒤 다시 메시지를 보내면 새 링크가 옵니다. 바인딩 링크는 그룹에 보내지 않습니다 — 먼저 1:1을 여세요.

아직 연결하지 않은 채 **그룹**에서 @멘션하면 봇이 그룹에서 1:1 채팅을 열라고 안내합니다. 연결 링크는 그룹에 게시되지 않습니다(베어러 자격 증명이므로 URL은 1:1에서만 전달됩니다).

<Callout type="warning">
**워크스페이스 멤버**만 봇을 사용할 수 있습니다. 멤버가 아니거나 신원 연결을 건너뛰면 봇이 실행되지 않습니다 — 메시지는 버려집니다(감사 목적으로만 기록되며 본문은 저장되지 않음).
</Callout>

### 채팅과 명령

- **그룹에서** — 봇을 그룹에 추가한 뒤 `@your-bot <메시지>`를 보냅니다. 후속 질문마다 다시 @하세요(봇은 ShareCRM이 라우팅한 메시지만 받습니다).
- **1:1 채팅에서** — 봇을 열고 직접 메시지를 보냅니다. @가 필요 없으며 모든 메시지가 읽힙니다.
- **이슈 만들기** — `/issue Safari 로그인 리다이렉트가 깨짐`을 보내고 필요하면 다음 줄에 설명을 추가합니다. Multica가 동기적으로 이슈를 만들고 ID와 제목을 채팅에 돌려줍니다.
- **새로 시작** — `/new <메시지>`로 이전 컨텍스트 없이 실행하거나, `/new`만 보내 다음 비어 있지 않은 메시지에 fresh 의도를 적용합니다. 단독 `/new`는 확인을 받으며, pending 의도는 이후 채팅 작업이 큐에 들어갈 때까지 유지됩니다. 두 방식 모두 기존 대화 기록은 삭제하지 않습니다.

## 관리와 연결 해제

워크스페이스 전체 관리는 **Settings → Integrations**에 있습니다.

- **Connected bots**는 워크스페이스의 모든 봇과 각각 연결된 에이전트를 나열합니다(모든 멤버가 볼 수 있음).
- **Disconnect**는 **owner / admin만** 가능합니다. 봇은 ShareCRM 메시지 수신을 멈추고 연결을 해제합니다. 설치 기록은 감사용으로 남으며 나중에 다시 연결할 수 있습니다.

## 권한

- **연결 / 연결 해제**에는 워크스페이스 **owner** 또는 **admin**이 필요합니다.
- **봇과 대화**하려면 ShareCRM 신원이 연결된 워크스페이스 멤버여야 합니다. 그 외는 모두 버려집니다.
- 버려진 메시지의 본문은 저장되지 않습니다 — 감사용 드롭 사유만 기록됩니다.

## 자체 호스팅 설정

Multica Cloud에서는 이 연동이 이미 사용 가능합니다 — 이 섹션을 건너뛰세요.

자체 호스팅의 경우 ShareCRM은 **at-rest 암호화 키를 설정하기 전까지 꺼져 있습니다**. 이 키는 각 봇의 App Secret을 데이터베이스에 저장하기 전에 암호화합니다. App ID는 비밀이 아닌 installation 라우팅 식별자로 평문 저장됩니다. BYO에는 배포 수준의 OAuth client id/secret이 **필요 없습니다** — 각 installation은 admin이 붙여넣은 자격 증명을 사용합니다.

1. 32바이트 키를 생성해 API 서버에 설정합니다.

   ```dotenv
   MULTICA_SHARECRM_SECRET_KEY=<base64-encoded 32-byte key>
   ```

   예: `openssl rand -base64 32`.

2. API를 재시작합니다. 키가 설정되기 전까지 **Settings → Integrations**에 "ShareCRM integration not enabled" 안내가 표시되고 **Connect ShareCRM** 진입점도 숨겨진 상태로 남습니다.

<Callout type="info">
키는 정확히 32바이트로 디코딩되어야 합니다 — `openssl rand -base64 32`로 가능합니다. 장기 시크릿으로 취급하세요. 교체하거나 분실하면 저장된 자격 증명을 복호화할 수 없어 모든 봇을 다시 연결해야 합니다. "계정 연결" 링크는 웹 앱 URL(`MULTICA_APP_URL`, 미설정 시 `FRONTEND_ORIGIN`)로 만들어집니다 — 일반 배포에는 이미 있으므로 채팅 쪽 추가 설정은 없습니다. 멤버가 바인드 링크를 열 때 브라우저에서 해당 URL에 접근할 수 있어야 합니다.
</Callout>

같은 App ID는 동시에 **하나의** 활성 SSE 연결만 가질 수 있습니다. Multica channel supervisor는 installation마다 임대를 걸어 단일 백엔드 레플리카가 연결을 소유합니다. 여러 레플리카에서는 임대를 가진 레플리카만 스트림을 유지합니다.
