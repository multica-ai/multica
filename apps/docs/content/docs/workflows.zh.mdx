工作流规定项目里的任务经过哪些步骤、每一步由谁处理、要做什么。

例如，一套研发交付流程可以这样安排：

| 步骤 | 谁来处理 | 做什么 |
|---|---|---|
| 开发 | 开发智能体 | 完成修改，准备好交给审查。 |
| 审查 | 审查智能体 | 检查结果，通过后交给 QA，需要修改时退回开发。 |
| QA | 团队成员 | 试用结果，确认是否可以完成。 |

把任务移到审查这一步，就会交给审查智能体。任务的描述、讨论和之前的结果都留在原处，下一位处理人可以接着做。

**研发交付**模板就是这个结构。项目没有选用工作流时使用 **Default**：所有状态都可用，也不会自动交接，和以前的用法一样。

## 创建工作流

工作区的 `owner` 或 `admin` 可以在网页端或桌面端创建工作流：

<Steps>
<Step>

打开**设置 → 工作流**，选择**新建工作流**。可以从空白开始，也可以使用**研发交付**、**内容生产**或**社区维护**模板。

</Step>
<Step>

填写名称，选择需要的状态列，拖动中间的列调整顺序。

</Step>
<Step>

选择一列，设置任务进入时**不交接**、**交给智能体**或**交给成员**。成员列表里也可以选择**项目负责人**。

</Step>
<Step>

如果交给智能体，写清这一步要做什么，再选择**完成后进入**哪一步（不选时默认进入下一列）、**打回时退回到**哪一步（这一步认为收到的工作不合格、需要返工时使用）。因外部原因无法继续时用 **Blocked**，不要用退回。

</Step>
<Step>

预览智能体会收到的说明，然后保存。

</Step>
</Steps>

如果添加了新状态，先保存工作流，再为这个状态设置交接。

**不交接**会保留原来的负责人。**交给成员**只改变负责人，不启动智能体。**交给智能体**会请它开始处理这一步；你仍需有权限调用它，它所在的电脑也需要在线才能执行。

## 在项目中使用

打开项目，在**工作流**属性中选择刚才的工作流。工作区的 `owner`、`admin`，以及担任项目负责人的成员可以切换它。

确认窗口会列出哪些任务保留当前状态。如果新工作流没有某些任务正在使用的状态，需要为这些任务选择去处。切换工作流本身不会交接任务，也不会启动智能体。

项目看板会按工作流显示各列，任务的状态列表也只提供这个工作流里的步骤，并标出进入后交给谁。没有选用其他工作流的项目使用 **Default**，之后也可以切回它。

## 把任务交给下一步

修改任务状态，或把卡片拖到另一列。如果这一步设有交接，先确认接收人；交给智能体时，还可以查看它会收到的说明。

<WorkflowDemo />

在项目中新建任务时，如果没有选择负责人，而任务所在的状态设有交接，任务会直接交给这一步的处理人；处理人是智能体时会立即开始。新建窗口会提示"创建后交给"谁。想先建好再说，可以把任务放在 Backlog。

上一位负责人是智能体、而且它仍在运行或等待开始时，确认窗口会多出停止或取消它的选项，默认勾选。除非想让两位智能体同时处理，保留勾选就行；它已发表的评论和已保存的工作不会丢。

"完成后进入"和"打回时退回到"告诉智能体接下来该把任务移到哪里。一次运行结束不会自行推进任务，状态由负责这一步的成员或智能体更新；智能体把任务移进下一步时，同样会触发那一步的交接。

交接记录和说明会留在任务动态中。在项目看板的工作流菜单中，可以查看完整流程。

## 调整已有工作流

多个项目可以共用一个工作流。在**设置 → 工作流**中保存的修改会对这些项目一起生效。如果只想给一个项目换一套流程，可以复制工作流，再让这个项目使用副本。

管理员也可以直接在项目看板上设置交接：把鼠标移到列头，点击**交给…**，或点击已有的处理人。如果这个工作流还被其他项目使用，会询问"这次修改用在哪？"。选择只用于当前项目时，系统会自动复制一份工作流给它，其他项目不受影响。

移除一列时，如果还有任务停在那里，需要为它们选择新状态。其他任务保持不变，这次移动也不会启动智能体。工作流列表下方的状态库可以修改状态名称和颜色，使用同一个状态的地方都会同步变化。

删除工作流前，需要先把使用它的项目切换到其他工作流。任务会保留当前状态。

如果**设置**中没有**工作流**，说明当前工作区还不能使用这个功能，状态仍在**设置 → 任务状态**中管理。
