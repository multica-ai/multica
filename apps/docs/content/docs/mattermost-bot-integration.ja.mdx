Multica は、自社の Mattermost サーバーで作成したボットアカウントに接続します。1 つのボットが 1 つの Multica エージェントに対応します。独自の Mattermost アイデンティティが必要なエージェントごとに、別々のボットを作成してください。

Mattermost 対応は[コミュニティメンテナンス](/community-maintained)です。すべてのリリースに含まれますが、公式サポート SLA はありません。問題は [GitHub issues](https://github.com/multica-ai/multica/issues) に報告してください。

## 事前準備

- ボットの接続は Multica ワークスペースのオーナーまたは管理者が行います。
- Multica API サーバーから Mattermost サーバーへ HTTP または HTTPS で到達できる必要があります。Mattermost はセルフホストのため、多くの場合は公開アドレスではなく内部アドレスです。
- Mattermost 側でボットアカウントが有効になっている必要があります（**システムコンソール → インテグレーション → ボットアカウント**）。
- ボットのアクセストークンが必要です。パスワードと同じ扱いにしてください。

## 1. ボットアカウントを作成する

1. Mattermost で**システムコンソール → インテグレーション → ボットアカウント**を開き、ボットアカウントの作成が有効か確認します。
2. チームのメインメニューから**インテグレーション → ボットアカウント**を開き、**ボットアカウントを追加**をクリックします。
3. ユーザー名（メンバーが `@` メンションする名前）、表示名、アイコンを設定します。
4. **ボットアカウントを作成**をクリックし、表示されたトークンをコピーします。Mattermost はこれを一度しか表示しません。
5. ボットを動作させたいチャンネルに追加します。ボットは自分が参加しているチャンネルのメッセージしか受け取れません。

<Callout type="warning">
トークンを課題・チャットメッセージ・ログ・ソースリポジトリに貼り付けないでください。漏洩した場合は**インテグレーション → ボットアカウント**で失効させ、新しいトークンで再接続します。
</Callout>

<Callout type="info">
個人アクセストークンではなく**ボットアカウント**を使ってください。Multica は個人トークンを拒否します。自分の投稿が受信メッセージとして戻り、ボットが自分自身に応答してしまうためです。
</Callout>

## 2. エージェントに接続する

1. Multica で**エージェント**を開き、対象のエージェントを選択して**インテグレーション**を開きます。
2. **Mattermost に接続**をクリックします。
3. Mattermost のサーバー URL（例：`https://mattermost.example.com`）とボットアクセストークンを貼り付け、**接続**をクリックします。

Multica はサーバーに問い合わせてトークンを検証し、そのアカウントがボットであることを確認し、トークンを暗号化して保存し、監視付きの WebSocket 接続を 1 本開きます。すでに別のエージェントやワークスペースに接続済みのボットは、先にそちらで切断してください。

サーバー URL はインストール情報と一緒に保存されるため、同じ Multica ワークスペース内の 2 つのエージェントを、異なる 2 つの Mattermost 環境のボットに接続できます。

## 初回利用とアカウント連携

メンバーが初めてボットにメッセージを送ると、ボットは 1 回限りの Multica アカウント連携リンクを送ります。リンクを開いて同じ Multica ワークスペースにサインインし、Mattermost に戻ってもう一度メッセージを送ってください。リンクは 15 分で失効します。再度ボットにメッセージを送れば新しいリンクが届きます。

チャンネルでは、ボットがこのリンクを公開の場に投稿することはありません。まず DM を開くよう促します。

ボットを利用できるのは現在のワークスペースメンバーだけで、メンバーシップはメッセージごとに再確認されます。

## ボットを使う

### ダイレクトメッセージ

ボットとの DM を開いてテキストを送ります。`@` メンションは不要です。

### チャンネルとグループメッセージ

ボットをチャンネルに追加し、`@` メンションします。受理されたメッセージはそのスレッドの Multica 会話を継続します。ボット宛でないチャンネル上の雑談は収集されません。

スレッドのルート投稿をボット自身が書いている場合は、メンションなしの返信もボットに届きます。ボットが始めた会話は名前を繰り返さずに続けられます。人が立てたスレッドでは、毎回メンションしてください。

各スレッドがそれぞれ独立した Multica チャットです。1 つのチャンネル内の 2 つのメンションスレッドは 2 つの独立した会話になり、DM は 1 本の連続した会話になります。

### コマンド

- `/issue <タイトル>` は Multica の課題を作成します。続く行は任意の説明になります。タイトルなしの `/issue` は使い方を返します。
- `/new` は空の Multica チャットを新規作成し、そのスレッドの以降のメッセージをそこへ振り分けます。`/new <メッセージ>` はそのメッセージを最初のターンにします。
- `/clear` は現在の Multica チャットを保ったまま、次の空でないメッセージからエージェントに見えるコンテキストを新しくします。

<Callout type="info">
これらは通常のメッセージ本文として入力する Multica のメッセージコマンドです。Mattermost のスラッシュコマンドではないため、システムコンソールへの登録は不要です。
</Callout>

### 返信と対応コンテンツ

ボットはリクエストが来たスレッドに返信し、エージェントの Markdown をそのままレンダリングし、サーバーの最大投稿サイズに収まるよう長い返信を分割します。返信はストリーミングではなく、エージェントの完了後に一度に投稿されます。

このバージョンはテキストのみに対応します。テキストと添付ファイルを含む投稿はテキストとして扱われます。ファイル・画像などテキストを含まない投稿には、DM の場合とボットを明示的に宛先にした場合に未対応である旨を返します。ボット宛でないチャンネル上のメディアには何も返しません。

入力中インジケーターはありません。Mattermost は WebSocket 経由でのみそれを公開しており、処理中のメッセージに対して Multica から呼べるサーバー側の同等手段がないためです。

## 接続を管理する

**設定 → インテグレーション → Mattermost** で、接続済みボットと各ボットが属するサーバーを確認できます。オーナーと管理者は切断できます。切断すると接続が閉じて送信も止まりますが、Multica の会話と監査記録は保持されます。

## セルフホスト設定

API サーバーを起動する前に、安定した 32 バイトの暗号化キーを設定します。

```dotenv
MULTICA_MATTERMOST_SECRET_KEY=<base64 エンコードされた 32 バイトのキー>
```

`openssl rand -base64 32` で生成できます。長期的に保管してください。紛失やローテーションを行うと保存済みのボットトークンが復号できなくなり、各ボットの再接続が必要になります。

サーバー側に Mattermost のホストは設定しません。各インストールが自身のサーバー URL を持つため、1 つの Multica デプロイで複数の Mattermost サーバー上のボットを扱えます。

連携リンクは `MULTICA_APP_URL`（未設定時は `FRONTEND_ORIGIN`）を使います。生成されるアドレスはメンバーから到達可能である必要があります。

<Callout type="warning">
Multica は Mattermost サーバーとの通信で HTTP リダイレクトを一切追跡しません。設定ミスによるリダイレクトでボットトークンが別のホストに送られることはありません。デプロイでリダイレクト（HTTP から HTTPS など）が発生する場合は、ブラウザーで実際に使う最終 URL を入力してください。
</Callout>

## トラブルシューティング

- **ボットを検証できない**：まずサーバー URL と API サーバーのネットワーク／プロキシ設定を確認します。トークンの再発行が必要なのは Mattermost 自身が拒否した場合だけで、エラーメッセージが両者を区別します。
- **「このトークンはユーザーアカウントのものです」**：個人アクセストークンを貼り付けています。ボットアカウントを作成し、そのトークンを使ってください。
- **チャンネルで返信がない**：ボットがそのチャンネルのメンバーであること、メッセージが `@` メンションしているか、ボットが始めたスレッドへの返信であることを確認します。
- **`@channel` でボットが動かない**：意図した挙動です。ボットは自分の名前にのみ反応するため、ブロードキャストのメンションでチャンネル中のボットが一斉に反応することはありません。
- **連携リンクの期限切れ**：ボットにもう一度 DM を送り、最新のリンクを使ってください。
- **ボットが実行されない**：エージェントがアーカイブされていないか、[ランタイム](/daemon-runtimes)がオンラインかを確認します。
