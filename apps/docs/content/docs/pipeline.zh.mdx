**倡议**是一项业务：一款产品、一条功能线或一次市场试验。你会这样思考它："发票工具进展如何？"它不是项目（一组工作），也不是议题（一项任务）。

倡议沿着**流水线**推进，流水线是固定的阶段序列。每个阶段都有负责的小队，以及必须产出的成果，通常是知识文档。

## 阶段

默认流水线有七个阶段。每个阶段同时也是一个议题状态，因此倡议的关联议题会跟随其进展。

| 阶段 | 初始公司中负责的小队 | 典型成果 |
| --- | --- | --- |
| Validate（验证） | Product Discovery | 验证报告 |
| Define（定义） | Product Analysis | 产品简报、分析 |
| Plan（规划） | Planning | 路线图、预算申请、PRD |
| Build（构建） | Build | 测试报告、候选版本 |
| Launch（发布） | Release & Ops | 发布计划、发布清单 |
| Operate（运营） | Support | 指标报告 |
| Learn（复盘） | Build | 复盘报告 |

发布关卡始终由你决定。规划关卡的批准会批准一份预算申请；运营阶段以一次评审关卡结束，有三种结果：继续、扩大或终止。初始公司会创建这些小队。参见[初始公司](/starter-company)。

## 开始倡议

倡议有两种开始方式：

- **已批准的机会。** 小队提交一份带有论点的 `opportunity` 提案。批准后，会在其目标阶段（默认 `validate`）创建倡议。
- **直接创建。** 在流水线页面创建，或调用 `POST /api/initiatives`。CLI 没有创建命令。

## 看板与倡议面板

**流水线**页面以看板展示，每个阶段一列，每个倡议一张卡片。打开卡片查看面板。面板显示论点、当前阶段和负责小队、所需成果（可对不需要的成果使用 **Waive**，即豁免）、等待你处理的关卡、倡议的评论，以及阶段变更时间线。

管理员还可以把倡议**强制**推进到某个阶段。强制操作会记录在治理日志中。

## 推进倡议

负责小队通过确认阶段来推进。成果齐备后，倡议即会前进。

```bash
multica initiative list
multica initiative show <id>
multica initiative attest <id>   # 由负责小队执行：成果齐备时推进
multica initiative advance <id>  # 在当前阶段允许时越过该阶段
multica initiative shelve <id>   # 暂停倡议；仅限所有者和管理员
```

其他操作通过 API 或应用完成：把倡议退回较早的阶段、关闭倡议，或恢复已暂停的倡议。暂停和关闭都会记录在治理日志中。

关卡需要你的决定。关卡阶段就绪时，系统会提交一份 `stage_gate` 提案。批准后倡议前进；驳回则把倡议退回，并唤醒其负责人。参见[提案](/proposals)。

<Callout type="info">
发布从来不会自动进行。无论自主等级如何，发布关卡都由你决定。参见[自主与授权](/autonomy-and-approvals)。
</Callout>

## 工作成果存放在哪里

倡议产出的文档进入 **ventures**（项目库）知识库，每个倡议一个文件夹。每个阶段的构建和启动都是倡议看板项目中的议题。
