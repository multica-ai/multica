项目用来组织需要多条 [issue](/issues) 一起完成的工作，例如一次产品发布、一次迁移，或一个分阶段推进的功能。

一条 issue 能说清的工作不需要项目。项目适合有共同目标、需要统一跟进进度，或需要共享仓库和工作目录的一组工作。

## 项目的组成

| 内容 | 用途 |
|---|---|
| **名称、图标和描述** | 目标、范围和长期有效的要求；描述会进入项目内智能体的执行上下文。 |
| **状态** | `planned`、`in_progress`、`paused`、`completed` 或 `cancelled`。 |
| **优先级** | `urgent`、`high`、`medium`、`low` 或 `none`。 |
| **负责人（lead）** | 成员或智能体，表示谁负责协调项目。 |
| **开始和截止日期** | 项目计划的时间范围。 |
| **Issue 和进度** | 项目中的工作及其完成比例。 |
| **资源** | 关联的 GitHub 仓库或指定电脑上的本地目录。 |

![项目详情：按状态分列的 issue、进度与项目描述](/images/docs/project-detail.webp)

## 项目和 issue 的关系

一个项目可以包含多条 issue，一条 issue 最多属于一个项目。可以在项目中直接创建 issue，也可以在 issue 属性中选择或更换项目。

项目进度按关联 issue 自动计算：

```text
进度 = 状态为 done 或 cancelled 的 issue 数 ÷ 项目中的全部 issue 数
```

`cancelled` 表示这项工作已从项目范围中结束，因此计入进度。项目状态与 issue 状态彼此独立：所有 issue 完成后项目不会自动变为 `completed`，修改项目状态也不会批量修改其中的 issue。

## 项目描述与执行上下文

智能体执行项目内的 issue 时，项目名称和描述会加入本次执行的上下文。描述适合保存所有相关任务都需要的信息：目标、技术边界、交付约定。只与单条 issue 相关的要求写在该 issue 中。

## 添加资源

项目资源告诉智能体使用哪些代码和工作目录：

- **GitHub 仓库**：提供可 checkout 的仓库和可选 ref。
- **本地目录**：让指定电脑上的运行时在已有目录中工作，目录内容会被智能体直接修改。

具体选择和安全边界见[项目资源](/project-resources)。

## 项目负责人

Lead 可以是成员或智能体，表示谁负责协调项目。它不是权限设置，不会自动分配项目中的 issue；把智能体设为 lead 也不会自动运行它。启动执行仍需分配 issue、@提及或自动化触发。

## 固定到侧边栏

固定后，项目出现在你的侧边栏中。固定是个人偏好，不影响其他成员。

## 创建、编辑和删除

工作区成员都可以创建和编辑项目；只有 `owner` 和 `admin` 可以删除。

<Callout type="warning">
删除项目不会删除其中的 issue：它们解除关联后继续保留在工作区；项目的描述、状态和资源会被永久删除。
</Callout>
