项目用来组织需要多条 [任务](/issues) 一起完成的工作，例如一次产品发布、一次迁移，或一个分阶段推进的功能。

一条任务能说清的工作不需要项目。项目适合有共同目标、需要统一跟进进度，或需要共享仓库和工作目录的一组工作。

## 项目的组成

| 内容 | 用途 |
|---|---|
| **名称、图标和描述** | 目标、范围和长期有效的要求；描述会进入项目内智能体的执行上下文。 |
| **状态** | `planned`、`in_progress`、`paused`、`completed` 或 `cancelled`。 |
| **优先级** | `urgent`、`high`、`medium`、`low` 或 `none`。 |
| **负责人（lead）** | 成员或智能体，表示谁负责协调项目。 |
| **访问权限** | 整个工作区，或仅项目成员。见[私有项目](#private-projects)。 |
| **开始和截止日期** | 项目计划的时间范围。 |
| **任务和进度** | 项目中的工作及其完成比例。 |
| **资源** | 关联的 GitHub 仓库或指定电脑上的本地目录。 |
| **工作流** | 任务经过哪些步骤，以及每一步由谁接手。 |

## 浏览项目

打开**全部项目**，在显示菜单中选择**表格**或**看板**。两种布局都支持搜索，以及按状态、优先级和负责人筛选。可按状态、优先级、负责人或[文件夹](#folders)分组，表格也可不分组。在看板中把项目拖到另一列，会修改对应字段。

表格可显示开始日期、截止日期、进度和最近活动，也可按这些字段、名称、状态、优先级或创建时间排序。布局、分组、排序、显示列和筛选条件按用户与工作区保存，并在设备间同步；搜索文字不保存。

## 项目和任务的关系

一个项目可以包含多条任务，一条任务最多属于一个项目。可以在项目中直接创建任务，也可以在任务属性中选择或更换项目。

项目进度按关联任务自动计算：

```text
进度 = 状态属于 done 或 closed 分类的任务数 ÷ 项目中的全部任务数
```

内置状态里就是 `done` 和 `cancelled`，归入这两个分类的自定义状态也一样计入。`cancelled` 表示这项工作已从项目范围中结束，所以算进进度。

项目状态和任务状态各管各的：所有任务完成后，项目不会自动变为 `completed`；修改项目状态，也不会批量修改其中的任务。

## 项目描述与执行上下文

智能体执行项目内的任务时，项目名称和描述会加入本次执行的上下文。所有相关运行都需要知道的信息写在描述里，比如目标、技术边界、交付约定；只与单条任务相关的要求写在那条任务中。

## 添加资源

项目资源告诉智能体使用哪些代码和工作目录：

- **GitHub 仓库**：提供可 checkout 的仓库和可选 ref。
- **本地目录**：让指定电脑上的运行时使用已有目录：智能体直接修改该目录，或在它的独立 worktree 中工作。

具体选择和安全边界见[项目资源](/project-resources)。

## 选择工作流

项目的**工作流**决定看板有哪些列，以及任务进入每一步时交给谁。例如开发交给一个智能体，审查交给另一个，最后交给成员验收。没有选用其他工作流时，使用 **Default**：所有状态都可用，也不会自动交接。创建流程和切换已有项目的方法见[工作流](/workflows)。

## 项目负责人

项目负责人可以是成员或智能体，担任负责人的成员还可以为项目切换工作流。设置负责人不会把任务分配给它，也不会启动任何工作；想让某一步交给项目负责人，在工作流里把这一步的处理人设为**项目负责人**。

## 私有项目 [#private-projects]

项目的**访问权限**分为**整个工作区**和**仅项目成员**两种。私有项目及其中的任务、评论和附件，只有成员名单里的人能看到。对其他人来说，它不会出现在列表和搜索中，打开链接也会显示不存在。

### 谁能看到私有项目

- **只有成员名单里的人**。工作区角色不带来任何访问权限：不在名单里的 `owner` 或 `admin` 也看不到这个项目。他们和其他人一样被加入名单，也可以被移出。
- **智能体**跟随它所代表的人。只有触发运行的人和智能体的所有者都在名单里，这次运行才能看到私有项目。私有项目中的任务只能分配给所有者在名单里的智能体。
- 成员离开工作区时，会同时离开其中所有私有项目。

<Callout type="info">
如果你是 `owner` 或 `admin`，某个私有项目不再出现，说明你不在它的成员名单里。请管理该项目访问权限的成员把你加进去；工作区所有者也可以在设置中加入（见[工作区所有者恢复访问](#workspace-owner-recovery)）。
</Callout>

### 谁能管理成员名单

管理访问权限包括添加和移除成员、更换项目负责人，以及把项目改回整个工作区可见。以下人可以操作：

- 在名单里的 `owner` 和 `admin`。
- 项目认定的一位访问管理者，在**访问权限**对话框中标为**管理访问权限**：负责人是名单里的人时就是负责人；否则是创建者（如果在名单里）；再否则是在名单里时间最长的成员。

私有项目的负责人和其他项目一样，可以是成员、智能体，也可以留空。访问管理者不单独保存，每次都根据负责人、创建者和名单计算，所以负责人变化或有人离开时会随之改变。把某个人设为负责人会把他加入名单；要把当前负责人移出名单，先更换负责人。其他成员可以查看名单，但不能修改。智能体不能修改任何项目的访问权限。

### 创建私有项目，或把项目改为私有

- **新建项目**：在创建对话框中打开**访问权限**，选择**仅项目成员**并添加成员。你始终在名单里，被设为负责人的人也是。
- **已有项目**：在项目属性中点击**访问权限**，选择**仅项目成员**。把整个工作区可见的项目改为私有需要 `owner` 或 `admin`；操作者会被加入名单，负责人是人时也一起加入。
- **CLI**：给 `project create` 或 `project update` 加上 `--visibility private`，用 `--member`（名称、邮箱或用户 ID，可重复）指定初始名单。之后用 `project member list|add|remove` 管理名单。

```bash
multica project create --title "Pricing revamp" --visibility private --member alice@example.com --member Bob
multica project update <project-id> --visibility private --member alice@example.com
multica project member add <project-id> carol@example.com
```

把私有项目改回**整个工作区**后，`owner`、`admin` 和 `member`都能看到这个项目及其中的任务、评论和附件。访客仍需获邀访问该项目。在界面中保存前会要求确认；`multica project update --visibility workspace` 则直接生效。

### 工作区所有者恢复访问 [#workspace-owner-recovery]

私有项目的名单里可能没有 `owner` 或 `admin`，甚至一个成员都不剩。工作区 `owner` 可以在**设置 → 常规 → 私有项目**中介入，这一部分只有所有者能看到（`admin` 看不到）。这里列出每个私有项目的名称和成员，不显示其他内容：加入之前，任务、评论和附件都看不到。

点击**加入**并确认，即可把自己加入成员名单。你会像其他成员一样出现在名单中，现有成员会收到收件箱通知；作为在名单里的所有者，你可以管理项目的访问权限。加入不会改变负责人。成员全部离开的项目也这样恢复：先加入，再在项目页面管理或删除它。

## 文件夹 [#folders]

文件夹把相关的项目放在一起，比如同一次发布或同一个团队的项目，让侧边栏的项目分区保持简洁。`owner`、`admin` 和 `member` 共享同一组文件夹，都可以新建、重命名、删除文件夹，以及把项目移进移出。一个项目最多属于一个文件夹，文件夹不能嵌套。文件夹只用于整理，不改变谁能看到项目。

- **新建文件夹**：点击侧边栏项目分区的 **+**，选择**新建文件夹**；或在项目菜单中选择**移动到文件夹 → 新建文件夹…**，新建的同时把该项目放进去。
- **移动项目**：在项目菜单中选择**移动到文件夹**，或在侧边栏把项目拖到文件夹上、拖出文件夹。新建项目时可以在创建对话框中选择文件夹；文件夹行上的 **+** 会直接在该文件夹中新建项目。
- **重命名或删除文件夹**：在侧边栏右键点击文件夹。删除文件夹后，其中的项目回到顶层，其他内容不受影响。

侧边栏中哪些文件夹展开、文件夹和项目的排列顺序，都是个人设置，不影响其他成员。项目分区的筛选同样作用于文件夹内部：项目全部被筛掉的文件夹会隐藏，而空文件夹会保留，方便往里放项目。在**全部项目**中按**文件夹**分组，可以按文件夹查看项目；在看板中把项目拖到另一列，会把它移到对应的文件夹。

## 固定到侧边栏

固定后，项目出现在你的侧边栏中。固定是个人偏好，不影响其他成员。

项目分区的设置中，**仅显示默认图标**会把该分区的自定义项目图标显示为默认项目图标。默认关闭，不会修改项目本身的图标。

## 归档和恢复

在项目菜单中选择**归档项目**，或在项目列表中选择**归档**。能编辑项目的人也能归档或恢复它。归档后，项目会从常规项目列表和选择器中隐藏，不能再向其中新建或移入任务。已有任务、历史记录和设置都保留，已有任务仍可查看和编辑，项目状态也不会改变。

向该项目创建任务的已启用自动化会被暂停。恢复时，在项目列表的标题菜单中切换到**已归档的项目**，选择**恢复**，也可在项目页面选择**恢复项目**。恢复项目不会重新启用这些自动化，需要时再单独启用。

## 创建、编辑和删除

`owner`、`admin` 和 `member` 都可以创建和编辑项目。成员可以删除自己或自己当前拥有的智能体创建的项目；智能体只能删除自己创建的项目。人类 `owner` 和 `admin` 可以删除任何项目，包括创建者未知的旧项目。私有项目只有成员名单里的人能编辑或删除，所以 `owner` 或 `admin` 需要先在名单里。

<Callout type="warning">
删除项目不会删除其中的任务：它们解除关联后继续保留在工作区；项目的描述、状态和资源会被永久删除。
</Callout>

## 移到另一个工作区

用 [CLI](/cli#移动项目) 移动单个项目。这是 Draft 功能：移动期间不会拦截普通写入。并发设计确定前，不要在有并发写入时使用。你必须是来源工作区的 `owner`，并且在目标工作区拥有 `owner` 或 `admin` 权限；智能体不能移动项目。

预览会列出阻碍项、成员访问变化、字段映射和来源工作区的清理项。未结束的运行、启用的唤醒规则、绑定项目的自动化、尚未关闭的关联 PR、跨项目任务关系和本地目录资源都会阻止移动，需先处理再确认。

任务、评论、附件和原始作者信息一起移动。标签按名称匹配，状态按生命周期分类回退；无法匹配的自定义属性和选项，以及不属于目标工作区的负责人、lead 和订阅者会被清除。来源工作区的固定项、视图、收件箱条目、未读标记、停用的唤醒规则、已关闭的 PR 关联和聊天项目上下文会被移除。项目改用目标工作区的默认工作流。

任务按原顺序获得目标工作区编号。携带来源工作区 header 调用 `GET /api/moves/resolve?issue=OLD-7` 可解析旧编号：仅属于来源工作区的成员只能看到任务已移动，目标工作区成员还可看到当前位置。移回曾经所属的工作区时，原编号未被占用就会恢复。旧项目引用使用 `?project=<uuid>`。

运行历史保留原智能体。目标工作区成员可以读取任务的运行及消息；删除来源工作区仍会删除其智能体的运行历史和原有用量。附件存储 key 不变；已认证下载按附件当前工作区判断权限，本地 `/uploads/*` 按现有设计保持公开。普通删除后仍保留移动审计和旧编号记录；解析接口只返回仍然存在的对象位置。
