한 작업을 에이전트가 계속 책임져야 한다면 이슈를 해당 에이전트에게 할당하세요. 에이전트는 이슈의 설명과 논의를 읽고 자신의 설정과 스킬을 사용해 작업한 뒤 진행 상황과 결과를 원래 이슈에 기록합니다.

담당자를 바꾸지 않고 에이전트가 특정 요청 하나만 처리하게 하려면 [댓글의 @멘션](/mentioning-agents)을 사용하세요.

## 할당하고 실행 시작

1. 이슈를 열고 **담당자**를 클릭합니다.
2. 에이전트 또는 스쿼드를 선택합니다.
3. 확인 창에서 시작될 에이전트를 확인합니다.
4. 필요하면 인계 설명을 입력한 뒤 **시작**을 선택합니다.

![할당 확인 창: 인계 설명을 입력하거나 지금은 시작하지 않도록 선택할 수 있습니다.](/images/docs/assign-confirm-dialog.webp)

인계 설명은 이번 실행에만 사용됩니다. 범위, 순서, 이번에 특히 주의할 점을 보충하기에 적합합니다. 장기적으로 적용할 요구 사항은 이슈, 프로젝트 설명, 에이전트 지시문에 작성하세요.

스쿼드에 할당하면 이슈 담당자는 스쿼드가 되고 스쿼드 리더가 먼저 실행을 시작합니다. 리더는 스쿼드의 작업 방식에 따라 다른 멤버에게 넘길지 판단합니다.

## 할당 후 실행 과정

Multica가 에이전트의 [실행 태스크](/tasks)를 만듭니다. 온라인 런타임이 태스크를 가져가면 로컬 AI 코딩 도구를 호출하고, 이후 진행 상황, 댓글, 결과가 이슈에 표시됩니다.

런타임이 일시적으로 오프라인이면 태스크는 큐에서 기다립니다. 태스크는 해당 런타임에 연결되어 있으며 다른 컴퓨터로 옮겨 실행되지 않습니다.

에이전트는 실행 중 다음 작업을 할 수 있습니다.

- 이슈의 설명, 속성, 댓글 읽기
- 연결된 스킬, MCP, 프로젝트 컨텍스트 사용
- 로컬 작업 디렉터리에서 파일 읽기, 명령 실행, 내용 수정
- 댓글 작성 및 이슈 상태 업데이트

구체적인 기능은 에이전트 설정, 런타임 환경, 사용자의 호출 권한에 따라 제한됩니다.

## 할당만 하고 지금은 시작하지 않기

확인 창에서 **지금은 시작하지 않기**를 선택하면 담당자만 저장되고 이번 실행 태스크는 생성되지 않습니다. 먼저 담당자를 정하고 배경이나 의존성이 준비된 뒤 시작할 때 적합합니다.

`backlog` 상태에서도 에이전트를 할당하는 것만으로 실행이 시작되지 않습니다. 이슈를 `backlog`에서 다른 상태로 옮기거나 댓글에서 담당자에게 추가 요청을 해야 이후 실행이 생성됩니다.

이 효과는 `backlog` 카테고리에만 적용되며, 그 카테고리의 [사용자 지정 상태](/issues#사용자-지정-상태)도 똑같이 동작합니다. 이미 `done` 또는 `cancelled` 상태인 이슈도 에이전트에게 할당하거나 다시 할당하면 즉시 실행이 시작됩니다.

## 할당 권한

할당 가능 여부는 에이전트의 Access가 결정합니다.

- **나만**: 에이전트 owner만 호출할 수 있습니다.
- **지정한 멤버**: owner와 목록에 포함된 멤버가 호출할 수 있습니다.
- **전체 워크스페이스**: 모든 워크스페이스 멤버가 호출할 수 있습니다.

워크스페이스 owner와 admin은 에이전트를 관리할 수 있지만 "보인다"는 것이 "실행할 수 있다"는 뜻은 아닙니다. 담당자 선택기에서는 호출 권한이 없는 에이전트가 비활성화됩니다. 전체 규칙은 [에이전트](/agents#권한과-access)를 참고하세요.

## 담당자 변경 또는 제거

담당자를 다른 에이전트로 바꾸면 새 담당자의 실행이 새로 시작됩니다. 멤버를 선택하면 담당자만 바뀌고 AI 코딩 도구는 호출되지 않습니다. 담당자를 제거해도 태스크가 생성되지 않습니다.

<Callout type="warning">
담당자 변경, 할당 해제, 이슈 상태 변경은 이미 시작된 실행을 중지하지 않습니다. 중단해야 한다면 실행 로그에서 해당 실행 태스크를 중지하세요.
</Callout>

## CLI 사용

```bash
multica issue assign MUL-42 --to "Agent name"
multica issue assign MUL-42 --to-id <agent-uuid> --no-start
multica issue status MUL-42 in_progress --no-start
multica issue assign MUL-42 --unassign
```

스크립트에서는 `--to-id <uuid>`를 사용하면 이름이 같은 객체를 잘못 매칭하는 일을 피할 수 있습니다. UUID는 `multica agent list --output json` 또는 `multica workspace member list --output json`으로 확인합니다.

할당이 담당자만 기록하고 새 태스크를 만들면 안 되는 경우(예: 같은 에이전트가 다른 실행에서 이미 해당 이슈를 처리 중인 경우)에는 `--no-start`를 사용하세요. `issue update`와 `issue status`에서도 같은 플래그를 사용할 수 있습니다. 담당자와 상태를 모두 바꾸는 소유권 전용 흐름이라면 두 명령 모두에 이 플래그를 전달해야 합니다. 할당을 억제해도 이후 상태 변경이 시작하는 실행까지 자동으로 억제되지는 않습니다.
