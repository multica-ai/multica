Multica 使用你在 [Discord 开发者门户](https://discord.com/developers/applications)创建的 Bot。一个 Bot 对应一个 Multica 智能体；需要多个独立 Bot 身份时，为每个智能体分别创建。

Discord 集成[由社区维护](/community-maintained)：每个版本都会随包发布，但不附带官方支持 SLA。遇到问题请提到 [GitHub 任务](https://github.com/multica-ai/multica/issues)。

## 开始前

- 连接操作需要工作区 owner 或 admin 权限。
- API 服务器必须能够访问 `https://discord.com` 和 `wss://gateway.discord.gg`。
- 你需要 Discord 开发者门户中的 Bot token；它等同于密码。

## 1. 创建 Bot

1. 打开 [Discord 开发者门户](https://discord.com/developers/applications)，新建一个应用。
2. 进入 **Bot**，点击 **Reset Token** 并复制 token。
3. 在 **Privileged Gateway Intents** 中启用 **Message Content Intent**。Multica 通过该 intent 读取消息正文；未启用时，服务器频道消息的正文为空。
4. 在 **OAuth2 → URL Generator** 中选择 `bot` scope 以及 **View Channels**、**Send Messages**、**Read Message History** 权限，打开生成的 URL 把 Bot 邀请到服务器。

<Callout type="warning">
不要把 token 发到任务、聊天、日志或代码仓库。若已泄露，请在 Discord 开发者门户中重置，再用替换后的 token 重新连接。
</Callout>

## 2. 连接到智能体

1. 在 Multica 打开 **智能体**，选择目标智能体并进入 **集成**。
2. 点击 **连接 Discord**。
3. 粘贴 Bot token，然后点击 **连接**。

Multica 会实时请求 Discord 验证 Bot，加密保存 token，并启动一条受监督的 Gateway 连接。一个 Bot 若已连接到其他智能体或工作区，必须先在原处断开。

## 首次使用与账号绑定

成员第一次向 Bot 发消息时，会收到一次性 Multica 账号绑定链接。打开链接，登录同一工作区的 Multica 账号，再回到 Discord 重新发送消息。链接 15 分钟后过期；再私聊 Bot 即可获取新链接。

在服务器频道中，Bot 不会公开发送带凭据性质的绑定链接，只会让发送者先私聊 Bot。

只有当前工作区成员能使用 Bot；每条消息都会重新校验成员身份。

## 使用 Bot

### 私聊

直接打开与 Bot 的私聊发送文字，不需要 @。

### 服务器频道

把 Bot 加入服务器频道后，@它即可。未 @ Bot 的频道消息不会开启对话，也不会形成一轮。每个频道是一段持续的 Multica 对话。

### 命令

- `/new` 创建一个新的空 Multica Chat，并把该 Discord 对话的后续消息路由到新 Chat；`/new <消息>` 会把消息作为新 Chat 的第一轮。
- `/clear` 保留当前 Multica Chat，把新的智能体可见上下文应用到下一条非空消息；`/clear <消息>` 会把消息作为上下文边界后的第一轮。
- `/issue <标题>` 创建 Multica 任务，后续行作为可选描述；不带标题时返回用法提示。

Discord 不会把 `/issue`、`/new`、`/clear` 注册为原生 slash 命令，请作为普通消息文字发送。在服务器频道中需要带上 @：`@YourBot /issue 修复构建`。

### 回复与内容范围

智能体执行结束后，Bot 会把回复发到原频道，并引用触发消息。超长回复会按 Discord 单条 2000 字符的限制分段发送。不支持流式输出或消息编辑。

消息附带的文件只会以 `[File: report.pdf]` 之类的文字标记交给智能体，文件本身不会被下载。智能体暂时无法把文件发回 Discord。

## 管理与断开

在 **设置 → 消息渠道 → Discord** 查看所有已连接 Bot。owner 和 admin 可以断开。断开会关闭 Gateway 连接并停止后续回复，但保留 Multica 对话与审计记录。

## 自托管配置

启动 API 服务器前配置一个长期稳定的 32 字节加密密钥：

```dotenv
MULTICA_DISCORD_SECRET_KEY=<base64 编码的 32 字节密钥>
```

可用 `openssl rand -base64 32` 生成。丢失或轮换此密钥后，已有 Bot token 无法解密，需要逐个重新连接。

绑定链接使用 `MULTICA_APP_URL`，未设置时回退到 `FRONTEND_ORIGIN`；生成的地址必须能被成员访问。服务器网络或代理还必须允许 HTTPS 访问 `discord.com` 和 WebSocket 访问 `gateway.discord.gg`；Go 会读取标准的 `HTTPS_PROXY` 和 `NO_PROXY` 环境变量。

## 故障排查

- **无法验证 Bot**：先检查服务器网络和代理。只有 Discord 明确拒绝 token 时才需要重置。
- **服务器频道消息正文为空**：在 Discord 开发者门户为该应用启用 **Message Content Intent**，然后重新连接。
- **频道里不回复**：确认 Bot 能看到该频道，并且消息 @ 了它。
- **绑定链接过期**：重新私聊 Bot，并使用最新链接。
- **Bot 不执行**：检查智能体是否已归档，以及它使用的[运行时](/daemon-runtimes)是否在线。
