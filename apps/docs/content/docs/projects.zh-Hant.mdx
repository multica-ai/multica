專案用來組織需要多條 [任務](/issues) 一起完成的工作，例如一次產品釋出、一次遷移，或一個分階段推進的功能。

一條任務能說清的工作不需要專案。專案適合有共同目標、需要統一跟進進度，或需要共享倉庫和工作目錄的一組工作。

## 專案的組成

| 內容 | 用途 |
|---|---|
| **名稱、圖示和描述** | 目標、範圍和長期有效的要求；描述會進入專案內 AI 代理的執行上下文。 |
| **狀態** | `planned`、`in_progress`、`paused`、`completed` 或 `cancelled`。 |
| **優先順序** | `urgent`、`high`、`medium`、`low` 或 `none`。 |
| **負責人（lead）** | 成員或 AI 代理，表示誰負責協調專案。 |
| **開始和截止日期** | 專案計劃的時間範圍。 |
| **任務和進度** | 專案中的工作及其完成比例。 |
| **資源** | 關聯的 GitHub 倉庫或指定電腦上的本地目錄。 |
| **工作流** | 任務經過哪些步驟，以及每一步由誰接手。 |

## 專案和任務的關係

一個專案可以包含多條任務，一條任務最多屬於一個專案。可以在專案中直接建立任務，也可以在任務屬性中選擇或更換專案。

專案進度按關聯任務自動計算：

```text
進度 = 狀態屬於 done 或 closed 分類的任務數 ÷ 專案中的全部任務數
```

內建狀態裡就是 `done` 和 `cancelled`，歸入這兩個分類的自定義狀態也一樣計入。`cancelled` 表示這項工作已從專案範圍中結束，所以算進進度。

專案狀態和任務狀態各管各的：所有任務完成後，專案不會自動變為 `completed`；修改專案狀態，也不會批次修改其中的任務。

## 專案描述與執行上下文

AI 代理執行專案內的任務時，專案名稱和描述會加入本次執行的上下文。所有相關執行都需要知道的資訊寫在描述裡，比如目標、技術邊界、交付約定；只與單條任務相關的要求寫在那條任務中。

## 新增資源

專案資源告訴 AI 代理使用哪些程式碼和工作目錄：

- **GitHub 倉庫**：提供可 checkout 的倉庫和可選 ref。
- **本地目錄**：讓指定電腦上的執行時在已有目錄中工作，目錄內容會被 AI 代理直接修改。

具體選擇和安全邊界見[專案資源](/project-resources)。

## 選擇工作流

專案的**工作流**決定看板有哪些列，以及任務進入每一步時交給誰。例如開發交給一個 AI 代理，審查交給另一個，最後交給成員驗收。沒有選用其他工作流時，使用 **Default**：所有狀態都可用，也不會自動交接。建立流程和切換已有專案的方法見[工作流](/workflows)。

## 專案負責人

專案負責人可以是成員或 AI 代理，擔任負責人的成員還可以為專案切換工作流。設定負責人不會把任務分配給它，也不會啟動任何工作；想讓某一步交給專案負責人，在工作流裡把這一步的處理人設為**專案負責人**。

## 固定到側邊欄

固定後，專案出現在你的側邊欄中。固定是個人偏好，不影響其他成員。

## 建立、編輯和刪除

只有 `owner` 和 `admin` 可以建立和刪除專案；任何成員都可以編輯。

<Callout type="warning">
刪除專案不會刪除其中的任務：它們解除關聯後繼續保留在工作區；專案的描述、狀態和資源會被永久刪除。
</Callout>
