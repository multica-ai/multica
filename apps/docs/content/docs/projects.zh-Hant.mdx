專案用來組織需要多條 [任務](/issues) 一起完成的工作，例如一次產品釋出、一次遷移，或一個分階段推進的功能。

一條任務能說清的工作不需要專案。專案適合有共同目標、需要統一跟進進度，或需要共享倉庫和工作目錄的一組工作。

## 專案的組成

| 內容 | 用途 |
|---|---|
| **名稱、圖示和描述** | 目標、範圍和長期有效的要求；描述會進入專案內 AI 代理的執行上下文。 |
| **狀態** | `planned`、`in_progress`、`paused`、`completed` 或 `cancelled`。 |
| **優先順序** | `urgent`、`high`、`medium`、`low` 或 `none`。 |
| **負責人（lead）** | 成員或 AI 代理，表示誰負責協調專案。 |
| **存取權限** | 整個工作區，或僅專案成員。見[私有專案](#private-projects)。 |
| **開始和截止日期** | 專案計劃的時間範圍。 |
| **任務和進度** | 專案中的工作及其完成比例。 |
| **資源** | 關聯的 GitHub 倉庫或指定電腦上的本地目錄。 |
| **工作流** | 任務經過哪些步驟，以及每一步由誰接手。 |

## 瀏覽專案

開啟**全部專案**，在顯示選單中選擇**表格**或**看板**。兩種版面都支援搜尋，以及按狀態、優先順序和負責人篩選。可按狀態、優先順序、負責人或[資料夾](#folders)分組，表格也可不分組。在看板中把專案拖到另一欄，會修改對應欄位。

表格可顯示開始日期、截止日期、進度和最近活動，也可按這些欄位、名稱、狀態、優先順序或建立時間排序。版面、分組、排序、顯示欄和篩選條件按使用者與工作區儲存，並在裝置間同步；搜尋文字不儲存。

## 專案和任務的關係

一個專案可以包含多條任務，一條任務最多屬於一個專案。可以在專案中直接建立任務，也可以在任務屬性中選擇或更換專案。

專案進度按關聯任務自動計算：

```text
進度 = 狀態屬於 done 或 closed 分類的任務數 ÷ 專案中的全部任務數
```

內建狀態裡就是 `done` 和 `cancelled`，歸入這兩個分類的自定義狀態也一樣計入。`cancelled` 表示這項工作已從專案範圍中結束，所以算進進度。

專案狀態和任務狀態各管各的：所有任務完成後，專案不會自動變為 `completed`；修改專案狀態，也不會批次修改其中的任務。

## 專案描述與執行上下文

AI 代理執行專案內的任務時，專案名稱和描述會加入本次執行的上下文。所有相關執行都需要知道的資訊寫在描述裡，比如目標、技術邊界、交付約定；只與單條任務相關的要求寫在那條任務中。

## 新增資源

專案資源告訴 AI 代理使用哪些程式碼和工作目錄：

- **GitHub 倉庫**：提供可 checkout 的倉庫和可選 ref。
- **本地目錄**：讓指定電腦上的執行時使用已有目錄：AI 代理直接修改該目錄，或在它的獨立 worktree 中工作。

具體選擇和安全邊界見[專案資源](/project-resources)。

## 選擇工作流

專案的**工作流**決定看板有哪些列，以及任務進入每一步時交給誰。例如開發交給一個 AI 代理，審查交給另一個，最後交給成員驗收。沒有選用其他工作流時，使用 **Default**：所有狀態都可用，也不會自動交接。建立流程和切換已有專案的方法見[工作流](/workflows)。

## 專案負責人

專案負責人可以是成員或 AI 代理，擔任負責人的成員還可以為專案切換工作流。設定負責人不會把任務分配給它，也不會啟動任何工作；想讓某一步交給專案負責人，在工作流裡把這一步的處理人設為**專案負責人**。

## 私有專案 [#private-projects]

專案的**存取權限**分為**整個工作區**和**僅專案成員**兩種。私有專案及其中的任務、評論和附件，只有成員名單裡的人能看到。對其他人來說，它不會出現在列表和搜尋中，開啟連結也會顯示不存在。

### 誰能看到私有專案

- **只有成員名單裡的人**。工作區角色不帶來任何存取權限：不在名單裡的 `owner` 或 `admin` 也看不到這個專案。他們和其他人一樣被加入名單，也可以被移出。
- **AI 代理**跟隨它所代表的人。只有觸發執行的人和 AI 代理的擁有者都在名單裡，這次執行才能看到私有專案。私有專案中的任務只能分配給擁有者在名單裡的 AI 代理。
- 成員離開工作區時，會同時離開其中所有私有專案。

<Callout type="info">
如果你是 `owner` 或 `admin`，某個私有專案不再出現，說明你不在它的成員名單裡。請管理該專案存取權限的成員把你加進去；工作區擁有者也可以在設定中加入（見[工作區擁有者恢復存取](#workspace-owner-recovery)）。
</Callout>

### 誰能管理成員名單

管理存取權限包括新增和移除成員、更換專案負責人，以及把專案改回整個工作區可見。以下人可以操作：

- 在名單裡的 `owner` 和 `admin`。
- 專案認定的一位存取管理者，在**存取權限**對話框中標為**管理存取權限**：負責人是名單裡的人時就是負責人；否則是建立者（如果在名單裡）；再否則是在名單裡時間最長的成員。

私有專案的負責人和其他專案一樣，可以是成員、AI 代理，也可以留空。存取管理者不單獨儲存，每次都根據負責人、建立者和名單計算，所以負責人變化或有人離開時會隨之改變。把某個人設為負責人會把他加入名單；要把目前的負責人移出名單，先更換負責人。其他成員可以查看名單，但不能修改。AI 代理不能修改任何專案的存取權限。

### 建立私有專案，或把專案改為私有

- **新建專案**：在建立對話框中開啟**存取權限**，選擇**僅專案成員**並新增成員。你始終在名單裡，被設為負責人的人也是。
- **已有專案**：在專案屬性中點選**存取權限**，選擇**僅專案成員**。把整個工作區可見的專案改為私有需要 `owner` 或 `admin`；操作者會被加入名單，負責人是人時也一起加入。
- **CLI**：給 `project create` 或 `project update` 加上 `--visibility private`，用 `--member`（名稱、信箱或使用者 ID，可重複）指定初始名單。之後用 `project member list|add|remove` 管理名單。

```bash
multica project create --title "Pricing revamp" --visibility private --member alice@example.com --member Bob
multica project update <project-id> --visibility private --member alice@example.com
multica project member add <project-id> carol@example.com
```

把私有專案改回**整個工作區**後，所有工作區成員都能看到這個專案及其中的任務、評論和附件。在介面中儲存前會要求確認；`multica project update --visibility workspace` 則直接生效。

### 工作區擁有者恢復存取 [#workspace-owner-recovery]

私有專案的名單裡可能沒有 `owner` 或 `admin`，甚至一個成員都不剩。工作區 `owner` 可以在**設定 → 常規 → 私有專案**中介入，這一部分只有擁有者能看到（`admin` 看不到）。這裡列出每個私有專案的名稱和成員，不顯示其他內容：加入之前，任務、評論和附件都看不到。

點選**加入**並確認，即可把自己加入成員名單。你會像其他成員一樣出現在名單中，現有成員會收到收件箱通知；作為在名單裡的擁有者，你可以管理專案的存取權限。加入不會改變負責人。成員全部離開的專案也這樣恢復：先加入，再在專案頁面管理或刪除它。

## 資料夾 [#folders]

資料夾把相關的專案放在一起，例如同一次發布或同一個團隊的專案，讓側邊欄的專案區塊保持簡潔。資料夾是整個工作區共用的：所有成員看到同樣的資料夾，任何成員都可以新增、重新命名、刪除資料夾，以及把專案移進移出。一個專案最多屬於一個資料夾，資料夾不能巢狀。資料夾只用於整理，不改變誰能看到專案。

- **新增資料夾**：點擊側邊欄專案區塊的 **+**，選擇**新增資料夾**；或在專案選單中選擇**移動到資料夾 → 新增資料夾…**，新增的同時把該專案放進去。
- **移動專案**：在專案選單中選擇**移動到資料夾**，或在側邊欄把專案拖到資料夾上、拖出資料夾。新增專案時可以在建立對話框中選擇資料夾；資料夾列上的 **+** 會直接在該資料夾中新增專案。
- **重新命名或刪除資料夾**：在側邊欄右鍵點擊資料夾。刪除資料夾後，其中的專案回到最上層，其他內容不受影響。

側邊欄中哪些資料夾展開、資料夾和專案的排列順序，都是個人設定，不影響其他成員。專案區塊的篩選同樣作用於資料夾內部：專案全部被篩掉的資料夾會隱藏，而空資料夾會保留，方便往裡放專案。在**全部專案**中按**資料夾**分組，可以按資料夾檢視專案；在看板中把專案拖到另一欄，會把它移到對應的資料夾。

## 固定到側邊欄

固定後，專案出現在你的側邊欄中。固定是個人偏好，不影響其他成員。

專案區塊的設定中，**僅顯示預設圖示**會把該區塊的自訂專案圖示顯示為預設專案圖示。預設關閉，不會修改專案本身的圖示。

## 歸檔和恢復

在專案選單中選擇**歸檔專案**，或在專案列表中選擇**歸檔**。能編輯專案的人也能歸檔或恢復它。歸檔後，專案會從一般專案列表和選擇器中隱藏，不能再向其中建立或移入任務。已有任務、歷史記錄和設定都保留，已有任務仍可檢視和編輯，專案狀態也不會改變。

向該專案建立任務的已啟用自動化會被暫停。恢復時，在專案列表的標題選單中切換到**已歸檔的專案**，選擇**還原**，也可在專案頁面選擇**還原專案**。恢復專案不會重新啟用這些自動化，需要時再單獨啟用。

## 建立、編輯和刪除

工作區成員都可以建立和編輯專案。成員可以刪除自己或自己目前擁有的 AI 代理建立的專案；AI 代理只能刪除自己建立的專案。人類 `owner` 和 `admin` 可以刪除任何專案，包括建立者未知的舊專案。私有專案只有成員名單裡的人能編輯或刪除，所以 `owner` 或 `admin` 需要先在名單裡。

<Callout type="warning">
刪除專案不會刪除其中的任務：它們解除關聯後繼續保留在工作區；專案的描述、狀態和資源會被永久刪除。
</Callout>
