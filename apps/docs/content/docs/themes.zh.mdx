**设置 → 外观** 决定 Multica 在当前设备上的样子：模式、主题、文字和布局。所有改动立即生效。

<Callout type="info">
  主题和主题商店目前是 Beta。Multica 发版后，一个原本正常的主题可能需要作者更新。
</Callout>

## 模式与主题

**模式** 可选浅色、深色或跟随系统。也可以在搜索框（`⌘K`）里输入"主题"切换。

**主题** 决定全局的颜色、边框、阴影和圆角。Multica 自带 Default、Pop、GitHub、Blueprint 和 Notion；在下拉框里直接选，或者点 **管理** 带预览查看所有主题。一个主题可能支持浅色、深色或两者都支持，并跟随你选的模式。

有些主题带选项，比如强调色或页面宽度。使用这个主题时，选项会出现在 **主题选项** 里；**恢复主题默认** 把选项恢复成主题的默认值。

页面上的其他设置与主题无关：

| 分组 | 设置什么 |
|---|---|
| **界面文字** | 菜单、按钮、列表、侧边栏和标题的字体与字号。 |
| **内容文字** | 任务描述、评论、聊天和文档的字体、字号和行高，以及代码字体。 |
| **布局与辅助功能** | 信息密度、减少动态效果、提高对比度。 |

选了非默认的字体，或者打开了提高对比度时，以你的选择为准，而不是主题的。颜色由主题决定；想要主题没有提供选项的颜色，换一个主题，或者[自己做一个](/developers/themes)。

## 主题商店

**管理** 打开一个窗口，列出所有主题：内置主题、当前设备上的主题和社区主题商店。可以按名称或作者搜索，打开 **只看已安装** 隐藏没装的主题。

商店里每个主题是一张卡片：截图（在角落切换浅色和深色截图）、作者、描述、下载次数，以及它的 GitHub 仓库链接。没装的主题按下载次数从多到少排列。

<Steps>
<Step>

### 安装

点卡片上的 **安装**。主题会被下载、检查、保存到当前设备，并立即使用。

</Step>
<Step>

### 切换

在任意已安装或内置的主题上点 **使用**。正在用的主题标着 **使用中**。

</Step>
<Step>

### 移除

在已安装的主题上点 **移除**。如果它正在使用，Multica 会回到 Default。

</Step>
</Steps>

商店主题由社区制作，上架前会经过自动检查：不能运行代码，不能从网络加载任何东西，也不能使用主题以外的文件。但主题仍然可以改变每个页面的样式，包括弹窗和警告。

下载次数包含每一次安装和每一次更新，统计的是使用同一个 Multica 服务端的所有人。

## 更新

装过商店主题后，外观页会出现 **商店主题** 一行。点 **检查更新** 查找新版本，然后点 **全部更新**；也可以在卡片上用 **更新到 …** 单独更新一个主题。更新会保留主题的选项值，也不会改变你当前在用的主题。

主题不会在你不知情的情况下自动更新。

## 导入主题

别人发给你的主题文件，或者你自己做的主题，从 **制作自己的主题 → 导入主题** 安装：

- **主题文件（.zip）** 安装压缩包形式的主题。
- **主题文件夹** 安装解压后的主题。

安装前，Multica 会显示主题的名称、作者和版本。只安装你信任的人做的主题。导入一个与已安装主题 id 相同的主题，会替换它。

想从头做一个主题，见[制作主题](/developers/themes)。

## 主题出问题时

主题可能隐藏或弄乱界面的一部分。回到 Default 有两种方法：

- 在地址末尾加上 `?theme=default` 打开 Multica；
- 页面加载完后立刻按住 **Shift** 一会儿。桌面端先用 `⌘R`（Windows 和 Linux 上是 `Ctrl+R`）重新加载，再按住 **Shift**。

关闭窗口前，主题会一直暂停。外观页会显示一条提示，点 **恢复我的主题** 重新启用；你也可以在那里换一个主题，或者移除出问题的主题。

## 保存在哪里

模式、主题、主题选项和已安装的主题都保存在当前设备上，不会同步到账号。每个浏览器、每个桌面端各有一份，同一设备上的所有工作区共用。

## 自托管

自托管的服务端默认读取官方仓库 [multica-ai/multica-themes](https://github.com/multica-ai/multica-themes)。服务端从 GitHub 拉取主题和截图并缓存，应用从你的服务端下载。下载次数按服务端分别统计。

| 变量 | 作用 |
|---|---|
| `MULTICA_THEME_STORE` | 设为 `off` 关闭主题商店。之后 **管理** 只列出各设备上已有的主题，服务端也不再请求仓库。 |
| `MULTICA_THEME_REGISTRY_URL` | 让主题商店改读另一个仓库的 `index.json`，比如官方仓库的 fork。 |

服务端的其他配置见[环境变量](/environment-variables)。
