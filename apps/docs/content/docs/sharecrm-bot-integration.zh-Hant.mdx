把任意[AI 代理](/agents)接入一個紛享銷客 Bot，團隊就能在紛享銷客裡直接使用它——私聊 Bot、在群裡 @ 它，或者輸入 `/issue` 直接建立一個 [Multica 任務](/issues)，不用開啟應用。

紛享銷客整合[由社群維護](/community-maintained)：每個版本都會隨包釋出，但不附帶官方支援 SLA。遇到問題請提到 [GitHub 任務](https://github.com/multica-ai/multica/issues)。

紛享銷客走的是**自帶應用（bring-your-own-app，BYO）**模式：工作區管理員在紛享銷客開放平臺建立機器人憑據，再把它的憑據貼上進 Multica。每個 AI 代理都有**它自己的**紛享銷客機器人——所以多個 AI 代理可以在同一個組織裡各自擁有一個獨立、可單獨 @ 的 Bot。（這一點和 [Lark](/lark-bot-integration) 不同，Lark 的繫結是掃碼安裝流程。）

整個設定流程在下面，大約五分鐘。最後你會得到兩個憑據貼上進 Multica：

- 一個 **App ID** —— 機器人應用的 client id
- 一個 **App Secret** —— 機器人應用的 client secret

私有化部署可選填 **API 地址**（預設 `https://open.fxiaoke.com`）。

## 設定你的紛享銷客機器人

### 1. 在紛享銷客開放平臺建立機器人憑據

1. 用管理員帳號開啟[紛享銷客開放平臺](https://open.fxiaoke.com)（或你的私有化控制檯）。
2. 建立（或開啟）Multica 將連線的那個機器人應用。
3. 複製該應用的 **App ID** 和 **App Secret**。
4. 確認機器人可以**接收訊息**（私聊與群 @）並**傳送回覆**。Multica 透過 SSE 長連線**主動向外**連線——你**不需要**為聊天配置任何公網 webhook URL。

這就是 Multica 在平臺層所需的一切：

| 配置項 | 為什麼需要它 |
|---|---|
| **機器人應用** | 簽發 Multica 鑑權用的 App ID / App Secret。 |
| **接收訊息** | 讓機器人能收到單聊訊息，以及群裡 @ 了它的訊息（群訊息在到達 Multica 前已由紛享銷客側過濾）。 |
| **傳送訊息** | 讓機器人能把 AI 代理回覆和提示發回同一會話。 |
| **SSE 長連線** | Multica 主動撥出並保持推送連線——**無需任何公網 webhook / URL** 接收聊天訊息。 |

這裡**既沒有 Multica 側的 webhook URL，也沒有 OAuth 重定向 URL**，因為機器人跑在 SSE 長連線上，而 BYO 不使用 OAuth。

<Callout type="info">
紛享銷客沒有原生的「正在輸入」指示器，所以——和釘釘一樣——Bot 會在開始處理時先回一條簡短的「正在處理」提示，完整回覆在 AI 代理處理完後送達。短時間內連發的多條訊息會合併為一條提示。
</Callout>

### 2. 在 Multica 裡連線它

1. 在 **Agents → _你的 AI 代理_** 開啟該 AI 代理 → **Integrations** tab（或左側欄的 **Integrations** 區塊）。
2. 點選 **連線紛享銷客**。
3. 貼上 **App ID** 和 **App Secret**。公有雲請把 **API 地址** 留空；私有化部署則填你的 API 主機。
4. 點選 **連線**。Multica 會用該 API 地址校驗憑據（換取 token）。
5. AI 代理顯示 **已連線到紛享銷客**。Bot 現在透過它自己的 SSE 連線在監聽了。

<Callout type="warning">
這兩個憑據必須來自**同一個**紛享銷客機器人應用，而那個應用恰好對應**一個** AI 代理。連線一個已經連到別的 AI 代理或工作區的 App ID 會被拒絕。要把一個機器人挪到另一個 AI 代理，先斷開它；用一個**新的** App ID 重新連線某個 AI 代理，會就地更新那個 AI 代理的 Bot。
</Callout>

<Callout type="info">
要給**多個 AI 代理**做這套設定？每個 AI 代理都把整套流程走一遍——每個 AI 代理都有自己的一對 App ID / App Secret，它們會顯示成各自獨立的 Bot。
</Callout>

## 這個整合能做什麼

| 入口 | 行為 |
|---|---|
| **AI 代理 → Integrations** | 所有者和管理員能看到 **連線紛享銷客**；連線後它會變成一個 **已連線到紛享銷客** 徽標，並帶一個 **斷開連線** 操作。 |
| **私聊 Bot** | 工作區成員在單聊裡直接給 Bot 發訊息。這段對話會成為該 AI 代理的一個 Multica [chat](/chat) 會話；每一條訊息都會被讀取。 |
| **群裡 @ 它** | 把 Bot 加進群再 @ 它。只有紛享銷客投遞給 Bot 的訊息會被讀取——Bot 不會監聽整個群。 |
| **圖片** | 私聊和群 @ 都可以發圖片（PNG、JPEG、GIF、WebP、BMP）。檔案和語音不會交給 AI 代理。 |
| **`/issue` 命令** | 以 `/issue <標題>` 開頭，會按輸入直接、同步地以你的身份建立 Multica 任務，並在原對話中返回任務編號和標題；後續行會作為描述。同一條訊息裡的圖片也會作為附件加到任務上。這條命令不會出現在 Multica Chat；新建任務是 Multica 中記錄的處理結果。 |
| **`/new` 命令** | 傳送 `/new` 會建立一個新的空 Multica Chat，後續紛享銷客訊息會路由到新 Chat。傳送 `/new <你的訊息>` 會建立新 Chat，並把訊息作為第一輪。之前的 Chat 仍儲存在 Multica 中，可以繼續使用。 |
| **`/clear` 命令** | 傳送 `/clear` 會保留當前 Multica Chat，並把新的 AI 代理可見上下文應用到下一條訊息。傳送 `/clear <你的訊息>` 會把訊息作為邊界後的第一輪。完整 Chat 歷史仍會顯示在 Multica 中。 |
| **回覆** | AI 代理的答覆會被以純文字發回同一個單聊或群裡（交付時會去掉 Markdown）。 |

## 使用 Bot（成員）

### 第一條訊息：繫結你的帳號

第一次**私聊** Bot 時，它會回一條 **繫結你的帳號** 提示，指向產品內的 **/sharecrm/bind** 頁面。點開連結、登入 Multica，你的紛享銷客身份就會繫結到你的 Multica 成員身份——正是這一步讓 AI 代理能以你的身份行事（比如 `/issue` 會把任務記在你名下）。這個連結是一次性的，大約 15 分鐘後過期。約一分鐘內再發訊息會指向已傳送的連結，而不會重新生成；視窗過後再發訊息才會拿到新連結。繫結連結**不會**發到群裡——請先開啟 1:1 私聊。

如果還沒繫結就先在**群裡** @ Bot，它會在群裡提示你去單聊完成繫結。繫結連結**不會**發到群裡（它是一次性憑據，只在 1:1 會話中下發）。

<Callout type="warning">
只有**工作區成員**才能使用 Bot。如果你不是成員，或者跳過了身份繫結，Bot 不會執行——你的訊息會被丟棄（僅出於審計目的記錄，不儲存訊息內容）。
</Callout>

### 對話與命令

- **在群裡** —— 把 Bot 加進群，然後 `@your-bot <你的訊息>`。每次追問都要重新 @ 它一下（Bot 只接收紛享銷客路由給它的訊息）。
- **在單聊裡** —— 開啟 Bot 並直接給它發訊息；不用 @，每一條訊息都會被讀取。
- **傳送圖片** —— 在私聊或群 @ 裡傳送 PNG、JPEG、GIF、WebP 或 BMP 圖片（每條最多 8 張，每張不超過 10 MB）。檔案和語音暫不支援。AI 代理回覆仍是純文字。
- **建立任務** —— 傳送 `/issue Safari 上登入跳轉壞了`，需要時可在後續行補充描述。同一條訊息裡的圖片會作為附件加到任務上。Multica 會同步建立任務，並在聊天中返回編號和標題。
- **新建 Chat** —— 傳送 `/new` 會建立一個新的空 Multica Chat，後續紛享銷客訊息會路由到新 Chat；也可以傳送 `/new <你的訊息>`，把訊息作為第一輪。之前的 Chat 仍儲存在 Multica 中，可以繼續使用。
- **清空上下文** —— 傳送 `/clear` 會保留當前 Multica Chat，並把新的 AI 代理可見上下文應用到下一條訊息；也可以傳送 `/clear <你的訊息>`，把訊息作為邊界後的第一輪。完整 Chat 歷史仍會顯示在 Multica 中。

## 管理與斷開

工作區級別的管理在 **設定 → 訊息渠道 → 紛享銷客**：

- **Connected bots** 列出工作區裡每個 Bot 以及它各自繫結的 AI 代理（所有成員都能看到）。
- **Disconnect** 僅限 **所有者 / 管理員**。它會讓 Bot 停止接收紛享銷客訊息並拆掉它的連線；安裝記錄會保留以便審計，之後你可以重新連線。

## 權限

- **連線 / 斷開** 需要工作區**所有者**或**管理員**。
- **和 Bot 對話** 需要你是工作區成員、已繫結紛享銷客身份，並擁有目標 AI 代理的執行權限。不滿足這些條件的訊息會被拒絕。
- 對於被丟棄的訊息，絕不儲存訊息內容——只記錄一個丟棄原因，用於審計。

## 自託管配置 [#自部署配置]

在 Multica Cloud 上這個整合已經可用——可跳過本節。

自託管時，**在你設定好靜態加密金鑰之前，紛享銷客是關閉的**。這個金鑰會在每個機器人的 App Secret 落庫前對其加密；App ID 作為非敏感的安裝路由標識明文儲存。BYO 在部署層面**不需要** OAuth client id/secret——每個安裝用的都是管理員貼上進來的那對憑據。

1. 生成一個 32 位元組的金鑰並設定到 API 伺服器：

   ```dotenv
   MULTICA_SHARECRM_SECRET_KEY=<base64-encoded 32-byte key>
   ```

   例如：`openssl rand -base64 32`。

2. 重啟 API。在金鑰設定好之前，**設定 → 訊息渠道 → 紛享銷客** 會顯示一條「紛享銷客整合未啟用」提示，**連線紛享銷客** 入口也會保持隱藏。

<Callout type="info">
這個金鑰必須正好解碼出 32 位元組——`openssl rand -base64 32` 就能做到。把它當成一個長期有效的金鑰：輪換或丟失它會讓已儲存的憑據無法解密，迫使每個 Bot 重新連線。「繫結你的帳號」連結是用你的 Web 應用地址（`MULTICA_APP_URL`，未設定時回退到 `FRONTEND_ORIGIN`）拼出來的——正常部署裡這個值本來就有，聊天側無需額外配置。成員在瀏覽器裡開啟繫結連結時，需要能訪問該 URL。
</Callout>

同一個 App ID 同一時間只允許**一條**活躍的 SSE 連線。Multica 的 channel supervisor 會為每個安裝分配租約，由單個後端副本持有連線；多副本部署時，只有持有租約的副本保持流。
