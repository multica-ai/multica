既存の DingTalk 接続は、DM と @メンションを割り当て済み[エージェント](/agents)へ送り続けます。`/issue`、`/new`、画像、本人確認、検出済みグループの実行も維持されます。

<Callout type="info">
  新しいエージェント単位の DingTalk 接続とグループ再割り当ては廃止されました。既存接続とルートマッピングは実行互換性のため維持されます。
</Callout>

## 既存 Bot を使う

- DM は割り当て済みエージェントとの Multica [Chat](/chat) になります。
- グループでは Bot を @メンションしたメッセージだけが、保持されたグループルートで実行されます。
- 対象メッセージの画像は Multica ストレージへコピーされます。
- **`/issue <タイトル>`** は紐づけ済みメンバー名義でイシューを作成します。
- **`/new <メッセージ>`** は履歴を保ったまま以前の文脈なしで実行します。

最初の対象メッセージで一度だけ使える `/dingtalk/bind` URL が返る場合があります。正しいワークスペースへサインインして開いてください。この本人確認コールバックは独立した契約です。

## 保持された接続を管理する

**Settings → Integrations** で既存 Bot と割り当て済みエージェントを確認できます。検出済みグループルートは読み取り専用で、新しい再割り当ては廃止済みです。workspace owner と admin は接続を切断できます。会話と監査記録は保持されます。

割り当て済みエージェントをアーカイブすると、復元されるまでそのルートの処理は停止します。

## セルフホスト

既存の暗号化済み認証情報には `MULTICA_DINGTALK_SECRET_KEY` が必要です。保存済み認証情報を読めなくしないようキーを安定して保持してください。Stream mode は外向きに接続するため、公開 webhook URL は不要です。

## トラブルシューティング

- **新規接続やルート選択がない**: エージェント単位の writer は廃止済みです。
- **Bot が応答しない**: 接続、割り当て済みエージェント、[Runtime](/daemon-runtimes) を確認してください。
