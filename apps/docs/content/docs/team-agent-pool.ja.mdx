このガイドは、各自がターミナルで自分のエージェントを動かすのではなく、AI コーディングエージェントを共有したい複数の開発者のチームを対象にしています。別々のページで説明している機能をつなげて紹介します。[ロール](/members-roles)、エージェントの [Access](/agents#権限と-access)、[ランタイムの共有](/daemon-runtimes#プライベートと公開)、[スクワッド](/squads)、[ワークフロー](/workflows)です。

Multica のワークスペースでは、メンバーとエージェントが同じタスクを扱います。どのタスクも人、エージェント、スクワッドのいずれにも割り当てられます。エージェントは進捗をコメントで報告し、成果を渡すときにタスクを `in_review` に移し、すべての実行がタスクに記録されます。

## それぞれの役割

| チームがしたいこと | 使うもの | 設定する場所 |
|---|---|---|
| 人とエージェントのすべての作業を 1 か所で見る | 1 つのワークスペース。リスト、ボード、テーブル、ガント、スイムレーンのレイアウト | [タスク](/issues) |
| ワークスペースに誰が所属し、何を管理できるかを決める | ロール：`owner`、`admin`、`member`、プロジェクト単位のゲスト | [メンバーとロール](/members-roles) |
| 特定のエージェントを誰が実行できるかを決める | エージェントの Access：**プライベート**、**ワークスペースに公開**、**特定のメンバーに公開** | [エージェント](/agents#権限と-access) |
| エージェントが動くコンピューターを共有する | プライベート、公開、または特定のメンバーと共有するランタイム | [ランタイムの共有](/daemon-runtimes#プライベートと公開) |
| 毎回エージェントを選ばずに、適切なエージェントへ作業を渡す | リーダーエージェントが各タスクを振り分けるスクワッド | [スクワッド](/squads) |
| 作業をエージェントからレビュー担当へ渡し、差し戻す | レビューのステータス、コメント、ワークフローの引き継ぎ | [ワークフロー](/workflows) |
| チームのやり方を複数のエージェントで再利用する | エージェントに付けるスキル | [スキル](/skills) |
| 誰かが始めなくても定期的な作業を実行する | スケジュールや webhook で動くオートパイロット | [オートパイロット](/autopilots) |
| コストと失敗に目を配る | エージェントごとの使用量とエラーのレポート | [分析](/analytics) |

## 例：10 人のエンジニアリングチーム

以下の手順で、10 人の開発者が 3 つのエージェントを共有する構成を作ります。名前や人数はチームに合わせて変えてください。

1. **ワークスペースを作ってメンバーを招待する。** `owner` または `admin` が開発者を `member` として招待し、1〜2 人のリードを `admin` にします。1 つのプロジェクトだけを追う業務委託の人は、そのプロジェクトを共有した[ゲスト](/members-roles#ゲスト)として参加します。
2. **コンピューターを接続する。** 自分のマシンでエージェントを動かしたい開発者は [Multica Desktop](/desktop-app) を開きます。そのマシンがランタイムとして登録されます。チーム全体が頼るエージェントには、クラウド VM などの共用マシンを `multica setup` で接続し、その所有者がランタイムを公開するか、特定のメンバーと共有します。ランタイムを共有すると他の人もそこでエージェントを実行できますが、AI コーディングツールのログインは共有されません。
3. **共有エージェントを作る。** たとえば Claude Code の **Frontend** エージェント、Codex の **Backend** エージェント、別のツールの **Reviewer** エージェントを、すべて共用ランタイム上に作ります。指示を書き、チームの[スキル](/skills)を付けます。誰でも使ってよいエージェントは Access を**ワークスペースに公開**に、機密性の高い認証情報を持つエージェントは**特定のメンバーに公開**にします。
4. **スクワッドを作る。** 3 つのエージェントをスクワッドにまとめ、リーダーエージェントを決めます。メンバーはタスクをスクワッドに割り当て、リーダーが担当を選びます。
5. **レビューを組み込む。** プロジェクトで**開発デリバリー**などの[ワークフロー](/workflows)を選びます。開発はエンジニアリングエージェント、レビューは Reviewer エージェント、QA はメンバーが担当します。
6. **割り当てを始める。** 開発者はタスクを作り、エージェント、スクワッド、チームメイトのいずれかに割り当てます。エージェントは共用ランタイムで作業し、結果を各タスクに残します。

個人の試行は他の人の邪魔になりません。開発者が自分のノートパソコンで**プライベート**にしているエージェントは、ほかの人の選択肢に表示されません。

## メンバーごとに使えるエージェントをどう管理するか

各エージェントには owner と Access 設定があります。Access は、そのエージェントを誰が実行できるか、つまりタスクの割り当て、@メンション、チャットを誰ができるかを決めます。

| Access | 実行できる人 |
|---|---|
| **プライベート**（既定） | エージェントの owner だけ。 |
| **ワークスペースに公開** | ロールが `owner`、`admin`、`member` のいずれかのメンバー。 |
| **特定のメンバーに公開** | エージェントの owner と選んだメンバー。 |

チームで特に重要なルール：

- ワークスペースの `owner` と `admin` はすべてのエージェントを表示・管理できますが、許可されていないエージェントをロールの権限で実行することはできません。Access を変更できるのはエージェントの owner だけです。
- ゲストはエージェントを実行することも @メンションすることもできません。
- 担当者の選択肢と @メンションのメニューには、その人が実行できるエージェントだけが表示されます。
- スクワッドで権限が広がることはありません。スクワッドに割り当てたり @メンションしたりするには、そのリーダーを実行できる必要があります。
- メンバーを削除すると、ほかのエージェントの Access リストでその人に与えられていた許可も消えます。
- エージェントの環境変数に入れた認証情報を表示できるのはワークスペースの `owner` と `admin` だけで、読み取りのたびに監査ログに記録されます。[環境変数と認証情報](/agents-create#環境変数と認証情報)を参照してください。

プライベートプロジェクトは 2 つ目の境界になります。プライベートプロジェクトはメンバーリストに載っている人にだけ表示され、エージェントの実行からも、実行を始めた人とエージェントの owner の両方がリストに載っている場合にだけ見えます。[プライベートプロジェクト](/projects#private-projects)を参照してください。

## 人とエージェントはどう作業を引き継ぐか

引き継ぎは割り当てとコメントで行い、各ステップの間のコンテキストはタスクに残ります。

1. **エージェントがコードを書く。** タスクをエージェントに割り当てます。エージェントは開始時に `in_progress` にし、途中でコメントを残し、成果を渡すときに `in_review` にします。通常は pull request が付きます。
2. **チームメイトがレビューする。** レビュー担当は、タスク上で実行の実行ログとリンクされた PR を確認します。[GitHub 連携](/github-integration)を使うと、タスクに PR の状態、CI の結果、コンフリクトが表示されます。
3. **エージェントがレビュー指摘を直す。** レビュー担当はタスクに返信し、そのエージェントか別のエージェントを @メンションして、直す内容を伝えます。メンションされたエージェントは、これまでの議論を含めて同じタスクを引き受けます。まだ実行中なら、返信を[今の実行に届ける](/mentioning-agents#実行中のエージェントに割り込む)こともできます。
4. **作業を閉じる。** 既定では、エージェントは `in_review` で止まります。`done` にするのは人か GitHub 連携です。GitHub 連携は既定で、リンクされたすべての PR がマージされるとタスクを `done` にします。

この手順を場当たり的でなく固定したい場合は、[ワークフロー](/workflows)を使います。各ステータスをエージェントかメンバーに任せ、そのステップの指示と、**完了したら移動**する先と**差し戻す先**を設定します。これで、タスクがレビューに入るとレビュー用エージェントに渡り、差し戻されると開発に戻ります。

## 各エージェントが何をしているかをどう把握するか

- サイドバーの**実行中**ビューに、ワークスペース全体でいまエージェントが実行中のタスクが並びます。
- エージェント一覧に、各エージェントの稼働状態（ランタイムから取得）と負荷（作業中、待機中、アイドル）が表示されます。
- 各タスクには、すべての実行の実行ログ（ツール呼び出し、コマンド、エラーとタイムスタンプ）が残ります。[実行](/tasks)を参照してください。
- [インボックス](/inbox)は、作業が自分に割り当てられたとき、エージェントが自分を @メンションしたとき、フォロー中のタスクにコメントしたとき、実行が失敗したときに知らせます。すべてのステップを通知するわけではありません。
- [分析](/analytics)には、ワークスペースのコスト、トークン、実行時間、失敗した実行が表示され、エージェントごとのランキングと失敗の理由も確認できます。

<Callout type="info">
一般のメンバーには、他の人の**プライベート**のエージェントは表示されません。その使用量は分析の「その他のエージェント」の行に、名前なしでまとめて表示されます。
</Callout>
