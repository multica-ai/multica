어떤 작업은 중간에 기다릴 수밖에 없습니다. 공급업체의 견적, 동료의 답변, 하위 태스크의 완료를 기다리는 경우입니다. 이럴 때 태스크에 **깨우기** 규칙을 추가합니다. "이 일이 생기면 이 에이전트를 깨워서 이것을 하게 한다"는 규칙입니다. 조건이 맞으면 에이전트는 그 태스크에서 일반 실행을 시작해 최신 상황을 읽고, 결과는 평소처럼 댓글로 남깁니다.

규칙은 태스크에 저장되므로 기다리는 동안 돌아가는 실행은 없습니다. 멤버는 태스크 사이드바에서 깨우기를 만들고, 에이전트는 실행 중에 [CLI](#cli)로 다음 확인을 예약합니다. 두 방법 모두 같은 종류의 규칙을 만듭니다.

## 깨우기 만들기 [#create]

<Steps>
<Step>

태스크를 열고 사이드바 **깨우기** 영역 오른쪽의 **+**를 클릭합니다.

</Step>
<Step>

**조건**에서 조건을 고르고 시간, 기다릴 사람, 기다릴 상태처럼 그 조건에 필요한 값을 채웁니다.

</Step>
<Step>

**깨울 대상**에서 에이전트를 고릅니다. 태스크 담당자가 에이전트라면 이미 선택되어 있습니다. 런타임에 연결되어 있고 내가 실행할 권한이 있는 에이전트만 고를 수 있습니다. [권한과 Access](/agents#권한과-access)를 참고하세요.

</Step>
<Step>

**깨운 후 수행할 일**에 지시를 씁니다. 예: "공급업체 견적이 다 왔는지 확인하고, 다 왔으면 비교표로 정리해 주세요." 최대 12,000바이트입니다. 나중에 수정할 수 있으며, 수정한 내용은 이후 깨우기에만 적용됩니다.

</Step>
<Step>

**만들기**를 클릭합니다.

</Step>
</Steps>

깨우기가 시작한 실행은 규칙을 만든 사람을 대신해 동작합니다. 실행이 시작되기 전에 Multica는 그 사람이 아직 이 에이전트를 실행할 수 있는지 다시 확인합니다.

아래 태스크에서 운영 도우미는 견적을 요청해 두고 공급업체의 회신을 기다리고 있습니다. 깨우기를 추가한 뒤 깨우는 시각으로 건너뛰어 보세요. '정기 확인'을 고르면 아직 아무것도 오지 않은 날 에이전트가 댓글 없이 확인을 끝내는 모습도 볼 수 있습니다.

## 기다릴 수 있는 것 [#conditions]

| 그룹 | 조건 | 깨우는 때 |
|---|---|---|
| 시간 | 특정 시각 | 10분 후, 1시간 후, 내일 09:00, 또는 직접 정한 시간. 한 번만 깨웁니다. |
| 시간 | 정기 확인 | 매시간, 매일 09:00, 평일 09:00 중 하나이며 내 시간대로 계산합니다. 종료일이 꼭 필요하고, 그날이 끝나면 멈춥니다. |
| 협업 | 누군가 답글 | 태스크에 새 댓글이 달렸을 때. 특정 멤버나 에이전트로 좁힐 수 있습니다. |
| 협업 | 필드가 특정 값으로 바뀜 | 태스크의 상태, 담당자, 라벨, 사용자 지정 속성이 정한 값이 되었을 때. |
| 실행과 하위 태스크 | 에이전트 실행 종료 | 이 태스크에서 특정 에이전트(또는 아무 에이전트)의 실행이 성공, 실패, 취소되었을 때. |
| 실행과 하위 태스크 | 하위 태스크 완료 | 모든 하위 태스크가 닫혔을 때(`done` 또는 `cancelled`), 또는 정한 단계까지가 모두 닫혔을 때. 하위 태스크가 없으면 트리거되지 않습니다. |
| 연결 | 연결된 PR의 CI 종료 | PR 병합이나 병합 충돌도 고를 수 있습니다. 이 태스크에 직접 연결된 PR만 보며, 여러 개라면 하나만 맞아도 됩니다. CI와 충돌은 GitHub PR에서만 동작합니다. |
| 연결 | 다른 태스크의 상태 | 다른 태스크가 완료, 완료 또는 취소, 검토 중이 되었을 때. |
| | 사용자 지정 이벤트 | 반응, 첨부 파일, 댓글 수정, 스레드 해결 등 25가지 원본 이벤트 중에서 고릅니다. |

필드, 하위 태스크, PR, 다른 태스크 조건은 Multica가 직접 확인합니다. 만들 때 이미 조건이 맞는다면 다음 확인(약 30초 이내)에서 깨웁니다. CI만 예외로, 규칙을 만든 뒤에 끝난 검사만 셉니다.

시간 외의 조건은 "어떤 일이 생기기를 기다리는" 규칙이며, 설정이 세 가지 더 있습니다.

- **트리거 횟수**: 기본은 **한 번만 트리거**입니다. **반복 깨우기**로 바꾸면 **최대** 횟수(5, 10, 20, 50회, 기본 20회)도 정합니다.
- **최대 대기**: 1, 3, 7, 30일 중 하나이며 기본은 7일입니다.
- **시간 초과 시**: 기본은 에이전트를 깨워 처리하게 하며, 기다리던 일이 일어나지 않았다는 사실이 전달됩니다. **그대로 종료**를 고를 수도 있습니다.

태스크 담당자가 에이전트라면 멤버의 댓글이 원래 그 에이전트를 트리거합니다. 같은 에이전트에게 '누군가 답글' 깨우기를 더해도 실행이 늘지 않고, 댓글로 시작된 실행에 합쳐질 뿐입니다. 지시를 덧붙이고 싶을 때만 쓰세요.

## 깨운 뒤 [#after-wake]

- 에이전트는 태스크에서 일반 실행을 시작해 태스크, 댓글, 깨우기 지시를 읽고, 마지막에 댓글 하나를 남깁니다. 댓글에는 '깨우기' 태그와 조건이 붙고, [실행 로그](/tasks)에도 같은 계기가 표시됩니다.
- 정기 확인에서 답할 만한 일이 없으면 에이전트는 **조용한 확인**으로 끝낼 수 있습니다. 댓글은 남기지 않고, 태스크 타임라인과 규칙의 실행 기록에 메모만 남깁니다. 연달아 이어진 조용한 확인은 타임라인에서 한 줄로 합쳐집니다.
- 에이전트가 직접 남긴 댓글이나 태스크 변경으로는 그 에이전트가 깨어나지 않습니다.
- 같은 에이전트의 실행이 이 태스크에서 시작을 기다리고 있으면, 깨우기는 그 실행에 합쳐지고 실행을 하나 더 만들지 않습니다.
- 깨우기가 기다리는 동안 태스크 헤더에 "운영 도우미: 답글 대기"처럼 태스크가 무엇을 기다리는지 표시됩니다. 클릭하면 깨우기 영역으로 이동합니다.

## 확인하고 관리하기 [#manage]

사이드바의 깨우기 영역에는 이 태스크의 규칙이 나열됩니다. 조건, 깨울 대상, 다음 실행 시각, 남은 시간이 보입니다. 규칙을 클릭하면 출처, 유효 기간, 지시, **실행 기록**(최근 실행, 댓글을 남겼는지, 조용한 확인 내용)을 볼 수 있습니다.

| 작업 | 결과 |
|---|---|
| 스위치 끄기 | 이후 깨우기를 멈추고 아직 시작하지 않은 실행을 거둬들입니다. 이미 시작한 실행은 계속되므로, 필요하면 실행 로그에서 중지합니다. |
| **지금 깨우기** | 조건을 기다리지 않고 이 규칙으로 지금 한 번 깨웁니다. |
| 지시 수정 | 이후 깨우기에만 적용되며 진행 중인 실행은 그대로입니다. |
| **삭제** | 규칙이 더는 깨우지 않습니다. 시작하지 않은 실행은 거둬들이고, 시작한 실행은 계속됩니다. |
| **다시 활성화** / **시간 다시 설정** | 한 번만 트리거되는 규칙을 실행 후 다시 켭니다. 특정 시각 규칙은 새 시간을 고릅니다. |

끝난 규칙은 **깨우기 기록**으로 옮겨집니다. 규칙은 만든 사람과 워크스페이스 owner, admin만 관리할 수 있습니다. 에이전트가 실행 중에 만든 깨우기는 그 실행을 시작한 멤버의 것으로 기록되며 "운영 도우미 생성 (리레이 대리)"처럼 표시됩니다.

워크스페이스 전체의 깨우기는 **오토파일럿** 페이지의 **작업 깨우기** 탭에서 볼 수 있습니다. 상태(깨우기 대기 또는 실행 중, 일시중지됨, 꺼짐, 종료됨), 트리거 방식, 출처, 에이전트로 거르고, 여러 개를 한 번에 끄거나, 태스크를 먼저 고른 뒤 새로 만들 수 있습니다.

## 자동으로 끝나거나 멈추는 경우 [#limits]

- 태스크가 완료되거나 취소되면 그 태스크의 깨우기가 모두 꺼지고, 아직 시작하지 않은 실행은 거둬들입니다. 태스크를 다시 열어도 되살아나지 않습니다. 완료되거나 취소된 태스크에는 깨우기를 만들 수 없습니다.
- 기다리는 규칙이 **최대 대기**에 이르면 **시간 초과 시** 설정대로 처리합니다. 정기 확인은 종료일에 멈춥니다.
- 반복 규칙은 최대 횟수에 이르면 자동으로 일시중지됩니다. 기다리는 규칙은 다른 깨우기와 서로를 깨울 때(사람이 끼지 않은 채 트리거 연쇄가 세 번째로 그 규칙을 지날 때), 그리고 1시간 안에 12번 넘게 트리거될 때도 일시중지됩니다. 일시중지된 규칙은 누군가 다시 켤 때까지 꺼져 있고, 횟수는 처음부터 다시 셉니다.
- 태스크 하나에 동시에 켜 둘 수 있는 깨우기는 32개, 워크스페이스 전체로는 1,000개까지입니다.

## 하위 태스크가 끝나면 상위 태스크 깨우기 [#child-done]

하위 태스크가 있는 태스크의 깨우기 영역에는 **시스템** 표시가 붙은 규칙이 나타납니다. 따로 만들 필요는 없습니다.

- 한 단계의 하위 태스크가 모두 닫히고 뒤 단계가 아직 기다리고 있으면 상위 태스크의 담당자를 깨웁니다. 모든 하위 태스크가 닫히면 한 번 더 깨웁니다. 단계가 없는 하위 태스크는 마지막 하나가 닫힐 때 한 번 깨웁니다.
- 담당자가 에이전트면 그 에이전트를, 스쿼드면 리더를 깨웁니다. 멤버에게는 대신 인박스 알림을 보냅니다. 담당자가 없으면 아무도 깨우지 않습니다.
- 상위 태스크가 `backlog`에 있는 동안은 깨우지 않고, `backlog`를 벗어나면 한 번 몰아서 깨웁니다.
- 기본 지시는 어떤 단계가 닫혔고 다음 단계가 무엇인지 알려 주며, 의존성을 확인한 뒤 다음 단계의 하위 태스크를 `backlog`에서 꺼내라고 합니다. 모두 닫히면 결과를 상위 태스크에 모으게 합니다.

상위 태스크의 담당자는 이미 이 규칙으로 깨어나므로, 같은 목적으로 '하위 태스크 완료' 깨우기를 더할 필요는 없습니다. 단계를 나누는 방법은 [태스크](/issues#프로젝트와-하위-태스크)를 참고하세요.

태스크 하나에서는 워크스페이스 멤버 누구나 이 규칙을 끄거나 지시(최대 4,000바이트)를 바꿀 수 있습니다. 에이전트는 바꿀 수 없습니다. 바꾼 태스크는 더는 워크스페이스 기본값을 따르지 않습니다.

워크스페이스 owner와 admin은 **설정 → 깨우기**에서 기본값을 정합니다. 기본으로 켤지(처음에는 켜져 있음)와 기본 지시입니다. 기본 지시를 비워 두면 내장 지시를 씁니다. 이 페이지에는 자체 설정을 쓰는 진행 중 태스크 수도 표시됩니다.

## 에이전트가 직접 예약하게 하기 [#cli]

에이전트는 실행 중에 `multica issue wakeup`으로 이 태스크의 다음 실행을 예약하고 지금 실행을 마칩니다. `--agent-id`를 빼면 명령을 실행한 에이전트 자신을 깨웁니다. 내 터미널에서도 같은 명령을 쓸 수 있으며, 이때는 `--agent-id`로 에이전트를 지정합니다.

```bash
# 내일 09:00(상하이 시간)에 다시 보기
multica issue wakeup create OPS-56 --kind at --at 2026-10-21T09:00:00+08:00 \
  --instruction "공급업체 견적이 다 왔는지 확인하고, 다 왔으면 비교표로 정리"

# 평일 매일 09:00에 확인하고, 일주일 뒤 끝내기
multica issue wakeup create OPS-56 --kind cron --cron "0 9 * * 1-5" --timezone Asia/Shanghai \
  --expires-in 168h --instruction "견적 메일을 확인하고 새 견적이 있으면 비교표 업데이트"

# 리레이의 답글을 최대 3일 기다리고, 시간이 지나도 한 번 깨우기
multica issue wakeup create OPS-56 --event comment.created \
  --filter-actor-type member --filter-actor-id <리레이의 사용자 ID> \
  --expires-in 72h --on-timeout wake --instruction "리레이의 답변에 따라 이어서 진행"

# 태스크가 검토 중이 될 때까지 기다리기
multica issue wakeup create OPS-56 --until-status in_review --instruction "결과물을 확인하고 정리"
```

- **시간**: `--kind at`에 `--after 10m` 또는 `--at <RFC3339 시간>`. `--kind every --every 1h`는 고정 간격(최소 1분). `--kind cron --cron "<5개 필드 표현식>"`에는 `--timezone`을 붙입니다(기본 UTC).
- **이벤트**: `--event` 뒤에 이벤트 이름을 쉼표로 구분해 씁니다. `multica issue wakeup events`가 모든 이벤트와 필터를 보여 줍니다. `--mode continuous`는 반복 깨우기로 만듭니다.
- **조건**: `--until-status`, `--until-assignee`, `--until-label`, `--until-property`, `--until-children-done [--stage N]`, `--until-pr checks|merged|conflicts`, `--until-issue <태스크> --until-issue-state done|ended|in_review|blocked`. 깨우기 하나에 `--until-*`는 하나만 쓸 수 있고 `--event`와 함께 쓸 수 없습니다.
- **끝내는 방법**: CLI는 대기 기한을 자동으로 붙이지 않습니다. `--expires-in 72h`나 `--expires-at <RFC3339 시간>`으로 끝을 정하세요. `--on-timeout wake`를 붙이면 이벤트 규칙이 기한이 되었을 때 한 번 더 깨웁니다. `--max-fires N`(1–1000)은 반복 규칙의 실행 횟수에 상한을 둡니다.
- **답이 남는 곳**: `--parent <댓글 ID>`를 붙이면 깨운 뒤의 답글이 원래 스레드에 남습니다.

기존 규칙 관리:

| 명령 | 하는 일 |
|---|---|
| `multica issue wakeup list <태스크>` | 태스크의 깨우기 목록 |
| `multica issue wakeup get <태스크> <깨우기 ID>` | 깨우기 하나의 전체 설정 보기 |
| `multica issue wakeup runs <태스크> <깨우기 ID>` | 최근 실행, 트리거 이유, 조용한 확인 메모, 댓글 여부 |
| `multica issue wakeup update <태스크> <깨우기 ID>` | `create`와 같은 플래그로 전체 설정을 바꾸고 다시 켜기 |
| `multica issue wakeup disable <태스크> <깨우기 ID>` | 끄고 아직 시작하지 않은 실행 거둬들이기 |
| `multica issue wakeup trigger <태스크> <깨우기 ID>` | 지금 한 번 깨우기 |
| `multica issue wakeup delete <태스크> <깨우기 ID>` | 규칙을 삭제하고 아직 시작하지 않은 실행 거둬들이기 |
| `multica issue wakeup checkin <태스크> <깨우기 ID> --note "..."` | 답할 일이 없는 정기 확인을 조용히 끝내기. 이 규칙이 시작한 실행에서만 호출 가능 |

`list`, `get`, `runs`에 `--output table`을 붙이면 표로 출력합니다. 다른 명령은 [CLI 사용](/cli)을 참고하세요.

## 오토파일럿과의 차이 [#vs-autopilots]

[오토파일럿](/autopilots)은 일정이나 Webhook으로 새 작업을 반복해서 시작하며, 그때마다 태스크를 새로 만들 수 있습니다. 깨우기는 이미 있는 태스크 하나에 붙어, 정한 시각이나 어떤 일이 생긴 뒤 에이전트를 그 태스크로 돌려보내고, 태스크가 끝나면 함께 끝납니다.
