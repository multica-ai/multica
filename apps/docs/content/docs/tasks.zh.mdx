智能体每开始一次工作，Multica 就创建一条**运行记录**，写明这次运行由什么触发、交给了哪个智能体、进行到哪里、最后是否成功。

## 任务与运行

任务保存一项工作的目标、讨论、负责人和最终状态；运行记录智能体对这项工作的一次执行。

| | 任务 | 运行 |
| --- | --- | --- |
| 记录什么 | 一项持续推进的工作 | 智能体的一次执行 |
| 持续多久 | 可以反复讨论、补充和重新分配 | 从触发开始，到完成、失败或取消为止 |
| 数量关系 | 一个任务可以包含多次运行 | 每次运行都有独立记录 |

同一个任务可以先后交给不同的智能体，也可以在失败后重新运行。每次都产生一条新的运行记录，旧记录不会被覆盖。

## 触发来源

以下操作会触发一次执行：

- 把任务分配给智能体或小队。
- 在评论中提及智能体。
- 在对话中向智能体发送消息。
- 由自动化按计划或外部事件触发。
- [任务唤醒](/issue-wakeups)的事件、时间或条件到了。

入口不同，智能体拿到的上下文也不同，执行方式则是一样的：Multica 创建运行，运行时领取它，再调用智能体配置的 AI 编程工具。

## 执行过程

一次运行通常会经过以下状态：

| 状态 | 表示什么 |
| --- | --- |
| `deferred` | 已安排稍后触发，到达指定时间后进入队列 |
| `queued` | 正在等待运行时领取 |
| `dispatched` | 运行时已经领取，正在启动 AI 编程工具 |
| `waiting_local_directory` | 目标本地目录正被另一条执行占用，等待目录锁释放 |
| `running` | AI 编程工具正在执行 |
| `completed` | 这次执行已正常结束 |
| `failed` | 执行出错或中断 |
| `cancelled` | 执行被手动停止 |

运行时在线时，新运行通常很快开始；运行入队后运行时离线，运行会留在队列中等它恢复。排得久不会让运行过期：运行时还在发心跳，就说明它只是忙，积压的运行可以一直排下去。排队中的运行要**同时**满足两个条件才会失败：绑定的运行时心跳缺席超过重连宽限期，**并且**这条运行自己也已经排队满这么久。第二个条件照顾的是"指派给一台已经休眠的机器"的情况：运行不会立刻失败，你有完整的一个宽限期把机器唤醒。

<Callout type="info">
如果触发前系统已经知道目标运行时离线，部分即时操作会直接提示当前无法运行，不再创建一条没人能领取的运行。
</Callout>

心跳正常的运行时可以执行长时间运行，服务器不会仅因为运行时间较长就强制结束它。运行时会根据实际活动判断进程是否已经卡住；相关设置见[环境变量](/environment-variables#守护进程配置)。

## 查看执行记录

任务产生的所有运行都列在任务右侧栏的**执行日志**里。这一段默认展开：进行中的运行固定在最上面，下面是**最近**结束的 3 次运行；更早的记录点**打开时间线**查看。每一行显示触发来源、执行智能体和状态。没看到这一段时，用任务顶部的面板按钮打开右侧栏；窗口较窄时它默认收起。

页面开着时，执行日志通过实时连接自动更新，新的运行、状态变化和智能体的评论会直接出现，不用手动刷新。

智能体工作期间，任务顶部还有一个实时状态条，例如 "Engineer 在工作"。悬停可以看到同样的进行中运行，不用离开当前页面。

在执行日志里：

- 点击某一行的 **查看记录**，查看智能体的消息、工具调用和错误信息。运行还在进行时，弹窗开着的这段时间内容会实时追加，也可以用 **最新在前**切换事件顺序。
- 停止排队中、启动中、等待本地目录或正在工作的运行。
- 对失败或已取消的运行发起重试。

## 失败与自动重试

运行时短暂离线、守护进程重启、执行超时或 AI 编程工具网络中断等临时故障，可以触发自动重试。普通运行默认最多执行两次；工具网络中断最多执行三次。

智能体自身返回的错误通常不会自动重试。鉴权失效、额度不足、配置错误、模型无法完成请求，都要先处理原因，再手动重试。

自动化的**仅运行**模式不会自动重试，以免和下一次计划执行重叠。**创建任务**模式产生的是普通任务运行，基础设施故障仍按上面的规则重试。两种模式都可以在自动化运行历史中查看最终结果。

当一条任务上没有其他活动运行，也没有新的重试等待执行时，失败会让处于 `in_progress` 的任务回到 `todo`。

## 失败原因参考

执行日志和[统计](/analytics#错误页签)里的失败原因分两类：不带前缀的原因码由平台记录，`agent_error.*` 由 AI 编程工具的报错归类而来。

<Tab value="平台侧" id="platform-reasons">

| 原因 | 含义 | 处理 |
| --- | --- | --- |
| `runtime_offline` | 执行期间运行时离线 | 恢复运行时后重试，见[守护进程与运行时](/daemon-runtimes) |
| `queued_expired` | 运行时心跳缺席超过重连宽限期，且该运行也已排队满这么久 | 确认运行时在线后重试 |
| `runtime_recovery` | 守护进程重启后回收了中断的执行 | 直接重试 |
| `environment_prepare_failed` | 守护进程没能准备好本次执行的运行环境——工作目录，或写入其中的本地运行时配置 | 先看原始错误定位是哪一步失败，再检查那台机器：磁盘空间、权限、目录是否仍被占用，或 AI 编程工具的本地配置 |
| `cancelled` | 被手动停止，或随归档、删除一并取消 | 无需处理 |
| `timeout` | 超过守护进程配置的执行时长上限 | 缩小任务范围，或调整守护进程的 `agent_timeout` |
| `iteration_limit` | 达到执行轮次上限 | 缩小任务范围 |
| `agent_blocked` | 智能体主动报告无法继续 | 按它在评论中的说明补充信息 |
| `api_invalid_request` | 平台 API 拒绝了非法请求 | 重试；反复出现时报告问题 |
| `codex_semantic_inactivity` | Codex 长时间无有效输出被判停滞 | 重试，或调整 Codex 停滞超时 |

</Tab>

| `process_failure` | 工具进程异常退出 | 查看执行日志定位后重试 |
| `empty_or_unparseable_output` | 工具无输出或输出无法解析 | 重试；反复出现时检查工具安装 |
| `agent_timeout` | 工具长时间无响应被终止 | 重试或缩小任务范围 |
| `unknown` | 未能归类的失败 | 查看执行日志中的原始报错 |

## 手动重试

在执行日志中点击某一行的重试按钮，会再次调用**当时负责这次运行的智能体**。即使任务后来换了负责人，也不会改用新负责人。

重试会尽量保留上一次已经写入本地目录的文件。原会话仍然安全、又由同一个运行时领取时，会接着之前的会话继续。上下文溢出、无效请求这类会污染会话的错误，会在原工作目录上开新会话；原目录已经不存在时，改用新的工作目录。

通过 CLI 找到原运行，再重试：

```bash
multica issue runs <issue-id> --full-id
multica issue rerun-task <run-id>
```

使用完整运行 UUID 时可以省略 `--issue`；短 ID 前缀必须用 `--issue` 指定任务。命令会沿用原智能体和触发上下文，会话与目录的复用规则和重试按钮相同。添加 `--fresh` 可从新的会话和工作目录开始。

旧命令 `multica issue rerun <issue-id>` 已弃用，并从帮助列表中隐藏。现有脚本仍可使用它，行为保持为让当前负责人从新会话和工作目录开始。

## 运行完成与任务完成

`completed` 只表示这一次运行正常结束，不代表任务的目标已经确认达成。运行结束后，仍然可以检查结果、继续讨论、补充要求或再次触发智能体；任务是否完成，看它的状态。

## 状态与超时速查

以下数字是服务器的默认配置。

| 状态 | 含义 | 超时与后果 |
| --- | --- | --- |
| `deferred` | 已安排稍后触发 | 到达预定时间后进入 `queued`，再按下面的规则计时 |
| `queued` | 等待运行时领取 | 只要运行时还在心跳就一直等待，并且无论如何都会在入队后至少保留一个重连宽限期；两个窗口都过去才会失败，且不会自动重试 |
| `dispatched` | 运行时已领取，正在启动工具 | 停留超过 **5 分钟**按失败处理 |
| `waiting_local_directory` | 等待本地目录锁释放 | 没有独立超时；目录释放后回到启动流程 |
| `running` | AI 编程工具正在执行 | 不设固定时长上限；以运行时心跳判定存活，心跳每 15 秒一次，失去心跳的运行时最迟约 3 分钟被判为离线。其上的运行要等心跳缺席超过重连宽限期（`MULTICA_RUNTIME_RECONNECT_GRACE`，默认 3 小时）才失败；守护进程重启时，会直接回收这些运行 |

自动重试只覆盖以下临时故障，且仅适用于挂在任务或对话上的运行（自动化**仅运行**模式除外）：

| 可自动重试的失败原因 | 执行次数上限 |
| --- | --- |
| 运行时离线 | 默认 2 次（首次执行 + 1 次重试） |
| 守护进程重启后回收 | 默认 2 次 |
| 平台判定执行超时 | 默认 2 次 |
| Codex 长时间无有效输出 | 默认 2 次 |
| Skill 包下载失败 | 默认 2 次（此时智能体进程尚未启动，已下载的包走本地缓存） |
| 工具网络中断 | 最多 3 次，最后一次延迟约 5 秒发起 |

其余失败原因（鉴权、额度、配置、模型等）都不会自动重试，需要先处理原因再手动重试。
