Multica の iOS クライアントはまだ App Store にありません。Mac で公開されているソースリポジトリから Release 版をビルドし、自分の iPhone にインストールできます。Android では同じ React Native クライアントから署名済みのスタンドアロン APK をビルドできます。

インストールしたアプリはデフォルトで Multica Cloud に接続し、既存のアカウントでそのままサインインできます。ワークスペース、タスク、コメント、実行履歴はすべてサーバー側に保存されるため、Web や Desktop から同期する必要はありません。

ワークスペースとプロジェクトのタスク一覧は全ページを読み込み、同じステータス順でグループ化します。ステータスの見出しをタップすると折りたたみ・展開でき、件数は常に表示されます。子タスクがある場合、詳細画面のアクティビティの上に識別子、タイトル、ステータスが並び、タップして開けます。

## Android APK

JDK 17 と Android SDK 36 を準備し、リポジトリ外に Release 署名鍵を設定してから、ルートで実行します：

```bash
pnpm -C apps/mobile android:release
```

APK は既定で Multica Cloud に接続し、Metro は不要です。署名、環境切り替え、セルフホスト接続とインストール確認は [Android ビルドガイド](https://github.com/multica-ai/multica/blob/main/apps/mobile/docs/android-release.md)を参照してください。バックグラウンドのプッシュ通知は含まれません。以下は iPhone の手順です。

## 事前準備

必要なもの:

- Xcode をインストールした Mac。
- **Xcode → Settings → Accounts** でサインイン済みの Apple ID。
- USB で接続した iPhone。
- iPhone の **設定 → プライバシーとセキュリティ** でデベロッパモードを有効にしておくこと。
- Node.js、pnpm、Git。

Xcode や実機の開発環境がまだ設定されていない場合は、先に Expo の [iOS デバイスの環境セットアップ](https://docs.expo.dev/get-started/set-up-your-environment/)を完了してください。

## iPhone へのインストール

<Steps>
<Step>
リポジトリをクローンして依存関係をインストールします:

```bash
git clone https://github.com/multica-ai/multica.git
cd multica
pnpm install
```
</Step>
<Step>
リポジトリのルートから実行します:

```bash
pnpm ios:mobile:device:prod:release
```

これは Metro に依存しない Release 版をビルドし、接続中の iPhone にインストールします。初回ビルドは iOS の依存関係をダウンロードして React Native をコンパイルするため時間がかかりますが、以降は Xcode のキャッシュを再利用します。
</Step>
<Step>
iPhone でアプリを開きます。起動がブロックされた場合は、**設定 → 一般 → VPN とデバイス管理** で対応する開発者証明書を信頼してください。
</Step>
</Steps>

## 無料署名の 7 日制限

無料の Apple ID で署名したアプリは 7 日間しか使えません。期限が切れたら、iPhone を Mac に接続し直し、同じビルドコマンドをもう一度実行すれば再署名できます。

Apple Developer Program アカウントで署名すると有効期間が長くなり、TestFlight や正式な配布にも使えます。どちらの署名でも、再インストールや再署名によってサーバー側のデータが失われることはありません。

## 署名の失敗

Xcode が `No matching provisioning profiles found` と報告する場合、デフォルトの bundle identifier があなたの Apple ID に属していない可能性があります。自分が管理する逆ドメイン名に切り替えて再ビルドしてください:

```bash
export EXPO_BUNDLE_IDENTIFIER_PROD=com.yourname.multica
pnpm ios:mobile:device:prod:release
```

この値はあなたの Apple Developer team で利用できれば十分で、Multica のアカウントやワークスペースには影響しません。

## 更新

自分でインストールした iOS ビルドは自動更新されません。最新のコードを取得し、依存関係を更新して再ビルドします:

```bash
git pull --ff-only
pnpm install
pnpm ios:mobile:device:prod:release
```

## セルフホストインスタンスへの接続

ログイン画面の **Server settings**、またはログイン後の **Settings → Server settings** を開きます。**API URL**（バックエンドのルート）と **Web URL**（ブラウザーとリンクのアドレス）を入力して保存します。同一オリジンと別ホストの両方に対応し、再起動後も保持されます。再ビルドは不要です。**Restore Cloud defaults** を選んで保存すると Multica Cloud に戻ります。

両方のアドレスには、端末が信頼する証明書を持つ HTTPS が必要です。カスタムポートとベースパスに対応します。例：API `https://multica.example.com:8443/backend`、Web `https://multica.example.com:8443/app`。API アドレス末尾の `/api` は除去され、リクエストパス側で追加されます。`/auth` と `/ws` も同じバックエンドルートを使います。配布 APK は HTTP や証明書検証の回避に対応しません。`localhost` は端末自身を指します。

どちらかのアドレスを変更するとログアウトし、ローカルの下書き、ワークスペース選択、キャッシュを消去します。選択したインスタンスで再ログインしてください。サーバー側のデータは元のインスタンスに残ります。添付ファイルと画像には選択したサーバーから新しい署名 URL を取得し、セッショントークンを外部ブラウザーに渡しません。

開発ビルドと初回インストール時の既定値は [`apps/mobile/README.md`](https://github.com/multica-ai/multica/blob/main/apps/mobile/README.md) を参照してください。
