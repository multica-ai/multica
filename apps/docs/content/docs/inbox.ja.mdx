インボックスは、あなたに関係する作業の動きを集め、注意が必要な変化がどこで起きたかを知らせます。完全なアクティビティログではなく、経緯は対応するタスクに残っています。

## インボックスの場所

インボックスは **作業** パネルのセクションで、ピン留め済みの下、ビューとプロジェクトの上にあります。ピン留めがないときは最初のセクションになります。未読数はセクション名の横と、アプリレールの **作業** のバッジに表示されます。**作業** を右クリックすると **すべて既読にする** を使えます。

セクションにはタスクごとに 1 行ずつ、新しい順に、既読・未読を問わず並びます。行にはタスクのステータス、タイトルと時刻、誰が何をしたかが表示され、未読の行にはドットが付きます。行にカーソルを合わせると、タイトル全文とコメントを表示するカードが開き、**開く**、**既読にする**、**アーカイブ** を使えます。

スマートフォンでは、作業パネルはドロワーの中にあります。そのインボックスセクションの末尾にある **すべての通知** から、独自のリストとフィルターを持つインボックスページを開けます。

## インボックスに届くもの

主な通知は次のとおりです。

- タスクがあなたに割り当てられた、またはあなたから外された
- 購読中のタスクに新しいコメントが付いた、または担当者・優先度・日付が変わった（他の人のタスクは既定で重要な更新のみ。後述）
- 購読中のタスクのステータスが変わった（既定でオフの **ステータス変更** をオンにした場合）
- タスクの説明やコメントで誰かがあなたを @メンションした
- あなたが作成したタスクやコメントにリアクションが付いた
- 購読中のタスクでエージェントの実行が失敗した
- 購読中のプロジェクトでタスクが作成された
- [エージェント経由のタスク作成](/issues#エージェントで作成)が完了または失敗した
- 購読中のオートパイロットが新しいタスクを作成した、または連続した失敗により一時停止された

自分の操作は自分には通知されません。同じタスクの複数の通知は 1 行にまとめられ、開くとそのタスクの最近の変化を確認できます。

## 自動購読の発生源

次の関係者はタスクを自動的に購読します。

- タスクの作成者
- 新しい担当者
- コメントした人
- タスクの説明で新たに @メンションされた人
- オートパイロットで事前設定された購読メンバー

担当者が変わっても、既存の購読は解除されません。タスクのページでいつでも購読・購読解除できます。購読解除後は通常の更新はインボックスに届かなくなりますが、あなたへの直接の @メンションは引き続き個別に通知されます。

<Callout type="info">
**ステータス変更** がオンなら、サブタスクのステータスが変わると親タスクの購読者にも通知されます。サブタスクのコメント、優先度、日付の変更は親タスクには伝わりません。
</Callout>

## 他の人のタスク

他の人やその人のエージェントに割り当てられたタスクでは、作成・コメント・メンションによって自動的に購読した場合、既定で重要な更新だけが届きます。あなたへの @メンション、参加したスレッドへの返信、そして（**ステータス変更** がオンなら）`in_review`・`blocked`・`done` など人の確認が必要なステータスです。通常のコメントやその他の変更はタスクに残ります。自分で購読したタスク、プロジェクト経由で購読しているタスク、あなたやあなたのエージェントに割り当てられたタスクには、オンにしている種類の通知が引き続きすべて届きます。

タスクのページでは、こうした購読に **重要な更新のみ** と表示されます。メニューの **すべてのアクティビティを受け取る** を選ぶと、このタスクの明示的な購読に変わります。その後このタスクを重要な更新のみに戻す方法はなく、購読解除だけが可能です。**デフォルトを変更** は **設定 → 通知** を開きます。**購読中のタスク** の先頭にある **他の人のタスク** を **すべてのアクティビティ** にすると、こうしたタスクすべてにアクティビティが届くようになります。

## エージェントとインボックス

インボックスの通知はワークスペースメンバーに属します。実行を開始した上流のユーザーがランタイム所有者本人であるとサーバーが確認できた場合だけ、エージェントはその所有者の通知を読み取り、処理できます。このユーザー情報はエージェントの委任チェーンで引き継がれます。この規則はインボックスのすべての操作に適用されます。アクティブ一覧、アーカイブ、スヌーズ中の一覧、未読件数、そしてすべての変更です。他の人が開始した実行、開始した人を確認できない実行、タスクとの紐付けがないクラウドノードの認証情報は拒否されます。エージェントが読み取る未読件数は実行中のワークスペースのものだけで、所有者の他のワークスペースは含みません。通知を削除できるのは人だけです。エージェントによる変更は、どのエージェントがどの実行で誰の代わりに行ったかとともにサーバーに記録されます。

コメントでの @メンション、タスクの割り当て、オートパイロットのトリガーは、直接実行を作成し、エージェントに通知は残しません。`@all` もメンバーにのみ通知します。

## CLI から管理する

既存の CLI ログインで通知を読み取り、処理できます。一覧表示で既読になることはありません。

```sh
multica inbox count
multica inbox list --unread --since 1d --output json
multica inbox list --issue MUL-123
multica inbox list --archived     # または --snoozed
```

各行には通知 ID、タスクキー、種類、送信元、タイトル、コメントや変更の短い要約が表示されます。`--unread`、`--issue`（タスクキーまたは UUID）、`--since`（RFC 3339 の時刻、または `2h`、`1d`、`1w` のような期間）、`--project`、`--type` で一覧を絞り込めます。`--archived` はアーカイブ全体をページごとに読むので、ずっと前にアーカイブしたタスクも見つけて復元できます。`--project` は完全な UUID または一意の ID プレフィックスを受け付け、`multica project list` に表示される短い ID も使えます。一致なしや曖昧な場合はエラーになります。表にはタスク、コメント、プロジェクトの ID も残り、要約は短く切られます。`--output json` には要約の全文が含まれます。

一覧に表示される ID で通知を処理します。

```sh
multica inbox read <id>...                      # unread <id>... で元に戻す
multica inbox read --issue MUL-123              # 1 つのタスクのすべての通知
multica inbox archive <id>...                   # unarchive <id>... で復元
multica inbox snooze <id>... --until tomorrow   # RFC 3339、30m、3h、1d、1w。unsnooze <id>... で終了
```

アプリと同様に、タスクの通知を既読、アーカイブ、スヌーズにするとタスク全体に適用され、未読に戻すとその通知だけが変わります。1 つの ID が失敗しても残りは処理され、失敗した ID を報告してゼロ以外の終了コードで終わります。

一括操作はインボックスのメニューと同じです。`multica inbox read --all` と、`--all`、`--read`（最新の通知が既読のタスク）、`--completed`（`done` または `closed` カテゴリのステータスのタスク）を付けた `multica inbox archive` です。`--yes` が必要で、手動で実行する場合は確認を入力することもできます。スヌーズ中のタスクは対象外ですが、`--completed` は例外です。アプリと同じく、完了またはクローズ済みのタスクはスヌーズ中でもアーカイブし、スヌーズを終了します。どの変更も、タスク全体を含めて実際に変更した通知の件数を出力します。すでにその状態だったものは 0 件です。`--output json` では同じ件数と ID ごとの結果を返します。CLI から通知は削除できません。

許可されたエージェント実行はこれらすべてにタスクの認証情報を使い、ユーザーのログイン情報にはフォールバックしません。

## 通知の処理

行をクリックすると、そのタスクが開き、通知の対象のコメントまたはアプリのリクエストの位置に移動します。タスクを開いている間、その行はハイライトされたままで、もう一度クリックするとその位置に戻ります。タスクを開くと通知は既読になりますが、行はリストに残ります。オートパイロットの一時停止やエージェント経由の作成結果など、タスクのない通知はインボックスページで開きます。

インボックスから開いたタスクのヘッダーには、インボックスの操作が並びます。

- **スヌーズ**（`H`）は、指定した時間までタスクをインボックスから外し、次の通知を開きます。詳しくは下の「タスクをスヌーズする」を参照してください。
- **完了にする** は、タスクを `done` にし、通知をアーカイブして、次の通知を開きます。**自分が完了したタスクをアーカイブ** がオフでも、この通知はアーカイブされます。タスクがまだ完了またはキャンセルされていないときに表示されます。
- **アーカイブ**（`E`）は、通知をアーカイブして次の通知を開きます。アーカイブしてもタスクは変更・削除されません。
- **購読解除してアーカイブ**（`⇧E`）は、自分のタスクではないとき（担当者が自分でも自分のエージェントでもない）に表示されます。タスクの購読を解除し、通知をアーカイブして次の通知を開きます。以降の通常の更新はインボックスに届きませんが、@メンションは引き続き通知されます。サブタスクがある場合は、このタスクのみか、すべてのサブタスクを含めるかを選べます。このタスクのみの場合は確認メッセージの **元に戻す** で購読を元どおりに戻せます。サブタスクごと解除した場合はここでは戻せないので、タスクのページで購読し直してください。ホバーカードと行の右クリックメニューにも同じ操作があります。

次の通知とは、セクションが現在のフィルターで表示している次の行のことです。リストに戻らずにインボックスを順に片付けられます。

セクション見出しのフィルターボタンでは、通知の種類、受信日時、送信者で絞り込めるほか、タスクのステータスや優先度でも絞り込めます。絞り込み中はボタンが常に表示され、**フィルターをクリア** で元に戻せます。

セクションの ⋯ メニューには、**アーカイブ済みを表示** と次の一括操作があります。

- **すべて既読にする**
- **既読の項目をすべてアーカイブ**
- **完了した項目をアーカイブ**（`done` または `closed` カテゴリのタスクの通知）
- **すべてアーカイブ**

**アーカイブ済みを表示** を開くと、アーカイブした通知がスクロールに合わせて読み込まれます。フィルターは、まだ読み込まれていない通知も含め、アーカイブ全体に適用されます。アーカイブ済みの通知は既読状態を保持するため、**アーカイブ解除**（または `E`）すると元のまま戻ります。

## タスクをスヌーズする

スヌーズすると、タスクは指定した時間までインボックスから外れ、その時間になると未読のまま一番上に戻ります。タスクのヘッダーの目覚まし時計ボタン（または `H`）、行にカーソルを合わせたときにアーカイブの横に出るボタン、または行のホバーカードからスヌーズできます。**1 時間**、**3 時間**、**1 日**、**3 日**、**1 週間** のほか、**日時を選択…** で 1 年以内の任意の日時を選べます。1 日以上のスヌーズは今の時刻のまま戻りますが、22:00〜6:00 にスヌーズした場合は朝 9:00 に戻ります。確認メッセージから元に戻せます。時間を変更した場合は、元の時間に戻ります。

スヌーズ中のタスクは次のように扱われます。

- 新しい通知も一緒に待機し、未読バッジには数えられません。戻ってきた行には **スヌーズ終了** と、その間に届いた更新の数が表示されます。
- 名指しでメンションされたとき、自分に割り当てられたとき、実行が失敗したとき、アプリが操作を求めたとき、すべてのサブタスクが完了したときは早めに戻ります。`@all` へのメンションでは戻りません。
- **すべて既読にする** や一括アーカイブはスヌーズ中のタスクをスキップします。アーカイブするとスヌーズは終了します。**自分が完了したタスクをアーカイブ** がオンのときに自分でタスクを完了した場合も同じです。
- ほかの場所からタスクを開いても既読にはならず、スヌーズも終了しません。ヘッダーに戻る時間が表示され、そこから今すぐ戻す（`H`）か時間を変更できます。

スヌーズは自分のインボックスだけに影響します。スヌーズ中のタスクは Views の **スヌーズ中** ビュー、またはインボックスメニューの **スヌーズ中を表示** から確認できます。

## 通知がインボックスから外れるとき

既読にしても通知はインボックスから消えません。行が外れるのは次の場合だけです。

- 行、ホバーカード、タスクのヘッダー、または一括操作から、あなたがアーカイブしたとき
- タスクをスヌーズしたとき。これは一時的で、指定した時間になるか、対応が必要な通知が届くと戻ります。上の「タスクをスヌーズする」を参照してください。
- **自分が完了したタスクをアーカイブ** がオン（既定でオン）の状態で、あなた自身がタスクを `done` または `closed` カテゴリのいずれかのステータスにしたとき。アーカイブされるのは、そのタスクに届いたあなた自身の通知だけで、既読かどうかは問いません。ほかの人やエージェントがタスクを完了した場合、その通知はあなたのインボックスに残るので、変化を見逃しません。
- 「実行失敗」の通知で、タスクが人に引き継がれるステータスになったとき。対象は `in_review`、`started` カテゴリのカスタムステータス、`done`・`closed` カテゴリのすべてのステータスです。誰がステータスを変えたかにかかわらず、そのタスクの全員分の「実行失敗」の通知がアーカイブされ、上の設定には左右されません。`blocked` は例外です。人に引き継がれはしますが作業は止まったままなので、それまでの失敗の記録はまだ確認する必要があります。
- そのワークスペースのインボックスが 2,000 件を超えたとき。新しい 2,000 件を残し、それより古い通知は既読かどうかにかかわらず、少し後に自動でアーカイブされます。スヌーズから戻った通知やアーカイブから戻した通知は、戻った時点の新しさで数えます。スヌーズ中のタスクの通知は数えず、そのまま残ります。

アーカイブされた行は、開いているウィンドウからもすぐに消えます。ただし、いま開いている行は別です。その通知がほかの理由でインボックスから外れたとき（ステータスからタスクを `done` にした、別のウィンドウでアーカイブされた、編集でセクションのフィルターに合わなくなった）、行は元の位置でハイライトされたまま残り、タスクのヘッダーに何が起きたかが表示されます。**元に戻す** で通知が戻り、**次へ**（または `E`）で次の行が開きます。行が消えるのは、ほかへ移ったときです。

開いている行を自分で処理したとき（タスクのヘッダー、その行、ホバーカード、その行を含む一括操作）は、代わりに次の行が開きます。残りがなければ、タスクは開いたままです。アーカイブ、完了にする、一括操作の確認には **元に戻す** があり、通知は戻りますが、タスクのステータスはそのままです。

その後に届いた通知は、再びインボックスに入ります。

**設定 → 通知 → インボックスから外れるとき** には、**自分が完了したタスクをアーカイブ** のスイッチと、アーカイブ済みの通知へのリンクがあります。

## 表示と通知タイプ

インボックスセクションの見出しにある設定ボタンで表示設定を開けます。この設定はこのデバイスにだけ保存されます。

- **表示件数**：5、10、20 件。残りは「さらに N 件を表示」の行にまとまります。
- **コンパクト表示**：1 件を 2 行ではなく 1 行で表示します。
- **未読数**：セクション名の横の数字です。
- **「作業」に未読バッジを表示**：アプリレールの作業のバッジです。

その下の **受け取る通知** で、通知の種類ごとにオン・オフできます。これは **設定 → 通知** のスイッチと同じもので、設定では届き方ごとにまとめられています。

| グループ | 種類 |
|---|---|
| **あなたに関するもの** | 担当の割り当て、メンション、リアクション |
| **購読中のタスク** | ステータス変更、コメント、優先度と期限 |
| **購読中のプロジェクト** | 新しいタスク |
| **エージェント** | エージェントのアクティビティ（実行の失敗、エージェントが求めたアプリ操作のブロックや期限切れ） |

**ステータス変更** は既定でオフ、ほかの種類は既定でオンです。オフにした種類の通知は作られず、オンに戻しても見逃した分は戻りません。変更そのものはタスクに記録され続けます。エージェント経由の作成結果、オートパイロットの一時停止など一部のタイプはこれらのグループの対象外で、常に届きます。システム通知とブラウザ通知はデスクトップのバナーを制御するもので、インボックス自体は変わりません。
