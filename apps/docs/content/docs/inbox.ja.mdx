インボックスは、あなたに関係する作業の動きを集め、注意が必要な変化がどこで起きたかを知らせます。完全なアクティビティログではなく、経緯は対応するタスクに残っています。

## インボックスの場所

インボックスは **作業** パネルのセクションで、ピン留め済みの下、ビューとプロジェクトの上にあります。ピン留めがないときは最初のセクションになります。見出しには **インボックス**、**スヌーズ中**、**アーカイブ済み** の 3 つのタブがあります。名前が表示されるのは開いているタブだけで、ほかの 2 つはアイコンになり、ポインタを合わせると名前が出ます。開いているタブをもう一度選ぶとセクションを折りたためます。未読数は **インボックス** の横と、アプリレールの **作業** のバッジに表示されます。**作業** を右クリックすると **すべて既読にする** を使えます。

**インボックス** タブにはタスクごとに 1 行ずつ、新しい順に、既読・未読を問わず並びます。行にはタスクのステータス、タイトルと時刻が表示され、未読の行にはドットが付きます。表示設定で **コンパクト表示** をオフにすると、誰が何をしたかが 2 行目に加わります。行にカーソルを合わせると、タイトル全文とコメントを表示するカードが開き、**開く**、**既読にする**（既読のときは **未読にする**）、**スヌーズ**、**アーカイブ** を使えます。行を右クリックすると、**新しいタブで開く**、**既読にする / 未読にする**、**アーカイブ**（アーカイブ済みタブでは **アーカイブ解除**）、**購読解除してアーカイブ**、**削除** を選べます。

スマートフォンでは、作業パネルはドロワーの中にあります。そのインボックスセクションの末尾にある **すべての通知** から、独自のリスト、同じ 3 つのタブ、フィルターを持つインボックスページを開けます。

## インボックスに届くもの

主な通知は次のとおりです。

- タスクがあなたに割り当てられた、またはあなたから外された
- 購読中のタスクに新しいコメントが付いた、または担当者・優先度・日付が変わった（他の人のタスクは既定で重要な更新のみ。後述）
- 購読中のタスクのステータスが変わった（既定でオフの **ステータス変更** をオンにした場合）
- タスクの説明やコメントで誰かがあなたを @メンションした
- あなたが作成したタスクやコメントにリアクションが付いた
- 購読中のタスクでエージェントの実行が失敗した
- 購読中のプロジェクトでタスクが作成された
- 自分に割り当てられたタスクの[ブロッカー](/issues#relations)がすべて終了した（**待機中のタスクが終了しました**）
- [エージェント経由のタスク作成](/issues#エージェントで作成)が完了または失敗した
- 購読中のオートパイロットが新しいタスクを作成した、または連続した失敗により一時停止された

自分の操作は自分には通知されません。同じタスクの複数の通知は 1 行にまとめられ、開くとそのタスクの最近の変化を確認できます。

## 自動購読の発生源

次の関係者はタスクを自動的に購読します。

- タスクの作成者
- 新しい担当者
- コメントした人
- タスクの説明で新たに @メンションされた人
- オートパイロットで事前設定された購読メンバー

担当者が変わっても、既存の購読は解除されません。タスクのページでいつでも購読・購読解除できます。購読解除後は通常の更新はインボックスに届かなくなりますが、あなたへの直接の @メンションは引き続き個別に通知されます。

<Callout type="info">
**ステータス変更** がオンなら、サブタスクのステータスが変わると親タスクの購読者にも通知されます。サブタスクのコメント、優先度、日付の変更は親タスクには伝わりません。
</Callout>

## 他の人のタスク

他の人やその人のエージェントに割り当てられたタスクでは、作成・コメント・メンションによって自動的に購読した場合、既定で重要な更新だけが届きます。あなたへの @メンション、参加したスレッドへの返信、そして（**ステータス変更** がオンなら）`in_review`・`blocked`・`done` など人の確認が必要なステータスです。通常のコメントやその他の変更はタスクに残ります。自分で購読したタスク、プロジェクト経由で購読しているタスク、あなたやあなたのエージェントに割り当てられたタスクには、オンにしている種類の通知が引き続きすべて届きます。

タスクのページでは、こうした購読に **重要な更新のみ** と表示されます。メニューの **すべてのアクティビティを受け取る** を選ぶと、このタスクの明示的な購読に変わります。その後このタスクを重要な更新のみに戻す方法はなく、購読解除だけが可能です。**デフォルトを変更** は **設定 → 通知** を開きます。**購読中のタスク** の先頭にある **他の人のタスク** を **すべてのアクティビティ** にすると、こうしたタスクすべてにアクティビティが届くようになります。

## エージェントとインボックス

インボックスの通知はワークスペースメンバーに属します。実行を開始した上流のユーザーがランタイム所有者本人であるとサーバーが確認できた場合だけ、エージェントはその所有者の通知を読み取り、処理できます。このユーザー情報はエージェントの委任チェーンで引き継がれます。この規則はインボックスのすべての操作に適用されます。アクティブ一覧、アーカイブ、スヌーズ中の一覧、未読件数、そしてすべての変更です。他の人が開始した実行、開始した人を確認できない実行、タスクとの紐付けがないクラウドノードの認証情報は拒否されます。エージェントが読み取る未読件数は実行中のワークスペースのものだけで、所有者の他のワークスペースは含みません。通知を削除できるのは人だけです。エージェントによる変更は、どのエージェントがどの実行で誰の代わりに行ったかとともにサーバーに記録されます。

コメントでの @メンション、タスクの割り当て、オートパイロットのトリガーは、直接実行を作成し、エージェントに通知は残しません。`@all` もメンバーにのみ通知します。

## CLI から管理する

既存の CLI ログインで通知を読み取り、処理できます。一覧表示で既読になることはありません。

```sh
multica inbox count
multica inbox list --unread --since 1d --output json
multica inbox list --issue MUL-123
multica inbox list --archived     # または --snoozed
```

各行には通知 ID、タスクキー、種類、送信元、タイトル、コメントや変更の短い要約が表示されます。`--unread`、`--issue`（タスクキーまたは UUID）、`--since`（RFC 3339 の時刻、または `2h`、`1d`、`1w` のような期間）、`--project`、`--type` で一覧を絞り込めます。`--archived` はアーカイブ全体をページごとに読むので、ずっと前にアーカイブしたタスクも見つけて復元できます。`--project` は完全な UUID または一意の ID プレフィックスを受け付け、`multica project list` に表示される短い ID も使えます。一致なしや曖昧な場合はエラーになります。表にはタスク、コメント、プロジェクトの ID も残り、要約は短く切られます。`--output json` には要約の全文が含まれます。

一覧に表示される ID で通知を処理します。

```sh
multica inbox read <id>...                      # unread <id>... で元に戻す
multica inbox read --issue MUL-123              # 1 つのタスクのすべての通知
multica inbox archive <id>...                   # unarchive <id>... で復元
multica inbox snooze <id>... --until tomorrow   # RFC 3339、30m、3h、1d、1w。unsnooze <id>... で終了
```

アプリと同様に、タスクの通知を既読、アーカイブ、スヌーズにするとタスク全体に適用され、未読に戻すとその通知だけが変わります。1 つの ID が失敗しても残りは処理され、失敗した ID を報告してゼロ以外の終了コードで終わります。

一括操作はインボックスのメニューと同じです。`multica inbox read --all` と、`--all`、`--read`（最新の通知が既読のタスク）、`--completed`（`done` または `closed` カテゴリのステータスのタスク）を付けた `multica inbox archive` です。`--yes` が必要で、手動で実行する場合は確認を入力することもできます。スヌーズ中のタスクは対象外ですが、`--completed` は例外です。アプリと同じく、完了またはクローズ済みのタスクはスヌーズ中でもアーカイブし、スヌーズを終了します。どの変更も、タスク全体を含めて実際に変更した通知の件数を出力します。すでにその状態だったものは 0 件です。`--output json` では同じ件数と ID ごとの結果を返します。CLI から通知は削除できません。

許可されたエージェント実行はこれらすべてにタスクの認証情報を使い、ユーザーのログイン情報にはフォールバックしません。

## 通知の処理

行をクリックすると、インボックスページでその通知が開き、対象のコメントの位置に移動します。オートパイロットの一時停止やエージェント経由の作成結果など、タスクのない通知も含め、すべての通知がここで開きます。開いている間、その行はハイライトされたままで、もう一度クリックするとその位置に戻ります。開くと通知は既読になりますが、行はリストに残ります。タスクのヘッダーの **タスクページで開く**（↗）でタスクを単独のページで開けます。そのページにはインボックスの操作は表示されません。スマートフォンでは戻る矢印でリストに戻ります。

<InboxDemo />

コメント欄の上に、操作のグループが中央に浮かんで表示されます。通知を片付けるための操作が、タスク自体のもの、通知のものの順に並び、それぞれの横にショートカットが表示されます。

- **ステータス**、**担当者**、**クイックアクション** はタスクそのものを変更します。プロパティと同じです。クイックアクションはワークスペースにあるときだけ表示されます。
- **スヌーズ**（`H`）は、指定した時間までタスクをインボックスから外し、次の通知を開きます。詳しくは下の「タスクをスヌーズする」を参照してください。
- **アーカイブ**（`E`）は塗りつぶしボタンで、通知をアーカイブして次の通知を開きます。アーカイブしてもタスクは変更・削除されません。タスクを終えるときはステータスを変えます。既定ではそれで通知もアーカイブされます（下の「通知がインボックスから外れるとき」を参照）。
- 常に右端にある **⋯** には、使用頻度の低い操作が入っています。
  - **未読にする / 既読にする**（`U`）は、開いている通知を閉じずにその場で未読・既読を切り替えます。
  - **購読解除してアーカイブ**（`⇧E`）は、自分のタスクではないとき（担当者が自分でも自分のエージェントでもない）に表示されます。タスクの購読を解除し、通知をアーカイブして次の通知を開きます。以降の通常の更新はインボックスに届きませんが、@メンションは引き続き通知されます。サブタスクがある場合は、メニューに「このタスクのみ」と「すべてのサブタスクを含める」の 2 つが並び、`⇧E` でその選択肢を開いた状態のメニューが開きます。このタスクのみの場合は確認メッセージの **元に戻す** で購読を元どおりに戻せます。サブタスクごと解除した場合はここでは戻せないので、タスクのページで購読し直してください。ホバーカードと行の右クリックメニューにも同じ操作があります。

ウィンドウが狭いときは、まずショートカット、次に名前が省かれます。ボタンにカーソルを合わせると両方が表示されます。

次の通知とは、セクションが現在のフィルターで表示している次の行のことです。リストに戻らずにインボックスを順に片付けられます。`J` / `K` を押すと、アーカイブせずに現在のタブの前後へ移動できます。

**インボックス** と **アーカイブ済み** タブでは、セクションの ⋯ メニューの **フィルター** で、通知の種類、受信日時、送信者で絞り込めるほか、タスクのステータスや優先度でも絞り込めます。絞り込み中はセクション見出しに条件数付きのフィルターボタンが表示され、そこから開き直せます。**フィルターをクリア** で元に戻せます。

**インボックス** タブでは、セクションの ⋯ メニューに次の一括操作があります。

- **すべて既読にする**
- **既読の項目をすべてアーカイブ**
- **完了した項目をアーカイブ**（`done` または `closed` カテゴリのタスクの通知）
- **すべてアーカイブ**（実行前に確認ダイアログが表示され、アクティブな通知のみをアーカイブします。スヌーズ中のタスクはそのまま残ります）

**アーカイブ済み** タブには、アーカイブした通知がスクロールに合わせて読み込まれます。フィルターは、まだ読み込まれていない通知も含め、アーカイブ全体に適用されます。アーカイブ済みの通知は既読状態を保持するため、行または開いた通知の上の操作グループにある **インボックスに戻す**（または `E`）で元のまま戻ります。

## タスクをスヌーズする

スヌーズすると、タスクは指定した時間までインボックスから外れ、その時間になると未読のまま一番上に戻ります。タスクの上の操作グループにある **スヌーズ**（または `H`）、行にカーソルを合わせたときにアーカイブの横に出るボタン、または行のホバーカードからスヌーズできます。**1 時間**、**3 時間**、**1 日**、**3 日**、**1 週間** のほか、**日時を選択…** で 1 年以内の任意の日時を選べます。1 日以上のスヌーズは今の時刻のまま戻りますが、22:00〜6:00 にスヌーズした場合は朝 9:00 に戻ります。確認メッセージから元に戻せます（`Z`）。時間を変更した場合は、元の時間に戻ります。

スヌーズ中のタスクは次のように扱われます。

- 新しい通知も一緒に待機し、未読バッジには数えられません。戻ってきた行には **スヌーズ終了** と、その間に届いた更新の数が表示されます。
- 名指しでメンションされたとき、自分に割り当てられたとき、実行が失敗したとき、すべてのサブタスクが完了したとき、またはすべてのブロッカーが終了したときは早めに戻ります。`@all` へのメンションでは戻りません。
- **すべて既読にする** や一括アーカイブはスヌーズ中のタスクをスキップします。アーカイブするとスヌーズは終了します。**自分が対応したタスクをアーカイブ** が完了を含む（既定で含む）ときに自分でタスクを完了した場合も同じです。
- タスクページから直接開いても既読にはならず、スヌーズも終了しません。**スヌーズ中** タブから開くと操作グループに戻る時間が表示され、その時間をクリックすると今すぐ戻す（`H`）か別の時間を選べます。

スヌーズは自分のインボックスだけに影響します。スヌーズ中のタスクは **スヌーズ中** タブにあり、各行のボタンで今すぐ戻せます。

**スヌーズ中** タブを読み込めない場合は、 **再試行** を選びます。更新に失敗しても、読み込み済みの項目は表示されたままです。

## 通知がインボックスから外れるとき

既読にしても通知はインボックスから消えません。行が外れるのは次の場合だけです。

- 行、ホバーカード、タスクの上の操作グループ、または一括操作から、あなたがアーカイブしたとき
- タスクをスヌーズしたとき。これは一時的で、指定した時間になるか、対応が必要な通知が届くと戻ります。上の「タスクをスヌーズする」を参照してください。
- あなた自身がタスクに対応したとき。何を対応とみなすかは **設定 → 通知** の **自分が対応したタスクをアーカイブ** で決まります。既定の **完了またはエージェントを起動したとき** では、タスクを `done`・`closed` カテゴリのステータスにすることと、実際にエージェントへ作業を渡す操作（エージェントを起動するコメント・クイックアクション・実行中への追記、`backlog` 以外でのエージェントやスクワッドへの割り当て、エージェントやスクワッド担当タスクの `backlog` からの昇格、`todo` を含む、エージェント担当のワークフロー列への移動、再実行、手動ウェイクアップ）が対象です。エージェントを起こさない整理（未割り当ての `backlog` → `todo`、`backlog` での事前割り当て、割り当て解除、`/note` コメント、トリガー抑止、ランタイム不可によるブロックなど）はアーカイブされません。**完了したとき** は `done` と `closed` だけ、**しない** で自動アーカイブはオフ、**カスタム** では操作を 1 つずつ選べ、既定では対象外の返信・ステータス前進・担当者変更・優先度・プロジェクト・日付・ラベルの変更も選べます。アーカイブされるのは、そのタスクに届いたあなた自身の通知だけで、既読かどうかは問いません。ほかの人やエージェントが同じ操作をした場合、その通知はあなたのインボックスに残るので、変化を見逃しません。
- 「実行失敗」の通知で、タスクが人に引き継がれるステータスになったとき。対象は `in_review`、`started` カテゴリのカスタムステータス、`done`・`closed` カテゴリのすべてのステータスです。誰がステータスを変えたかにかかわらず、そのタスクの全員分の「実行失敗」の通知がアーカイブされ、上の設定には左右されません。`blocked` は例外です。人に引き継がれはしますが作業は止まったままなので、それまでの失敗の記録はまだ確認する必要があります。
- そのワークスペースのインボックスが 2,000 件を超えたとき。新しい 2,000 件を残し、それより古い通知は既読かどうかにかかわらず、少し後に自動でアーカイブされます。スヌーズから戻った通知やアーカイブから戻した通知は、戻った時点の新しさで数えます。スヌーズ中のタスクの通知は数えず、そのまま残ります。

アーカイブされた行は、開いているウィンドウからもすぐに消えます。ただし、いま開いている行は別です。その通知が自動でインボックスから外れたとき（ステータスからタスクを `done` にした、エージェントを起動した、別のウィンドウでアーカイブされた、編集でセクションのフィルターに合わなくなった）、行は元の位置でハイライトされたまま残り、操作グループに **アーカイブを取り消す**（`Z`）が表示され、押すと通知が戻ります。カーソルを合わせると、アーカイブされた理由とこの先どうなるかが「進行中 に変更 · 新しい動きがあるとインボックスに戻ります」のように表示されます。エージェントを起動したときは、タスクのヘッダーに作業中であることが表示され、サイドバーの行も移動するまでその場で更新されます。操作グループの **ステータス**、**担当者**、**クイックアクション** で変更して通知がアーカイブされたときも、これらの操作はグループに残るので続けて変更できます。塗りつぶしボタンになった **次へ**（`E`）で次の行が開きます。自分のタスクでなければ、右端の **⋯** に **このタスクの購読を解除** があり、通知はそのまま残ります。スヌーズ中のタスクや **アーカイブ済み** タブから開いたタスクの操作グループにもあります。行が消えるのはほかへ移ったときで、実行中のタスクは **ビュー → 実行中** で引き続き確認できます。それがインボックスの最後の通知だった場合、**次へ** は出ません。`E` で空になったインボックスが開きます。

開いている行を自分で処理したとき（操作グループ、その行、ホバーカード、その行を含む一括操作）は、代わりに次の行が開きます。残りがなければ、インボックスのページが開き、**インボックスは空です** と表示されます。直前の操作が示されて **元に戻す**（または `Z`）で取り戻せるほか、スヌーズ中のタスク数と次に戻る時刻が表示されます。フィルターでほかの通知が隠れているだけのときは、残りの件数と **フィルターを解除して続ける** が代わりに表示されます。戻るとタスクに戻れます。アーカイブと一括操作の確認には **元に戻す** があり、通知は戻りますが、タスクのステータスはそのままです。**元に戻す** のある確認メッセージ（アーカイブ、スヌーズ、購読解除のいずれも）は 10 秒間表示され、表示中に `Z` を押すとその操作を取り消せます。

その後に届いた通知は、再びインボックスに入ります。

**設定 → 通知 → インボックスから外れるとき** には、**自分が対応したタスクをアーカイブ**（**しない**、**完了したとき**、**完了またはエージェントを起動したとき**、**カスタム**）とアーカイブ済みの通知へのリンクがあります。

## 表示と通知タイプ

インボックスセクションの見出しにある設定ボタンで表示設定を開けます。この設定はこのデバイスにだけ保存されます。

- **表示件数**：5、10、20 件。残りは「さらに N 件を表示」の行にまとまります。
- **コンパクト表示**：1 件を 1 行で表示します。既定でオンで、オフにすると誰が何をしたかが 2 行目に加わります。
- **未読数**：セクション名の横の数字です。
- **「作業」に未読バッジを表示**：アプリレールの作業のバッジです。

その下の **受け取る通知** で、通知の種類ごとにオン・オフできます。これは **設定 → 通知** のスイッチと同じもので、設定では届き方ごとにまとめられています。

| グループ | 種類 |
|---|---|
| **あなたに関するもの** | 担当の割り当て、メンション、リアクション |
| **購読中のタスク** | ステータス変更、コメント、優先度と期限 |
| **購読中のプロジェクト** | 新しいタスク |
| **エージェント** | エージェントのアクティビティ（実行の失敗） |

**ステータス変更** は既定でオフ、ほかの種類は既定でオンです。オフにした種類の通知は作られず、オンに戻しても見逃した分は戻りません。変更そのものはタスクに記録され続けます。エージェント経由の作成結果、オートパイロットの一時停止など一部のタイプはこれらのグループの対象外で、常に届きます。システム通知とブラウザ通知はデスクトップのバナーを制御するもので、インボックス自体は変わりません。

**コメント** の下の **スクワッド内の引き継ぎを含める** は、リーダーとエージェントが作業を受け渡すコメントが対象です。スクワッドに割り当てたタスクでも、コメントでスクワッドを @ メンションしたタスクでも同じです。リーダーがエージェントやスクワッドを @ メンションして依頼するコメントと、エージェントからの報告がこれに当たります。既定でオンで、オフにすると人に向けたコメントだけが届きます。あなたや他のメンバーを @ メンションしたコメント、人のコメントへのエージェントの返信、エージェント実行の失敗は引き続き届きます。スクワッドが作業を終えたときの最終報告も届きます。エージェントの報告のあと、リーダーの実行が作業を渡さずコメントも書かずに終わったら、その報告がそこで届きます。ステータス変更は **ステータス変更** のスイッチに従います。
