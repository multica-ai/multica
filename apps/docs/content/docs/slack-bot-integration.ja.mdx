既存の Slack Bot 接続は、Slack アプリと 1 つの[エージェント](/agents)の対応を維持します。メンバーは Bot への DM、チャンネルでの @メンション、ファイル送信、`/issue` を引き続き利用できます。

<Callout type="info">
  新しいエージェント単位の Slack 接続は廃止されました。既存接続は動作を続け、**Settings → Integrations** に表示されます。
</Callout>

## 既存 Bot を使う

- DM は割り当て済みエージェントとの Multica [Chat](/chat) になります。
- チャンネルとグループでは Bot を @メンションしたメッセージだけが実行されます。
- 対象メッセージのファイルはエージェント用に Multica ストレージへコピーされます。
- **`/issue <タイトル>`** は紐づけ済みメンバー名義でイシューを作成します。
- **`/new <メッセージ>`** は履歴を消さず、以前の文脈なしで実行します。

最初のメッセージで一度だけ使えるアカウント連携 URL が返る場合があります。対象ワークスペースの Multica アカウントで開いてください。この本人確認コールバックは独立した契約であり、新しいエージェント接続ではありません。

## 保持された接続を管理する

**Settings → Integrations** で既存 Bot と割り当て済みエージェントを確認できます。workspace owner と admin は接続を切断できます。切断後も会話と監査記録は保持されます。

## セルフホスト

既存の暗号化済み Slack 認証情報には `MULTICA_SLACK_SECRET_KEY` が必要です。保存済み認証情報を読めなくしないよう、キーを安定して保持してください。Socket Mode は外向きに接続するため、保持接続に公開 Request URL は不要です。

## トラブルシューティング

- **新規接続アクションがない**: エージェント単位のブラウザー接続は廃止済みです。
- **Bot が応答しない**: 接続が有効で、割り当て済みエージェントがアーカイブされておらず、[Runtime](/daemon-runtimes) がオンラインか確認してください。
