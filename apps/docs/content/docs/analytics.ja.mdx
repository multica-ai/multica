サイドバーの**分析**ページには、ワークスペース全体のエージェント使用量がまとまっています。コスト、トークン、実行時間、実行回数、そして失敗した実行です。ワークスペースのメンバーなら誰でも開けます。ランタイムごとの使用量はランタイムの詳細ページに、1 つのタスクにかかった費用はその**実行履歴**ダイアログにあります。どちらも後半で説明します。

## ページの構成

ページは**使用量**と**エラー**の 2 つのタブに分かれ、右上の 2 つのフィルターを共有します。

- **期間**: `1d`、`7d`、`30d`（既定）、`90d`、`180d`。`1d` はあなたのタイムゾーンの 0 時からの「今日」で、直近 24 時間ではありません。
- **プロジェクト**: 既定は**すべてのプロジェクト**です。プロジェクトを選ぶと、そのプロジェクトのタスクで動いた実行だけを集計します。チャットなど、どのタスクにも属さない実行は含まれません。

日付の区切りはあなたのタイムゾーンに従います。**設定 → 環境設定 → タイムゾーン**で設定した値を使い、未設定ならブラウザーのタイムゾーンを使います。ヘッダーには使用中のタイムゾーンとデータの更新時刻が表示されます。数値はサーバーが 5 分ごとに集計し、開いているページも同じ間隔で再読み込みするため、終わったばかりの実行が表示されるまで数分かかることがあります。すぐに見たいときは更新ボタンを押します。

エラータブに切り替えるとアドレスに `?tab=errors` が付きます。そのリンクを送れば、相手もエラータブから開けます。

## 使用量タブ

上部の 4 つの数値:

| カード | 内容 |
| --- | --- |
| **コスト** | 米ドル建ての概算。計算方法は[コストの計算方法](#コストの計算方法)を参照 |
| **トークン** | 入力・出力・キャッシュ読み取り・キャッシュ書き込みの合計。下の行に入力と出力を個別に表示 |
| **実行時間** | 終了した実行の所要時間の合計。各実行の開始から終了まで |
| **実行** | 期間内に終了した実行の数と、そのうち失敗した数 |

実行時間と実行の数に入るのは、実際に動き始めた実行（完了、失敗、途中でキャンセル）だけです。待機中にキャンセルされた実行は含まれません。

推移カードでは、トークン・コスト・時間・実行の 4 つの指標を同じ時間軸で切り替え、**日別**と**週別**の単位を選べます。`30d` と `90d` はどちらも選べ、`1d` と `7d` は日別のみ、`180d` は週別のみです。週は月曜始まりで、まだ終わっていない今週は薄い色で描かれ、ホバーすると 7 日中何日経過したかが表示されます。

**リーダーボード**はエージェントごとのトークン・コスト・時間・実行を並べ、どの項目でも並べ替えられます。上位 10 件を表示し、残りは**すべて表示**で開きます。複数のエージェントをまとめた行が出ることがあります。

- **削除済みエージェント**: 削除されたエージェントの使用量を 1 行にまとめたもの。各行を足すと上部の合計と一致します。
- **その他のエージェント**: あなたが見られないエージェントを 1 行にまとめたもの。ワークスペースのオーナーと管理者は、メンバーが作ったすべてのエージェントを見られます。一般メンバーには他人のプライベートエージェントが見えず、その使用量は名前なしでこの行にだけ入ります。

あるエージェントの実行の一部がトークンを報告していないと、そのトークンとコストの前に `≥` が付き、名前の下に使用量が報告されていない実行の数が出ます。

## エラータブ

上部に**失敗した実行**、**失敗率**、**影響を受けたエージェント**が並びます。失敗率は期間内に終了したすべての実行に対する割合で、カードの下に分子と分母が書かれています。

その下には次のカードがあります。

- **日別エラー**（または週別エラー）: 棒の色分けが失敗の分類です。
- **失敗の内訳**: 期間内の全失敗を分類ごとに分けたもの。**エラーコードを表示**を押すと元の失敗理由コードに切り替わり、ログ検索やタスクへの貼り付けに使えます。
- **失敗の多いエージェント**: 既定は失敗数の順で、9 件目以降は展開して表示します。**失敗率**で並べると、実行が 10 回未満のエージェントは後ろに回ります。回数が少ないと割合はあまり当てにならないためです。エージェント名をクリックすると詳細ページが開き、最近の実行と失敗ごとの理由を確認できます。

失敗理由コードは 7 つに分類されます。

| 分類 | 含まれるもの | 主な対処 |
| --- | --- | --- |
| 認証 | プロバイダーの認証失敗やアクセス拒否、API キーなどの設定不足 | AI コーディングツールで再ログインするか、設定を補う |
| レート制限 | レート制限、容量不足、クォータや残高の枯渇 | 時間をおいて再試行するか、上限を引き上げる |
| タイムアウト | 実行のタイムアウト、ツールの無応答、Codex の停滞 | タスクの範囲を絞るか、タイムアウト設定を調整する |
| プロバイダー | プロバイダーのサーバーエラー、ネットワーク障害、モデルが使えない、リクエストの拒否 | 時間をおいて再試行するか、使えるモデルに切り替える |
| ランタイム | ランタイムのオフライン、デーモンの再起動、待機の期限切れ、skill バンドルのダウンロード失敗、ツールが見つからない・古い、実行環境の準備失敗 | 実行したコンピューターを確認する |
| エージェント | ツールプロセスの異常終了、出力を解析できない、コンテキスト超過、反復回数の上限、エージェントが続行不能と報告 | 実行ログを確認し、タスクを見直して再試行する |
| その他 | 分類できない失敗 | 元のエラーコードと実行ログを確認する |

各コードの意味と対処は[実行 · 失敗理由リファレンス](/tasks#失敗理由リファレンス)を参照してください。

## コストの計算方法

分析に出るコストはすべて米ドル建ての概算で、AI コーディングツールやモデルプロバイダーの請求額ではありません。

- Multica は公開されているモデル料金の表を持っており、入力・出力・キャッシュ読み取り・キャッシュ書き込みそれぞれの 100 万トークンあたりの単価を、報告されたトークン数に掛けます。
- AI コーディングツール自身がコストを報告した場合（Grok Build など）は、その値をそのまま使い、概算はしません。
- 料金表にないモデルは、トークンは数えますがコストは $0 として扱います。そうしたモデルにはランタイムの使用量から[カスタム価格](#カスタム価格)を設定できます。
- プロンプトが一定の長さを超えると単価が上がるモデルがあります。集計データからは各リクエストの長さがわからないため一律に標準料金で計算し、こうした実行は低めに見積もられることがあります。

トークンは AI コーディングツールが報告します。ツールが報告しない場合、その実行は実行時間と実行の数には入りますが、トークンとコストは加算されません。たとえば現在の GitHub Copilot CLI は出力にトークン数を含めないため、これを使うエージェントはリーダーボードで `≥` と未報告の数が表示されます。

## ランタイムの使用量

**ランタイム**を開いて各ランタイムの詳細ページに入ると、そのランタイムの使用量が表示されます。プライベートなランタイムの使用量はオーナーだけが、公開ランタイムの使用量はメンバー全員が見られます。

- 上部は**コスト**、**キャッシュによる節約**、**トークン**です。コストは同じ長さの前の期間と比べた増減が付きます。キャッシュによる節約は、キャッシュ読み取りを通常の入力単価で払っていたら余分にいくらかかったかの概算で、下にヒット率が出ます。
- **このランタイムでコストが発生した時期**: 日別または週別のコストかトークン。**ヒートマップ**に切り替えると、直近 26 週の毎日のコストをマスの濃さで表示します。上の期間の選択には左右されません。
- **エージェント別**と**モデル別**: その期間のコストがどのエージェント、どのモデルに使われたか。
- **日別内訳テーブル**: 展開すると、日付とモデルごとに各種トークンの数が並びます。

ランタイムページの期間は `7d`、`30d`、`90d`、`180d` です。

## カスタム価格

選んだ期間に料金表にないモデルが含まれると、ランタイムの使用量の上に、価格が管理されていないモデルの数と、そのトークンがコストから除外されていることを知らせる表示が出ます。**カスタム価格を設定**を押し、モデルごとに入力・出力・キャッシュ読み取り・キャッシュ書き込みの単価を 100 万トークンあたりの USD で入れて保存します。すべてのモデルに価格が付いた後も、あとで変更できるように**カスタム価格を編集**ボタンが残ります。あるモデルの価格を消すには、そのフィールドをすべて空にして保存するか、横の削除ボタンを押します。

<Callout type="info">
カスタム価格はこのデバイスのブラウザーかデスクトップアプリにだけ保存されます。アカウントには同期されず、ワークスペースの他のメンバーとも共有されません。このデバイスではすべてのワークスペースに適用されます。他のメンバーの画面では、これらのモデルは引き続き $0 のままです。
</Callout>

カスタム価格が使われるのは料金表にないモデルだけで、組み込みの単価は上書きできません。AI コーディングツールが自ら報告したコストも置き換えません。保存すると、このデバイス上の分析ページ、ランタイムの使用量、タスクの実行履歴が新しい単価で計算し直されます。

## タスクのコスト

各タスクのサイドバーにある**実行ログ**には、そのタスクの**費用**、**トークン**、**エージェント作業**の時間と、実行ごとに 1 本ずつのコストバーが出ます。合計、コストバー、または**タイムラインを開く**をクリックすると**実行履歴**ダイアログが開きます。

- 上部に**費用**、**トークン**（そのうちキャッシュの割合）、**出力**、**エージェント作業**、**実行回数**がまとまっています。エージェント作業は各実行の所要時間の合計で、横の「経過」は最初の実行の開始から最後の実行の終了までの時間です。実行回数の横には失敗、キャンセル、進行中の数が並びます。
- グラフは**実行ごと**にすると実行 1 回につき 1 本の棒で費用・トークン・エージェント作業を表示し、**累計**にすると累計費用が時間とともに増える線を表示します。
- **エージェント別**と**モデル別**の帯で、費用がどのエージェント、どのモデルに使われたかがわかります。
- その下には実行が日ごとに並び、**実行の詳細**を開くとその実行の費用の内訳と、キャッシュヒットで節約できた額が見られます。

ダイアログの下部には、費用が概算であることと、価格のないモデルの名前が記されます。

## CLI で確認する

```bash
multica issue usage <issue-id>
multica runtime usage <runtime-id> --days 30
```

`issue usage` はタスクのトークン合計（入力、出力、キャッシュ読み取り、キャッシュ書き込み）と実行回数を出力します。`RUNS` は終了した実行の数、`METERED_RUNS` は使用量を報告した数、`UNREPORTED` は報告しなかった数です。報告のない実行があると、トークン合計に `>=` が付きます。実際の値はそれ以上という意味です。

`runtime usage` はランタイムのトークン使用量を日付、プロバイダー、モデルごとに並べます。`--days` の既定は 90、最大 365 です。

どちらの表にもコストの概算は含まれません。`--output json` を付けると API が返す元データを出力します。
