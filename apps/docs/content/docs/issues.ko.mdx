태스크는 Multica에서 작업을 계획하는 기본 단위입니다. 기능 하나, 버그 하나, 조사 하나처럼 멤버나 에이전트가 책임지고 진행해야 하는 모든 작업이 태스크가 될 수 있습니다. 관련 논의, 상태 변경, 모든 실행이 그 태스크에 기록되므로 채팅 기록이나 터미널 로그를 다시 뒤질 필요가 없습니다.

## 태스크의 구성

| 내용 | 용도 |
|---|---|
| **제목과 설명** | 목표, 배경, 요구 사항, 인수 조건입니다. |
| **상태와 우선순위** | 작업이 어느 단계에 있고 무엇을 먼저 처리할지 나타냅니다. |
| **담당자** | 워크스페이스 멤버, 에이전트 또는 스쿼드입니다. |
| **날짜, 라벨, 사용자 지정 속성** | 계획, 분류, 팀 고유 필드입니다. |
| **프로젝트와 상하위 관계** | 더 큰 작업 범위에 포함하거나 하위 태스크로 나눕니다. |
| **활동과 실행 로그** | 댓글, 상태 변경, 실행, 에이전트가 반환한 결과입니다. |
| **산출물** | 댓글에 올린 파일입니다. 같은 파일을 다시 올리면 버전으로 묶입니다. |

## 태스크 만들기

**태스크** 페이지나 프로젝트에서 새 태스크를 만듭니다. 사이드바의 **새 태스크**나 `C` 키를 누르면 지난번에 쓴 방식으로 생성 대화상자가 열립니다. **직접 만들기**에서는 제목과 속성을 직접 입력하며, 제목만 있으면 만들 수 있고 다른 속성은 언제든 보충할 수 있습니다. **에이전트로 만들기**에서는 요청 내용만 적으면 됩니다. 방식은 대화상자 아래쪽에서 바꿀 수 있고, 이미 입력한 내용은 그대로 넘어갑니다.

각 태스크에는 `MUL-123` 같은 번호가 있습니다. 숫자는 워크스페이스 안에서 증가합니다. 관리자가 워크스페이스의 태스크 접두사를 바꾸면 번호가 새 접두사로 표시됩니다. 자세한 내용은 [워크스페이스](/workspaces#워크스페이스-만들기)를 참고하세요.

### 에이전트로 만들기

할 일을 적고 **생성자**에서 에이전트나 스쿼드를 고른 뒤 **만들기**를 클릭합니다. 대화상자는 바로 닫히고, 에이전트가 백그라운드에서 요청을 제목과 설명으로 정리해 태스크를 만듭니다. 성공하든 실패하든 인박스로 알림이 옵니다. 실패 알림에는 **고급 양식으로 수정**이 있어, 원래 적은 요청이 직접 만들기 양식에 채워집니다.

<IssueDraftDemo />

- 에이전트는 요청을 원래 뜻대로 옮겨 적고, 적지 않은 요구 사항이나 완료 조건을 덧붙이지 않습니다.
- 요청에서 담당자를 지목하면("리레이에게 맡겨 줘" 등) 그 사람에게 할당합니다. 지목하지 않으면 담당자는 **생성자**에서 고른 대상, 즉 그 에이전트 자신이거나 고른 스쿼드입니다. 새 태스크는 `todo` 상태로 만들어지므로, 담당자가 에이전트이면 태스크가 만들어진 뒤 바로 작업을 시작합니다.
- 대화상자에서 고른 프로젝트, 우선순위, 마감일은 그대로 쓰이며, 에이전트가 글에서 다른 값을 추측하지 않습니다. 프로젝트는 처음부터 보이고, 우선순위와 마감일은 **⋯** 메뉴에 있습니다. 항상 보일 필드는 **설정 → 환경설정 → 태스크 생성 시 표시할 필드**에서 정합니다.
- **하나 더 만들기**를 켜 두면 보낸 뒤에도 대화상자가 닫히지 않아 다음 요청을 이어서 쓸 수 있습니다.
- **생성자** 목록에는 내가 할당할 수 있는 에이전트와 스쿼드만 나옵니다. 에이전트 런타임의 multica CLI 버전이 너무 낮으면 데몬을 업그레이드하거나 직접 만들기로 바꾸라는 안내가 나옵니다.

## 담당자 선택

| 담당자 | 결과 |
|---|---|
| **멤버** | 해당 멤버가 후속 작업을 책임지며 실행은 생성되지 않습니다. |
| **에이전트** | 해당 에이전트의 실행이 생성됩니다. |
| **스쿼드** | 스쿼드 리더가 먼저 받은 뒤 누구에게 맡길지 결정합니다. |

에이전트나 스쿼드에 할당할 때 태스크가 `backlog` 상태가 아니면 즉시 큐에 들어갑니다. 런타임이 오프라인이면 실행은 큐에서 기다립니다. 보관된 에이전트와 스쿼드는 할당할 수 없습니다.

할당은 에이전트의 접근 범위(Access)를 우회하지 않습니다. 스쿼드에 할당하면 리더의 Access를 확인합니다. 자세한 내용은 [태스크를 에이전트에게 할당하기](/assigning-issues)를 참고하세요.

## 상태

모든 워크스페이스에는 기본 상태 7개가 준비되어 있고, 이들은 4개의 수명 주기 카테고리로 묶입니다.

<Tabs items={["카테고리별", "상태별"]}>
<Tab value="카테고리별" id="status-categories">

| 카테고리 | 기본 상태 | 의미 |
|---|---|---|
| `unstarted` | `backlog`, `todo` | 아직 시작하지 않은 작업. 계획된 것이든 미뤄둔 것이든 같습니다. |
| `started` | `in_progress`, `in_review`, `blocked` | 이미 시작했거나, 검토를 기다리거나, 지금은 진행할 수 없는 상태. |
| `done` | `done` | 성공적으로 끝난 종료 상태. |
| `closed` | `cancelled` | 더 이상 진행하지 않는 종료 상태이며, 성공적인 완료는 아닙니다. |

카테고리는 태스크가 수명 주기의 어느 구간에 있는지 판단하는 데만 쓰입니다. 보드와 목록, 필터, 정렬은 모두 개별 상태를 기준으로 동작하며, 에이전트와 자동화가 의존하는 특별한 동작도 개별 상태에 붙어 있습니다.

</Tab>
<Tab value="상태별" id="built-in-statuses">

| 상태 | 의미 |
|---|---|
| `backlog` | 지금은 시작하지 않습니다. 에이전트에게 할당된 태스크도 `backlog`에서 벗어나야 실행이 생성됩니다. |
| `todo` | 작업이 명확하며 시작을 기다립니다. |
| `in_progress` | 처리 중입니다. |

| `blocked` | 지금은 계속 진행할 수 없습니다. |
| `cancelled` | 더 이상 진행하지 않으며 기록은 유지합니다. |

</Tab>

<IssueStatusDemo />

멤버와 에이전트는 상태를 직접 바꿀 수 있습니다. 프로젝트가 [워크플로](/workflows)를 사용하면 그 안의 단계에서 선택합니다. 인계가 있는 단계로 옮기면 담당자가 바뀌고 에이전트에게 작업을 요청할 수 있습니다.

에이전트는 작업 진행에 따라 태스크 상태를 업데이트합니다. 기본적으로 작업을 시작하면 `in_progress`로, 결과를 전달하면 `in_review`로 바꿉니다. 프로젝트에 워크플로가 있다면 해당 단계와 인계 지침을 따릅니다.

<Callout type="info">
다음 두 가지 변경은 시스템이 수행합니다.

- 실행이 실패하고 해당 태스크에 다른 실행이 없으며 재시도도 트리거되지 않으면 `in_progress`가 `todo`로 돌아갑니다.
- 태스크에 연결된 PR이 모두 병합되면 태스크가 워크스페이스가 정한 상태(기본값 `done`)로 바뀝니다. 워크스페이스가 "변경하지 않음"으로 설정했거나 해당 태스크만 상태 변경을 끈 경우는 제외합니다. 자세한 내용은 [GitHub 연동](/github-integration)을 참고하세요.
</Callout>

### 사용자 정의 상태

워크스페이스의 `owner` 또는 `admin`은 **코드 리뷰**, **QA**, **재작업** 같은 상태를 추가할 수 있습니다. **설정**에 **워크플로**가 있으면 그 아래의 상태 라이브러리에서 관리합니다. 없으면 **설정 → 태스크 상태**를 사용합니다.

만들 때 **시작 전**, **시작됨**, **완료**, **종료** 중 하나의 분류를 선택하며, 이 분류는 나중에 바꿀 수 없습니다. 사용자 정의 상태가 기본 상태의 특별한 동작을 얻지는 않습니다. 예를 들어 이름을 “대기”로 정해도 에이전트가 일시 정지되지는 않습니다.

- 기본 상태는 이름과 색을 바꾸거나 보관할 수 없습니다.
- 사용자 정의 상태는 입력한 이름으로 표시됩니다. 이름이나 색을 바꾸면 같은 상태를 쓰는 모든 곳에 적용됩니다.
- 보관하기 전에 완료·취소된 태스크를 포함해 해당 상태의 모든 태스크를 적절한 다른 상태로 옮겨야 합니다. 사용자 정의 워크플로에서도 제거하세요. 보관한 뒤에는 선택지에 표시되지 않습니다.

상태 라이브러리에는 사용 가능한 상태가 모여 있고, 프로젝트 워크플로는 사용할 상태와 순서를 정합니다.

## 사용자 지정 속성

심각도, 고객, 예산처럼 팀에 필요한 항목은 사용자 지정 속성으로 추가합니다. 워크스페이스의 `owner` 또는 `admin`이 **설정 → 속성**에서 관리하며, 한 워크스페이스에서 동시에 활성화할 수 있는 속성은 20개까지입니다.

유형은 텍스트, 숫자, 선택, 다중 선택, 날짜, 체크박스, URL, 멤버, 멤버(다중 선택), 텍스트 목록, URL 목록이며 만든 뒤에는 바꿀 수 없습니다. 속성은 필터에 쓸 수 있고, 보드는 선택 유형 속성으로 그룹화할 수 있으며, 숫자와 날짜 속성은 정렬에 쓸 수 있습니다.

더 쓰지 않는 속성은 보관할 수 있습니다. 선택기와 필터에서는 사라지지만 태스크에 들어 있는 값은 남고, 나중에 복원할 수 있습니다.

## 태스크와 실행

태스크는 계속 유지되는 작업 기록이고 [실행](/tasks)은 에이전트가 한 번 실행한 기록입니다. 하나의 태스크에서 첫 구현, 추가 수정, 재검토처럼 여러 실행이 차례로 생성될 수 있습니다. 실행이 "완료됨"인 것은 이번 실행이 끝났다는 뜻일 뿐이고, 에이전트가 질문에 답했다고 해서 태스크의 작업이 전달된 것도 아닙니다. 태스크의 완료 여부는 태스크 상태를 기준으로 판단합니다.

## 산출물

멤버와 에이전트가 댓글에 올린 파일은 태스크 사이드바의 **산출물**에 모입니다. 여기에는 최근 이미지 3개와 다른 파일 4개가 바로 보이고, 모두 보기를 누르면 전체 산출물을 올린 댓글별로 보면서 이미지, 문서, 동영상, 기타로 거를 수 있습니다. 파일 뷰어에서 `G`를 눌러도 같은 화면이 열립니다. 태스크 설명에 첨부한 파일은 입력 자료라서 산출물에 들어가지 않습니다.

이름과 형식이 같은 파일을 다시 올리면 같은 산출물의 새 버전이 됩니다. 산출물에는 하나만 버전 번호(예: `v2`)와 함께 표시되고, 댓글의 파일 카드에도 각각 몇 번째 버전인지 나옵니다. 뷰어에서 버전 번호를 클릭하면 이전 버전으로 바꿀 수 있고, **댓글에서 보기**를 누르면 그 파일을 올린 댓글로 이동합니다.

## 프로젝트와 하위 태스크

하나의 태스크는 최대 하나의 [프로젝트](/projects)에 속할 수 있습니다. 프로젝트는 그 안의 실행에 공유 설명과 리소스를 제공합니다. 다른 프로젝트로 옮겨도 복사본이 만들어지지 않습니다.

큰 작업은 하위 태스크로 나눌 수 있습니다. 상위 태스크에는 전체 목표를 남기고 하위 태스크는 각각 독립적으로 진행합니다. 상위와 하위 태스크의 상태는 서로 연동되지 않습니다.

하위 태스크에는 **단계**(stage)를 지정해 1, 2, 3처럼 묶어서 진행할 수 있습니다. 현재 가장 이른 미완료 단계의 모든 하위 태스크가 `done` 또는 `cancelled`가 되면 상위 태스크에 "하위 태스크 완료" 알림이 전달됩니다. 상위 태스크 담당자가 에이전트이면 에이전트가 깨어나 다음 단계로 진행할지 결정합니다. 단계를 지정하지 않은 하위 태스크는 같은 묶음으로 간주하며 모두 끝났을 때 한 번 알립니다. 이 깨우기는 시스템이 합니다. 규칙과 다른 깨우기 방식은 [태스크 깨우기](/issue-wakeups)를 참고하세요.

## 뷰와 표시 설정 [#보기-전환]

태스크 페이지에서는 리스트, 보드, 테이블, 간트, 스윔레인 다섯 가지 레이아웃을 제공합니다. 상태, 담당자, 프로젝트, 기타 속성으로 필터링할 수 있으며 모두 같은 태스크 집합을 표시합니다.

**보기** 메뉴에서 현재 레이아웃을 조정합니다. 보드는 상태, 담당자, 프로젝트, 선택 유형 속성으로, 스윔레인은 상위 태스크, 프로젝트, 담당자로 그룹화합니다. 정렬, 하위 태스크 표시 여부, 카드에 보일 속성, 보드에 보일 열도 정할 수 있습니다(상태 필터가 걸려 있으면 열을 바꿀 수 없습니다).

### 뷰 저장

자주 쓰는 필터와 표시 설정 조합은 뷰로 저장할 수 있습니다. 뷰 바 옆의 **뷰** 버튼에서 **새 뷰**를 고르고 이름과 공개 범위를 정합니다.

| 공개 범위 | 볼 수 있는 사람 | 수정·삭제할 수 있는 사람 |
|---|---|---|
| **나만 보기** | 나 | 나 |
| **워크스페이스 구성원에게 표시** | 워크스페이스 구성원 전체 | 나, 그리고 워크스페이스의 `owner`와 `admin` |

뷰에 저장한 표시 설정은 **기본 표시**입니다. 구성원이 처음 열 때 이 방식으로 보이고, 이후에는 각자 조정하며 서로 영향을 주지 않습니다. 뷰는 만든 페이지에만 나타납니다. 프로젝트에서 만든 뷰는 그 프로젝트에 속하고, **내 태스크**에서 만든 뷰는 항상 나만 봅니다.

뷰 바의 뷰는 끌어서 순서를 바꿀 수 있고, **뷰 관리**에서 바꾼 순서와 표시 여부는 나에게만 적용됩니다. 뷰를 오른쪽 클릭하면 수정, 삭제, **사이드바에 고정**을 할 수 있습니다.

### 사이드 미리보기

태스크 카드나 행을 클릭하면 기본적으로 전체 페이지가 열립니다. **설정 → 환경설정 → 태스크 열기**에서 **사이드 미리보기**로 바꾸면 페이지 오른쪽 패널에서 열리고, 페이지 헤더와 도구 모음은 그대로 쓸 수 있습니다. 어느 쪽을 고르든 Shift+클릭하면 다른 쪽으로 열립니다. 이 설정은 지금 쓰는 기기에만 적용됩니다.

미리보기가 열려 있을 때 `J` / `K`로 다음·이전 태스크로, 보드에서는 `H` / `L`로 옆 열로 이동하고, `Esc`로 닫습니다. **전체 페이지로 열기**를 누르면 태스크 페이지로 갑니다.

## 일괄 수정

리스트, 테이블, 하위 태스크 목록에서 여러 태스크를 선택하면 화면 아래에 일괄 작업 도구 모음이 나타나, 상태·우선순위·담당자를 한꺼번에 바꾸거나 삭제할 수 있습니다. 테이블에서는 Shift+클릭으로 범위를 선택합니다.

- 선택한 태스크가 여러 프로젝트에 걸쳐 있으면 상태 메뉴에는 모든 태스크의 워크플로가 허용하는 상태만 나옵니다. 변경을 지원하지 않는 태스크는 그대로 두고 나머지만 바꿉니다.
- 일괄 상태 변경은 바로 적용됩니다. 에이전트에게 할당된 태스크가 `backlog`에서 벗어나면 평소처럼 실행이 시작됩니다.
- 에이전트나 스쿼드에게 일괄 할당할 때는 시작될 실행을 먼저 확인합니다. 선택한 태스크가 모두 `backlog`이면 확인 없이 할당합니다.

## 중복으로 표시

같은 일이 두 번 등록됐다면, 남는 쪽 태스크에서 상태 메뉴나 태스크 작업 메뉴의 **관계**에서 **중복으로 표시**를 고르고 원본 태스크를 선택합니다. 후보로는 제목이 비슷한 태스크와 최근에 본 태스크가 먼저 나옵니다.

표시하면 그 태스크는 `cancelled`가 되고 원본 태스크를 기억합니다.

- 제목 위에 **중복 원본:** 배너가 나타나 원본 태스크로 연결되고, 원본의 현재 상태도 보여 줍니다. 리스트, 보드, 테이블에서는 태스크 옆에 원본 번호가 붙은 화살표가 나옵니다.
- 원본 태스크의 사이드바에는 **중복 항목**이 생겨, 중복으로 표시된 태스크와 각 작성자를 보여 줍니다.
- 잘못 표시했다면 배너의 **중복 아님**을 클릭하세요. 태스크가 `todo`로 돌아갑니다. 상태를 `cancelled`가 아닌 다른 상태로 바꿔도 표시가 사라집니다.

중복 관계는 한 단계뿐입니다. 이미 중복인 태스크는 원본이 될 수 없고, 중복 항목이 있는 태스크는 다른 태스크의 중복으로 표시할 수 없습니다. 프로젝트 워크플로에 `cancelled`가 없으면 태스크 작업 메뉴에 이 항목이 나오지 않습니다.

## 태스크 삭제

모든 워크스페이스 멤버가 태스크를 삭제할 수 있습니다.

<Callout type="warning">
삭제는 복구할 수 없습니다. 태스크와 댓글, 첨부 파일, 관련 기록이 영구적으로 제거되고 끝나지 않은 실행도 취소됩니다. 더 이상 진행하지 않으려면 상태를 `cancelled`로 바꾸세요. 논의와 결과는 계속 확인할 수 있습니다.
</Callout>
