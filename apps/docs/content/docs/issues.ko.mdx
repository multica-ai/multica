태스크는 Multica에서 작업을 계획하는 기본 단위입니다. 기능 하나, 버그 하나, 조사 하나처럼 멤버나 에이전트가 책임지고 진행해야 하는 모든 작업이 태스크가 될 수 있습니다. 관련 논의, 상태 변경, 모든 실행이 한곳에 남으므로 채팅 기록이나 터미널 로그에서 컨텍스트를 다시 조합할 필요가 없습니다.

## 태스크의 구성

| 내용 | 용도 |
|---|---|
| **제목과 설명** | 목표, 배경, 요구 사항, 인수 조건입니다. |
| **상태와 우선순위** | 작업이 어느 단계에 있고 무엇을 먼저 처리할지 나타냅니다. |
| **담당자** | 워크스페이스 멤버, 에이전트 또는 스쿼드입니다. |
| **날짜, 라벨, 사용자 지정 속성** | 계획, 분류, 팀 고유 필드입니다. |
| **프로젝트와 상하위 관계** | 더 큰 작업 범위에 포함하거나 하위 태스크로 나눕니다. |
| **활동과 실행 로그** | 댓글, 상태 변경, 실행, 에이전트가 반환한 결과입니다. |

![태스크 상세: 설명, 논의, 오른쪽 속성, 실행 로그](/images/docs/quickstart-run-result.webp)

## 태스크 만들기

**태스크** 페이지나 프로젝트에서 새 태스크를 만들고 제목을 입력합니다. 다른 속성은 언제든 보충할 수 있습니다.

각 태스크에는 `MUL-123` 같은 번호가 있습니다. 숫자는 워크스페이스 안에서 증가합니다. 관리자가 워크스페이스의 태스크 접두사를 바꾸면 번호가 새 접두사로 표시됩니다. 자세한 내용은 [워크스페이스](/workspaces#워크스페이스-만들기)를 참고하세요.

## 담당자 선택

| 담당자 | 결과 |
|---|---|
| **멤버** | 해당 멤버가 후속 작업을 책임지며 실행은 생성되지 않습니다. |
| **에이전트** | 해당 에이전트의 실행이 생성됩니다. |
| **스쿼드** | 스쿼드 리더가 먼저 받은 뒤 누구에게 맡길지 결정합니다. |

에이전트나 스쿼드에 할당할 때 태스크가 `backlog` 상태가 아니면 즉시 큐에 들어갑니다. 런타임이 오프라인이면 실행은 큐에서 기다립니다. 보관된 에이전트와 스쿼드는 할당할 수 없습니다.

할당은 에이전트의 접근 범위(Access)를 우회하지 않습니다. 스쿼드에 할당하면 리더의 Access를 확인합니다. 자세한 내용은 [태스크를 에이전트에게 할당하기](/assigning-issues)를 참고하세요.

## 상태

모든 워크스페이스에는 기본 상태 7개가 준비되어 있고, 이들은 4개의 수명 주기 카테고리로 묶입니다.

| 카테고리 | 기본 상태 | 의미 |
|---|---|---|
| `unstarted` | `backlog`, `todo` | 아직 시작하지 않은 작업. 계획된 것이든 미뤄둔 것이든 같습니다. |
| `started` | `in_progress`, `in_review`, `blocked` | 이미 시작했거나, 검토를 기다리거나, 지금은 진행할 수 없는 상태. |
| `done` | `done` | 성공적으로 끝난 종료 상태. |
| `closed` | `cancelled` | 더 이상 진행하지 않는 종료 상태이며, 성공적인 완료는 아닙니다. |

카테고리는 수명 주기 판단을 단순하게 유지하기 위한 것입니다. 보드와 목록, 필터, 정렬은 모두 개별 상태를 기준으로 동작하며, 구체적인 상태에는 에이전트와 자동화가 의존하는 더 세밀한 동작이 남아 있습니다.

| 상태 | 의미 |
|---|---|
| `backlog` | 지금은 시작하지 않습니다. 에이전트에게 할당된 태스크도 `backlog`에서 벗어나야 실행이 생성됩니다. |
| `todo` | 작업이 명확하며 시작을 기다립니다. |
| `in_progress` | 처리 중입니다. |
| `in_review` | 결과가 있으며 검토를 기다립니다. |
| `done` | 완료되었습니다. |
| `blocked` | 지금은 계속 진행할 수 없습니다. |
| `cancelled` | 더 이상 진행하지 않으며 기록은 유지합니다. |

멤버와 에이전트는 상태를 직접 바꿀 수 있습니다. 프로젝트가 [워크플로](/workflows)를 사용하면 그 안의 단계에서 선택합니다. 인계가 있는 단계로 옮기면 담당자가 바뀌고 에이전트에게 작업을 요청할 수 있습니다.

에이전트는 작업 진행에 따라 태스크 상태를 업데이트합니다. 보통 시작하면 진행 중으로, 결과를 전달하면 검토 대기로 표시합니다. 프로젝트에 워크플로가 있다면 해당 단계와 인계 지침을 따릅니다. 실행이 끝난 것만으로 태스크가 완료되지는 않으며, 질문에 답한 것만으로 전체 작업을 마친 것도 아닙니다.

<Callout type="info">
다음 두 가지 변경은 시스템이 수행합니다.

- 실행이 실패하고 해당 태스크에 다른 실행이 없으며 재시도도 트리거되지 않으면 `in_progress`가 `todo`로 돌아갑니다.
- 태스크에 연결된 PR이 모두 병합되면 태스크가 워크스페이스가 정한 상태(기본값 `done`)로 바뀝니다. 워크스페이스가 "변경하지 않음"으로 설정했거나 해당 태스크만 상태 변경을 끈 경우는 제외합니다. 자세한 내용은 [GitHub 연동](/github-integration)을 참고하세요.
</Callout>

### 사용자 정의 상태

워크스페이스의 `owner` 또는 `admin`은 **코드 리뷰**, **QA**, **재작업** 같은 상태를 추가할 수 있습니다. **설정**에 **워크플로**가 있으면 그 아래의 상태 라이브러리에서 관리합니다. 없으면 **설정 → 태스크 상태**를 사용합니다.

만들 때 미시작, 진행 중, 완료, 취소 중 무엇을 나타내는지 선택합니다. 이 분류는 나중에 바꿀 수 없습니다. 사용자 정의 상태가 기본 상태의 특별한 동작을 얻지는 않습니다. 예를 들어 이름을 “대기”로 정해도 에이전트가 일시 정지되지는 않습니다.

- 기본 상태는 이름과 색을 바꾸거나 보관할 수 없습니다.
- 사용자 정의 상태는 입력한 이름으로 표시됩니다. 이름이나 색을 바꾸면 같은 상태를 쓰는 모든 곳에 적용됩니다.
- 보관하기 전에 완료·취소된 태스크를 포함해 해당 상태의 모든 태스크를 적절한 다른 상태로 옮겨야 합니다. 사용자 정의 워크플로에서도 제거하세요. 보관한 뒤에는 선택지에 표시되지 않습니다.

상태 라이브러리에는 사용 가능한 상태가 모여 있고, 프로젝트 워크플로는 사용할 상태와 순서를 정합니다.

## 태스크와 실행

태스크는 계속 유지되는 작업 기록이고 [실행](/tasks)은 에이전트가 한 번 실행한 기록입니다. 하나의 태스크에서 첫 구현, 추가 수정, 재검토처럼 여러 실행이 차례로 생성될 수 있습니다. 실행이 "완료됨"인 것은 이번 실행이 끝났다는 뜻일 뿐이며, 태스크의 완료 여부는 태스크 상태를 기준으로 판단합니다.

## 프로젝트와 하위 태스크

하나의 태스크는 최대 하나의 [프로젝트](/projects)에 속할 수 있습니다. 프로젝트는 그 안의 실행에 공유 설명과 리소스를 제공합니다. 다른 프로젝트로 옮겨도 복사본이 만들어지지 않습니다.

큰 작업은 하위 태스크로 나눌 수 있습니다. 상위 태스크에는 전체 목표를 남기고 하위 태스크는 각각 독립적으로 진행합니다. 상위와 하위 태스크의 상태는 서로 연동되지 않습니다.

하위 태스크에는 **단계**(stage)를 지정해 1, 2, 3처럼 묶어서 진행할 수 있습니다. 현재 가장 이른 미완료 단계의 모든 하위 태스크가 `done` 또는 `cancelled`가 되면 상위 태스크에 "하위 태스크 완료" 알림이 전달됩니다. 상위 태스크 담당자가 에이전트이면 에이전트가 깨어나 다음 단계로 진행할지 결정합니다. 단계를 지정하지 않은 하위 태스크는 같은 묶음으로 간주하며 모두 끝났을 때 한 번 알립니다.

## 보기 전환

태스크 페이지에서는 목록, 보드, 표, 간트 차트, 스윔레인 다섯 가지 보기를 제공합니다. 상태, 담당자, 프로젝트, 기타 속성으로 필터링하고 정렬할 수 있으며 모두 같은 태스크 집합을 표시합니다.

## 태스크 삭제

모든 워크스페이스 멤버가 태스크를 삭제할 수 있습니다.

<Callout type="warning">
삭제는 복구할 수 없습니다. 태스크와 댓글, 첨부 파일, 관련 기록이 영구적으로 제거되고 끝나지 않은 실행도 취소됩니다. 더 이상 진행하지 않으려면 상태를 `cancelled`로 바꾸세요. 논의와 결과는 계속 확인할 수 있습니다.
</Callout>
