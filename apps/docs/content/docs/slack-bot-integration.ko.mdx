기존 Slack Bot 연결은 Slack 앱과 하나의 [에이전트](/agents) 매핑을 유지합니다. 멤버는 Bot DM, 채널 @멘션, 파일 전송, `/issue`를 계속 사용할 수 있습니다.

<Callout type="info">
  새 에이전트별 Slack 연결은 폐기되었습니다. 기존 연결은 계속 실행되며 **Settings → Integrations**에 표시됩니다.
</Callout>

## 기존 Bot 사용

- DM은 할당된 에이전트와의 Multica [Chat](/chat)이 됩니다.
- 채널과 그룹에서는 Bot을 @멘션한 메시지만 실행됩니다.
- 대상 메시지의 파일은 에이전트가 사용할 수 있도록 Multica 스토리지로 복사됩니다.
- **`/issue <제목>`**은 연결된 워크스페이스 멤버 이름으로 이슈를 만듭니다.
- **`/new <메시지>`**는 기록을 보존하면서 이전 대화 맥락 없이 실행합니다.

첫 메시지에서 일회용 계정 연결 URL이 돌아올 수 있습니다. 해당 워크스페이스의 Multica 계정으로 여세요. 이 신원 콜백은 독립 계약이며 새 에이전트 연결이 아닙니다.

## 유지된 연결 관리

**Settings → Integrations**에서 기존 Bot과 할당된 에이전트를 확인할 수 있습니다. 워크스페이스 owner와 admin은 연결을 해제할 수 있으며 기존 대화와 감사 기록은 유지됩니다.

## 셀프 호스팅

기존 암호화 Slack 자격 증명에는 `MULTICA_SLACK_SECRET_KEY`가 필요합니다. 저장된 자격 증명을 읽을 수 없게 만들지 않도록 키를 안정적으로 유지하세요. Socket Mode는 외부로 연결하므로 공개 Request URL은 필요하지 않습니다.

## 문제 해결

- **새 연결 작업이 없음**: 에이전트별 브라우저 연결은 폐기되었습니다.
- **Bot이 응답하지 않음**: 연결이 활성 상태이고 할당된 에이전트가 보관되지 않았으며 [Runtime](/daemon-runtimes)이 온라인인지 확인하세요.
