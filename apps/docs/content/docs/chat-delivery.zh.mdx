秘书可以在应用之外联系你。你选择加入后，每日简报会发送到你的聊天应用。在 Telegram、Slack 和飞书中，你还可以通过消息下方的按钮决定提案。其他聊天应用可以与秘书交流，但不接收简报。

## 各应用的功能

| 聊天应用 | 与秘书和智能体交流 | 简报推送 | 通过按钮决定 |
| --- | --- | --- | --- |
| Telegram | 是 | 是 | 是 |
| Slack | 是 | 是 | 是 |
| 飞书（Lark） | 是 | 是 | 是 |
| 钉钉（DingTalk） | 是 | 否 | 否 |
| 企业微信（WeCom） | 是 | 否 | 否 |

各应用的设置请参见其独立页面：[Telegram](/telegram-bot-integration)、[Slack](/slack-bot-integration)、[飞书](/lark-bot-integration) 和[钉钉](/dingtalk-bot-integration)。本版本中企业微信没有单独的设置页面，由运营者进行配置。

<Callout type="info">
聊天平台必须已经连接到你的 Multica 账户。简报推送使用该连接，它不会自己建立连接。
</Callout>

## 选择加入

每位成员在公司的简报设置中自行选择：

- **Brief push**（简报推送）：开或关。默认关闭。
- **Chat**（聊天）：发送到哪个已连接的聊天。每位成员可以选择一个。
- **Quiet hours**（安静时段）：一段小时范围（0 到 23），期间不发送任何内容。该时段可以跨越午夜。落在时段内的简报会推迟到时段结束后发送。

相同设置可通过 `GET` 和 `PUT /api/company/brief-push` 访问。可选择的聊天列表位于 `GET /api/company/brief-push/bindings`。

## 消息内容

推送的消息刻意保持简短。它包括简报标题、待决定的数量、前三项决定及其链接，以及完整简报的链接。

发布简报只会为每位选择加入的成员排队一次投递。由独立任务负责发送。发送失败会最多重试五次，两次尝试之间等待一、二、四、八分钟。仍然失败的投递会记录为失败。投递失败永远不会导致简报本身失败。

## 通过按钮决定

在 Telegram、Slack 和飞书中，消息里的每项决定都带有 **approve**（批准）、**reject**（驳回）和 **snooze**（稍后）按钮。每个按钮携带针对该提案和动作的签名令牌，有效期为 24 小时。

你按下按钮时，服务器会通过你建立的连接，判断聊天用户对应的 Multica 成员。只有所有者或管理员可以做决定。智能体不能按按钮。如果聊天用户不是所有者或管理员，按钮会回复一个打开应用的链接。已决定的事项会移除其消息中的按钮。

## 聊天命令

已与 Multica 关联的成员可以在与秘书的聊天中发送以下命令：

- `/brief` 返回最新的简报。
- `/decisions` 列出待决定的提案。

命令必须是消息首行的全部内容。`/briefing`，以及句子中间的命令，都不会被识别。

## 限制

- 本版本中，钉钉和企业微信不接收简报或按钮。它们的消息会作为普通对话转给秘书和智能体。
