이 가이드는 각자 터미널에서 자기 에이전트를 돌리는 대신 AI 코딩 에이전트를 함께 쓰고 싶은 여러 개발자로 이루어진 팀을 위한 것입니다. 여러 페이지에 나뉘어 설명된 기능을 하나로 엮습니다. [역할](/members-roles), 에이전트 [Access](/agents#권한과-access), [런타임 공유](/daemon-runtimes#비공개와-공개), [스쿼드](/squads), [워크플로](/workflows)입니다.

Multica 워크스페이스에서는 멤버와 에이전트가 같은 태스크를 다룹니다. 어떤 태스크든 사람, 에이전트, 스쿼드에게 할당할 수 있습니다. 에이전트는 댓글로 진행 상황을 알리고, 결과를 넘길 때 태스크를 `in_review`로 옮기며, 모든 실행은 태스크에 기록됩니다.

## 각 기능이 하는 일

| 팀에 필요한 것 | 사용할 기능 | 설정하는 곳 |
|---|---|---|
| 사람과 에이전트의 모든 작업을 한곳에서 보기 | 하나의 워크스페이스. 리스트, 보드, 테이블, 간트, 스윔레인 레이아웃 | [태스크](/issues) |
| 누가 워크스페이스에 속하고 무엇을 관리할지 정하기 | 역할: `owner`, `admin`, `member`, 프로젝트 단위 게스트 | [멤버와 권한](/members-roles) |
| 특정 에이전트를 누가 실행할지 정하기 | 에이전트의 Access: **비공개**, **워크스페이스에 공개**, **특정 사용자에게 공개** | [에이전트](/agents#권한과-access) |
| 에이전트가 실행되는 컴퓨터 공유하기 | 비공개, 공개 또는 특정 멤버와 공유하는 런타임 | [런타임 공유](/daemon-runtimes#비공개와-공개) |
| 매번 고르지 않아도 알맞은 에이전트에게 작업 보내기 | 리더 에이전트가 태스크를 배분하는 스쿼드 | [스쿼드](/squads) |
| 에이전트의 작업을 리뷰어에게 넘기고 다시 돌려보내기 | 리뷰 상태, 댓글, 워크플로 인계 | [워크플로](/workflows) |
| 팀의 작업 방식을 여러 에이전트에서 재사용하기 | 에이전트에 붙이는 스킬 | [스킬](/skills) |
| 아무도 시작하지 않아도 반복 작업 실행하기 | 일정이나 webhook으로 실행되는 오토파일럿 | [오토파일럿](/autopilots) |
| 비용과 실패 살피기 | 에이전트별 사용량과 오류 보고 | [분석](/analytics) |

## 예시: 10명 규모의 엔지니어링 팀

아래 단계는 개발자 10명이 에이전트 3개를 함께 쓰는 구성을 만듭니다. 이름과 숫자는 팀에 맞게 바꾸세요.

1. **워크스페이스를 만들고 멤버를 초대합니다.** `owner` 또는 `admin`이 개발자를 `member`로 초대하고, 리드 한두 명을 `admin`으로 지정합니다. 프로젝트 하나만 따라가면 되는 외주 인력은 그 프로젝트를 공유받은 [게스트](/members-roles#게스트)로 참여합니다.
2. **컴퓨터를 연결합니다.** 자기 컴퓨터에서 에이전트를 돌리고 싶은 개발자는 [Multica Desktop](/desktop-app)을 엽니다. 그러면 그 컴퓨터가 런타임으로 등록됩니다. 팀 전체가 의존하는 에이전트에는 클라우드 VM 같은 공용 머신을 `multica setup`으로 연결하고, 소유자가 그 런타임을 공개하거나 특정 멤버와 공유합니다. 런타임을 공유하면 다른 사람도 그곳에서 에이전트를 실행할 수 있지만, AI 코딩 도구의 로그인은 공유되지 않습니다.
3. **공용 에이전트를 만듭니다.** 예를 들어 Claude Code 기반 **Frontend** 에이전트, Codex 기반 **Backend** 에이전트, 다른 도구 기반 **Reviewer** 에이전트를 모두 공용 런타임에 만듭니다. 지침을 작성하고 팀의 [스킬](/skills)을 붙입니다. 누구나 써도 되는 에이전트는 Access를 **워크스페이스에 공개**로, 민감한 자격 증명을 가진 에이전트는 **특정 사용자에게 공개**로 설정합니다.
4. **스쿼드를 만듭니다.** 세 에이전트를 하나의 스쿼드에 넣고 리더 에이전트를 정합니다. 사람들은 태스크를 스쿼드에 할당하고, 리더가 담당자를 고릅니다.
5. **리뷰 단계를 둡니다.** 프로젝트에서 **개발 딜리버리** 같은 [워크플로](/workflows)를 선택합니다. 개발은 엔지니어링 에이전트, 리뷰는 Reviewer 에이전트, QA는 멤버가 맡습니다.
6. **할당을 시작합니다.** 개발자는 태스크를 만들어 에이전트, 스쿼드 또는 동료에게 할당합니다. 에이전트는 공용 런타임에서 작업하고 결과를 각 태스크에 남깁니다.

개인 실험은 다른 사람을 방해하지 않습니다. 개발자가 자기 노트북에서 **비공개**로 둔 에이전트는 다른 사람의 선택 목록에 나타나지 않습니다.

## 멤버별로 사용할 수 있는 에이전트를 어떻게 관리하나요?

모든 에이전트에는 owner와 Access 설정이 있습니다. Access는 누가 그 에이전트를 실행할 수 있는지, 즉 태스크를 할당하고 @멘션하고 대화할 수 있는지를 정합니다.

| Access | 실행할 수 있는 사람 |
|---|---|
| **비공개** (기본값) | 에이전트 owner만. |
| **워크스페이스에 공개** | 역할이 `owner`, `admin`, `member` 중 하나인 멤버. |
| **특정 사용자에게 공개** | 에이전트 owner와 선택한 멤버. |

팀에서 특히 중요한 규칙:

- 워크스페이스 `owner`와 `admin`은 모든 에이전트를 보고 관리할 수 있지만, 권한을 받지 않은 에이전트를 역할만으로 실행할 수는 없습니다. Access는 에이전트 owner만 바꿀 수 있습니다.
- 게스트는 에이전트를 실행하거나 @멘션할 수 없습니다.
- 담당자 선택 목록과 @멘션 메뉴에는 그 사람이 실행할 수 있는 에이전트만 표시됩니다.
- 스쿼드가 권한을 넓혀 주지는 않습니다. 스쿼드에 할당하거나 @멘션하려면 그 리더를 실행할 수 있어야 합니다.
- 멤버를 제거하면 다른 에이전트의 Access 목록에서 그 사람이 받은 권한도 지워집니다.
- 에이전트 환경 변수에 넣은 자격 증명은 워크스페이스 `owner`와 `admin`만 열어 볼 수 있고, 읽을 때마다 감사 기록이 남습니다. [환경 변수와 자격 증명](/agents-create#환경-변수와-자격-증명)을 참고하세요.

비공개 프로젝트는 두 번째 경계입니다. 비공개 프로젝트는 멤버 목록에 있는 사람에게만 보이며, 에이전트 실행에서는 실행을 시작한 사람과 에이전트 owner가 모두 목록에 있을 때만 보입니다. [비공개 프로젝트](/projects#private-projects)를 참고하세요.

## 사람과 에이전트는 작업을 어떻게 주고받나요?

인계는 할당과 댓글로 이루어지고, 단계 사이의 맥락은 태스크에 남습니다.

1. **에이전트가 코드를 작성합니다.** 태스크를 에이전트에게 할당합니다. 에이전트는 시작할 때 `in_progress`로 바꾸고, 진행하면서 댓글을 남기고, 결과를 넘길 때 `in_review`로 바꿉니다. 보통 pull request가 함께 올라옵니다.
2. **동료가 리뷰합니다.** 리뷰어는 태스크에서 실행 로그와 연결된 PR을 확인합니다. [GitHub 연동](/github-integration)을 쓰면 태스크에 PR 상태, CI 결과, 충돌이 표시됩니다.
3. **에이전트가 리뷰 의견을 반영합니다.** 리뷰어는 태스크에 답글을 달고 그 에이전트나 다른 에이전트를 @멘션해 무엇을 고칠지 알려 줍니다. 멘션된 에이전트는 지금까지의 논의를 모두 가진 채 같은 태스크를 이어받습니다. 아직 실행 중이라면 답글이 [현재 실행에 바로 전달](/mentioning-agents#실행-중인-에이전트에게-끼어들기)될 수 있습니다.
4. **작업을 마무리합니다.** 기본적으로 에이전트는 `in_review`에서 멈춥니다. `done`은 사람이 정하거나 GitHub 연동에 맡깁니다. GitHub 연동은 기본적으로 연결된 PR이 모두 병합되면 태스크를 `done`으로 옮깁니다.

이 단계를 그때그때가 아니라 고정된 절차로 만들려면 [워크플로](/workflows)를 쓰세요. 각 상태를 에이전트나 멤버에게 맡기고, 그 단계의 지침과 함께 **완료 후 이동**할 단계와 **반려 시 되돌릴 단계**를 설정합니다. 그러면 태스크가 리뷰 단계에 들어갈 때 리뷰 에이전트에게 넘어가고, 반려되면 개발 단계로 돌아갑니다.

## 각 에이전트가 무엇을 하는지 모두가 어떻게 보나요?

- 사이드바의 **실행 중** 보기는 워크스페이스 전체에서 지금 에이전트가 실행 중인 태스크를 보여 줍니다.
- 에이전트 목록은 각 에이전트의 가용 상태(런타임 기준)와 작업량(작업 중, 대기 중, 유휴)을 보여 줍니다.
- 각 태스크에는 모든 실행의 실행 로그(도구 호출, 명령, 오류와 타임스탬프)가 남습니다. [실행](/tasks)을 참고하세요.
- [인박스](/inbox)는 작업이 나에게 할당되었을 때, 에이전트가 나를 @멘션하거나 내가 팔로우하는 태스크에 댓글을 달았을 때, 실행이 실패했을 때 알려 줍니다. 모든 단계를 알리지는 않습니다.
- [분석](/analytics)은 워크스페이스의 비용, 토큰, 실행 시간, 실패한 실행을 보여 주고, 에이전트별 순위와 실행이 실패한 이유도 보여 줍니다.

<Callout type="info">
일반 멤버는 다른 사람의 **비공개** 에이전트를 볼 수 없습니다. 그 사용량은 분석에서 이름 없이 **기타 에이전트** 한 행으로 합쳐집니다.
</Callout>
