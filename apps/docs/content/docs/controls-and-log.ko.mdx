두 가지 도구가 당신이 회사를 통제할 수 있게 합니다. **회사 제어**는 워크스페이스 전체에서 자동 작업을 멈추고, **거버넌스 로그**는 회사의 거버넌스 방식을 바꾸는 모든 변경을 기록합니다. 로그는 편집하거나 삭제할 수 없습니다.

## 회사 상태

회사는 다음 세 상태 중 하나에 있습니다.

| 상태 | 루틴과 위임 실행 | 채팅과 당신이 시작한 실행 |
| --- | --- | --- |
| `running`(실행 중) | 정상 실행 | 정상 실행 |
| `paused`(일시 정지) | `company_paused` 사유로 보류됩니다. 오토파일럿은 건너뛰고, 웨이크업은 발동하지 않습니다. | 계속 동작 |
| `quiet`(조용함) | 조용한 시간이 끝날 때까지 미뤄지며, 버려지지는 않습니다 | 계속 동작 |

일시 정지 중에는 지식 자동 공개와 파이프라인 자동 진행이 멈추고, 상시 승인도 적용되지 않습니다. 비서의 브리프와 채팅은 계속 동작하므로, 회사의 상황을 보고 회사와 대화할 수 있습니다.

오피스 헤더의 **Pause**(일시 정지)가 회사를 일시 정지합니다. **stop running work**(실행 중인 작업 중지)를 함께 선택하면, 진행 중인 루틴과 위임 실행도 취소됩니다.

```bash
multica company status
multica company pause --stop-running
multica company resume
```

오너와 관리자는 일시 정지와 재개를 할 수 있습니다. 멤버는 상태를 볼 수 있습니다.

### 조용한 시간

조용한 시간은 워크스페이스 시간대 기준으로 매일 정해진 시간대이며, 그 동안 루틴 실행이 미뤄집니다. 기본값은 22:00부터 07:00까지입니다. 미뤄진 실행은 시간대가 끝날 때 시작됩니다. 아무것도 버려지지 않습니다.

```bash
multica company quiet --enable --start 22:00 --end 07:00 --timezone Europe/Paris
multica company quiet --disable
```

시간은 시간대 기준 `HH:MM` 형식입니다. 조용한 시간은 **Controls**(제어) 탭에서도 설정할 수 있습니다.

<Callout type="info">
일시 정지하면 약 1분 안에 루틴 실행이 멈춥니다. 웹훅으로 시작된 실행은 데몬이 가져가는 시점에 보류되므로, 일시 정지 중에도 실행 목록에는 `issue_created`로 보일 수 있습니다. 그래도 그 실행은 시작되지 않습니다.
</Callout>

## 거버넌스 로그

로그는 회사의 거버넌스 방식을 바꾸는 작업을 추가만 할 수 있는 기록입니다. 다음이 포함됩니다.

- 제안 정책의 생성, 철회, 자동 승인에서의 사용;
- 예산의 설정, 연장, 보류, 해제;
- 자율성 수준 변경;
- 적용되고 되돌려진 조직 변경;
- 지식 자동 공개;
- 단계가 강제 이동된 이니셔티브;
- 회사의 일시 정지와 재개;
- 활성화된 목표;
- 게시된 리뷰.

각 항목에는 종류, 행위자(사람, 에이전트, 시스템, 또는 정책), 대상, 요약, 세부 정보가 있습니다. **거버넌스**의 **Log**(로그) 탭을 열면 종류, 행위자, 대상으로 걸러 보거나 CSV로 내보낼 수 있습니다.

```bash
curl -H "Authorization: Bearer $MULTICA_TOKEN" -H "X-Workspace-ID: $WORKSPACE_ID" \
  "$MULTICA_API/api/governance/events?kind=budget_hold"
curl -H "Authorization: Bearer $MULTICA_TOKEN" -H "X-Workspace-ID: $WORKSPACE_ID" \
  -o governance.csv "$MULTICA_API/api/governance/events.csv"
```

CSV 내보내기는 최대 50,000행입니다. 그 이상이면 HTTP 413을 반환하므로, 필터를 좁힌 뒤 다시 내보내세요.

로그에는 애플리케이션에서 수정하거나 삭제하는 경로가 없습니다. 워크스페이스 전체를 삭제할 때만 사라집니다. 보관 기간은 무기한입니다.

## 시스템 상태

**Controls** 탭은 각 예약 작업의 마지막 성공 시각과 지연, 전달 실패, 지식 사이드카의 상태, 예산 게이트 캐시의 경과 시간을 보여 줍니다. API는 `GET /api/governance/health`입니다. 멈춘 작업은 브리프에 위험 항목으로 나타납니다.

## 제한 사항

- 회사 상태 엔드포인트는 `GET`과 `PUT /api/office/company-state`, 그리고 `PUT /api/office/quiet-hours`입니다. 위의 CLI 명령은 이들을 감쌉니다.
