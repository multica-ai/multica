Multica 使用你透過 Telegram 官方 [@BotFather](https://t.me/BotFather) 建立的 Bot。一個 Bot 對應一個 Multica AI 代理；需要多個獨立 Bot 身份時，為每個 AI 代理分別建立。

<Callout type="info">
Telegram 整合[由社群維護](/community-maintained)：隨每個版本釋出，但沒有官方支援 SLA。遇到問題請提交 [GitHub 任務](https://github.com/multica-ai/multica/issues)。
</Callout>

## 開始前

- 連線操作需要工作區 owner 或 admin 權限。
- API 伺服器必須能夠訪問 `https://api.telegram.org`。
- 你需要 @BotFather 簽發的 Bot token；它等同於密碼。

## 連線 Bot

<Steps>
<Step>

### 建立 Bot [#1-建立-bot]

1. 開啟 [@BotFather](https://t.me/BotFather)，傳送 `/newbot`。
2. 設定顯示名稱和一個以 `bot` 結尾的使用者名稱。
3. 複製 HTTP API token。
4. 預設保持 **Group Privacy** 開啟，這是可見範圍最小的配置：Telegram 只會把命令、明確的 @ 和對 Bot 訊息的回覆投遞給 Bot。也可以關閉它，讓 Bot 把群裡周圍的討論作為上下文，代價是 Bot 會收到群裡的每一條訊息，詳見[Group Privacy 決定 Bot 能看到哪些訊息](#group-privacy)。

<Callout type="warning">
不要把 token 發到任務、聊天、日誌或程式碼倉庫。若已洩露，請在 @BotFather 中撤銷，再用替換後的 token 重新連線。
</Callout>

</Step>
<Step>

### 連線到 AI 代理 [#2-連線到 AI 代理]

1. 在 Multica 開啟 **AI 代理**，選擇目標 AI 代理並進入 **訊息渠道**。
2. 點選 **新增訊息管道**，再選擇 **Telegram**。
3. 貼上 Bot token，然後點選 **連線**。

Multica 會實時請求 Telegram 驗證 Bot，檢查是否存在與長輪詢衝突的 webhook，加密儲存 token，並啟動一條受監督的 `getUpdates` 連線。一個 Bot 若已連線到其他 AI 代理或工作區，必須先在原處斷開。

</Step>
</Steps>

## 第一次使用 [#首次使用與帳號繫結]

成員第一次向 Bot 發訊息時，會收到一次性 Multica 帳號繫結連結。開啟連結，登入同一工作區的 Multica 帳號，再回到 Telegram 重新傳送訊息。連結 15 分鐘後過期；再私聊 Bot 即可獲取新連結。

在群裡，Bot 不會公開傳送帶憑據性質的繫結連結，只會讓傳送者先私聊 Bot。

只有當前工作區成員能使用 Bot；每條訊息都會重新校驗成員身份。

## 在 Telegram 中交代工作 [#使用-bot]

### 私聊

直接開啟 Bot 傳送文字，不需要 @。

### 群聊與 forum topic

把 Bot 加入群後，@ 它，或直接回復它發過的訊息。被接受的訊息會保留在持續的 Multica 對話中：普通群聊各自延續一段對話，forum 的每個 topic 分別隔離。

<Accordions type="multiple">
<Accordion title="沒有發給 Bot 的群訊息" id="unaddressed-group-messages">

未明確發給 Bot 的群訊息本身不會開啟對話，也不會單獨形成一輪，但會被暫存在一個很小的記憶體緩衝裡：每個群（或每個 forum topic）保留 Bot 收到的最近 10 條，伺服器重啟即清空。之後有成員透過 @ 或回覆 Bot 的訊息向它發出指令時，這些暫存訊息會作為只讀上下文附在該輪指令之前，並隨這一輪一起儲存進對話記錄。

緩衝裡的圖片或檔案在上下文中只顯示為 `[Image]` 之類的標記和 caption，檔案本身不會被獲取。`/new` 開啟的新對話不帶這段上下文。

</Accordion>
<Accordion title="Group Privacy 決定 Bot 能看到哪些訊息" id="group-privacy">

緩衝裡有什麼取決於 Telegram 投遞了什麼。Group Privacy 開啟時只有命令、明確的 @ 和對 Bot 的回覆，所以上下文裡只有之前明確發給它的訊息。

想讓它看到普通群聊，請在 @BotFather 裡關閉 Group Privacy，再把 Bot 移出群重新加入，此後 Bot 會收到群裡的每一條訊息。被設為群管理員的 Bot 無論隱私設定如何都會收到全部訊息，因此不改 @BotFather 也會把普通群聊納入上下文。

</Accordion>
<Accordion title="回覆其他成員的訊息" id="replying-to-members">

回覆其他成員的訊息時必須同時 @ Bot，被引用訊息的傳送者及文字（或 caption）才會隨新指令進入上下文；只回覆成員而不 @ Bot 不會觸發。

發給 Bot 的回覆所引用的訊息若帶圖片或檔案，無論傳送者是誰，該檔案也會一併附上。

</Accordion>
</Accordions>

### 命令

- `/new` 建立一個新的空 Multica Chat，並把該 Telegram 對話的後續訊息路由到新 Chat；`/new <訊息>` 會把訊息作為新 Chat 的第一輪。回覆其他成員並明確 @ Bot 時，被選中的引用內容仍會附在第一輪中。
- `/clear` 保留當前 Multica Chat，把新的 AI 代理可見上下文應用到下一條非空訊息；`/clear <訊息>` 會把訊息作為上下文邊界後的第一輪，明確選擇的回覆引用仍會保留。
- `/issue <標題>` 建立 Multica 任務，後續行作為可選描述；不帶標題時返回用法提示。
- 群聊支援 `/issue@your_bot` 這種 Telegram 命令字尾。

### 回覆與內容範圍

Bot 透過傳送並編輯 Telegram 訊息來流式展示文字回覆，引用觸發訊息、保留 forum topic，並按 Telegram 長度限制自動分段。AI 代理工作時，同一則訊息下方會列出它目前的步驟（如執行命令、讀取檔案）和已用時間：私聊顯示每一步的具體物件，群聊只顯示工作型別。可用 `MULTICA_TELEGRAM_TOOL_PROGRESS`（`off`、`summary`、`detail`）調整。

圖片、檔案、影片、語音和音訊訊息會作為同一對話的附件交給 AI 代理，caption 作為訊息正文；AI 代理生成的檔案會在回覆之後發回聊天。這兩個方向都需要服務端配置物件儲存（見下文自託管部分）。

<Accordions type="multiple">
<Accordion title="最終回覆的投遞與排隊" id="reply-delivery">

最終回覆在程序內非同步投遞。正常情況下，某個聊天的退避等待不會佔用 worker；快取達到容量上限並壓縮退避狀態時，同一 Bot installation 下的其他聊天可能被保守延遲。終態佇列有固定容量，超限執行會被明確拒絕並記錄錯誤；佇列不會跨服務重啟恢復。

</Accordion>
<Accordion title="圖片、檔案和其他媒體" id="media">

回覆一條帶有圖片、檔案、影片、語音或音訊的訊息（私聊，或在群裡向 Bot 發出指令時，無論傳送者是誰），會把該訊息作為引用附在你的指令前，並把它的檔案一併交給 AI 代理，這樣你可以指定之前的某張圖片或某段影片。

Telegram 只允許 Bot 下載 20 MB 以內的檔案；檔案無法獲取時（太大或下載失敗），Bot 會告訴你，AI 代理只會看到一個佔位符。

AI 代理生成的檔案作為單獨的訊息發回聊天：10 MB 以內的圖片內聯顯示，其餘 50 MB 以內的檔案以檔案形式到達；無法確認送達時 Bot 會說明，檔案仍保留在 Multica 的回覆附件裡。

未配置物件儲存時，Bot 對媒體訊息回覆不支援提示，AI 代理也會被告知無法傳送檔案。貼紙、位置、投票等非檔案訊息在私聊中以及群裡明確 @ Bot 時會收到同樣的提示，群裡未 @ 的此類訊息保持靜默。

</Accordion>
</Accordions>

## 管理連線 [#管理與斷開]

開啟 **設定 → 訊息渠道**，按平台檢視已連接的 AI 代理。點選 AI 代理，進入其詳細頁面的 **訊息渠道**。工作區 owner/admin 可以在這裡開啟 Bot 的管理選單，斷開連線。斷開會停止長輪詢和後續回覆，但保留 Multica 對話與審計記錄。

## 自託管配置

啟動 API 伺服器前配置一個長期穩定的 32 位元組加密金鑰：

```dotenv
MULTICA_TELEGRAM_SECRET_KEY=<base64 編碼的 32 位元組金鑰>
```

可用 `openssl rand -base64 32` 生成。丟失或輪換此金鑰後，已有 Bot token 無法解密，需要逐個重新連線。

繫結連結使用 `MULTICA_APP_URL`，未設定時回退到 `FRONTEND_ORIGIN`；生成的地址必須能被成員訪問。伺服器網路或代理還必須允許 HTTPS 訪問 `api.telegram.org`；Go 會讀取標準的 `HTTPS_PROXY` 和 `NO_PROXY` 環境變數。

## 常見問題 [#故障排查]

- **無法驗證 Bot**：先檢查伺服器網路和代理。只有 Telegram 明確拒絕 token 時才需要重新生成。
- **webhook 衝突**：連線前移除這個 Bot 已有的 webhook；Telegram 不允許 webhook 與 `getUpdates` 同時使用。
- **409 輪詢衝突**：另一個 Multica 例項或程序正在輪詢同一個 Bot。停止另一個消費者，或為不同環境使用不同 Bot。
- **群裡不回覆**：確認 Bot 已入群，並且訊息 @ 了它或回覆了它的訊息。
- **繫結連結過期**：重新私聊 Bot，並使用最新連結。
- **Bot 不執行**：檢查 AI 代理是否已歸檔，以及它使用的[執行時](/daemon-runtimes)是否線上。
