收件箱汇总与你有关的工作动态，提醒你哪里出现了需要关注的变化。它不是完整的活动日志，前因后果仍在对应的任务里。

## 在哪里找到收件箱

收件箱是**工作**面板里的一个分区，排在固定之后、视图和项目之前；没有固定项时，它就是第一个分区。分区标题栏有三个标签：**收件箱**、**已延后**和**已归档**。只有当前标签显示名称，另外两个显示为图标，悬停可看到名称。再次点击当前标签可以折叠这个分区。未读数显示在**收件箱**旁，也会以角标显示在应用侧栏的**工作**上；右键点击**工作**可以**全部标为已读**。

**收件箱**标签每个任务占一行，最新的在前，已读和未读都在。每行显示任务状态、标题和时间，第二行显示谁做了什么；未读的行带一个圆点。在显示设置里打开**紧凑显示**，每行只保留一行。鼠标悬停在某行上会弹出卡片，显示完整标题和评论内容，并提供**打开**、**标为已读**和**归档**。

在手机上，工作面板收在抽屉里。其中的收件箱分区末尾有**全部通知**，点开是收件箱页面，带自己的列表、同样的三个标签和筛选。

## 收件箱的内容

常见通知包括：

- 任务分配给你，或从你名下移走；
- 你订阅的任务出现新评论，或负责人、优先级和日期发生变化（别人的任务默认只推送关键更新，见下文）；
- 你订阅的任务状态发生变化，前提是你打开了默认关闭的**状态变更**；
- 有人在任务描述或评论中 @你；
- 你创建的任务或评论收到表情回应；
- 你订阅的任务中，智能体运行失败；
- 你订阅的项目里新建了任务；
- [通过智能体创建任务](/issues#通过智能体创建)的操作完成或失败；
- 你订阅的自动化创建了新任务，或自动化因连续失败被暂停。

自己的操作不会通知自己。同一任务的多条通知会合并成一行，打开后可查看这条任务最近的变化。

## 自动订阅的来源

以下参与者会自动订阅任务：

- 任务的创建者；
- 新的负责人；
- 发表评论的人；
- 在任务描述中被新增 @提及的人；
- 自动化中预先配置的订阅成员。

负责人变更不会取消原有订阅。可以在任务页面随时订阅或取消；取消后普通更新不再进入收件箱，直接 @你仍会单独通知。

<Callout type="info">
打开**状态变更**后，子任务的状态变化也会通知父任务的订阅者。子任务的评论、优先级和日期变化不会向父任务冒泡。
</Callout>

## 别人的任务

任务分配给别人或别人的智能体时，你因为创建、评论或被 @ 而自动产生的订阅，默认只推送关键更新：@你、回复你参与的讨论，以及（打开**状态变更**时）`in_review`、`blocked`、`done` 等需要人来看的状态。日常评论和其他变化留在任务里。你手动订阅的任务、通过项目订阅的任务，以及分配给你或你的智能体的任务，仍会收到你打开的所有通知类型。

任务页面会把这类订阅标为**仅关键更新**。点开后选**接收全部动态**，会把它变为对这个任务的手动订阅；之后这个任务无法再退回仅关键更新，只能取消订阅。**修改默认设置**会打开**设置 → 通知**，把**你订阅的任务**分组顶部的**别人的任务**改为**全部动态**，所有这类任务都会推送全部动态。

## 智能体与收件箱

收件箱通知属于工作区成员。只有服务端验证运行的上游触发人就是运行环境所有者时，智能体才能读取和处理该所有者的通知。这个身份会沿智能体调用链继承。这条规则覆盖收件箱的所有操作：活跃列表、归档、稍后提醒列表、未读数，以及所有修改。由他人触发、没有可验证触发人的运行，以及没有任务绑定的云节点凭证，都会被拒绝。智能体读取的未读数只包含运行所在的工作区，不包含所有者的其他工作区。只有人可以删除通知。智能体做的每次修改都会在服务端留下记录，写明是哪个智能体、哪次运行、代哪个人操作。

在评论中 @智能体、把任务分配给智能体或触发自动化，都会直接创建一次运行，不会给智能体留通知。`@all` 也只通知成员。

## 用 CLI 管理

复用现有 CLI 登录读取和处理通知。列出通知不会将其标为已读：

```sh
multica inbox count
multica inbox list --unread --since 1d --output json
multica inbox list --issue MUL-123
multica inbox list --archived     # 或 --snoozed
```

每行显示通知 ID、任务编号、类型、来自谁、标题，以及评论或变更的简短摘要。`--unread`、`--issue`（任务编号或 UUID）、`--since`（RFC 3339 时间，或 `2h`、`1d`、`1w` 这样的时长）、`--project` 和 `--type` 用于筛选列表。`--archived` 会逐页读取整个归档，早已归档的任务也能找到并恢复。`--project` 接受完整 UUID 或唯一 ID 前缀，包括 `multica project list` 显示的短 ID；无匹配或前缀有歧义时会报错。表格还保留任务、评论和项目 ID，摘要会截短；`--output json` 带完整摘要。

用列表里的 ID 处理通知：

```sh
multica inbox read <id>...                      # unread <id>... 撤销
multica inbox read --issue MUL-123              # 一个任务上的全部通知
multica inbox archive <id>...                   # unarchive <id>... 恢复
multica inbox snooze <id>... --until tomorrow   # RFC 3339、30m、3h、1d、1w；unsnooze <id>... 结束
```

与应用里一样，标为已读、归档或稍后提醒一条任务通知，会作用于整个任务；标为未读只改变这一条。某个 ID 失败不会中断其余 ID，命令会列出失败的条目并以非零状态退出。

批量操作与收件箱菜单一致：`multica inbox read --all`，以及带 `--all`、`--read`（最新通知已读的任务）或 `--completed`（处于 `done` 或 `closed` 类状态的任务）的 `multica inbox archive`。它们需要 `--yes`，手动运行时也可以输入确认；除 `--completed` 外，稍后提醒中的任务不受影响：与应用一致，`--completed` 也会归档稍后提醒中已完成或已关闭的任务，并结束稍后提醒。每次修改都会输出实际改动的通知条数，包括整个任务上的通知；本来就是该状态的记为 0。`--output json` 返回同一计数，以及每个 ID 的结果。CLI 不能删除通知。

获授权的智能体运行在这些操作中都使用任务凭证，不会回退到人的登录凭证。

## 处理通知

点击一行会在收件箱页面打开这条通知，并定位到它所指的评论。所有通知都在这里打开，包括没有对应任务的通知，例如自动化暂停和快速创建结果。通知开着时这一行保持高亮，再点一次会重新定位到那里。打开通知会把它标为已读，但这一行仍留在列表里。任务上方的**收件箱**可以回到列表，**在任务页打开**（↗）会在单独的任务页打开这个任务，那里不显示收件箱栏。

<InboxDemo />

任务页头下方有一条收件箱栏。它先说明谁在什么时候做了什么，再给出通常能处理掉这条通知的操作：

- **状态**、**负责人**和**快捷操作**直接修改任务本身，和属性里一样；工作区有快捷操作时才会出现。
- **延后**（`H`）把任务移出收件箱，到你选的时间再回来，并打开下一条。详见下方的「延后任务」。
- **归档**（`E`）会归档这条通知并打开下一条。归档不会修改或删除任务。要结束任务，请修改它的状态；默认情况下这也会归档它的通知（见下文「通知何时离开收件箱」）。
- **取消订阅并归档**（`⇧E`）：任务不是你的（负责人不是你，也不是你拥有的智能体）时出现。它取消你对这个任务的订阅，归档这条通知并打开下一条；之后普通动态不再进入收件箱，@你仍会通知。有子任务时可以选择只退订这个任务，或连同全部子任务一起退订。只退订这个任务时，提示里可以**撤销**，订阅会按原来的方式恢复；连同子任务一起退订无法在这里撤销，可以在任务页面重新订阅。悬停卡片和行的右键菜单里也有这个操作。

"下一条"是分区在当前筛选下列出的下一行，因此不用回到列表，就能把收件箱一条条处理完。

分区标题栏的筛选按钮可以按通知类型、收到时间和来自谁筛选，也可以按任务的状态和优先级筛选。分区处于筛选状态时，这个按钮会一直显示，点**清除筛选**即可恢复。

在**收件箱**标签下，分区的 ⋯ 菜单里有以下批量操作：

- **全部标为已读**；
- **归档全部已读**；
- **归档已完成**：归档 `done` 或 `closed` 分类下任务的通知；
- **归档全部**。

**已归档**标签列出已归档的通知，向下滚动可继续加载更早的记录。筛选覆盖全部归档记录，包括尚未加载的记录。已归档的通知会保留已读状态，因此点行上或已打开通知的收件箱栏里的**移回收件箱**（或按 `E`）时会原样回来。

## 延后任务

延后会把一个任务暂时移出你的收件箱，到你选的时间再回到最上面，并标为未读。可以点收件箱栏里的**延后**（或按 `H`），也可以在悬停收件箱行时点归档旁边的按钮，或在悬停卡片里点 **延后**。可选 **1 小时**、**3 小时**、**1 天**、**3 天**、**1 周**，或点 **选择日期和时间…** 选一年内的任意时间。按天延后时保留当前的钟点；在 22:00 到 6:00 之间延后的，会在早上 9:00 回来。延后后的提示里可以撤销（`Z`）；如果是改了时间，撤销会恢复原来的时间。

任务延后期间：

- 它的新通知会跟着一起等，不计入未读角标。回来时，这一行会显示 **延后到期** 以及期间有多少条动态；
- 有人点名 @ 你、它被指派给你、运行失败，或全部子任务完成时，它会提前回来。`@all` 提及不会唤醒它；
- **全部标为已读** 和各种全部归档操作会跳过它。归档它会结束延后；**自动归档我处理过的任务**包含完成（默认包含）时，你自己完成这个任务也一样；
- 直接打开这个任务的任务页不会把它标为已读，也不会结束延后。从**已延后**标签打开时，收件箱栏会显示它何时回来，点**修改时间**可以让它现在回来（`H`）或换个时间。

延后只影响你自己的收件箱。所有延后的任务都在**已延后**标签里，点每行的按钮可以让它现在回来。

如果**已延后**标签无法加载，可以点击 **重试**。刷新失败时，已加载的任务会继续显示。

## 通知何时离开收件箱

通知不会因为已读而离开收件箱。只有以下几种情况，一行才会移出：

- 你手动归档它：在它所在的行、悬停卡片、收件箱栏，或通过批量操作；
- 你延后了它的任务。这是暂时的：到你选的时间，或有需要你处理的通知时，它会回来。见上方的「延后任务」；
- 你亲自处理了它的任务，按**设置 → 通知**里**自动归档我处理过的任务**的选择来算。默认的**完成或触发智能体时**包括：把任务改为 `done` 或 `closed` 分类下的状态，以及任何实际触发了智能体运行的操作——触发智能体的评论、快捷操作或插话（steer），在非 `backlog` 状态下指派给智能体或小队，把已指派给智能体或小队的任务从 `backlog` 推进到活跃状态（包括 `todo`），进入带智能体处理者的工作流列，重新运行任务，或手动触发唤醒。没有唤醒智能体的整理动作（比如把未指派的任务从 `backlog` 改到 `todo`、在 `backlog` 中先指派智能体、取消指派、发 `/note` 备注、取消勾选触发，或因运行环境不可用被拦截）不会归档。**完成任务时**只算 `done` 和 `closed`，**从不**会关掉自动归档，**自定义**可以逐项勾选，包括默认不算的回复、推进状态、转交以及改优先级、改项目、改日期和改标签。只归档你自己在该任务上的通知，无论是否已读。别人或智能体做同样的操作时，通知会留在你的收件箱里，你仍能看到这个变化；
- 它是"运行失败"通知，且任务进入交回给人的状态：`in_review`、`started` 分类下的自定义状态，或 `done`、`closed` 分类下的任一状态。这会归档所有人在该任务上的"运行失败"通知，不论是谁改的状态，也不受上面的开关影响。`blocked` 例外：它同样交回给人，但工作还卡着，之前的失败记录还要看。
- 你在该工作区的收件箱超过 2,000 条通知。收件箱保留最新的 2,000 条，随后自动归档更早的通知，无论是否已读。从延后中回来或从归档中还原的通知，按回来的时间算作新通知。已延后任务上的通知不计入，也不会被归档。

打开着的窗口会立即移除已归档的行，但你正打开的那一行除外。它的通知因为其他原因离开收件箱时（你在状态里把任务改为 `done`、别的窗口归档了它，或修改后不再符合分区的筛选），这一行会在原位保持高亮，收件箱栏会说明发生了什么。在栏里改**状态**、**负责人**或运行**快捷操作**后通知被归档时，栏会写明是哪一项，比如“已改为进行中 · 通知已归档”，这几个操作也留在栏里，可以接着改。**撤销**（或按 `Z`）让通知回来，**下一条**（或按 `E`）打开下一行。你离开之后，这一行才会移出。如果这是收件箱里的最后一条通知，栏会改为显示**收件箱已清空**和延后中的任务数，用**前往我的工作**代替**下一条**；按 `E` 会打开已清空的收件箱。这是**归档后 → 停在当前任务**（默认）的行为；选**打开下一条**时，你的操作归档了正打开的通知后，会直接打开下一行（没有下一行时打开已清空的收件箱），提示里可以**撤销**。

如果是你自己把正打开的这一行处理掉（在收件箱栏、它所在的行、悬停卡片，或包含它的批量操作里），会直接打开下一行；没有剩下的行时，会打开收件箱页面，显示**收件箱已清空**：写明你刚才的操作，可以**撤销**（或按 `Z`）把它找回，并显示延后中的任务数和下一条回来的时间。如果是筛选隐藏了收件箱里的其余通知，会改为说明还剩多少条，并提供**清除筛选，继续处理**。返回上一页可以回到任务。归档和批量操作的提示里都可以**撤销**：通知会回来，任务的状态保持不变。带**撤销**的提示（归档、延后、取消订阅都一样）会停留 10 秒；提示还在时，按 `Z` 撤销这次操作。

之后该任务再有新通知，会重新进入收件箱。

**设置 → 通知 → 移出收件箱**里有**自动归档我处理过的任务**（**从不**、**完成任务时**、**完成或触发智能体时**、**自定义**）和**归档后**（**停在当前任务**或**打开下一条**），并提供已归档通知的入口。

## 显示与通知类型

收件箱分区标题栏的 ⋯ 菜单里（每个标签下都有）的**收件箱显示**会打开它的显示设置，只保存在当前设备上：

- **显示条数**：5、10 或 20 条；其余的收在"再显示 N 项"里。
- **紧凑显示**：每行只占一行高度，不显示谁做了什么。默认关闭。
- **未读数量**：分区标题旁的数字。
- **在"工作"上显示未读数**：应用侧栏里工作上的角标。

下方的**接收以下通知**可以分别开关每一类通知。它们和**设置 → 通知**里的开关是同一组，设置页按通知到达你的方式分组：

| 分组 | 类型 |
|---|---|
| **与你直接相关** | 分配、提及、表情回应 |
| **你订阅的任务** | 状态变更、评论、优先级与截止日期 |
| **你订阅的项目** | 新任务 |
| **智能体** | 智能体活动（运行失败，以及智能体请求的应用操作被拦截或过期） |

**状态变更**默认关闭，其余类型默认打开。关闭某一类后，不再创建这类通知，重新打开也不会补回错过的通知；相关变化仍然保存在任务中。快速创建结果和自动化暂停等少数类型不受这些分组控制，始终投递。系统通知和浏览器通知控制的是桌面横幅，不会改变收件箱本身。
