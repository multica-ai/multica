收件箱汇总与你有关的工作动态，提醒你哪里出现了需要关注的变化。它不是完整的活动日志，前因后果仍在对应的任务里。

## 收件箱的内容

常见通知包括：

- 任务分配给你，或从你名下移走；
- 你订阅的任务出现新评论，或负责人、状态、优先级和日期发生变化；
- 有人在任务描述或评论中 @你；
- 你创建的任务或评论收到表情回应；
- 你订阅的任务中，智能体运行失败；
- [通过智能体创建任务](/issues#通过智能体创建)的操作完成或失败；
- 你订阅的自动化创建了新任务，或自动化因连续失败被暂停。

自己的操作不会通知自己。同一任务的多条通知会合并成一项，打开后可查看这条任务最近的变化。

## 企微群通知（自托管）

把某位成员的任务通知从企微私聊改投群机器人时，在后端同时设置
`MULTICA_WECOM_NOTIFICATION_WEBHOOK_URL`、`MULTICA_WECOM_NOTIFICATION_WORKSPACE_ID`
和 `MULTICA_WECOM_NOTIFICATION_MEMBER_ID`，然后重启后端。分别填群机器人的
webhook、工作区 UUID 和成员的用户 UUID（收件箱的 `recipient_id`，不是成员关系行 ID）。
Webhook 含密钥，不要写进日志、任务评论或版本库。

卡片跳转需要 `WECOM_APP_URL`、`MULTICA_APP_URL` 或 `FRONTEND_ORIGIN` 中有一个
可被收件人访问的 HTTP(S) Web 地址；localhost、回环地址和通配监听地址会被拒绝。
「查看任务」入口与整张卡片都打开同一个工作区内的任务详情地址。
仅这位成员的任务通知改投，覆盖状态、评论、指派、取消指派、提及、优先级/日期变更、
表情反应和运行失败。原订阅、静音、成员权限及不通知本人操作的规则继续生效；
不是工作区全部活动广播。与智能机器人的对话及流式回复仍走原通道。群 webhook 不依赖智能机器人的加密密钥或在线连接。
多副本部署应给所有后端副本配置相同的改投规则。
配置不完整或非法时记录错误并保留原路由；清空三项并重启可回滚。切换前确认群成员可以
阅读这些原属个人收件箱的内容。

每条事件发送分层的 `text_notice` 原生卡片：编号及类型、任务名称、保留段落的正文摘要，
底部对齐展示真实优先级、截止时间、操作者和事件/通知时间，并保留任务入口。指派和取消指派展示涉及的人，指派人变化展示前后负责人；提及注明来自评论或任务描述，内部提及链接展示为可读名称。长正文按长度截取，完整内容到任务中查看。普通群 webhook 不提供对话流式。

投递沿用进程内通知总线，最多排队 64 条，单 worker 在单进程内按低于每分钟 20 条节流；
最近 2048 个收件箱事件 ID 在内存去重。没有持久 outbox、重启补发、跨副本去重或共享限流。
仅明确限流拒绝重试一次，网络结果不确定时不自动重发。队列满、失败和结果不确定均在
日志记录事件 ID 与结果，不记录正文和密钥；不会悄悄回流私聊，站内收件箱仍保留。
应监控这些日志；要保证整个部署的组合速率低于平台限制，应使用单一发送进程。

## 自动订阅的来源

以下参与者会自动订阅任务：

- 任务的创建者；
- 新的负责人；
- 发表评论的人；
- 在任务描述中被新增 @提及的人；
- 自动化中预先配置的订阅成员。

负责人变更不会取消原有订阅。可以在任务页面随时订阅或取消；取消后普通更新不再进入收件箱，直接 @你仍会单独通知。

<Callout type="info">
子任务的状态发生变化时，也会通知父任务的订阅者。子任务的评论、优先级和日期变化不会向父任务冒泡。
</Callout>

## 智能体不使用收件箱

收件箱只面向工作区成员。即使智能体是负责人或订阅者，它也不会读取收件箱通知。

在评论中 @智能体、把任务分配给智能体或触发自动化，都会直接创建一次运行，不会给智能体留通知。`@all` 也只通知成员。

## 处理通知

选择一条通知会把它标为已读。处理完后可以归档，归档不会修改或删除对应的任务。

<InboxDemo />

任务进入交回给人的状态后，它的"运行失败"通知会自动归档。这类状态包括 `in_review`、`started` 分类下的自定义状态，以及 `done`、`closed` 分类下的任一状态。`blocked` 例外：它同样交回给人，但工作还卡着，之前的失败记录还要看。

右键点击一条通知，可以使用**标为已读** / **标为未读**和**归档**（在"已归档"视图中是**取消归档**）。标为未读表达的是"我看过了，但还没处理完"：该通知重新变为未读，未读数也会回升；即使它还开着也保持未读，之后再打开一次才会照常标为已读。已归档的通知会保留已读状态，因此恢复时会原样回来。

收件箱菜单还可以：

- 全部标为已读；
- 归档全部或全部已读；
- 归档状态为 `done` 或 `cancelled` 的任务通知；
- 打开"已归档"并恢复某条通知。

从收件箱底部打开**已归档**，向下滚动可继续加载更早的通知。筛选覆盖全部归档记录，包括尚未加载的记录。

## 调整通知类型

打开**设置 → 通知**，可以分别开关：

- 分配；
- 状态变更；
- 评论；
- 提及；
- 优先级与日期；
- 智能体活动。

关闭某一类后，相关变化仍然保存在任务中，只是不再创建收件箱通知。表情回应、快速创建结果和自动化暂停等少数类型不受这六组控制，始终投递。系统通知和浏览器通知控制的是桌面横幅，不会改变收件箱本身。
