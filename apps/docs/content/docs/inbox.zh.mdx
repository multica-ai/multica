收件箱汇总与你有关的工作动态。它不是完整的活动日志，而是提醒你"哪里发生了需要关注的变化"；完整上下文仍然保存在对应的 issue 中。

## 收件箱的内容

常见通知包括：

- issue 分配给你，或从你名下移走；
- 你订阅的 issue 出现新评论，或负责人、状态、优先级和日期发生变化；
- 有人在 issue 描述或评论中 @你；
- 你创建的 issue 或评论收到表情回应；
- 你订阅的 issue 中，智能体执行失败；
- 通过智能体创建 issue 的操作完成或失败；
- 你订阅的自动化创建了新 issue，或自动化因连续失败被暂停。

自己的操作不会通知自己。同一 issue 的多条通知会合并成一项，打开后可查看这条 issue 最近的变化。

## 自动订阅的来源

以下参与者会自动订阅 issue：

- issue 的创建者；
- 新的负责人；
- 发表评论的人；
- 在 issue 描述中被新增 @提及的人；
- 自动化中预先配置的订阅成员。

负责人变更不会取消原有订阅。可以在 issue 页面随时订阅或取消；取消后普通更新不再进入收件箱，直接 @你仍会单独通知。

<Callout type="info">
子 issue 的状态发生变化时，也会通知父 issue 的订阅者。子 issue 的评论、优先级和日期变化不会向父 issue 冒泡。
</Callout>

## 智能体不使用收件箱

收件箱只面向工作区成员。即使智能体是负责人或订阅者，它也不会读取收件箱通知。

在评论中 @智能体、把 issue 分配给智能体或触发自动化，都会直接创建一次执行，而不是给智能体留一条通知。`@all` 也只通知成员。

## 处理通知

选择一条通知会把它标为已读。处理完后可以归档；归档不会修改或删除对应的 issue。issue 进入 `in_review`、`done` 或 `cancelled` 后，它的"执行失败"通知会自动归档。

右键点击一条通知，可以使用**标为已读** / **标为未读**和**归档**（在"已归档"视图中是**取消归档**）。标为未读表达的是"我看过了，但还没处理完"：该通知重新变为未读，未读数也会回升；即使它还开着也会保持未读——之后再打开一次才会照常标为已读。已归档的通知会保留已读状态，因此恢复时会原样回来。

收件箱菜单还可以：

- 全部标为已读；
- 归档全部或全部已读；
- 归档状态为 `done` 或 `cancelled` 的 issue 通知；
- 打开"已归档"并恢复某条通知。

## 调整通知类型

打开**设置 → 通知**，可以分别开关：

- 分配；
- 状态变更；
- 评论与提及；
- 优先级与日期；
- 智能体活动。

关闭某一类后，相关变化仍然保存在 issue 中，只是不再创建收件箱通知。表情回应、快速创建结果和自动化暂停等少数类型不受这五组控制，始终投递。系统通知和浏览器通知控制的是桌面横幅，不会改变收件箱本身。
