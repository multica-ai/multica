收件箱汇总与你有关的工作动态，提醒你哪里出现了需要关注的变化。它不是完整的活动日志，前因后果仍在对应的任务里。

## 在哪里找到收件箱

收件箱是**工作**面板的第一个分区，排在固定、视图和项目之前。未读数显示在分区标题旁，也会以角标显示在应用侧栏的**工作**上；右键点击**工作**可以**全部标为已读**。

这个分区每个任务占一行，最新的在前，已读和未读都在。每行显示任务状态、标题和时间，以及谁做了什么；未读的行带一个圆点。鼠标悬停在某行上会弹出卡片，显示完整标题和评论内容，并提供**打开**、**标为已读**和**归档**。

在手机上，工作面板收在抽屉里。其中的收件箱分区末尾有**全部通知**，点开是收件箱页面，带自己的列表和筛选。

## 收件箱的内容

常见通知包括：

- 任务分配给你，或从你名下移走；
- 你订阅的任务出现新评论，或负责人、优先级和日期发生变化（别人的任务默认只推送关键更新，见下文）；
- 你订阅的任务状态发生变化，前提是你打开了默认关闭的**状态变更**；
- 有人在任务描述或评论中 @你；
- 你创建的任务或评论收到表情回应；
- 你订阅的任务中，智能体运行失败；
- 你订阅的项目里新建了任务；
- [通过智能体创建任务](/issues#通过智能体创建)的操作完成或失败；
- 你订阅的自动化创建了新任务，或自动化因连续失败被暂停。

自己的操作不会通知自己。同一任务的多条通知会合并成一行，打开后可查看这条任务最近的变化。

## 自动订阅的来源

以下参与者会自动订阅任务：

- 任务的创建者；
- 新的负责人；
- 发表评论的人；
- 在任务描述中被新增 @提及的人；
- 自动化中预先配置的订阅成员。

负责人变更不会取消原有订阅。可以在任务页面随时订阅或取消；取消后普通更新不再进入收件箱，直接 @你仍会单独通知。

<Callout type="info">
打开**状态变更**后，子任务的状态变化也会通知父任务的订阅者。子任务的评论、优先级和日期变化不会向父任务冒泡。
</Callout>

## 别人的任务

任务分配给别人或别人的智能体时，你因为创建、评论或被 @ 而自动产生的订阅，默认只推送关键更新：@你、回复你参与的讨论，以及（打开**状态变更**时）`in_review`、`blocked`、`done` 等需要人来看的状态。日常评论和其他变化留在任务里。你手动订阅的任务、通过项目订阅的任务，以及分配给你或你的智能体的任务，仍会收到你打开的所有通知类型。

任务页面会把这类订阅标为**仅关键更新**。点开后选**接收全部动态**，会把它变为对这个任务的手动订阅；之后这个任务无法再退回仅关键更新，只能取消订阅。**修改默认设置**会打开**设置 → 通知**，把**你订阅的任务**分组顶部的**别人的任务**改为**全部动态**，所有这类任务都会推送全部动态。

## 智能体与收件箱

收件箱通知属于工作区成员。对于 `multica inbox list` 使用的活跃通知列表和归档通知，只有服务端验证运行的上游触发人就是运行环境所有者时，智能体才能读取该所有者的列表。这个身份会沿智能体调用链继承。由他人触发、没有可验证触发人的运行，以及没有任务绑定的云节点凭证，都不能读取。此保证只覆盖活跃列表和归档；稍后提醒、未读数和写接口沿用现有权限，另案处理。

在评论中 @智能体、把任务分配给智能体或触发自动化，都会直接创建一次运行，不会给智能体留通知。`@all` 也只通知成员。

## 用 CLI 读取

复用现有 CLI 登录，列出当前通知，不会将通知标为已读：

```sh
multica inbox list --project <project-id> --type mentioned --output json
```

`--project` 接受完整 UUID 或唯一 ID 前缀，包括 `multica project list` 显示的短 ID。前缀会先通过项目列表解析，再读取收件箱；无匹配或前缀有歧义时会报错。

两个筛选条件都可省略，在拉取当前收件箱后于本地应用。JSON 包含通知、任务、项目和可选的评论 ID，以及类型、标题、已读状态和创建时间。默认输出为表格。获授权的智能体运行使用任务凭证读取运行环境所有者的通知，不会回退到人的登录凭证。

## 处理通知

点击一行会打开对应的任务，并定位到通知所指的评论或应用请求。任务开着时这一行保持高亮，再点一次会重新定位到那里。打开任务会把通知标为已读，但这一行仍留在列表里。没有对应任务的通知，例如自动化暂停和快速创建结果，会在收件箱页面中打开。

<InboxDemo />

从收件箱打开的任务，页头会带上收件箱的操作：

- **延后**（`H`）把任务移出收件箱，到你选的时间再回来，并打开下一条。详见下方的「延后任务」。
- **标记为已完成**会把任务设为 `done`，归档这条通知，并打开下一条。即使关闭了**自动归档我完成的任务**，它也会归档这条通知。任务尚未完成或取消时才会出现。
- **归档**（`E`）会归档这条通知并打开下一条。归档不会修改或删除任务。
- **取消订阅并归档**（`⇧E`）：任务不是你的（负责人不是你，也不是你拥有的智能体）时出现。它取消你对这个任务的订阅，归档这条通知并打开下一条；之后普通动态不再进入收件箱，@你仍会通知。有子任务时可以选择只退订这个任务，或连同全部子任务一起退订。只退订这个任务时，提示里可以**撤销**，订阅会按原来的方式恢复；连同子任务一起退订无法在这里撤销，可以在任务页面重新订阅。悬停卡片和行的右键菜单里也有这个操作。

"下一条"是分区在当前筛选下列出的下一行，因此不用回到列表，就能把收件箱一条条处理完。

分区标题栏的筛选按钮可以按通知类型、收到时间和来自谁筛选，也可以按任务的状态和优先级筛选。分区处于筛选状态时，这个按钮会一直显示，点**清除筛选**即可恢复。

分区的 ⋯ 菜单里有**查看已归档**和以下批量操作：

- **全部标为已读**；
- **归档全部已读**；
- **归档已完成**：归档 `done` 或 `closed` 分类下任务的通知；
- **归档全部**。

**查看已归档**会打开已归档的通知，向下滚动可继续加载更早的记录。筛选覆盖全部归档记录，包括尚未加载的记录。已归档的通知会保留已读状态，因此**取消归档**（或按 `E`）时会原样回来。

## 延后任务

延后会把一个任务暂时移出你的收件箱，到你选的时间再回到最上面，并标为未读。可以在任务页头点闹钟按钮（或按 `H`），也可以在悬停收件箱行时点归档旁边的按钮，或在悬停卡片里点 **延后**。可选 **1 小时**、**3 小时**、**1 天**、**3 天**、**1 周**，或点 **选择日期和时间…** 选一年内的任意时间。按天延后时保留当前的钟点；在 22:00 到 6:00 之间延后的，会在早上 9:00 回来。延后后的提示里可以撤销；如果是改了时间，撤销会恢复原来的时间。

任务延后期间：

- 它的新通知会跟着一起等，不计入未读角标。回来时，这一行会显示 **延后到期** 以及期间有多少条动态；
- 有人点名 @ 你、它被指派给你、运行失败、应用请求你操作，或全部子任务完成时，它会提前回来。`@all` 提及不会唤醒它；
- **全部标为已读** 和各种全部归档操作会跳过它。归档它会结束延后；开着 **自动归档我完成的任务** 时你自己完成这个任务，也一样；
- 从别处打开这个任务不会把它标为已读，也不会结束延后。任务页头会显示它何时回来，点开可以让它现在回来（`H`）或修改时间。

延后只影响你自己的收件箱。所有延后的任务都在视图里的 **已延后** 中，也可以从收件箱菜单的 **查看已延后** 进入。

## 通知何时离开收件箱

通知不会因为已读而离开收件箱。只有以下几种情况，一行才会移出：

- 你手动归档它：在它所在的行、悬停卡片、任务页头，或通过批量操作；
- 你延后了它的任务。这是暂时的：到你选的时间，或有需要你处理的通知时，它会回来。见上方的「延后任务」；
- 你亲自把它的任务改为 `done` 或 `closed` 分类下的任一状态，且**自动归档我完成的任务**处于开启状态（默认开启）。只归档你自己在该任务上的通知，无论是否已读。别人或智能体完成的任务，通知会留在你的收件箱里，你仍能看到这个变化；
- 它是"运行失败"通知，且任务进入交回给人的状态：`in_review`、`started` 分类下的自定义状态，或 `done`、`closed` 分类下的任一状态。这会归档所有人在该任务上的"运行失败"通知，不论是谁改的状态，也不受上面的开关影响。`blocked` 例外：它同样交回给人，但工作还卡着，之前的失败记录还要看。

打开着的窗口会立即移除已归档的行，但你正打开的那一行除外。它的通知因为其他原因离开收件箱时（你在状态里把任务改为 `done`、别的窗口归档了它，或修改后不再符合分区的筛选），这一行会在原位保持高亮，任务页头会说明发生了什么：**撤销**让通知回来，**下一条**（或按 `E`）打开下一行。你离开之后，这一行才会移出。

如果是你自己把正打开的这一行处理掉（在任务页头、它所在的行、悬停卡片，或包含它的批量操作里），会直接打开下一行；没有剩下的行时，任务保持打开。归档、标记为已完成和批量操作的提示里都可以**撤销**：通知会回来，任务的状态保持不变。

之后该任务再有新通知，会重新进入收件箱。

**设置 → 通知 → 移出收件箱**里有**自动归档我完成的任务**开关，并提供已归档通知的入口。

## 显示与通知类型

收件箱分区标题栏的设置按钮会打开它的显示设置，只保存在当前设备上：

- **显示条数**：5、10 或 20 条；其余的收在"再显示 N 项"里。
- **紧凑显示**：每行只占一行高度，而不是两行。
- **未读数量**：分区标题旁的数字。
- **在"工作"上显示未读数**：应用侧栏里工作上的角标。

下方的**接收以下通知**可以分别开关每一类通知。它们和**设置 → 通知**里的开关是同一组，设置页按通知到达你的方式分组：

| 分组 | 类型 |
|---|---|
| **与你直接相关** | 分配、提及、表情回应 |
| **你订阅的任务** | 状态变更、评论、优先级与截止日期 |
| **你订阅的项目** | 新任务 |
| **智能体** | 智能体活动（运行失败，以及智能体请求的应用操作被拦截或过期） |

**状态变更**默认关闭，其余类型默认打开。关闭某一类后，不再创建这类通知，重新打开也不会补回错过的通知；相关变化仍然保存在任务中。快速创建结果和自动化暂停等少数类型不受这些分组控制，始终投递。系统通知和浏览器通知控制的是桌面横幅，不会改变收件箱本身。
