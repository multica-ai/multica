댓글에서 에이전트를 @멘션하면 새 정보를 검토하거나 질문에 답하거나 현재 담당자를 돕게 할 수 있습니다. 해당 댓글이 이번 실행의 시작점이 되며 태스크의 담당자와 상태는 바뀌지 않습니다.

## 할당과 @멘션 중 선택

| | 에이전트에게 할당 | 댓글에서 에이전트 @멘션 |
|---|---|---|
| 적합한 경우 | 에이전트가 태스크 전체를 책임지게 할 때 | 현재 댓글을 에이전트가 처리하게 할 때 |
| 담당자 변경 | 예 | 아니요 |
| 상태 변경 | 아니요 | 아니요 |
| 한 번에 선택 | 에이전트 또는 스쿼드 하나 | 여러 에이전트 또는 스쿼드를 @멘션 가능 |
| 이번 실행의 초점 | 태스크 전체 | 트리거한 댓글과 같은 묶음으로 합쳐진 댓글 |

담당자를 명확히 정해야 한다면 [할당](/assigning-issues)을 사용하고, 논의에 잠시 참여시키기만 한다면 @멘션을 사용하세요.

## 트리거 미리보기

댓글 편집기에서 에이전트나 스쿼드를 선택하면 입력란 아래에 트리거 미리보기가 표시됩니다.

- 전송 후 어떤 에이전트가 작업을 시작하는지
- 대상이 직접 @멘션, 태스크 담당자, 스쿼드 리더 중 어디에서 정해졌는지
- 대상을 사용할 수 없는지 또는 호출 권한이 부족한지

특정 에이전트의 선택을 해제하면 이번 트리거만 건너뜁니다. 댓글에서 이름을 지울 필요가 없으며 에이전트의 Access도 바뀌지 않습니다.

![전송 전 트리거 미리보기: 전송 후 작업을 시작할 에이전트 목록](/images/docs/mention-trigger-preview.webp)

댓글을 게시하면 온라인 런타임이 보통 즉시 작업을 가져갑니다. 런타임이 오프라인이면 작업이 큐에서 기다립니다.

## 답글 자동 라우팅

@멘션이 없는 일반 댓글은 논의 컨텍스트에 따라 라우팅됩니다.

1. 에이전트의 댓글에 답하면 해당 에이전트에게 전달됩니다.
2. 이미 에이전트가 참여한 논의에 답하면 그 논의의 에이전트에게 전달됩니다.
3. 둘 다 해당하지 않는 최상위 댓글은 현재 에이전트 담당자에게 전달됩니다. 담당자가 스쿼드이면 리더가 처리합니다. 멤버의 댓글에 직접 다는 일반 답글은 담당자에게 폴백되지 않습니다. 에이전트나 스쿼드를 참여시키려면 명시적으로 @멘션하세요.

댓글에서 다른 대상(멤버 포함)을 명시적으로 @멘션하면 담당자 폴백을 사용하지 않습니다.

답글이 담당자가 아닌 에이전트를 트리거하면 Multica가 담당자의 지연 폴백 실행을 예약합니다. 대상 에이전트가 약 5분 안에 답하면 폴백이 자동으로 취소되고, 그렇지 않으면 담당자도 실행을 시작합니다.

## 연속 댓글 합치기

같은 에이전트가 같은 태스크에서 대기 중인 작업을 이미 가지고 있다면 새 댓글이 그 작업에 합쳐집니다. 이미 실행 중이라면 이후 댓글은 현재 작업이 끝난 뒤 하나의 후속 실행으로 합쳐집니다. 에이전트의 답을 기다리지 않고 정보를 계속 보충할 수 있습니다.

한 댓글에서 서로 다른 에이전트 여러 명을 @멘션하면 각 에이전트가 작업을 하나씩 받습니다. 여러 멘션이 같은 에이전트를 가리키면 한 번만 실행됩니다.

## 에이전트를 트리거하지 않는 메모

두 가지 방법이 있습니다.

- `/note`로 시작: 댓글이 멤버 사이의 메모로만 남고 어떤 에이전트도 트리거하지 않습니다.
- `@all` 사용: 모든 워크스페이스 멤버에게 알리고 해당 댓글이 담당자를 자동으로 트리거하지 않게 합니다.

트리거 미리보기에 에이전트가 남아 있다면 보내기 전에 선택을 해제하면 됩니다.

<Callout type="info">
`@all`에는 에이전트가 포함되지 않습니다. 에이전트에는 인박스가 없습니다. 에이전트가 작업하게 하려면 명시적으로 @멘션하거나, 관련 논의에 답하거나, 태스크를 에이전트에게 할당해야 합니다.
</Callout>

## Access 제한

@멘션으로 에이전트의 Access를 우회할 수 없습니다. 호출 권한이 없거나, 대상이 보관 처리되었거나, 사용할 수 있는 런타임이 없으면 트리거 미리보기에서 시작되지 않는 이유를 보여 줍니다. 댓글 자체는 정상적으로 게시할 수 있습니다. 세 가지 Access 설정의 의미는 [에이전트](/agents#권한과-access)를 참고하세요.

## 에이전트 간 @멘션

에이전트도 자신의 답변에서 다른 에이전트를 @멘션할 수 있습니다. A가 B를 @멘션하고 B가 다시 A를 @멘션하면 시스템은 같은 시점의 중복 실행을 합치지만 이 협업을 언제 끝내야 하는지는 판단하지 않습니다. 종료 조건은 에이전트 지시문에 작성해야 합니다.
