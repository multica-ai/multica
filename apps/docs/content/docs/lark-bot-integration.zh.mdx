把一个 Multica 智能体连接成飞书 Bot 后，已授权群聊或私聊的参与者无需 Labrastro 账号即可与它交流。智能体澄清、整理意见，再通过正常工具以自己的身份回填评论。对话和执行记录保存在工作区。

每个 Bot 只对应一个智能体。需要在飞书中使用多个智能体时，分别为它们连接 Bot。

## 连接 Bot

智能体的所有者、工作区 owner 和 admin 可以发起连接：

<Steps>
<Step>
打开 **智能体**，选择要接入飞书的智能体。
</Step>
<Step>
进入 **集成**，点击 **绑定到飞书**。
</Step>
<Step>
用飞书扫描二维码并确认授权。二维码只能用一次，过期后重新生成即可。
</Step>
<Step>
回到 Multica。页面显示 **已连接到飞书** 后，继续配置下方会话授权。
</Step>
</Steps>

已经连接的智能体不会再次显示扫码入口；需要改名或调整权限时，点击 **在飞书中管理**。

<Callout type="info">
目前只开放中国大陆版飞书的新连接入口。已有的国际版 Lark 连接仍可继续使用和管理。
</Callout>

## 授权会话

连接 Bot 后，打开该智能体的**集成**页或**设置 → 集成**，展开**与智能体交流**，填写允许接入的群聊和私聊 ID，点击**授权这些会话**。授权人需要能管理并调用该智能体。授权覆盖当前整个工作区内智能体的正常工具，允许会话中的所有参与者提供输入。

参与者无需绑定平台账号。成员绑定仍可用于定位个人通知收件地址。未配置的会话不会接入；修改或撤销授权会使旧外部运行授权失效。通知外发仍需单独配置授权。

## 在飞书中交代工作

### 私聊

直接给 Bot 发消息即可。连续消息保留在同一段 Multica 对话中，智能体的回复也发回当前对话。

### 群聊

先把 Bot 加入群聊，再 `@Bot` 并写下要求。Bot 只响应明确 @ 它的消息，执行时会带上群里最近的几条消息作为上下文。

### 讨论任务

说明任务标识或引用 Bot 发出的通知，再表达意见。智能体可能先追问，确认后以自己的身份将整理结果写入对应讨论串；消息不会立即逐字变成评论。

`/issue` 作为会话文本交给智能体，不直接执行成员命令。纯报告追问继续会话，不自动重跑已完成自动化或创建任务。裸“可以/继续”不构成多项变更的批准。`/new` 新建 Chat，`/clear` 开启新上下文；单独发送这两个控制命令不启动智能体运行。

## 接收智能体生成的图片和文件

外部授权会话不回传智能体生成的图片或文件，也不把任务引用改写成工作区链接。下述附件能力仅适用于成员绑定会话。投递时会重新检查会话授权；授权已撤销的排队附件不会继续发送。

部署启用附件回传后，智能体回复中的文字与受支持图片会在同一条飞书消息中混排，图片上传完成后更新原消息；文件另发到同一会话。没有正文的图片回复可直接发送图片消息。图片上限为 10 MB；不受支持、过大或被飞书明确拒绝的图片会按文件发送，文件上限为 30 MB。此功能需要服务端配置对象存储，并授予飞书应用资源上传权限。发送失败或无法确认送达时，附件仍保留在 Multica 的回复中；请求重发前，请先检查当前会话。

## 管理连接

打开 **设置 → 消息渠道 → 飞书** 可以查看工作区内已连接的 Bot。工作区 owner 和 admin 可以在这里断开连接；智能体所有者也可以回到该智能体的 **集成** 页面管理自己的 Bot。

断开后，Bot 不再接收新消息，已有的对话和审计记录不会随之删除。

## 自托管配置

Multica Cloud 无需额外配置。自托管部署需要先设置一个用于加密 Bot 凭据的密钥：

```dotenv
MULTICA_LARK_SECRET_KEY=<base64 编码的 32 字节密钥>
```

可以这样生成：

```bash
openssl rand -base64 32
```

重启 API 服务后，再从智能体的 **集成** 页面连接 Bot。该密钥需要长期保存：更换或丢失后，已有凭据无法解密，需要重新连接。

`MULTICA_LARK_HTTP_BASE_URL` 和 `MULTICA_LARK_CALLBACK_BASE_URL` 只用于代理、测试等特殊部署，正常情况下不需要设置。

## 常见问题

- **没有绑定按钮**：确认当前账号是智能体所有者、工作区 owner 或 admin，并检查自托管密钥是否已配置。
- **二维码失效**：关闭弹窗后重新发起连接。
- **会话未授权**：检查会话 ID、已保存授权，以及授权人是否仍为成员并能调用该智能体。
- **Bot 不执行**：检查智能体是否已归档，以及它使用的[运行时](/daemon-runtimes)是否在线。
- **Bot 完全不回复**：应用必须通过长连接推送事件，Multica 没有 webhook 接收地址。打开飞书开发者后台的 **事件与回调 → 事件配置**，确认订阅方式是使用长连接接收事件而不是请求地址，`im.message.receive_v1` 已订阅，并且包含该配置的版本已发布（企业需要审核时还要通过审核）。配成请求地址的应用照样能绑定、照样显示"已连接"，但一条消息都收不到。
