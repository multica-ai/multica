側邊欄的**統計**頁彙總整個工作區的 AI 代理用量：費用、token、耗時和執行數，以及失敗的執行。工作區成員都能開啟它。每個執行時自己的用量在執行時詳情頁，一條任務花了多少在它的**執行記錄**裡，見下文。

## 頁面結構

頁面分**用量**和**錯誤**兩個頁籤，共用右上角的兩個篩選：

- **時間範圍**：`1d`、`7d`、`30d`（預設）、`90d`、`180d`。`1d` 指今天，從你所在時區的 0 點算起，不是最近 24 小時。
- **專案**：預設**全部專案**。選定專案後，只統計這個專案下任務的執行；對話等不屬於任何任務的執行不計入。

日期按你的時區切分：先用**設定 → 偏好設定 → 時區**裡的設定，沒設定時用瀏覽器時區。頁頭顯示當前時區和資料更新時間。統計資料由伺服器每 5 分鐘彙總一次，頁面開著時也按這個間隔重新整理，剛結束的執行可能要過幾分鐘才出現；想馬上看可以點重新整理按鈕。

切到錯誤頁籤後，位址列會帶上 `?tab=errors`，把連結發給同事，對方開啟就是錯誤頁籤。

## 用量頁籤

頂部四個數字：

| 卡片 | 內容 |
| --- | --- |
| **費用** | 估算的美元費用，演算法見[費用怎麼算](#費用怎麼算) |
| **Token** | 輸入、輸出、快取讀取、快取寫入的合計；下面一行單列輸入和輸出 |
| **耗時** | 已結束執行的執行時長之和，從開始執行算到結束 |
| **執行數** | 時間範圍內結束的執行，以及其中失敗的個數 |

耗時和執行數只算真正開始執行過的執行（已完成、失敗或中途取消），排隊時就被取消的不算。

趨勢卡片在同一條時間軸上切換 Token、費用、耗時、執行數四種指標，**按天**和**按周**兩種粒度。`30d` 和 `90d` 兩種都能選；`1d`、`7d` 只能按天，`180d` 只能按周。按周時每週從週一開始，還沒過完的本週顏色較淺，懸停會標出"未滿 · 已過 N / 7 天"。

**排行榜**按 AI 代理列出 Token、費用、耗時和執行數，可以按其中任意一項排序，預設顯示前 10 個，點**展開全部**看其餘的。排行榜裡可能有兩行彙總：

- **已刪除的 AI 代理**：已經刪除的 AI 代理的用量合併成一行，保證各行加起來仍等於頂部合計。
- **其他 AI 代理**：你看不到的 AI 代理合併成一行。工作區所有者和管理員能看到所有成員建立的 AI 代理；普通成員看不到別人的私有 AI 代理，它們的用量只在這裡出現，不顯示名字。

某個 AI 代理有執行沒上報 token 時，它的 Token 和費用前面會加 `≥`，名字下方註明有幾次執行未上報用量。

## 錯誤頁籤

頂部是**失敗執行**、**失敗率**和**受影響 AI 代理**。失敗率按時間範圍內結束的全部執行計算，卡片下方寫著分子和分母。

下面依次是：

- **每日錯誤**（或每週錯誤）：每段顏色是一類失敗。
- **失敗構成**：時間範圍內全部失敗按類別拆分。點**展開錯誤碼**換成原始的失敗原因碼，可以拿去搜日誌或貼到任務裡。
- **問題最多的 AI 代理**：預設按失敗數排序，前 8 個之後要展開。按**失敗率**排序時，執行不足 10 次的 AI 代理排在後面，因為樣本太少，比例參考價值有限。點 AI 代理名字進入它的詳情頁，能看到最近的執行和每次失敗的原因。

失敗原因碼歸成七類：

| 類別 | 包括 | 一般怎麼處理 |
| --- | --- | --- |
| 認證 | 模型服務認證失敗或無權限、缺少 API key 等配置 | 在 AI 程式設計工具裡重新登入，或補齊配置 |
| 限流 | 限流、容量不足、配額或餘額用盡 | 稍後重試，或提高額度 |
| 超時 | 執行超時、工具長時間無響應、Codex 停滯 | 縮小任務範圍，或調整超時設定 |
| 模型服務 | 模型服務端錯誤、網路故障、模型不可用、請求被拒 | 稍後重試，或換一個可用模型 |
| 執行時 | 執行時離線、守護程序重啟、排隊過期、skill 包下載失敗、找不到工具或版本過舊、準備執行環境失敗 | 檢查執行這次執行的電腦 |
| AI 代理 | 工具程序異常退出、輸出無法解析、上下文超出、達到輪次上限、AI 代理報告無法繼續 | 檢視執行記錄，調整任務後重試 |
| 其他 | 無法歸類的失敗 | 檢視原始錯誤碼和執行記錄 |

每個原因碼的含義和處理見[執行 · 失敗原因參考](/tasks#失敗原因參考)。

## 費用怎麼算

統計裡的費用都是估算值，單位美元，不是 AI 程式設計工具或模型服務商的帳單：

- Multica 內建一張各模型的公開價目表，按每百萬 token 分別給輸入、輸出、快取讀取和快取寫入定價，用它乘以上報的 token 數。
- AI 程式設計工具自己報告了費用時（例如 Grok Build），這部分直接用報告的數字，不再估算。
- 價目表裡沒有的模型，token 照常計入，費用按 $0 計算。在執行時的用量裡可以給這些模型[設定自定義價格](#自定義價格)。
- 有些模型的提示超過一定長度後單價會上浮，彙總資料區分不出每次請求的長度，統一按標準價算，這類執行的估算可能偏低。

token 由 AI 程式設計工具上報。工具沒有上報時，這次執行仍計入耗時和執行數，但不計 token 和費用。例如目前的 GitHub Copilot CLI 不在輸出中提供 token 數，用它的 AI 代理在排行榜上會顯示 `≥` 和未上報的次數。

## 執行時的用量

開啟**執行時**，進入某個執行時的詳情頁，可以看到這個執行時的用量。私有執行時的用量只有所有者能看到，公開執行時的用量所有成員都能看到。

- 頂部是**費用**、**快取節省**和 **Token**。費用下方是和上一個等長時間段的對比；快取節省估算快取讀取按原價計費會多花多少，下方是快取命中率。
- **這個執行時在何時消耗**：按天或按周顯示費用或 Token。切到**熱力圖**，用方格顏色深淺顯示最近 26 周每天的費用，不受上面的時間範圍影響。
- **按 AI 代理分攤**和**按模型分攤**：這段時間的費用分別落在哪些 AI 代理、哪些模型上。
- **每日明細表**：展開後按日期和模型列出每類 token 的數量。

執行時頁的時間範圍是 `7d`、`30d`、`90d`、`180d`。

## 自定義價格

所選時間範圍裡有模型不在價目表中時，執行時的用量上方會提示有幾個模型沒有維護價格，相關 token 未計入費用。點**設定自定義價格**，為每個模型填入輸入、輸出、快取讀取和快取寫入的單價，單位是美元 / 百萬 token，然後儲存。所有模型都有價格後，這裡仍保留**編輯自定義價格**按鈕，方便以後修改。要移除某個模型的價格，清空它的全部欄位再儲存，或點它旁邊的刪除按鈕。

<Callout type="info">
自定義價格只儲存在當前這臺裝置的瀏覽器或桌面應用裡，不同步到帳號，也不會分享給工作區其他成員；同一臺裝置上的所有工作區都會用它。其他成員看到的費用裡，這些模型仍按 $0 計算。
</Callout>

自定義價格只用於價目表裡沒有的模型，不能覆蓋內建價格，也不影響 AI 程式設計工具自己報告的費用。儲存後，這臺裝置上的統計頁、執行時用量和任務的執行記錄都會按新價格重新計算。

## 任務的花費

每條任務右側的**執行日誌**會顯示這條任務的**已花費**、**Token** 和**AI 代理工作**時長，以及每次執行一根的費用條。點合計、費用條或**開啟時間線**，開啟**執行記錄**對話方塊：

- 頂部彙總**已花費**、**Token**（其中多少來自快取）、**輸出**、**AI 代理工作**和**執行次數**。AI 代理工作是各次執行時長之和，旁邊的"歷時"是從第一次執行開始到最後一次結束經過的時間；執行次數旁邊列出失敗、取消和進行中的次數。
- 圖表切**按次**時每次執行一根柱，可以看費用、Token 或 AI 代理工作；切**累計**時顯示累計費用隨時間增長的曲線。
- **按 AI 代理**和**按模型**兩條色帶顯示費用落在誰身上、哪個模型上。
- 下方按天列出每次執行；展開**執行詳情**能看到這次執行的費用明細和快取命中節省了多少。

對話方塊底部會註明費用是估算值，以及哪些模型沒有價格。

## 用 CLI 檢視

```bash
multica issue usage <issue-id>
multica runtime usage <runtime-id> --days 30
```

`issue usage` 輸出一條任務的 token 合計（輸入、輸出、快取讀取、快取寫入）和執行次數。`RUNS` 是已結束的執行數，`METERED_RUNS` 是上報了用量的執行數，`UNREPORTED` 是沒有上報的；有執行沒上報時，token 數前面帶 `>=`，表示實際只會更多。

`runtime usage` 按日期、工具和模型列出一個執行時的 token 用量，`--days` 預設 90，最大 365。

兩條命令的表格只有 token，不含費用估算；加 `--output json` 輸出介面返回的原始資料。
