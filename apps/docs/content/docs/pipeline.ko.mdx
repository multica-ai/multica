**이니셔티브**는 하나의 벤처입니다. 제품, 기능 라인, 시장 실험이 해당합니다. 당신은 "청구서 도구는 어떻게 되어 가고 있나?"라는 식으로 생각합니다. 프로젝트(작업 묶음)도, 이슈(한 가지 작업)도 아닙니다.

이니셔티브는 **파이프라인**을 따라 움직입니다. 파이프라인은 고정된 단계의 순서입니다. 각 단계에는 담당 스쿼드와 반드시 만들어야 하는 산출물(보통 지식 문서)이 있습니다.

## 단계

기본 파이프라인에는 일곱 단계가 있습니다. 각 단계는 이슈 상태이기도 하므로, 이니셔티브에 연결된 이슈가 진행 상황을 따라갑니다.

| 단계 | 스타터 회사에서 담당하는 스쿼드 | 대표 산출물 |
| --- | --- | --- |
| Validate(검증) | Product Discovery | 검증 보고서 |
| Define(정의) | Product Analysis | 제품 브리프, 분석 |
| Plan(계획) | Planning | 로드맵, 예산 요청, PRD |
| Build(구축) | Build | 테스트 보고서, 릴리스 후보 |
| Launch(출시) | Release & Ops | 출시 계획, 출시 체크리스트 |
| Operate(운영) | Support | 지표 보고서 |
| Learn(학습) | Build | 회고 |

출시 관문은 항상 당신이 결정합니다. 계획 관문의 승인은 예산 요청을 승인합니다. 운영 단계는 계속, 확대, 종료 중 하나의 결과를 내는 검토 관문으로 끝납니다. 스타터 회사가 이 스쿼드들을 만듭니다. [스타터 회사](/starter-company)를 참고하세요.

## 이니셔티브 시작하기

이니셔티브는 두 가지 방법으로 시작합니다.

- **승인된 기회.** 스쿼드가 논거를 담은 `opportunity` 제안을 제출합니다. 승인하면 대상 단계(기본값 `validate`)에 이니셔티브가 만들어집니다.
- **직접 만들기.** 파이프라인 페이지에서 만들거나 `POST /api/initiatives`를 씁니다. CLI에는 생성 명령이 없습니다.

## 보드와 이니셔티브 패널

**Pipeline** 페이지는 단계마다 열이 있고 이니셔티브마다 카드가 있는 보드를 보여 줍니다. 카드를 열면 패널이 나옵니다. 패널에는 논거, 현재 단계와 담당 스쿼드, 필수 산출물(필요 없는 것은 **Waive**(면제)할 수 있음), 당신의 결정을 기다리는 관문, 이니셔티브의 댓글, 단계 변경 타임라인이 표시됩니다.

관리자는 이니셔티브를 특정 단계로 **Force**(강제 이동)할 수도 있습니다. 강제 이동은 거버넌스 로그에 기록됩니다.

## 이니셔티브 진행시키기

담당 스쿼드가 단계를 확인(attest)해서 진행시킵니다. 산출물이 갖춰지면 이니셔티브가 앞으로 나아갑니다.

```bash
multica initiative list
multica initiative show <id>
multica initiative attest <id>   # 담당 스쿼드가 실행: 산출물이 갖춰지면 진행
multica initiative advance <id>  # 현재 단계의 종료 조건이 허용하면 다음 단계로
multica initiative shelve <id>   # 이니셔티브 일시 정지. 오너와 관리자만
```

그 밖의 이동은 API나 앱에서 합니다. 이니셔티브를 이전 단계로 되돌리거나, 종료하거나, 일시 정지된 이니셔티브를 재개할 수 있습니다. 일시 정지와 종료는 거버넌스 로그에 기록됩니다.

관문 단계에는 당신의 결정이 필요합니다. 관문 단계가 준비되면 시스템이 `stage_gate` 제안을 제출합니다. 승인하면 이니셔티브가 진행되고, 반려하면 이니셔티브가 되돌아가며 리더가 깨어납니다. [제안](/proposals)을 참고하세요.

<Callout type="info">
출시는 자동으로 일어나지 않습니다. 자율성 수준과 관계없이 출시 관문은 당신이 결정합니다. [자율성과 승인](/autonomy-and-approvals)을 참고하세요.
</Callout>

## 작업이 저장되는 곳

이니셔티브가 만드는 문서는 **ventures**(벤처) 지식 베이스에 이니셔티브마다 폴더를 하나씩 두고 들어갑니다. 각 단계의 빌드와 킥오프는 이니셔티브 보드 프로젝트 안의 이슈입니다.
