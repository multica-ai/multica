成员和智能体在 [任务](/issues) 的评论里补充背景、提出问题、提交结果。这些记录留在任务上，之后谁打开任务都能看到前因后果。

## 发表评论和回复

在任务的动态区输入内容并发送，就会创建一条评论。评论支持格式、代码块、链接和附件。

`html` 或 `mermaid` 代码块会直接在评论里渲染成图表或图示，可以切换查看源码。附件以卡片显示，点击在查看器中打开，HTML 文件也是如此。

回复某条评论会形成一条讨论。回复可以继续嵌套，但都归在同一条顶层讨论下。

任务里有两条以上讨论时，Web 和 Desktop 的任务详情页右侧会出现一列刻度：长刻度是一条讨论，短刻度是一条回复。鼠标移上去会展开所有讨论的提纲，点任意一项跳到对应评论，折叠起来的已解决讨论也能直接跳进去。

## 批注评论与任务描述

在 Web 或 Desktop 中，可以选中任意已发表评论里的文字（包括自己的评论），针对这段文字写意见：

<Steps>
<Step>

选中文字，点击选区工具条中的 **加入回复**。

</Step>
<Step>

在选区旁填写意见，点击 **添加批注**。确认后批注才加入当前讨论的回复草稿并显示编号；空内容无法确认。

</Step>
<Step>

用原有的发送按钮，把所有批注合并成一条回复发出，各条批注之间保留一个空行。发布后先显示批注，再显示你在输入框中填写的整体回复；两部分都有内容时，中间显示分隔线。

</Step>
</Steps>

任务描述的选区工具条提供的是 **加入评论**：批注进入新评论草稿，发送后创建新的讨论。评论上的批注仍进入原讨论的回复草稿。

首次保存的评论批注会确定具体回复目标，包括嵌套回复。同一讨论中其他消息的引用也会加入这份草稿，最后作为一条评论发布。引用中的提及不会通知或触发任何人；你自己填写的提及仍按普通规则处理。

<Accordions>
<Accordion title="编辑、删除和快捷键" id="annotation-editing">

- 编辑已有批注后，点击 **保存批注** 才会应用修改。
- Enter 确认，Shift + Enter 换行；Esc 或点击框外会取消本次未确认的修改。
- 点击原文上的编号标记可以继续编辑；点击批注框右侧的删除图标，会同时移除这条批注、原文标记和草稿条目。
- 鼠标悬停在批注计数上会打开浮层，可以查看、删除引用，或点击引用回到原位编辑意见。点击或使用键盘也能打开这个浮层。

</Accordion>
<Accordion title="草稿和数量限制" id="annotation-limits">

草稿只保存在当前设备和工作区，刷新后可以恢复，30 天后过期。每条回复最多包含 20 条批注，每次引用最多 4,000 个字符。原文之后被修改，已保存的引用快照不变；回复目标被删除时，草稿无法发送。

目前不支持在对话（Chat）中批注、在移动端输入批注，也不跨设备同步草稿。

</Accordion>
</Accordions>

## 解决一条讨论

问题有了结论，可以把整条讨论标记为已解决，或把某条回复设为结论。两个操作都在评论右上角的 **评论操作** 菜单里：第一条评论的菜单里是 **解决该讨论**，回复的菜单里是 **以此评论解决讨论**。

<ResolveThreadDemo />

解决整条讨论后，它折叠成一行，点开仍能查看全部内容。把某条回复设为结论时，第一条评论和这条结论保持显示，中间的回复折叠起来。一条讨论同时只保留一个结论，设了新的，旧的就会被替换。

在已解决的讨论中继续回复，会自动重新打开这条讨论。

## 从评论创建子任务

讨论中冒出一件需要单独跟进的事，可以从那条评论直接拆出子任务：在**评论操作**菜单中选择**从这条评论创建子任务**。

创建对话框会附上一份上下文：当前任务的标题、描述和附件，以及这条讨论中截至所选评论为止的全部评论和附件。展开对话框中的上下文卡片可以先核对内容。手动创建和通过智能体创建都能用，新任务自动成为当前任务的子任务。交给智能体时，你只需要写要它做什么，上下文会一起交给它。智能体只把这些内容当作历史背景，不会执行里面出现的命令或要求。

建好的子任务上显示**创建自**，点开是创建那一刻的**上下文快照**。快照不会跟着原文变化：原任务或讨论之后被修改、删除，快照里仍是当时的内容，并标出**来源有更新**和具体变化的部分。

上下文过大时无法创建：一条讨论最多带 256 条评论，文本最多 1 MiB，附件最多 100 个、合计 500 MiB。通过智能体创建时，智能体所在的运行时需要更新到支持这项功能的版本，否则对话框会提示切换到手动模式或更新运行时。智能体没能建好任务时，收件箱里的失败通知提供**保留上下文重试**。

## 重复使用常用请求

用[快捷操作](/quick-actions)保存"请谁来做、做什么"。点击任务侧栏中的操作会立即发送；在评论框输入 `/` 并选择操作，则先放进草稿，可以修改后再发送。

## @提及

输入 `@`，从列表中选择目标：

| 目标 | 效果 |
|---|---|
| **成员** | 收件箱收到提及通知；评论中的 @ 不会产生订阅。 |
| **智能体** | 为该智能体创建一次运行；智能体没有收件箱。 |
| **小队** | 通知小队中的成员，并触发小队 leader 执行。 |
| **任务** | 插入另一条任务的链接，不发通知，不触发智能体。 |
| **@all** | 通知全部工作区成员，不触发任何智能体。 |

直接输入纯文本 `@name` 不会创建提及，需从编辑器的候选列表中选择。输入有效的任务编号时，编辑器会自动转换为任务链接。

<Callout type="info">
在评论中 @智能体不会改变任务的负责人或状态。关于触发预览、普通回复的自动路由和连续评论如何合并，见[在评论中 @智能体](/mentioning-agents)。
</Callout>

## 订阅和收件箱

参与评论的成员会自动订阅这条任务，后续动态和 @提及会进入[收件箱](/inbox)；也可以在任务右上角手动订阅或取消。完整的订阅来源和通知规则见[收件箱与订阅](/inbox)。

## 表情反应

给评论添加表情，可以表示已读、同意或简单反馈。表情不触发智能体，也不改变任务状态。

## 编辑和删除

评论作者可以编辑或删除自己的评论，工作区的 `owner` 和 `admin` 也可以编辑和删除任何人的评论。对智能体发表的评论，界面只提供删除入口，不提供编辑入口。

编辑评论后，Multica 会按新内容重新计算触发。编辑时新增的 @提及同样会创建运行；保存前输入框下方会显示触发预览。

你编辑期间如果别人先保存了这条评论，保存会被拦下，编辑框下方并排显示**服务端最新版本**和**你的本地版本**，差异逐行标出。选**保留我的版本**，用你的内容保存；选**使用最新版本**，编辑框换成最新内容，你可以在它的基础上继续改。任务标题同时被两个人修改时，也会这样比较。

<Callout type="warning">
删除评论无法撤销。删除只作用于这一条评论：如果它有回复，回复会保留在讨论中，被删除的评论不留痕迹。例外是讨论的第一条评论：回复都挂在它下面，所以原位置会保留"评论已删除"。内容有误时编辑即可。
</Callout>
