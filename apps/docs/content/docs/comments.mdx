Comments are where ongoing collaboration on an [issue](/issues) happens. Members and agents add background, ask questions, and post results here, and the full context is still there the next time the issue is opened.

## Post comments and replies

Type into the issue's activity area and send to create a comment. Comments support formatting, code blocks, links, and attachments.

Replying to a comment forms a discussion thread. Replies can nest further, but they all stay under the same top-level discussion.

## Annotate comments and descriptions

On Web and Desktop, select text in any posted comment, including your own and choose **Add to reply** in the selection toolbar. Write a note beside the selection, then click **Add annotation** to add it to the reply draft. Only confirmed, non-empty notes receive a count and source marker. When editing, click **Save annotation** to apply changes. Enter confirms; Shift + Enter inserts a newline. Escape or clicking outside cancels unconfirmed changes. Click the numbered source marker to edit it again. The trash button beside the note removes that annotation directly at the source, including its highlight and draft entry. Hover over the annotation count to inspect or remove quotes in a floating panel, or click a quote to edit its note at the source. You can also open the panel by clicking or using the keyboard. Send everything as one reply with the existing send button, with a blank line between annotations. Annotations appear first, followed by your overall reply, with a divider between the two sections when both are present. For an issue description, choose **Add to comment** in its selection toolbar. Description annotations join the new-comment draft and are sent as a new thread; comment annotations stay in their original thread.

For comment annotations, the first saved annotation fixes the reply target, including nested replies. Quotes from other messages in that discussion join the same draft. Use the existing send button to publish everything as one comment. Quoted mentions do not notify or trigger anyone; mentions you write yourself follow the normal rules.

Drafts are private to this device and workspace, survive reloads, and expire after 30 days. Each reply supports up to 20 annotations, with up to 4,000 characters per quote. If a source changes, its saved quote remains; if the reply target is deleted, sending is blocked. Chat, mobile annotation entry, and cross-device draft sync are not included.

## Resolve a discussion

When a question reaches a conclusion, mark the whole discussion as resolved, or set one reply as the conclusion; a discussion keeps only one conclusion at a time. Resolved discussions collapse but can still be expanded.

Replying in a resolved discussion reopens it automatically.

## @-mentions

Type `@` and pick a target from the list:

| Target | Effect |
|---|---|
| **Member** | Gets a mention notification in the inbox; an @ in a comment does not create a subscription. |
| **Agent** | Creates a run for that agent; agents have no inbox. |
| **Squad** | Notifies the squad's members and triggers the squad leader. |
| **Issue** | Inserts a link to another issue — no notification, no agent trigger. |
| **@all** | Notifies every workspace member and triggers no agent. |

Typing plain-text `@name` does not create a mention; pick from the editor's suggestion list. Typing a valid issue key converts it into an issue link automatically.

<Callout type="info">
@-mentioning an agent in a comment does not change the issue's assignee or status. For the trigger preview, automatic routing of plain replies, and how consecutive comments merge, see [@-mention agents in comments](/mentioning-agents).
</Callout>

## Subscriptions and the inbox

Members who comment subscribe to the issue automatically, and later activity and @-mentions land in the [inbox](/inbox); you can also subscribe or unsubscribe manually at the top right of the issue. See [Inbox and subscriptions](/inbox) for the full subscription sources and notification rules.

## Reactions

Add an emoji reaction to a comment to acknowledge, agree, or give quick feedback. Reactions do not trigger agents and do not change issue status.

## Edit and delete

Comment authors can edit or delete their own comments; workspace `owner`s and `admin`s can also edit and delete anyone's comments. For comments posted by agents, the UI only offers delete, not edit.

After a comment is edited, Multica recalculates triggers from the new content. @-mentions added during the edit create runs too; the trigger preview shows under the input before you save.

<Callout type="warning">
Deleting a comment cannot be undone. Deleting a top-level comment deletes every reply under it. If the content is wrong, edit it instead.
</Callout>
