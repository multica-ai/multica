description: AI コーディングエージェントを使うチームが、Linear や Jira を使い続けるべき場合、エージェントの作業を Multica に移すべき場合、両方を併用すべき場合。
---

Linear と Jira はどちらもタスクを AI エージェントに割り当てられます。どちらかをすでに使っているチームが「なぜ Multica を加えるのか」と考えるのは自然です。端的に言えば、違いは**エージェントがどこから来て、どこで動くか**です。Linear と Jira は独自の組み込みエージェントを持ち、サードパーティのエージェントサービスも接続できるトラッカーです。Multica は、チームがすでに使っている AI コーディングツールを、あなたが接続したコンピューター上で動かし、すべての実行をタスクに記録するワークスペースです。

このページの Linear と Jira に関する記述は、2026 年 11 月時点の公開ドキュメントに基づいています。最新の情報は [Linear のエージェントのドキュメント](https://linear.app/docs/agents-in-linear)と [Atlassian の発表記事](https://www.atlassian.com/blog/ai-at-work/your-jira-board-just-got-a-new-kind-of-teammate)を確認してください。

## 結論

- **Linear や Jira を使い続ける**：計画（サイクルやスプリント、ロードマップ、チーム横断のレポート）がプロセスの中心で、使いたいエージェントがすでにトラッカーと連携しているホスト型サービスである場合。
- **Multica を使う**：Claude Code、Codex、Cursor Agent、Copilot などの CLI をベースにした共有エージェントのプールを、自分のマシンやサーバーで動かし、エージェントごとのアクセス制御と完全な実行ログを持ち、すべてをセルフホストする選択肢も欲しい場合。
- **両方を使う**：計画は Linear や Jira に置き、作業の実行をエージェントに任せたい場合。Multica のエージェントは MCP サーバー経由で Linear を読み書きできます。両者の間に自動同期はありません。

| 何か | 人とエージェントがタスクを受け持つワークスペース。エージェントはあなたのランタイムで動く | エージェントプラットフォームを備えたタスク管理・計画ツール | Rovo エージェントとサードパーティのエージェントを備えたタスク・プロジェクト管理ツール |
| エージェントの作業を担うもの | [31 種類の AI コーディングツール](/providers)で設定したエージェント。あなたが接続したコンピューター上で Multica のデーモンが実行する | Linear Agent と、Linear の連携ディレクトリから追加したサードパーティのエージェント | Rovo エージェントと、GitHub Copilot や Cursor などの接続済みサードパーティのエージェント |
| エージェントのコードが動く場所 | あなたのノートパソコン、サーバー、VM。ツールのログインも自分のもの | 各エージェント連携による。多くはベンダーのクラウド | 各エージェントによる。多くはベンダーのクラウド |
| タスクの割り当てやエージェントへの @メンション | 可能。エージェントが担当者になる | 可能。エージェントは委任先（delegate）で、担当者は人のままにできる | 可能 |
| エージェントごとのツールとモデルの選択 | 可能。対応ツールならどれでもよく、エージェントごとに別のツールを使える | 追加したエージェントによる | エージェントによる |
| 各エージェントを誰が実行できるか | エージェントごとに**プライベート**、**ワークスペースに公開**、**特定のメンバーに公開** | 管理者が、追加したエージェントにアクセスを許すチームを選ぶ | Rovo Studio でエージェントの範囲を設定。Jira の権限の範囲内 |
| タスクで見られる実行の情報 | ツール呼び出し、コマンド、エラーを含む完全な実行ログとタイムスタンプ | タスク上のエージェントのアクティビティ。詳しさはエージェントによる | 作業項目に記録されるエージェントの操作 |
| エージェント間の振り分け | [スクワッド](/squads)：リーダーエージェントが担当を選ぶ。[ワークフロー](/workflows)：各ステータスをエージェントか人に渡す | トリアージルール（Triage rules）で新しいタスクをエージェントに委任できる | オートメーションルールやボードの列からエージェントを起動できる |
| 定期的なエージェントの作業 | [オートパイロット](/autopilots)が任意のエージェントをスケジュールや webhook で実行 | Loops が Linear Agent をスケジュールやイベントで実行 | Jira Automation がエージェントをスケジュールやイベントで実行 |
| チームのやり方の再利用 | エージェントに付ける[スキル](/skills) | ワークスペースとチームのエージェント向けガイダンス | Rovo Studio のエージェントの指示とナレッジ |
| セルフホスト | 可能。Docker Compose または Helm | 不可 | Jira Data Center |
| 計画機能 | プロジェクト、ステージ付きサブタスク、[ワークフロー](/workflows)、カスタムプロパティ、リスト・ボード・テーブル・ガント・スイムレーンのビュー | サイクル、プロジェクト、Initiatives、Insights | スプリント、ボード、タイムライン、JQL、レポート |
| ライセンス | ソースアベイラブル（source-available）。組織内での利用はセルフホストを含め無料 | プロプライエタリの SaaS | プロプライエタリ |

## Linear や Jira が向いている場合

- サイクルやスプリント、ロードマップ、ポートフォリオのレポートにプロセスが依存している。Multica にはプロジェクト、ワークフロー、ガントビューがありますが、サイクル、スプリント、ロードマップの計画機能はありません。
- プロダクト、デザイン、サポートを含むチームの大半がトラッカーで仕事をしていて、エージェントに渡すのは一部のタスクだけ。
- GitHub Copilot の coding agent や Cursor のクラウドエージェントのようなホスト型エージェントを好み、自分のコンピューターでエージェントを動かしたくない。
- トラッカーの連携エコシステムや、すでに整えたエンタープライズ向けの管理機能に頼っている。

## Multica が向いている場合

- **すでにコーディング CLI に支払っている。** Multica は、開発者が持っている Claude Code、Codex、Cursor Agent、Copilot CLI、Kimi などのサブスクリプションを動かします。ベンダーごとに別のエージェントサービスを契約する必要はありません。
- **コードと認証情報を自分のマシンに置いておきたい。** エージェントはあなたが接続したランタイムで動きます。Multica をセルフホストすれば、ワークスペースのデータも自社のサーバーに残ります。[セキュリティモデル](/security-model)を参照してください。
- **複数の開発者が同じエージェントを共有する。** エージェント、ランタイム、スキルはワークスペースに属し、Access で誰が各エージェントを実行できるかを決め、どのエージェントが何をしているかがボードでわかります。[チームでエージェントプールを共有する](/team-agent-pool)を参照してください。
- **エージェントが何をしたかを正確に見たい。** 各実行のツール呼び出しとコマンドはタスクに残り、作業中の[実行に割り込んで](/mentioning-agents#実行中のエージェントに割り込む)方向を修正することもできます。
- **レビューを後回しにせず、決まった手順にしたい。** エージェントは `in_review` で成果を渡し、[ワークフロー](/workflows)でレビュー用エージェントやチームメイトに渡し、却下されれば差し戻せます。

## Linear や Jira と併用する

多くのチームは計画にはトラッカーを使い続け、エージェントが作業する部分に Multica を使います。

1. ロードマップとチーム横断の計画は Linear や Jira に置いたままにします。
2. エージェント向けのエンジニアリングタスクを Multica のプロジェクトに作り、リポジトリとドキュメントを[プロジェクトリソース](/project-resources)として付けます。
3. エージェントに作業中に Linear を読み書きさせたい場合は、ワークスペースの `owner` か `admin` が**設定 → MCP サーバー**で Linear の MCP サーバーを追加し、それらのエージェントに割り当てます。[ワークスペースで共有する MCP サーバー](/agents-create#ワークスペースで共有する-mcp-サーバー)を参照してください。

Multica は Linear や Jira からのインポートも同期も行いません。どのタスクをどちらのシステムで管理するかを決めておいてください。
