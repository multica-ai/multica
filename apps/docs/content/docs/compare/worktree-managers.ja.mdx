Conductor、Claude Squad、Orca は、1 人の開発者が複数のコーディングエージェントをそれぞれ別の git worktree で並行して動かし、その成果をレビューするためのツールです。Beads は、リポジトリと一緒に置くタスクトラッカーをエージェントに提供します。Multica が扱うのは隣り合う別の課題で、**チーム**が 1 つのワークスペースでエージェント、タスク、ランタイム、スキルを共有することです。どれが必要かは、主に関わる人数で決まります。

このページのほかのツールに関する記述は、2026 年 11 月時点の公開ドキュメントに基づいています：[Conductor](https://www.conductor.build/docs/concepts/git-worktrees)、[Claude Squad](https://github.com/smtg-ai/claude-squad)、[Orca](https://orca.dev/docs/model/worktrees)、[Beads](https://github.com/gastownhall/beads)。最新の情報はそれぞれを確認してください。

## 結論

- **1 人の開発者が自分のマシンでエージェントを動かし、差分を 1 つずつ自分でレビューする**：Conductor、Claude Squad、Orca のような worktree 管理ツールがよく合い、始めるのも多くの場合より簡単です。
- **エージェントに計画と依存関係のグラフをリポジトリ内で管理させたい**：Beads。
- **複数の人がエージェントを共有する**、エージェントをノートパソコン以外のマシンで動かす、ほかのタスクと同じように作業を割り当てる、アクセス制御や定期的な作業が必要：Multica。

これらは排他的ではありません。開発者は手元で見ながら進める作業には worktree 管理ツールを使い続け、時間のかかる作業や定型の作業を Multica の共有エージェントに任せることもできます。

## worktree 管理ツールが向いている場合

- 1 人の開発者として、複数のエージェントを並べて見ながら作業したく、それぞれにターミナルと差分ビューアーが欲しい。
- すべての変更を、自分のマシンから出す前に自分でインタラクティブにレビューしてマージする。
- 自分のエージェントをほかの人が見たり、割り当てたり、再利用したりする必要がない。

Multica には、アプリ内の差分ビューアーも、タスクごとのターミナルもありません。レビューは pull request で行い、タスクには実行の実行ログが残ります。

## Multica が向いている場合

- **複数の人がエージェントを使う。** エージェント、ランタイム、[スキル](/skills)はワークスペースに属し、[Access](/agents#権限と-access) で誰が各エージェントを実行できるかを決め、どのエージェントが何をしているかを全員が見られます。[チームでエージェントプールを共有する](/team-agent-pool)を参照してください。
- **ノートパソコンを閉じてもエージェントを動かし続けたい。** サーバーや VM を[ランタイム](/daemon-runtimes)として接続し、エージェントをそこで動かします。チームメイトと共有もできます。
- **作業をタスクとして管理したい。** 割り当て、ステータス、コメント、サブタスク、レビュー手順を含む[ワークフロー](/workflows)、PR のリンクが、ローカルのセッションではなく 1 つのタスクにまとまります。
- **繰り返し発生する作業がある。** [オートパイロット](/autopilots)がスケジュールや webhook でエージェントを起動し、各実行が記録されます。
- **チャットから作業を受け付けたい。** Slack、Feishu などの[チャット連携](/channels)からエージェントを起動できます。

## Multica で複数の Claude Code を衝突なく同時に動かすには

別々のタスクを、同じランタイム上の 1 つ以上のエージェントに割り当てます。各実行は `~/multica_workspaces` の下に専用の作業ディレクトリを持ち、リポジトリは共有キャッシュから、通常はそれぞれ別の git worktree としてチェックアウトされるため、並行する実行が同じチェックアウトを編集することはありません。既定では、1 台のコンピューターで同時に動く実行は最大 20、エージェントごとに最大 6 です。[同時実行の上限](/daemon-runtimes#同時実行の上限)を参照してください。並行する実行は、マシンの処理能力と Claude Code アカウントの使用量の上限を共有する点は変わりません。

自分のマシンにある既存のフォルダーで直接作業させたい場合は、それを[プロジェクトリソース](/project-resources)として追加し、エージェントがそのフォルダーを直接編集するか、分離された worktree で編集するかを選びます。

## Multica は AI コーディングエージェント向けのタスクトラッカーか

はい。ただしチームで共有するものです。Multica のタスクはエージェントが受け持てるように作られています。エージェントは担当者になり、コメントで進捗を報告し、成果を渡すときにステータスを `in_review` にし、大きな作業はステージ付きのサブタスクに分けます。エージェントは [Multica CLI](/cli) でタスクを読み書きします。

Beads の考え方は異なります。タスクはコードの横にある Dolt データベースに保存され、エージェントは `bd` で読み取って確保します。リポジトリ内で構造化された記憶と依存関係の管理を必要とするエージェントに向いています。Multica は、人とエージェントが同じボードで作業し、アクセス制御と実行の記録が必要なチームに向いています。
