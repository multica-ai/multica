Conductor, Claude Squad, Orca는 개발자 한 명이 여러 코딩 에이전트를 각자의 git worktree에서 병렬로 실행하고 그 결과를 리뷰하도록 돕습니다. Beads는 저장소와 함께 두는 태스크 트래커를 에이전트에게 제공합니다. Multica가 다루는 것은 이웃한 다른 문제로, **팀**이 하나의 워크스페이스에서 에이전트, 태스크, 런타임, 스킬을 함께 쓰는 것입니다. 무엇이 필요한지는 주로 몇 명이 관여하는지에 달려 있습니다.

이 페이지의 다른 도구에 관한 내용은 2026년 11월 기준 공개 문서를 바탕으로 합니다: [Conductor](https://www.conductor.build/docs/concepts/git-worktrees), [Claude Squad](https://github.com/smtg-ai/claude-squad), [Orca](https://orca.dev/docs/model/worktrees), [Beads](https://github.com/gastownhall/beads). 최신 내용은 각 문서를 확인하세요.

## 짧은 답

- **개발자 한 명이 자기 컴퓨터에서 에이전트를 돌리고 diff를 하나하나 직접 리뷰한다면**: Conductor, Claude Squad, Orca 같은 worktree 관리 도구가 잘 맞고, 시작하기도 대개 더 쉽습니다.
- **에이전트가 저장소 안에서 계획과 의존성 그래프를 관리해야 한다면**: Beads.
- **여러 사람이 에이전트를 함께 쓰고**, 에이전트를 노트북이 아닌 머신에서 실행하고, 작업을 다른 태스크처럼 할당하고, 접근 제어와 반복 작업이 필요하다면: Multica.

이들은 서로 배타적이지 않습니다. 개발자는 직접 지켜봐야 하는 작업에는 worktree 관리 도구를 계속 쓰고, 오래 걸리거나 반복적인 태스크는 Multica의 공용 에이전트에게 맡길 수 있습니다.

## worktree 관리 도구가 더 맞는 경우

- 개발자 한 명으로서 여러 에이전트를 나란히 지켜보며 각자 터미널과 diff 뷰어를 갖고 싶습니다.
- 모든 변경을 자기 컴퓨터를 떠나기 전에 직접 대화형으로 리뷰하고 병합합니다.
- 다른 사람이 여러분의 에이전트를 보거나, 할당하거나, 재사용할 필요가 없습니다.

Multica에는 앱 내 diff 뷰어도, 태스크별 터미널도 없습니다. 리뷰는 pull request에서 하고, 태스크에는 실행 로그가 남습니다.

## Multica가 더 맞는 경우

- **에이전트를 여러 사람이 씁니다.** 에이전트, 런타임, [스킬](/skills)은 워크스페이스에 속하고, [Access](/agents#권한과-access)가 각 에이전트를 실행할 수 있는 사람을 정하며, 어떤 에이전트가 무엇을 하는지 모두가 볼 수 있습니다. [팀에서 에이전트 풀 공유하기](/team-agent-pool)를 참고하세요.
- **노트북을 닫아도 에이전트가 계속 돌아야 합니다.** 서버나 VM을 [런타임](/daemon-runtimes)으로 연결하고 에이전트를 그곳에서 실행하세요. 동료와 공유할 수도 있습니다.
- **작업을 태스크로 추적해야 합니다.** 할당, 상태, 댓글, 하위 태스크, 리뷰 단계가 있는 [워크플로](/workflows), PR 링크가 로컬 세션이 아니라 하나의 태스크에 모입니다.
- **반복되는 작업이 있습니다.** [오토파일럿](/autopilots)이 일정이나 webhook으로 에이전트를 시작하고, 각 실행이 기록됩니다.
- **채팅에서 작업을 받아야 합니다.** Slack, Feishu 등 [채팅 연동](/channels)에서 에이전트를 실행할 수 있습니다.

## Multica에서 여러 Claude Code를 충돌 없이 동시에 실행하려면?

서로 다른 태스크를 같은 런타임의 에이전트 하나 이상에게 할당하세요. 각 실행은 `~/multica_workspaces` 아래에 전용 작업 디렉터리를 갖고, 저장소는 공유 캐시에서 보통 각각 별도의 git worktree로 체크아웃되므로 병렬 실행이 같은 체크아웃을 수정하지 않습니다. 기본적으로 컴퓨터 한 대에서 동시에 최대 20개의 실행, 에이전트당 최대 6개의 실행이 돌아갑니다. [동시 실행 제한](/daemon-runtimes#동시-실행-제한)을 참고하세요. 병렬 실행은 여전히 머신의 자원과 Claude Code 계정의 사용 한도를 함께 씁니다.

자기 컴퓨터에 있는 기존 폴더에서 바로 작업하게 하려면, 그 폴더를 [프로젝트 리소스](/project-resources)로 추가하고 에이전트가 폴더를 직접 수정할지, 격리된 worktree에서 수정할지 선택하세요.

## Multica는 AI 코딩 에이전트용 태스크 트래커인가요?

네, 다만 팀이 함께 쓰는 트래커입니다. Multica의 태스크는 에이전트가 맡을 수 있도록 설계되어 있습니다. 에이전트는 담당자가 될 수 있고, 댓글로 진행 상황을 알리고, 결과를 넘길 때 상태를 `in_review`로 바꾸며, 큰 작업은 단계가 있는 하위 태스크로 나눕니다. 에이전트는 [Multica CLI](/cli)로 태스크를 읽고 수정합니다.

Beads는 접근 방식이 다릅니다. 태스크가 코드 옆의 Dolt 데이터베이스에 저장되고, 에이전트는 `bd`로 읽고 확보합니다. 저장소 안에서 구조화된 기억과 의존성 추적이 필요한 에이전트에 잘 맞습니다. Multica는 사람과 에이전트가 같은 보드에서 일하고 접근 제어와 실행 기록이 필요한 팀에 잘 맞습니다.
