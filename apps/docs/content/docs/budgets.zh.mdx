**预算**为一个范围和一个周期设定开支上限。开支按该范围发起的运行计算。接近上限时，预算会发出警告。在 `hold`（暂停）模式下达到上限时，该范围内新的自动运行会等待，并显示可见的原因，直到你采取行动。

## 设定预算

打开**治理**，选择 **Budgets** 标签页。创建预算时可设置：

| 字段 | 含义 |
| --- | --- |
| 范围 | 公司、楼层、小队或倡议 |
| 周期 | 周、月或季度 |
| 金额 | 每个周期的上限，单位为美元 |
| 软限制 | 预算开始警告的比例，默认 80% |
| 模式 | `warn`（仅警告）。`hold`（暂停）会在达到上限时暂停新运行。 |
| 运行类别 | 预算可以暂停哪些类别的运行。默认为例行和委派运行。 |

创建对话框默认为 `warn`。未设置模式的预算默认为 `hold`。没有经过测试的新预算最好先用 `warn`。

预算也可以通过 `budget` 提案创建。小队负责人提交时需附金额、理由和预期价值；批准后即设置预算。倡议的规划关卡批准会创建每月 100 美元的 `warn` 预算。初始公司会为全公司创建每月 500 美元的 `warn` 预算。参见[初始公司](/starter-company)。

## 运行类别

每次运行都属于一个类别，类别决定预算能否暂停它：

| 类别 | 由谁发起 | 能否被预算暂停 |
| --- | --- | --- |
| `human` | 人，通过评论、聊天或分配 | 从不。你随时可以与公司交流。 |
| `routine` | 自动化、唤醒或运营评审 | 是，前提是预算的类别包含它 |
| `delegated` | 一个小队的智能体把工作交给另一个小队，或小队负责人的调度 | 是，前提是预算的类别包含它 |

秘书的每日简报及其补跑运行不受限制。

## 暂停的工作方式

检查发生在排队任务交给守护进程时，以及自动化调度时。当预算处于 `hold` 模式，且其开支加上该范围内进行中运行所预留的成本，已达到金额加上任何延期额度时，预算会暂停该任务。预留成本是该范围内近期运行成本的第 90 百分位数。

被暂停的任务仍保留在队列中，不会失败。平台为每个任务记录一次暂停，并在预算的暂停列表中显示原因 **budget hold**（预算暂停）。被暂停的自动运行会记为已跳过，并附该原因。当预算获得延期或提高上限、你释放暂停、周期滚动，或任务被取消时，暂停即被解除。

预算计数器会随运行完成而更新，因此每次认领时检查不需要读取运行历史。数字可能滞后几秒。

## 你的操作

- **延期**：为当前周期增加一定金额。延期会被记录。
- **提高**预算。
- **释放暂停**，一次性生效。被暂停的任务重新可被认领。
- 不做任何操作：周期滚动后自动重置。

需要更多预算的小队负责人可以改为提交 `budget` 提案。每次延期、释放和暂停都会显示在[治理日志](/controls-and-log)中。

<Callout type="info">
开支记在运行创建时所在的周期内，按 UTC 计算。运行成本优先采用提供商报告的数值。若无报告，则由服务器根据令牌数量和其自身的价格表估算。
</Callout>

## 限制

- 预算在 Budgets 标签页中管理，也可通过 `GET` 和 `POST /api/budgets`、`PATCH /api/budgets/{id}`、`POST /api/budgets/{id}/extend`、`POST /api/budgets/{id}/release-holds`、`GET /api/budgets/{id}/periods`，以及 `GET /api/budget-holds` 管理。CLI 没有预算命令。
- 请求体限制为 16 KiB。
