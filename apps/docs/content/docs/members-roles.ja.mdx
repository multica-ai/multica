[ワークスペース](/workspaces)に参加した人は全員メンバーで、各メンバーは `owner`、`admin`、`member` のいずれか 1 つのロールを持ちます。ロールが制御するのはワークスペース設定とチーム管理だけです。タスクの作成やコメントの投稿といった日常のコラボレーションは、すべてのメンバーに開かれています。

## 3 つのロール

| 操作 | owner | admin | member |
|---|:---:|:---:|:---:|
| ワークスペースの閲覧と日常のコラボレーション | ✓ | ✓ | ✓ |
| ワークスペース設定の変更 | ✓ | ✓ | — |
| `admin` または `member` の招待 | ✓ | ✓ | — |
| `admin`、`member` の変更・削除 | ✓ | ✓ | — |
| `owner` の付与・剥奪・削除 | ✓ | — | — |
| ワークスペースの削除 | ✓ | — | — |

ワークスペースには常に最低 1 人の `owner` が必要です。最後の `owner` は降格も削除もできず、退出もできません。

<Callout type="info">
ロールは、誰がエージェントを実行できるかを決めません。各エージェントには独自のアクセス範囲（Access）があり、`owner` や `admin` もそれを迂回して、許可されていないエージェントを実行することはできません。詳しくは[エージェント](/agents#権限と-access)を参照してください。
</Callout>

## メンバーの招待

`owner` と `admin` は、設定 → メンバーでメールアドレスを入力し、ロールを選んで招待を送信します。招待で付与できるのは `admin` または `member` だけです。`owner` にするには、先にワークスペースへ参加してもらい、既存の `owner` が昇格させます。

![メンバー管理：招待フォームとロール付きのメンバー一覧](/images/docs/members-roster.webp)

招待された人はそのメールアドレスでログインすれば承諾でき、事前のサインアップは不要です。招待の有効期間は 7 日間で、期限切れ後は再送してください。サインアップを制限しているセルフホストのインスタンスでは、まだアカウントを持たない招待者のサインアップにも引き続きサインアップルールが適用されます。[ログインとサインアップ設定](/auth-setup#招待とサインアップ制限)を参照してください。

招待リンクはメールにのみ含まれ、プロダクトの画面にはそれを表示・コピーする場所がありません。メールの送信に失敗しても招待レコードは残るため、取り消してから送り直せます。

## ロールの変更

`admin` は `admin` と `member` の間でロールを変更でき、この 2 つのロールのメンバーを削除することもできます。`owner` が関わる変更 — 昇格、変更、削除 — を実行できるのは `owner` だけです。

ロールの変更はただちに反映されます。

## メンバーの削除

削除されたメンバーは、ただちにワークスペースへのアクセス権を失います。そのメンバーが作成したタスク、コメント、その他のコラボレーション記録はワークスペースに残ります。

<Callout type="warning">
メンバーを削除すると同時に、そのメンバーが所有するランタイムは無効化され、それに紐づくエージェントはアーカイブされ、未完了の実行はキャンセルされます。そのメンバーがエージェントのアクセス範囲（Access）で得ていた許可も消去され、再参加しても自動では復元されません。
</Callout>
