[ワークスペース](/workspaces)の `owner`、`admin`、`member` はタスクの作成とコメントの投稿ができます。設定やメンバーを管理する権限はロールによって異なります。[ゲスト](#ゲスト)は共有されたプロジェクトでのみ、タスクの閲覧とコメントの投稿ができます。

## メンバーの管理権限 [#3-つのロール]

| 操作 | owner | admin | member |
|---|:---:|:---:|:---:|
| ワークスペースの閲覧と日常のコラボレーション | ✓ | ✓ | ✓ |
| ワークスペース設定の変更 | ✓ | ✓ | — |
| `admin` または `member` の招待 | ✓ | ✓ | — |
| `admin`、`member` の変更・削除 | ✓ | ✓ | — |
| `owner` の付与・剥奪・削除 | ✓ | — | — |
| ワークスペースの削除 | ✓ | — | — |

ワークスペースには常に最低 1 人の `owner` が必要です。最後の `owner` は降格も削除もできず、退出もできません。

<Callout type="info">
ゲストはエージェントを実行できません。各エージェントには独自のアクセス範囲（Access）があり、`owner` や `admin` もそれを迂回して、許可されていないエージェントを実行することはできません。詳しくは[エージェント](/agents#権限と-access)を参照してください。
</Callout>

<Callout type="info">
ロールでプライベートプロジェクトが見られるようになることもありません。`owner` や `admin` も、メンバーリストに載っている場合にだけプライベートプロジェクトを見られます。詳しくは[プライベートプロジェクト](/projects#private-projects)を参照してください。
</Callout>

## メンバーの招待

`owner` と `admin` は**設定 → メンバー**で**メンバーを招待**をクリックし、メールアドレスを入力してロールを選び、送信します。招待で付与できるのは `admin`、`member`、または[ゲスト](#ゲスト)です。`owner` にするには、先にワークスペースへ参加してもらい、既存の `owner` が昇格させます。

![メンバー管理：招待フォームとロール付きのメンバー一覧](/images/docs/members-roster.webp)

招待された人はそのメールアドレスでログインすれば承諾でき、事前のサインアップは不要です。招待の有効期間は 7 日間で、期限切れ後は再送してください。サインアップを制限しているセルフホストのインスタンスでは、保留中かつ有効期限内の招待があれば、allowlist に追加せずにそのメールアドレスでアカウントを作成できます。[ログインとサインアップ設定](/auth-setup#招待とサインアップ制限)を参照してください。

招待リンクはメールにのみ含まれ、プロダクトの画面にはそれを表示・コピーする場所がありません。メールの送信に失敗しても招待レコードは残るため、取り消してから送り直せます。

そのまま転送できるリンクが必要な場合は、**設定 → メンバー**の**共有リンク**でロールと有効期限を選んで生成します。リンクを受け取った人は、期限が切れるか取り消されるまで、選んだロールで参加できます。

## ゲスト

ゲストには、共有されたプロジェクトだけが表示されます。それらのプロジェクトでは、タスクの閲覧、コメント、リアクション、フォローができます。タスクの作成や編集、エージェントの実行やメンション、ワークスペース設定の表示はできず、ほかのプロジェクト、エージェント、オートパイロット、ランタイムも見えません。

`owner` と `admin` は、招待ダイアログで**ゲスト**を選び、表示するプロジェクトを指定してゲストを招待します。メンバーのアクションメニューからは、メンバーをゲストにする（エージェント、オートパイロット、ランタイムへのアクセスが取り消されます）、ゲストをメンバーにする、**アクセスできるプロジェクトを管理**でゲストのプロジェクトを変更する、といった操作ができます。

## ロールの変更

メンバー一覧で対象メンバーの右側にある操作メニューを開き、**ロールを変更**を選びます。変更はただちに反映されます。

`admin` は `admin` と `member` の間でロールを変更でき、この 2 つのロールのメンバーを削除することもできます。`owner` が関わる変更（昇格、変更、削除）を実行できるのは `owner` だけです。

## メンバーの削除

削除されたメンバーは、ただちにワークスペースへのアクセス権を失います。そのメンバーが作成したタスク、コメント、その他のコラボレーション記録はワークスペースに残ります。

<Callout type="warning">
メンバーを削除すると同時に、そのメンバーが所有するランタイムは無効化され、それに紐づくエージェントはアーカイブされ、未完了の実行はキャンセルされます。そのメンバーがエージェントのアクセス範囲（Access）で得ていた許可も消去され、再参加しても自動では復元されません。
</Callout>
