Multica のエージェントを Feishu Bot に接続すると、許可された DM やグループの参加者は Labrastro アカウントなしで対話できます。エージェントが内容を確認・整理し、通常のツールで自分の名義のコメントを投稿します。会話と実行記録はワークスペースに保存されます。

各 Bot に接続できるエージェントは 1 つだけです。Feishu で複数のエージェントを使う場合は、エージェントごとに Bot を接続してください。

## Bot を接続する

エージェントの所有者、ワークスペースの owner、admin が接続を開始できます。

<Steps>
<Step>
**エージェント**を開き、Feishu に接続するエージェントを選びます。
</Step>
<Step>
**連携**を開き、**Feishu に接続**をクリックします。
</Step>
<Step>
Feishu で QR コードをスキャンし、認証を承認します。QR コードは 1 回しか使えません。期限が切れた場合は再生成してください。
</Step>
<Step>
Multica に戻ります。画面に **Feishu に接続済み**と表示されたら、次に会話を許可してください。
</Step>
</Steps>

接続済みのエージェントにはスキャン画面は再表示されません。名前や権限を変更する場合は、**Feishu で管理**をクリックします。

<Callout type="info">
現在、新規接続を利用できるのは中国本土版の Feishu だけです。既存の国際版 Lark 接続は、引き続き利用および管理できます。
</Callout>

## 会話を許可する

接続後、エージェントの**連携**ページまたは**設定 → 連携**で会話設定を開き、許可するグループと DM の ID を保存します。許可するメンバーにはエージェントの管理権限と呼び出し権限が必要です。範囲は現在のワークスペース全体で、許可された会話の全参加者が入力できます。

参加者のアカウント連携は不要です。メンバー連携は個人通知の宛先確認に引き続き利用できます。未設定の会話は拒否されます。許可の変更・取り消しで以前の外部実行の権限は失効します。通知の送信許可は別の設定です。

## Feishu から仕事を依頼する

### DM

Bot にそのままメッセージを送ります。後続のメッセージは同じ Multica のチャットセッションに保持され、エージェントの返信も現在の DM に返されます。

### グループチャット

Bot をグループへ追加し、`@Bot` に続けて依頼内容を入力します。Bot が応答するのは、明示的に @メンションされたメッセージだけです。実行時には、グループの直近の数件のメッセージもコンテキストとして渡されます。

### タスクを相談する

タスクを指定するか Bot の通知を引用し、意見を伝えてください。エージェントは必要に応じて確認し、自分の名義で適切なスレッドに要約を投稿します。各メッセージが即座にコメントになるわけではありません。

`/issue` は会話テキストであり、メンバー用の直接操作ではありません。レポートへの質問で自動化の再実行やタスク作成は行いません。「はい」「続けて」だけでは一括承認になりません。`/new` は新しい Chat、`/clear` は新しいコンテキストを開始します。単独の制御コマンドは実行を開始しません。

## エージェントが生成した画像とファイル

外部の許可済み会話では、生成した画像やファイルの送信と、タスク参照のワークスペースリンクへの書き換えは無効です。以下の添付機能はメンバー連携済みの会話だけに適用されます。配信時に会話の権限を再確認し、許可が取り消された待機中の添付ファイルは送信しません。

添付ファイルの送信が有効な場合、エージェントの返信本文と対応形式の画像は、同じ Feishu メッセージ内に表示されます。画像はアップロード完了後に元のメッセージへ反映され、ファイルは同じ会話へ別のメッセージで送信されます。本文のない画像のみの返信は、画像メッセージで送信できます。画像の上限は 10 MB です。非対応形式、上限超過、または Feishu が明示的に拒否した画像は、30 MB を上限にファイルとして送信されます。オブジェクトストレージとアプリのリソースアップロード権限が必要です。送信に失敗した場合や到着を確認できない場合も、添付ファイルは Multica の返信に残ります。再送を依頼する前に、会話を確認してください。

## 接続を管理する

**設定 → メッセージング → Lark**を開くと、ワークスペースに接続済みの Bot を確認できます。ワークスペースの owner と admin はここから接続を解除できます。エージェントの所有者は、そのエージェントの**連携**ページから自分の Bot を管理できます。

接続を解除すると、Bot は新しいメッセージを受信しなくなります。既存の会話と監査記録は削除されません。

## セルフホスト設定

Multica Cloud では追加設定は不要です。セルフホスト環境では、Bot の認証情報を暗号化するキーを先に設定してください。

```dotenv
MULTICA_LARK_SECRET_KEY=<base64-encoded 32-byte key>
```

次のコマンドで生成できます。

```bash
openssl rand -base64 32
```

API サービスを再起動した後、エージェントの**連携**ページから Bot を接続します。このキーは継続して保管してください。変更または紛失すると既存の認証情報を復号できなくなり、Bot の再接続が必要になります。

`MULTICA_LARK_HTTP_BASE_URL` と `MULTICA_LARK_CALLBACK_BASE_URL` は、プロキシやテストなどの特殊な環境でのみ使用します。通常は設定する必要はありません。

## よくある問題

- **接続ボタンが表示されない**: 現在のアカウントがエージェントの所有者、ワークスペースの owner、admin のいずれかであることを確認します。セルフホストの場合は暗号化キーも確認してください。
- **QR コードの期限が切れた**: ダイアログを閉じて、接続をもう一度開始します。
- **会話が許可されない**: チャット ID、保存済みの許可、許可者のメンバー資格と呼び出し権限を確認してください。
- **Bot が実行しない**: エージェントがアーカイブされていないことと、使用する[ランタイム](/daemon-runtimes)がオンラインであることを確認します。
- **Bot がまったく応答しない**: アプリは長時間接続でイベントを送信する必要があります。Multica に webhook の受信 URL はありません。Feishu/Lark の開発者コンソールで **イベントとコールバック → イベント設定** を開き、購読方法がリクエスト URL ではなく長時間接続になっていること、`im.message.receive_v1` が購読されていること、その設定を含むバージョンが公開済み（テナントで審査が必要な場合は承認済み）であることを確認します。リクエスト URL に設定されたアプリも接続自体は成功し「接続済み」と表示されますが、メッセージは 1 件も届きません。
