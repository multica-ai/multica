---
title: 让智能体开始工作
description: 触发智能体的四种方式，以及触发之后去哪里查看进展。
---

在 Multica 中，智能体不会自己开始工作。每一次执行都由一个明确的动作触发。共有四种方式：

| 方式 | 适用场景 | 操作 |
| --- | --- | --- |
| **分配 issue** | 这项工作由智能体全程负责 | [分配 issue 给智能体](/assigning-issues)，issue 处于 `todo` 或更靠后的状态时立即开始 |
| **在评论中 @智能体** | 请智能体处理一条具体请求，不改变 issue 的负责人 | [在评论中 @它](/mentioning-agents)，也可以直接回复智能体的评论继续对话 |
| **直接对话** | 一个问题或一次尝试，不需要建 issue | [和智能体开始对话](/chat)，每条消息触发一轮执行 |
| **自动化** | 重复性工作，希望按时间或外部事件自动进行 | [创建自动化](/autopilots)，由时间表、webhook 或手动触发 |

四种方式共用以下规则：

- 你只能触发自己**有权限运行**的智能体，由智能体的 Access 设置决定，与你的工作区角色无关。
- 在 issue 中触发前，输入框下方会显示**触发预览**，明确列出这条内容会唤醒谁；不想触发任何智能体时，用 `/note` 留言。
- 处于 `backlog` 的 issue 不会触发执行；把它移到 `todo` 后，已分配的智能体才会开始。

## 查看进展

每次触发都会创建一次[执行任务](/tasks)。进展会实时写回触发它的地方——issue 的时间线或对话窗口；在执行日志里可以查看完整过程、停止执行或重试。

执行迟迟未开始时，多数是运行时不在线，按[故障排查](/troubleshooting)中"任务不开始"一节检查。
