Le client iOS de Multica n'est pas encore disponible sur l'App Store. Vous pouvez compiler une version Release à partir du dépôt de code source public sur un Mac et l'installer sur votre propre iPhone. Il n'existe pas encore de client Android.

L'application installée se connecte par défaut à Multica Cloud ; connectez-vous avec votre compte existant. Les espaces de travail, les tâches, les commentaires et l'historique des exécutions sont tous stockés sur le serveur : rien n'a besoin d'être synchronisé depuis le web ou Desktop.

## Prérequis

Il vous faut :

- un Mac sur lequel Xcode est installé ;
- un identifiant Apple connecté dans **Xcode → Settings → Accounts** ;
- un iPhone connecté en USB ;
- le mode développeur activé sur l'iPhone dans **Réglages → Confidentialité et sécurité** ;
- Node.js, pnpm et Git.

Si Xcode ou l'environnement de développement sur appareil n'est pas encore configuré, suivez d'abord la [configuration de l'environnement pour appareil iOS](https://docs.expo.dev/get-started/set-up-your-environment/) d'Expo.

## Installer sur votre iPhone

<Steps>
<Step>
Clonez le dépôt et installez les dépendances :

```bash
git clone https://github.com/multica-ai/multica.git
cd multica
pnpm install
```
</Step>
<Step>
Exécutez depuis la racine du dépôt :

```bash
pnpm ios:mobile:device:prod:release
```

Cette commande compile une version Release sans dépendance à Metro et l'installe sur l'iPhone connecté. La première compilation télécharge les dépendances iOS et compile React Native ; les suivantes réutilisent le cache de Xcode.
</Step>
<Step>
Ouvrez l'application sur l'iPhone. Si iOS en bloque l'ouverture, faites confiance au certificat de développeur dans **Réglages → Général → VPN et gestion de l'appareil**.
</Step>
</Steps>

## Limite de 7 jours de la signature gratuite

Les applications signées avec un identifiant Apple gratuit ne fonctionnent que 7 jours. À l'expiration, reconnectez l'iPhone à votre Mac et relancez la même commande de compilation pour signer l'application à nouveau.

Les builds signées avec un compte Apple Developer Program restent valides plus longtemps et peuvent aussi servir pour TestFlight et la distribution habituelle. Quel que soit le type de signature, réinstaller ou signer à nouveau l'application ne fait jamais perdre les données stockées côté serveur.

## Échecs de signature

Si Xcode signale `No matching provisioning profiles found`, il est possible que l'identifiant de bundle par défaut n'appartienne pas à votre identifiant Apple. Passez à un nom de domaine inversé que vous contrôlez, puis recompilez :

```bash
export EXPO_BUNDLE_IDENTIFIER_PROD=com.yourname.multica
pnpm ios:mobile:device:prod:release
```

La valeur doit seulement être disponible dans votre équipe Apple Developer ; elle n'a aucun effet sur votre compte ni sur vos espaces de travail Multica.

## Mettre à jour

La build iOS installée par vos soins ne se met pas à jour automatiquement. Récupérez le code le plus récent, mettez à jour les dépendances et recompilez :

```bash
git pull --ff-only
pnpm install
pnpm ios:mobile:device:prod:release
```

## Se connecter à une instance auto-hébergée

Les builds Release intègrent l'adresse de l'API dans l'application. `apps/mobile/.env.production` est commité avec les valeurs publiques par défaut de multica.ai : un clone neuf compile donc directement la version de production.

Pour vous connecter à une instance auto-hébergée :

<Steps>
<Step>
Copiez `apps/mobile/.env.production.example` vers `apps/mobile/.env.production.local`, puis renseignez les adresses dans la copie :

```dotenv
EXPO_PUBLIC_API_URL=https://api.example.com
EXPO_PUBLIC_WEB_URL=https://app.example.com
```

Le fichier `.local` remplace les valeurs commitées clé par clé et est ignoré par git : vos adresses personnelles n'arrivent jamais dans le dépôt. `EXPO_PUBLIC_API_URL` est obligatoire. `EXPO_PUBLIC_WEB_URL` alimente des entrées comme « Copy link » et « Open on web ». Définissez les deux : une clé omise reprend la valeur par défaut de multica.ai, et ces entrées ouvriraient alors multica.ai au lieu de votre instance.
</Step>
<Step>
Relancez la commande de compilation `pnpm ios:mobile:device:prod:release`. L'iPhone doit pouvoir joindre l'adresse de l'API ; si vous utilisez une adresse du réseau local, n'écrivez pas `localhost`, qui désigne sur l'iPhone le téléphone lui-même.
</Step>
</Steps>

<Callout type="warning">
Modifier directement `.env.production` change la configuration de production de la copie de travail actuelle. Gardez vos valeurs personnelles dans `.env.production.local`, ignoré par git.
</Callout>

Pour le développement mobile, l'utilisation du Simulateur ou la connexion à l'environnement de staging, consultez [`apps/mobile/README.md`](https://github.com/multica-ai/multica/blob/main/apps/mobile/README.md) dans le dépôt.
