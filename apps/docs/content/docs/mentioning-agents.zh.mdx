在评论中 @智能体，适合让它查看一条新信息、回答问题或协助当前负责人。评论会成为这次执行的起点，任务的负责人和状态都不会改变。

## 分配与 @提及的选择

| | 分配给智能体 | 在评论中 @智能体 |
|---|---|---|
| 适合 | 让智能体负责整条任务 | 请智能体处理当前评论 |
| 改变负责人 | 是 | 否 |
| 改变状态 | 否 | 否 |
| 一次选择 | 一个智能体或小队 | 可以 @多个智能体或小队 |
| 本轮焦点 | 整条任务 | 触发它的评论，以及同批合并的评论 |

需要明确负责人时使用[分配](/assigning-issues)；只需要临时加入讨论时使用 @提及。

## 触发预览

在评论编辑器中选择智能体或小队后，输入框下方会显示触发预览：

- 哪些智能体会在发送后开始工作；
- 目标来自直接 @提及、任务负责人还是小队 leader；
- 目标是否不可用，或你是否缺少调用权限。

取消选中某个智能体只跳过这一次触发，不需要删除评论中的名字，也不会修改智能体的 Access。

<MentionDemo />

评论发布后，在线的运行时通常立即领取；运行时离线时，运行留在队列中等待。

## 回复的自动路由

普通评论（不含任何 @）按讨论上下文路由：

1. 回复智能体的评论时，交给该智能体。
2. 在已有智能体参与的讨论中回复时，沿用这条讨论的智能体。
3. 都不满足的最外层评论，交给当前的智能体负责人；负责人是小队时，由 leader 处理。直接回复成员的普通评论不会走负责人兜底；需要智能体或小队加入时，请明确 @提及。

评论明确 @了其他对象（包括成员）时，不再使用负责人兜底。

回复始终交给目标智能体，即使它的运行时离线或正在忙碌，也不会超时后自动唤醒任务负责人。需要其他智能体参与时，请明确 @提及。

## 给正在运行的智能体插话

智能体做到一半、方向不对时，不必停下来重来。在评论框里写下修正并发送，这条消息会插进它当前的运行：它在当前步骤结束后读到，按新方向继续完成原任务。

<SteerDemo />

收件人正在运行时，评论框下方的标签会说明这条消息怎么送达，点开可以改：

| 选项 | 效果 |
|---|---|
| 插话到当前运行 | 在当前步骤结束后读到，并继续完成原任务。 |
| 本轮结束后开始 | 不打断当前运行，结束后作为新一轮处理。 |
| 停止并重新开始 | 立即停止当前运行，按这条消息从头开始。 |
| 本次不会开始 | 只发布评论，不触发这个智能体。 |

发送后，评论下方会先显示"等待 ... 读取"，读到后变为"... 已读取"；执行日志的步骤列表里也会标出它是在哪一步读到的。送达失败时，可以重试，或者改为作为新一轮发送。

- 插话只支持文字。带附件的消息会在本轮结束后处理。
- 插话需要智能体使用的 AI 编程工具支持；不支持时，选项里不会出现"插话到当前运行"。
- 默认选项在设置的**回复正在运行的智能体时**中调整，每条消息发送前仍可单独修改。
- 聊天里排队消息的**引导**不一样：它会先停掉当前回复，见[聊天](/chat#回复还没结束时继续发消息)。

## 连续评论的合并

同一个智能体在同一条任务上已有排队中的运行，此时新评论会合并进这次运行，开始时一并处理；它已经在执行时，按你在评论框中选择的方式处理，见上一节。可以连续补充信息，不必等智能体回复。

一条评论 @多个不同智能体时，每个智能体各得一次运行；多个提及指向同一个智能体时，只保留一次。

## 不触发智能体的留言

有两种方式：

- 以 `/note` 开头：评论作为成员之间的备注，不触发任何智能体。
- 使用 `@all`：通知全部工作区成员，同时关闭这条评论对负责人的自动触发。

触发预览中仍有智能体时，发送前取消选中即可。

<Callout type="info">
`@all` 不包含智能体。智能体没有收件箱；让它工作需要明确 @它、回复相关讨论，或把任务分配给它。
</Callout>

## Access 限制

@提及不能绕过智能体的 Access。无权调用、目标已归档或没有可用运行时时，触发预览会说明它不会启动；评论本身仍可正常发布。三档语义见[智能体](/agents#权限与-access)。

## 智能体之间的互相提及

智能体可以在自己的回复中 @其他智能体。A @ B、B 又 @ A 时，系统会合并同一时刻的重复执行，但不会判断这段协作该不该结束。什么时候停，要写进智能体指令。
