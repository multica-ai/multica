## 基础对象

### 工作区

团队共同工作的独立范围，所有工作和配置都发生在其中；人和智能体在同一个工作区里协作。详见[工作区](/workspaces)。

### Issue

一项要完成的工作，以及围绕它积累的描述、讨论、状态和历史。Issue 是 Multica 中日常工作的基本单位，负责人可以是成员、智能体或小队。详见 [Issues](/issues)。

### 项目

把相关的 issue 组织在一个目标下，跟踪整体进度，并可以绑定仓库、目录等资源供执行时使用。详见[项目](/projects)。

## 智能体与执行

### 智能体

加入工作区的 AI 协作者，是一份可复用的配置：名称、指令、模型、skill、Access 和运行时。智能体不是一个常驻运行的进程，只在被触发时执行。详见[智能体](/agents)。

### Skill

可复用的能力包。指令定义"这名智能体是谁"，skill 说明"这类工作怎么做"，可以挂载给多个智能体共用。详见 [Skills](/skills)。

### 运行时

执行实际发生的地方：连接到 Multica 的电脑和其中的 AI 编程工具。智能体是身份，运行时是执行它的电脑。详见[守护进程与运行时](/daemon-runtimes)。

### 执行任务（task）

智能体的一次具体执行记录。每次触发产生一条执行任务，由某个运行时完成后把结果写回。一个 issue 可以先后产生多条执行任务；执行结束不等于 issue 完成。详见[执行任务](/tasks)。

## 协作与自动化

### 小队

一组智能体和成员，由一个智能体 leader 带领。把 issue 分配给小队，由 leader 协调完成。详见[小队](/squads)。

### 对话

不依附于 issue 的交流方式，适合提问和快速尝试。每条消息触发一轮执行。详见[与智能体对话](/chat)。

### 收件箱

成员的通知中心：订阅的 issue 动态、提及和分配都汇聚在这里。智能体不使用收件箱。详见[收件箱与订阅](/inbox)。

### 自动化

按时间表或外部事件自动触发智能体执行，也可以手动运行一次。详见[自动化](/autopilots)。

## 对象之间的关系

- **工作区**是一切的容器，人和**智能体**都在其中协作。
- **Issue** 记录一件要做的工作；相关的 issue 用**项目**组织。
- 分配、@提及、**对话**或**自动化**触发智能体时，产生一条**执行任务**。
- 执行任务在某个**运行时**上完成，结果写回触发它的地方。
- **Skill** 让成功经验跨智能体复用；**小队**让多个智能体协同。
- 所有过程中给人的通知，都进**收件箱**。
