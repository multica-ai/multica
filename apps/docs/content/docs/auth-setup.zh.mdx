Multica 默认使用邮箱验证码登录，也可以增加 Google OAuth。已经存在的用户始终可以再次登录；注册限制只决定是否允许创建新账号。

## 邮箱验证码

用户输入邮箱后，Multica 会发送一个 6 位验证码。验证码 10 分钟内有效，验证成功后浏览器获得登录 cookie。

邮件可以通过 Resend 或 SMTP 发送。两者同时配置时，`SMTP_HOST` 优先。

### 使用 Resend

1. 在 [Resend](https://resend.com/) 验证发信域名并创建 API key。
2. 设置：

 ```dotenv
 RESEND_API_KEY=re_xxxxxxxxxxxxxxxx
 RESEND_FROM_EMAIL=noreply@example.com
 ```

3. 重启 API 服务。

`RESEND_FROM_EMAIL` 必须属于已经在 Resend 验证的域名。

### 使用 SMTP

最少需要设置主机和发件地址：

```dotenv
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USERNAME=multica
SMTP_PASSWORD=<password>
SMTP_FROM_EMAIL=noreply@example.com
```

常见连接方式：

| 场景 | 配置 |
|---|---|
| 内网匿名 relay | `SMTP_PORT=25`，用户名和密码留空 |
| STARTTLS | `SMTP_PORT=587`，默认会在服务器支持时升级 TLS |
| 隐式 TLS | `SMTP_PORT=465`，或显式设置 `SMTP_TLS=implicit` |

如果没有设置 `SMTP_FROM_EMAIL`，会回退到 `RESEND_FROM_EMAIL`。私有 CA 或自签证书需要把 CA 加入容器信任库；`SMTP_TLS_INSECURE=true` 会跳过证书校验，只应在可信内网中临时使用。

有些严格的 relay 还要求合法的 EHLO 名称：

```dotenv
SMTP_EHLO_NAME=mail.example.com
```

### 无邮件服务时的行为

服务器仍可启动，但验证码和邀请链接只会写入日志，不会发送邮件。这适合本地开发，不适合生产环境。

启动日志会说明当前使用的是 `Resend API`、`SMTP relay` 还是 `DEV mode`。

## 本地固定验证码

本地自动化测试可以设置固定验证码：

```dotenv
APP_ENV=development
MULTICA_DEV_VERIFICATION_CODE=888888
```

验证码必须是 6 位数字。`APP_ENV=production` 时固定验证码会被忽略。

<Callout type="warning">
不要在公网实例中启用固定验证码。生产环境的组合是 `APP_ENV=production` 加空的 `MULTICA_DEV_VERIFICATION_CODE`。
</Callout>

## Google 登录

1. 在 [Google Cloud Console](https://console.cloud.google.com/) 创建 OAuth 2.0 client。
2. 把 Multica 前端的回调地址加入 **Authorized redirect URIs**：

 ```text
 https://multica.example.com/auth/callback
 ```

3. 设置：

 ```dotenv
 GOOGLE_CLIENT_ID=xxxxx.apps.googleusercontent.com
 GOOGLE_CLIENT_SECRET=GOCSPX-xxxxxxxxxxxxxxx
 GOOGLE_REDIRECT_URI=https://multica.example.com/auth/callback
 ```

4. 重启 API 服务。

Google Console 与 `GOOGLE_REDIRECT_URI` 中的地址必须完全一致，包括协议、端口和结尾斜杠。配置生效后，登录页会出现 Google 登录按钮；前端镜像不需要重新构建。

## 企业目录（LDAP）登录

自托管的 Multica 可以直接使用企业内网 OpenLDAP 或 Active Directory 的账号密码登录。它是与邮箱验证码、Google 登录并列的第三条登录入口：成功后走的是同一套会话流程，下游（工作区、邀请、token、CLI）完全不知道用户从哪个入口进来。

1. 把 `LDAP_*` 指向目录服务。两个边界要记住：服务账号只需要 `LDAP_BASE_DN` 上的读/搜索权限，`LDAP_USER_FILTER` 里有且只有一个 `%s`。

 ```dotenv
 LDAP_ENABLED=true
 LDAP_URL=ldaps://openldap.corp.example.com:636
 LDAP_BASE_DN=ou=people,dc=corp,dc=example,dc=com
 LDAP_BIND_DN=cn=lookup,dc=corp,dc=example,dc=com
 LDAP_BIND_PASSWORD=lookup-only-password
 LDAP_USER_FILTER=(uid=%s)
 ```

2. 按目录类型调整过滤条件和属性：OpenLDAP 用 `uid`，AD 用 `sAMAccountName`。

 ```dotenv
 # OpenLDAP
 LDAP_USER_FILTER=(uid=%s)

 # Active Directory
 LDAP_USER_FILTER=(sAMAccountName=%s)
 ```

3. 重启 API 服务。

和 `GOOGLE_CLIENT_ID` 一样，前端在运行时通过 `/api/config` 得知是否启用了目录登录，登录页会直接出现对应的 Tab，前端镜像不需要重新构建。

### 行为

- 登录名是目录自己的标识（`uid` / `sAMAccountName`），不是邮箱。请求体里没有邮箱字段，调用方无法靠填写某个邮箱来认领别人的账号。
- Multica 以 `users.email` 匹配账号。从 `LDAP_EMAIL_ATTR` 取到的值会先转成小写再匹配：已有账号沿用原有身份，首次目录登录会创建账号。`LDAP_NAME_ATTR` 只在全新账号上预填显示名，也不会覆盖已有账号的邮箱。
- 密码错误与用户名不存在返回完全相同的 `401` 和相同文案，因此这个接口不能被用来枚举目录账号。一个登录名匹配到多条条目时同样按 `401` 处理，服务端日志会提示你到目录里消除重复，而不是随机挑一条。
- 目录登录不调用注册范围检查。`ALLOW_SIGNUP`、`ALLOWED_EMAILS`、`ALLOWED_EMAIL_DOMAINS` 在这里都不生效：Bind 成功本身就是准入判断，所以即使关闭了注册，已有账号依然能登录。
- 不做 LDAP 组到 Multica 角色的映射。新账号没有任何工作区成员身份，和普通人一样需要被邀请。
- 用户密码和服务账号密码都不会写入日志，目录返回的错误文本也会被归纳后再记录。登录名替换进 `LDAP_USER_FILTER` 前会做 RFC 4515 转义，其中的特殊字符只会按字面匹配，不会扩大查询范围。
- 该接口与发送验证码、Google 登录共用同一档限流（`RATE_LIMIT_AUTH`，默认每个 IP 每分钟 5 次），而不是更宽松的 verify-code 额度。

### 失败情况

用户看到的和服务端日志里记录的，是刻意分开的：

| 状态 | 含义 |
|---|---|
| `400` | 未填写用户名或密码 |
| `401` | 目录拒绝了这组凭证，或没有匹配到唯一条目 |
| `403` | Multica 账号处于临时禁用状态 |
| `502` | 无法连接目录服务，或配置不完整 |
| `503` | `LDAP_ENABLED` 不是 `true`，该集成未开启 |

如果密码确定没错却拿到 `502`，就该去看日志：服务账号 Bind 失败、`LDAP_USER_FILTER` 无法解析、条目的 `LDAP_EMAIL_ATTR` 为空，这三种都是部署侧的问题，不是登录者的问题。

目录登录不新增数据库迁移，也不新增表：账号匹配复用现有的 `users.email` 唯一键。

`LDAP_TLS_INSECURE=true` 会跳过证书校验，使目录流量（包括服务账号密码）存在被截获的风险，因此只应作为可信内网中的临时联调手段：

<Callout type="warning">
请改为把目录服务的 CA 加入容器信任库。`LDAP_TLS_INSECURE=true` 只接受 `ldaps://`（或 `ldapi://`）地址：明文 `ldap://` 根本没有证书可校验，密码也会明文传输，服务端会直接拒绝这种组合，而不是带着半保护状态启动。
</Callout>

全部变量与默认值见[环境变量](/environment-variables#企业目录ldap)。

## 注册范围控制

三个变量共同决定新账号能否创建：

| 变量 | 作用 |
|---|---|
| `ALLOWED_EMAILS` | 允许的完整邮箱，多个值用逗号分隔 |
| `ALLOWED_EMAIL_DOMAINS` | 允许的邮箱域名，多个值用逗号分隔 |
| `ALLOW_SIGNUP` | 未配置任何白名单时，是否允许注册；默认 `true` |

判断顺序如下：

1. 邮箱命中 `ALLOWED_EMAILS`，允许；
2. 或域名命中 `ALLOWED_EMAIL_DOMAINS`，允许；
3. 未命中时，如果 `ALLOW_SIGNUP=false`，拒绝；
4. `ALLOW_SIGNUP=true` 但设置了任意白名单且未命中，仍然拒绝；
5. 没有设置白名单且 `ALLOW_SIGNUP=true`，允许。

常见配置：

```dotenv
# 只允许公司域名
ALLOW_SIGNUP=false
ALLOWED_EMAIL_DOMAINS=company.com

# 再放行一位外部协作者
ALLOWED_EMAILS=partner@example.net
```

<Callout type="info">
两个白名单在 `ALLOW_SIGNUP=false` 时也可以作为明确的例外名单。
</Callout>

## 邀请与注册限制

邀请不会自动绕过注册限制：

- 对方已经有 Multica 账号时，可以登录并接受邀请；
- 对方还没有账号时，邮箱必须符合上面的注册规则。

在关闭开放注册的实例中邀请新成员时，先把对方邮箱加入 `ALLOWED_EMAILS`。账号创建并接受邀请后，可以再从名单中移除。

## 登录有效期

浏览器登录默认保持 30 天。可以用 `AUTH_TOKEN_TTL` 调整，支持 Go duration 或正整数秒数：

```dotenv
AUTH_TOKEN_TTL=720h
```

修改后需要重启 API 服务。这个值只影响之后签发的登录 cookie 和 JWT，不会延长已经签发的令牌。
