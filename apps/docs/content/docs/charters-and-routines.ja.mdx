憲章を持つスクワッドには、継続的な役割があります。憲章にはミッション、果たすべき成果、してはいけないこと、あなたに判断を仰ぐタイミングが書かれています。ルーティンは、それらの成果を生み出すスケジュール実行です。憲章のないスクワッドは、誰かが作業を割り当てたときにしか動きません。

## 憲章

スクワッドのパネルを開き、**Charter**（憲章）タブを選びます。メンバーは憲章を読めます。オーナー、管理者、スクワッドの作成者は編集できます。

| フィールド | 目的 |
| --- | --- |
| Mission（ミッション） | スクワッドが存在する理由。2,000文字まで |
| Responsibilities（責任範囲） | スクワッドが担当する領域。それぞれに短い説明を付けます |
| Outputs（成果） | スクワッドが生み出すもの。種類と周期を含みます（例：毎週の市場レポート） |
| Boundaries（境界） | スクワッドがしてはいけないこと（例：資金の支出、組織の変更） |
| Escalation（エスカレーション） | あなたに判断を仰ぐべき場合 |
| Intake（受付） | 他のスクワッドがこのスクワッドに依頼できること |
| Response hours（応答時間） | スクワッドが依頼に応答するまでの時間。1〜720、既定値は48 |

保存のたびに憲章のリビジョンが1つ進みます。フォームを開いた後に誰かがより新しいリビジョンを保存していた場合、保存は競合として拒否されるので、上書きする前にもう一方の変更を確認できます。

スクワッドのリーダーには、これらの項目から生成された、システムが管理する **Your charter**（あなたの憲章）のブロックが渡されます。その後に共通ルールが続きます。作業を始める前に会社のナレッジを検索すること。お金、社外への影響、組織の変更に関わることはプロポーザルとして提出すること。やることがない場合は理由を添えて `no action` を記録し、中身のない作業で埋めないこと。注意の上限を守ること。

<Callout type="info">
この用途については、憲章がスクワッドの説明に代わります。説明は一行のラベルとして残り、指示はリーダーのルーティングルールのままです。
</Callout>

## ルーティン

ルーティンは、スケジュール、目的、期待される成果を持つ、スクワッドに紐づいた通常の [オートパイロット](/autopilots) です。スケジューラーを追加するわけではありません。スケジュール、実行履歴、**Run now**（今すぐ実行）はオートパイロットのものです。

スクワッドのパネルの **Routines**（ルーティン）一覧から追加します。

- **既存のオートパイロットを紐づける**、または周期から**新規作成**します。周期は `daily`（毎日）、`weekdays`（平日）、`weekly`（毎週）、`biweekly`（隔週）、`monthly`（毎月）、または cron 式から選べます。
- 目的は200文字以内で書きます（例：「毎週の競合調査」）。
- 期待される成果を選びます：なし、Issue、プロポーザル、ナレッジドキュメント、レポートのいずれか。

一覧からルーティンを今すぐ実行、一時停止、削除できます。削除はルーティンの紐づけを解除するだけです。同時にそのオートパイロットを一時停止することもできます。

一覧には各ルーティンの状態と、直近および次回の実行時刻が表示されます。状態は次のとおりです。

| 状態 | 意味 |
| --- | --- |
| `on_time` | 直近の実行が完了し、期待された成果を出した、または理由付きで `no action` を記録した |
| `no_output` | 直近の実行は完了したが、成果がなく、`no action` も記録されていない |
| `late` | 次回の実行が、猶予期間（既定では24時間）を超えて遅れている |
| `failed` | 直近の実行が失敗した |
| `paused` | オートパイロットが一時停止されている |
| `held` | 会社の制御（[一時停止](/controls-and-log)や[予算](/budgets)の上限など）により実行が保留されている |
| `never_ran` | 作成済みで、最初の予定時刻がまだ来ていない |

これらの状態は、プラットフォームが実行履歴とスクワッドが作成した記録から導き出します。スクワッド自身が報告するものではありません。

## 運営レビュー

憲章を初めて保存すると、プラットフォームはスクワッドのために **Operating review**（運営レビュー）という毎週のルーティンを作成します。その指示では、スクワッドに次のことを求めます。

1. 先週の成果を憲章と照らし合わせ、遅れたもの、欠けたものを一覧にする。
2. 担当分野について、過去の決定や古くなったドキュメントを会社のナレッジで検索する。
3. 誰も頼んでいないが、やる価値のあることを多くても一つ挙げ、根拠を添える。
4. 注意の上限の範囲内でプロポーザルとして提出するか、理由付きの `no action` を記録する。
5. 古くなったナレッジドキュメントの更新案を作成する。下書きのみ。

運営レビューも普通のルーティンと同様に扱われ、その遵守状況も計測されます。ルーティンの一覧から一時停止できます。

## 制限

- 憲章とルーティンはアプリで管理します。`multica` CLI には憲章やルーティンのコマンドはありません。APIは `GET` と `PUT /api/squads/{id}/charter`、`GET` と `POST /api/squads/{id}/routines`、`DELETE /api/squads/{id}/routines/{routine_id}` です。
- 会社の一時停止や静穏時間によって保留されたルーティンは、`failed` ではなく `held` と表示されます。[コントロールとログ](/controls-and-log)を参照してください。
