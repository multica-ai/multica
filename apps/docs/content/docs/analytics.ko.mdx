사이드바의 **분석** 페이지는 워크스페이스 전체의 에이전트 사용량을 모아 보여 줍니다. 비용, 토큰, 실행 시간, 실행 횟수, 실패한 실행이 여기에 있습니다. 워크스페이스 멤버라면 누구나 열 수 있습니다. 런타임별 사용량은 런타임 상세 페이지에, 태스크 하나에 든 비용은 그 태스크의 **실행 기록** 대화상자에 있으며, 둘 다 아래에서 설명합니다.

## 페이지 구성

페이지는 **사용량**과 **오류** 두 탭으로 나뉘고, 오른쪽 위의 필터 두 개를 함께 씁니다.

- **기간**: `1d`, `7d`, `30d`(기본값), `90d`, `180d`. `1d`는 내 시간대의 자정부터 시작하는 오늘이며, 최근 24시간이 아닙니다.
- **프로젝트**: 기본값은 **모든 프로젝트**입니다. 프로젝트를 고르면 그 프로젝트에 속한 태스크의 실행만 집계하고, 채팅처럼 어느 태스크에도 속하지 않는 실행은 빠집니다.

날짜는 내 시간대 기준으로 나뉩니다. **설정 → 환경설정 → 시간대**에서 고른 값을 쓰고, 설정하지 않았으면 브라우저 시간대를 씁니다. 헤더에 현재 시간대와 데이터 업데이트 시각이 표시됩니다. 서버는 5분마다 수치를 집계하고 열려 있는 페이지도 같은 간격으로 새로고침하므로, 방금 끝난 실행은 몇 분 뒤에 나타날 수 있습니다. 바로 확인하려면 새로고침 버튼을 누르세요.

오류 탭으로 바꾸면 주소에 `?tab=errors`가 붙습니다. 이 링크를 동료에게 보내면 바로 오류 탭이 열립니다.

## 사용량 탭

맨 위의 네 가지 수치:

| 카드 | 내용 |
| --- | --- |
| **비용** | 달러 기준 추정치. 계산 방식은 [비용 계산 방식](#비용-계산-방식) 참고 |
| **토큰** | 입력, 출력, 캐시 읽기, 캐시 쓰기 토큰의 합계. 아래 줄에 입력과 출력을 따로 표시 |
| **실행 시간** | 끝난 실행들의 실행 시간 합계. 각 실행이 시작된 때부터 끝난 때까지 |
| **실행** | 기간 안에 끝난 실행 수와 그중 실패한 수 |

실행 시간과 실행 수에는 실제로 실행을 시작한 실행(완료, 실패, 도중 취소)만 들어갑니다. 대기 중에 취소된 실행은 빠집니다.

추이 카드는 토큰, 비용, 시간, 실행 네 가지 지표를 같은 시간 축에서 바꿔 가며 보여 주고, **일별**과 **주별** 단위를 고를 수 있습니다. `30d`와 `90d`는 둘 다 고를 수 있고, `1d`와 `7d`는 일별만, `180d`는 주별만 됩니다. 주는 월요일부터 시작하며, 아직 끝나지 않은 이번 주는 옅은 색으로 그려지고 마우스를 올리면 7일 중 며칠이 지났는지 표시됩니다.

**리더보드**는 에이전트별 토큰, 비용, 시간, 실행을 보여 주며 이 중 어느 항목으로든 정렬할 수 있습니다. 상위 10개를 보여 주고 나머지는 **전체 보기**로 펼칩니다. 여러 에이전트를 묶은 행이 나올 수 있습니다.

- **삭제된 에이전트**: 삭제된 에이전트들의 사용량을 한 행으로 합친 것입니다. 그래야 각 행의 합이 맨 위 합계와 맞습니다.
- **기타 에이전트**: 내가 볼 수 없는 에이전트들을 한 행으로 합친 것입니다. 워크스페이스 소유자와 관리자는 멤버가 만든 모든 에이전트를 볼 수 있습니다. 일반 멤버는 다른 사람의 비공개 에이전트를 볼 수 없으며, 그 사용량은 이름 없이 이 행에만 들어갑니다.

어떤 에이전트의 실행 중 일부가 토큰을 보고하지 않았으면 토큰과 비용 앞에 `≥`가 붙고, 이름 아래에 사용량을 보고하지 않은 실행 수가 표시됩니다.

아래 데모에서는 운영팀에 에이전트가 세 개 있습니다. 먼저 비용 추이를 보고, 누가 가장 많이 쓰는지 확인한 뒤, 오류 탭에서 실패 원인을 찾아봅니다.

## 오류 탭

맨 위에 **실패한 실행**, **실패율**, **영향받은 에이전트**가 있습니다. 실패율은 기간 안에 끝난 모든 실행을 기준으로 계산하며, 카드 아래에 분자와 분모가 적혀 있습니다.

그 아래에는 다음 카드가 이어집니다.

- **일별 오류**(또는 주별 오류): 막대의 색이 실패 분류를 나타냅니다.
- **실패 구성**: 기간 안의 모든 실패를 분류별로 나눈 것입니다. **오류 코드 표시**를 누르면 원래의 실패 원인 코드로 바뀌어, 로그를 검색하거나 태스크에 붙여 넣을 때 쓸 수 있습니다.
- **실패가 많은 에이전트**: 기본은 실패 수 순이며, 9번째부터는 펼쳐야 보입니다. **실패율**로 정렬하면 실행이 10회 미만인 에이전트는 뒤로 갑니다. 횟수가 적으면 비율이 큰 의미가 없기 때문입니다. 에이전트 이름을 클릭하면 상세 페이지가 열리고, 최근 실행과 실패마다의 원인을 볼 수 있습니다.

실패 원인 코드는 일곱 가지로 분류됩니다.

| 분류 | 포함되는 것 | 보통의 대처 |
| --- | --- | --- |
| 인증 | 프로바이더 인증 실패나 접근 거부, API 키 같은 설정 누락 | AI 코딩 도구에서 다시 로그인하거나 설정을 채우기 |
| 속도 제한 | 속도 제한, 용량 부족, 할당량이나 잔액 소진 | 잠시 뒤 재시도하거나 한도 올리기 |
| 시간 초과 | 실행 시간 초과, 도구 응답 없음, Codex 정체 | 태스크 범위를 줄이거나 시간 제한 조정 |
| 프로바이더 | 프로바이더 서버 오류, 네트워크 장애, 모델 사용 불가, 요청 거부 | 잠시 뒤 재시도하거나 사용 가능한 모델로 변경 |
| 런타임 | 런타임 오프라인, 데몬 재시작, 대기 만료, skill 번들 다운로드 실패, 도구 없음 또는 오래된 버전, 실행 환경 준비 실패 | 그 실행을 돌린 컴퓨터 확인 |
| 에이전트 | 도구 프로세스 비정상 종료, 출력 해석 불가, 컨텍스트 초과, 반복 횟수 한도, 에이전트가 계속할 수 없다고 보고 | 실행 로그를 확인하고 태스크를 고쳐 재시도 |
| 기타 | 분류할 수 없는 실패 | 원래 오류 코드와 실행 로그 확인 |

코드마다의 의미와 대처는 [실행 · 실패 원인 참조](/tasks#실패-원인-참조)를 보세요.

## 비용 계산 방식

분석에 나오는 비용은 모두 달러 기준 추정치이며, AI 코딩 도구나 모델 프로바이더의 청구서가 아닙니다.

- Multica에는 공개된 모델 요금표가 들어 있어, 입력, 출력, 캐시 읽기, 캐시 쓰기마다 정한 100만 토큰당 단가를 보고된 토큰 수에 곱합니다.
- AI 코딩 도구가 직접 비용을 보고하면(예: Grok Build) 추정하지 않고 그 값을 그대로 씁니다.
- 요금표에 없는 모델은 토큰은 집계하지만 비용은 $0으로 계산합니다. 이런 모델은 런타임 사용량에서 [사용자 지정 가격](#사용자-지정-가격)을 설정할 수 있습니다.
- 일부 모델은 프롬프트가 일정 길이를 넘으면 단가가 올라갑니다. 집계 데이터로는 요청마다의 길이를 알 수 없어 모두 표준 단가로 계산하므로, 이런 실행은 낮게 추정될 수 있습니다.

토큰은 AI 코딩 도구가 보고합니다. 도구가 보고하지 않은 실행은 실행 시간과 실행 수에는 들어가지만 토큰과 비용은 더해지지 않습니다. 예를 들어 현재 GitHub Copilot CLI는 출력에 토큰 수를 넣지 않기 때문에, 이 도구를 쓰는 에이전트는 리더보드에 `≥`와 보고되지 않은 실행 수가 표시됩니다.

## 런타임 사용량

**런타임**을 열고 런타임 상세 페이지로 들어가면 그 런타임의 사용량이 보입니다. 비공개 런타임의 사용량은 소유자만, 공개 런타임의 사용량은 모든 멤버가 볼 수 있습니다.

- 맨 위에는 **비용**, **캐시 절감**, **토큰**이 있습니다. 비용 아래에는 같은 길이의 이전 기간과 비교한 증감이 나옵니다. 캐시 절감은 캐시 읽기를 원래 입력 단가로 냈다면 얼마가 더 들었을지 추정한 값이며, 아래에 캐시 적중률이 표시됩니다.
- **런타임 비용 발생 시점**: 일별 또는 주별 비용이나 토큰. **히트맵**으로 바꾸면 최근 26주 동안 하루하루의 비용을 칸의 진하기로 보여 주며, 위의 기간 선택과 상관없습니다.
- **에이전트별**과 **모델별**: 그 기간의 비용이 어느 에이전트, 어느 모델에 쓰였는지.
- **일별 상세 테이블**: 펼치면 날짜와 모델별로 토큰 종류마다의 수가 나옵니다.

런타임 페이지의 기간은 `7d`, `30d`, `90d`, `180d`입니다.

## 사용자 지정 가격

고른 기간에 요금표에 없는 모델이 있으면, 런타임 사용량 위에 기본 가격이 등록되지 않은 모델 수와 그 토큰이 비용에서 빠졌다는 안내가 나옵니다. **사용자 지정 가격 설정**을 누르고, 모델마다 입력, 출력, 캐시 읽기, 캐시 쓰기 단가를 100만 토큰당 USD로 넣은 뒤 저장합니다. 모든 모델에 가격이 생긴 뒤에도 나중에 고칠 수 있도록 **사용자 지정 가격 편집** 버튼이 남습니다. 어떤 모델의 가격을 지우려면 그 필드를 모두 비우고 저장하거나, 옆의 삭제 버튼을 누릅니다.

<Callout type="info">
사용자 지정 가격은 이 기기의 브라우저나 데스크톱 앱에만 저장됩니다. 계정에 동기화되지 않고 워크스페이스의 다른 멤버와도 공유되지 않으며, 이 기기의 모든 워크스페이스에 적용됩니다. 다른 멤버 화면에서는 이 모델들이 여전히 $0으로 계산됩니다.
</Callout>

사용자 지정 가격은 요금표에 없는 모델에만 쓰이며, 기본 단가를 덮어쓸 수 없고 AI 코딩 도구가 직접 보고한 비용도 바꾸지 않습니다. 저장하면 이 기기의 분석 페이지, 런타임 사용량, 태스크 실행 기록이 새 단가로 다시 계산됩니다.

## 태스크 비용

태스크마다 사이드바의 **실행 로그**에 그 태스크의 **비용**, **토큰**, **에이전트 작업** 시간과 실행마다 하나씩의 비용 막대가 표시됩니다. 합계나 비용 막대, 또는 **타임라인 열기**를 클릭하면 **실행 기록** 대화상자가 열립니다.

- 맨 위에 **비용**, **토큰**(그중 캐시 비율), **출력**, **에이전트 작업**, **실행**이 요약됩니다. 에이전트 작업은 각 실행 시간의 합이고, 옆의 "경과"는 첫 실행이 시작된 때부터 마지막 실행이 끝난 때까지의 시간입니다. 실행 옆에는 실패, 취소, 진행 중인 횟수가 나옵니다.
- 차트를 **실행별**로 두면 실행마다 막대 하나로 비용, 토큰, 에이전트 작업을 보여 주고, **누적**으로 두면 누적 비용이 시간에 따라 늘어나는 선을 그립니다.
- **에이전트별**과 **모델별** 띠가 비용이 누구에게, 어느 모델에 쓰였는지 보여 줍니다.
- 아래에는 실행이 날짜별로 나열되며, **실행 세부 정보**를 펼치면 그 실행의 비용 내역과 캐시 적중으로 아낀 금액이 보입니다.

대화상자 맨 아래에는 비용이 추정치라는 점과 가격이 없는 모델 이름이 적혀 있습니다.

## CLI로 확인하기

```bash
multica issue usage <issue-id>
multica runtime usage <runtime-id> --days 30
```

`issue usage`는 태스크의 토큰 합계(입력, 출력, 캐시 읽기, 캐시 쓰기)와 실행 수를 출력합니다. `RUNS`는 끝난 실행 수, `METERED_RUNS`는 사용량을 보고한 실행 수, `UNREPORTED`는 보고하지 않은 실행 수입니다. 보고하지 않은 실행이 있으면 토큰 합계 앞에 `>=`가 붙습니다. 실제 값은 그보다 크다는 뜻입니다.

`runtime usage`는 런타임의 토큰 사용량을 날짜, 프로바이더, 모델별로 나열합니다. `--days`의 기본값은 90이고 최대 365입니다.

두 표 모두 비용 추정치는 없습니다. `--output json`을 붙이면 API가 돌려준 원본 데이터를 출력합니다.
