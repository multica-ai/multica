Multica 에이전트를 WeCom(企业微信) 스마트 봇으로 연결하면 팀 멤버가 봇과 DM을 나누고 그룹에서 @멘션하거나 `/issue`로 이슈를 만들 수 있습니다. 대화와 실행 기록은 계속 Multica 워크스페이스에 저장됩니다.

스마트 봇 하나는 에이전트 하나에만 대응합니다. WeCom에서 여러 에이전트를 사용하려면 각 에이전트에 별도의 봇을 연결하세요.

## 봇 연결

에이전트 owner, 워크스페이스 owner, admin이 연결을 시작할 수 있습니다.

1. **에이전트**를 열고 WeCom에 연결할 에이전트를 선택합니다.
2. **연동**으로 이동해 **WeCom에 연결**을 클릭합니다.
3. WeCom으로 QR 코드를 스캔하고 새 스마트 봇 생성을 승인합니다.
4. Multica로 돌아옵니다. 페이지에 **WeCom에 연결됨**이 표시되면 사용할 수 있습니다.

QR 코드는 5분간 유효합니다. 만료되면 **다시 스캔**을 클릭해 새로 생성하세요.

<Callout type="info">
스캔할 때마다 WeCom에 완전히 새로운 스마트 봇이 만들어집니다. 기존 봇을 다시 승인하는 방식이 아닙니다. 에이전트를 연결 해제한 뒤 다시 연결하면 이전과 다른 새 봇이 만들어지며, 이전 봇은 재사용되거나 복원되지 않습니다.
</Callout>

이미 연결된 에이전트에는 스캔 화면이 다시 표시되지 않습니다. 봇 이름 변경이나 권한 관리는 Multica에서 제공하지 않으므로 WeCom 관리자 콘솔에서 직접 처리하세요.

## 처음 사용

멤버가 DM으로 봇에 처음 메시지를 보내면 계정 연결 링크를 받습니다.

1. 링크를 열고 Multica에 로그인합니다.
2. 연결할 워크스페이스 계정을 확인합니다.
3. WeCom으로 돌아가 메시지를 다시 보냅니다.

연결을 마쳐야 Multica가 메시지를 보낸 워크스페이스 멤버를 확인할 수 있습니다. 멤버가 아닌 사람은 봇을 사용할 수 없습니다. 이는 봇을 스캔해서 설치한 사람에게도 동일하게 적용됩니다. 봇 설치와 자신의 WeCom 계정 연결은 서로 다른 단계입니다.

연결 링크는 봇과의 DM에서만 발급됩니다. 그룹 채팅에서는 연결되지 않은 멤버에게 먼저 봇과 DM하라고 안내합니다.

## WeCom에서 작업 요청

### DM

봇에 바로 메시지를 보내면 됩니다. 연속된 메시지는 같은 Multica 대화에 유지되며 에이전트의 답변도 현재 대화로 돌아옵니다.

### 그룹 채팅

먼저 봇을 그룹 채팅에 추가한 뒤 `@`와 요구 사항을 함께 작성합니다. 봇은 자신을 명시적으로 @멘션한 메시지에만 응답합니다. 실행할 때는 현재 대화에서 읽을 수 있는 최근 컨텍스트를 함께 사용합니다.

### 이슈 만들기

다음과 같이 보냅니다.

```text
/issue 로그인 후 리디렉션 문제 수정
Safari에서 로그인에 성공해도 로그인 페이지에 계속 머뭅니다.
```

첫 줄이 제목이 되고 나머지 내용이 설명이 됩니다. `/issue`만 보내면 Multica가 이전 메시지를 제목으로 사용하려고 시도합니다.

## 연결 관리

**설정 → 연동**에서 워크스페이스에 연결된 봇을 확인할 수 있습니다. 워크스페이스 owner와 admin은 여기서 연결을 해제할 수 있고, 에이전트 owner도 해당 에이전트의 **연동** 페이지에서 자신의 봇을 관리할 수 있습니다.

연결을 해제하면 봇이 새 메시지를 받지 않습니다. 기존 대화와 감사 기록은 함께 삭제되지 않습니다.

<Callout type="warning">
연결 해제는 Multica 쪽 연결만 끊을 뿐, WeCom에 있는 스마트 봇 자체를 삭제하지 않습니다. 완전히 삭제하려면 WeCom 관리자 콘솔에서 직접 삭제하세요.
</Callout>

## 자체 호스팅 설정

Multica Cloud에는 추가 설정이 필요 없습니다. 자체 호스팅 환경에서는 봇 자격 증명 암호화에 사용할 키를 먼저 설정해야 합니다.

```dotenv
MULTICA_WECOM_SECRET_KEY=<base64로 인코딩한 32바이트 키>
```

다음과 같이 생성할 수 있습니다.

```bash
openssl rand -base64 32
```

API 서비스를 다시 시작한 뒤 에이전트의 **연동** 페이지에서 봇을 연결하세요. 이 키는 장기간 보관해야 합니다. 키를 바꾸거나 잃어버리면 기존 자격 증명을 복호화할 수 없으므로 다시 연결해야 합니다.

Multica Cloud와 자체 호스팅 환경은 스마트 봇을 만들 때 사용하는 WeCom "source" ID를 기본적으로 공유하도록 설계되어 있습니다. 이는 보안 경계가 아니므로 자체 호스팅 사용자가 별도로 source를 발급받을 필요는 없습니다. `MULTICA_WECOM_SOURCE_ID`는 디버깅이나 향후 source 교체 시 이 기본값을 덮어쓸 때만 사용하며, 평소에는 설정할 필요가 없습니다.

## 자주 묻는 문제

- **연결 버튼이 없음**: 현재 계정이 에이전트 owner, 워크스페이스 owner, admin인지 확인하고 자체 호스팅 키가 설정되었는지 확인합니다.
- **QR 코드 만료**: 유효 기간은 5분입니다. 팝업을 닫고 연결을 다시 시작합니다.
- **봇이 계정 연결을 요구함**: 연결 링크를 열고 해당 워크스페이스의 Multica 계정으로 로그인합니다. 봇을 직접 설치한 사람이라도 이 단계는 필요합니다.
- **잠깐 끊겼다가 답장이 한참 늦게 옴**: Multica는 연결이 끊긴 동안 보내지 못한 답장을 자동으로 다시 보내지만, 최대 24시간 전까지만 되돌아봅니다. 그보다 오래된 것은 다시 보내지 않습니다.
- **봇이 실행되지 않음**: 에이전트가 보관 처리되었는지, 사용하는 [런타임](/daemon-runtimes)이 온라인인지 확인합니다.
- **다시 연결했는데 WeCom에 예전 봇이 남아 있음**: 정상적인 동작입니다. Multica에서 연결을 해제해도 WeCom의 스마트 봇은 삭제되지 않습니다. 더 이상 필요 없다면 WeCom 관리자 콘솔에서 직접 삭제하세요.
