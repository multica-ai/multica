Le Secrétaire est un agent unique pour tout l'espace de travail. Il lit ce que vos squads ont fait, puis rédige pour vous un bulletin par jour. Ce bulletin indique ce qui demande votre décision, ce qui avance et ce qui est bloqué. Vous ne recevez pas de rapport distinct de chaque squad.

Les squads travaillent comme d'habitude dans les tâches, les projets et les [propositions](/office). Ils ne rédigent jamais de rapport d'état pour vous. Le Secrétaire va chercher lui-même les faits dont il a besoin, si bien que les squads ne consomment pas d'exécutions pour rendre compte de leur état.

Vous lisez le bulletin dans le bureau, dans l'élément de boîte de réception **Bulletin prêt**, ou dans votre application de messagerie si vous l'avez activée. Voir [Livraison vers les applications de messagerie](/chat-delivery). La configuration se lance depuis la carte de configuration du bureau.

## Prérequis

- Un runtime Hermes en ligne sur la machine de votre choix. Installez-le en suivant [Installer un runtime d'agent](/install-agent-runtime), puis configurez un modèle dans Hermes lui-même.
- Le Secrétaire s'exécute sur ce seul runtime. Sa mémoire est stockée sur cette machine, elle ne suit donc pas l'espace de travail s'il est déplacé.

## Ce que crée la configuration

La configuration crée les objets suivants, et peut être relancée sans créer de doublons :

- Un agent nommé **Secretary**, privé, qui utilise Hermes sur le runtime choisi et n'exécute qu'une tâche à la fois.
- Un étage **Executive** et un squad **Executive Office** installé dessus. Le Secrétaire dirige ce squad, et vous en êtes membre.
- Le paramètre de l'espace de travail qui désigne le Secrétaire.
- L'automatisation **Daily brief**, active, et l'automatisation **Weekly review**, suspendue.

## Bulletin quotidien et revue hebdomadaire

Les deux sont des [automatisations](/autopilots) qui exécutent le Secrétaire.

| Automatisation | Quand | État après la configuration |
| --- | --- | --- |
| **Daily brief** | Chaque jour à 08:00, dans le fuseau horaire choisi à la configuration | Active |
| **Weekly review** | Vendredi à 17:00 | Suspendue. Activez-la depuis la page des automatisations. |

Si la machine était en veille à 08:00, cette exécution est sautée, comme toute exécution d'automatisation. Cliquez sur **Exécuter maintenant** sur l'automatisation pour obtenir le bulletin immédiatement.

Lorsqu'un bulletin est publié, les propriétaires de l'espace de travail reçoivent un élément de boîte de réception, **Bulletin prêt**. C'est la seule notification régulière du Secrétaire.

## Contenu d'un bulletin

Un bulletin est un document Markdown comportant six sections, dans cet ordre :

1. **Titre** : trois lignes au maximum. Un jour calme, il le dit, et le bulletin reste court.
2. **Décisions attendues de vous** : d'abord les propositions en attente, puis les blocages que vous seul pouvez lever. Chaque élément présente la situation, les options, la recommandation du Secrétaire et un lien. Cinq éléments au maximum sont listés, et le reste est compté.
3. **Avancement** : par étage, uniquement pour les squads qui ont des nouvelles. Un squad sans changement tient sur une ligne.
4. **Blocages et risques** : chacun avec une piste de sortie proposée.
5. **Veille** : notes sur le marché et le produit issues de l'étage Research depuis le dernier bulletin.
6. **Pour information** : anomalies de coût, de runtime et d'échec.

Un bulletin doit se lire en deux minutes. Le serveur refuse un bulletin dont une section manque et indique au Secrétaire laquelle ; le Secrétaire peut alors corriger et republier. Un bulletin est limité à 20 000 caractères.

## La synthèse (digest)

La synthèse est l'ensemble des faits à partir duquel le Secrétaire rédige. Le serveur la calcule à partir de la base de données : elle est donc bornée et ne dépend pas du modèle.

- **Par squad**, classé selon ce qui demande le plus d'attention : tâches terminées, en cours et bloquées ; tâches en cours sans activité depuis 72 heures ; exécutions échouées ; nombre de fois où le leader n'a rien fait ; propositions en attente ; et les tâches terminées les plus récentes, sous forme de liens.
- **Squads sans changement**, regroupés dans une seule liste.
- **L'espace de travail** : exécutions et coût sur la période, et runtimes hors ligne.

La synthèse détaille au maximum 20 squads. Les autres sont classés et comptés. Vous pouvez remonter jusqu'à 35 jours en arrière.

## Poser une question au Secrétaire dans le chat

Le Secrétaire est un agent : vous pouvez ouvrir un chat avec lui comme avec n'importe quel agent. Pour une question sur l'état de l'entreprise, il lit d'abord la synthèse et répond à partir d'elle, pas de mémoire. Pour une question sur ce que l'entreprise sait ou a décidé, il interroge d'abord la [base de connaissances](/knowledge-base) et cite ce qu'il trouve.

Le Secrétaire n'approuve pas les propositions à votre place. Sa réponse vous oriente vers le bulletin ou vers **Décisions** dans le bureau.

## Ce qu'il peut et ne peut pas faire

| Le Secrétaire peut | Le Secrétaire ne peut pas |
| --- | --- |
| Lire l'espace de travail via la CLI `multica` | Décider une proposition. Le serveur refuse les décisions prises par des agents. |
| Publier des bulletins | Publier un bulletin en tant qu'autre agent. Seul le Secrétaire ou un membre administrateur peut publier. |
| Commenter une tâche pour interroger un leader de squad, au plus trois fois par bulletin | Exécuter le travail d'un squad. Ses instructions le limitent à rendre compte et à poser des questions. |
| Enregistrer des brouillons dans la base de connaissances | Publier des connaissances. Un humain publie les brouillons. |

## La CLI

Le Secrétaire lance ces commandes depuis son runtime. `publish` exige d'être le Secrétaire ou un membre administrateur.

```bash
multica brief digest --since 24h --json
multica brief publish --kind daily --title "Daily brief" --file brief.md --proposal <proposal-id>
multica brief list --kind daily --limit 10
multica brief show <brief-id>
```

| Commande | Rôle |
| --- | --- |
| `digest` | Affiche la synthèse pour la période donnée par `--since`, une durée comme `30m`, `24h` ou `7d`, ou un horodatage RFC 3339. Par défaut, 24 heures. |
| `publish` | Publie un fichier Markdown. Requiert `--kind` (`daily`, `weekly` ou `ad_hoc`), `--title` et `--file`, ou `-` pour lire l'entrée standard. Répétez `--proposal` pour chaque proposition soulevée par le bulletin, afin que l'application affiche un lien. |
| `list` | Liste les bulletins, du plus récent au plus ancien. Filtrez avec `--kind`, limitez avec `--limit` (50 maximum). |
| `show` | Affiche un bulletin par son identifiant. |

Ajoutez `--json` ou `--output json` à n'importe quelle commande pour une sortie lisible par une machine.

## Mémoire et confidentialité

Le Secrétaire conserve vos préférences et vos instructions permanentes dans sa mémoire Hermes. Chaque fait sur l'entreprise provient de la synthèse au moment de l'exécution et des tâches qu'elle désigne. La mémoire peut être perdue, par exemple si le runtime est récupéré ou déplacé, si bien que rien dans l'espace de travail ne dépend d'elle.

Comme le Secrétaire peut lire tout l'espace de travail, la configuration le crée comme agent privé. Les [règles d'accès aux agents privés](/agents#permissions-and-access) déterminent qui peut l'exécuter.
