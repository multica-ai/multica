Multica는 [Discord 개발자 포털](https://discord.com/developers/applications)에서 만든 Bot을 사용합니다. Bot 하나는 Multica 에이전트 하나에 대응합니다. 자체 Bot이 필요한 에이전트마다 따로 만들어야 합니다.

Discord 연동은 [커뮤니티 유지보수](/community-maintained) 대상입니다. 모든 릴리스에 포함되지만 공식 지원 SLA는 없습니다. 문제는 [GitHub 이슈](https://github.com/multica-ai/multica/issues)로 알려 주세요.

## 시작하기 전에

- 워크스페이스 owner 또는 admin이 Bot을 연결해야 합니다.
- API 서버가 `https://discord.com`과 `wss://gateway.discord.gg`에 접근할 수 있어야 합니다.
- Discord 개발자 포털의 Bot token이 필요합니다. 비밀번호처럼 다루세요.

## 1. Bot 만들기

1. [Discord 개발자 포털](https://discord.com/developers/applications)을 열고 새 애플리케이션을 만듭니다.
2. **Bot**을 열고 **Reset Token**을 눌러 token을 복사합니다.
3. **Privileged Gateway Intents**에서 **Message Content Intent**를 켭니다. Multica는 이 intent로 메시지 본문을 읽습니다. 꺼 두면 서버 채널 메시지 본문이 비어 있습니다.
4. **OAuth2 → URL Generator**에서 `bot` scope와 **View Channels**, **Send Messages**, **Read Message History** 권한을 선택하고 생성된 URL로 서버에 Bot을 초대합니다.

<Callout type="warning">
token을 이슈, 채팅, 로그, 저장소에 붙여 넣지 마세요. 노출되면 개발자 포털에서 재설정한 뒤 새 token으로 다시 연결하세요.
</Callout>

## 2. 에이전트에 연결하기

1. Multica에서 **Agents**를 열고 대상 에이전트의 **Integrations**를 엽니다.
2. **Connect Discord**를 클릭합니다.
3. Bot token을 붙여 넣고 **Connect**를 클릭합니다.

Multica는 Discord에 Bot을 확인하고, token을 암호화해 저장하고, 감독되는 Gateway 연결 하나를 시작합니다. 이미 다른 에이전트나 워크스페이스에 연결된 Bot은 먼저 그곳에서 연결을 해제해야 합니다.

## 첫 사용과 계정 연결

멤버가 처음 Bot에 메시지를 보내면 일회용 Multica 계정 연결 링크를 받습니다. 링크를 열어 같은 워크스페이스의 Multica에 로그인한 뒤 Discord로 돌아와 메시지를 다시 보내세요. 링크는 15분 후 만료됩니다. Bot에 다시 메시지를 보내면 새 링크를 받습니다.

서버 채널에서는 Bot이 자격 증명이 담긴 링크를 공개하지 않습니다. 먼저 DM을 보내 달라고 안내합니다.

현재 워크스페이스 멤버만 Bot을 사용할 수 있습니다. 멤버십은 메시지마다 다시 확인합니다.

## Bot 사용하기

### DM

Bot과의 DM을 열고 바로 텍스트를 보냅니다. @멘션은 필요 없습니다.

### 서버 채널

Bot을 채널에 추가한 뒤 @멘션합니다. Bot을 멘션하지 않은 채널 메시지는 대화나 실행을 시작하지 않습니다. 채널마다 하나의 Multica 채팅이 계속됩니다.

### 명령

- `/new`는 새 빈 Multica 채팅을 만들고 이후 Discord 메시지를 그곳으로 라우팅합니다. `/new <메시지>`는 그 메시지를 첫 턴으로 사용합니다.
- `/clear`는 현재 Multica 채팅을 유지하면서 다음 비어 있지 않은 메시지부터 새 에이전트 가시 컨텍스트를 적용합니다. `/clear <메시지>`는 그 메시지를 경계 이후 첫 턴으로 사용합니다.
- `/issue <제목>`은 Multica 작업을 만들고 이어지는 줄을 선택적 설명으로 사용합니다. 제목이 없으면 사용법 안내를 반환합니다.

Discord는 `/issue`, `/new`, `/clear`를 네이티브 슬래시 명령으로 등록하지 않습니다. 일반 메시지 텍스트로 보내세요. 서버 채널에서는 @멘션을 포함합니다: `@YourBot /issue Fix the build`.

### 답장과 지원 콘텐츠

실행이 끝나면 Bot이 트리거 메시지를 인용해 답장을 게시합니다. 긴 답장은 Discord의 메시지당 2000자 제한에 맞춰 나눠 보냅니다. 스트리밍이나 메시지 편집은 지원하지 않습니다.

메시지에 첨부된 파일은 `[File: report.pdf]` 같은 텍스트 마커로 에이전트에 전달되며 파일 자체는 내려받지 않습니다. 에이전트가 Discord로 파일을 보내는 것은 아직 지원하지 않습니다.

## 연결 관리

**설정 → 메시징 → Discord**에서 연결된 Bot을 확인합니다. owner와 admin이 연결을 해제할 수 있습니다. 연결을 해제하면 Gateway 연결이 닫히고 이후 답장도 중단되지만, Multica 대화와 감사 기록은 유지됩니다.

## 셀프 호스팅 설정

API 서버를 시작하기 전에 안정적인 32바이트 암호화 키를 설정하세요.

```dotenv
MULTICA_DISCORD_SECRET_KEY=<base64로 인코딩한 32바이트 키>
```

`openssl rand -base64 32`로 생성할 수 있습니다. 장기간 보관하세요. 분실하거나 교체하면 기존 Bot token을 복호화할 수 없어 Bot마다 다시 연결해야 합니다.

연결 링크는 `MULTICA_APP_URL`을 사용하고, 없으면 `FRONTEND_ORIGIN`으로 대체합니다. 생성된 주소는 멤버가 접근할 수 있어야 합니다. 서버 네트워크나 프록시는 `discord.com` HTTPS와 `gateway.discord.gg` WebSocket을 허용해야 합니다. Go는 표준 `HTTPS_PROXY`와 `NO_PROXY`를 읽습니다.

## 문제 해결

- **Bot을 확인할 수 없음**: 먼저 서버 연결과 프록시 설정을 확인하세요. Discord 자체가 token을 거부할 때만 재설정합니다.
- **서버 채널 본문이 비어 있음**: 개발자 포털에서 **Message Content Intent**를 켠 뒤 다시 연결하세요.
- **채널에서 답장이 없음**: Bot이 채널을 볼 수 있고 메시지가 @멘션하는지 확인하세요.
- **연결 링크 만료**: Bot에 다시 DM을 보내 최신 링크를 사용하세요.
- **Bot이 실행되지 않음**: 에이전트가 보관되었는지, [런타임](/daemon-runtimes)이 온라인인지 확인하세요.
