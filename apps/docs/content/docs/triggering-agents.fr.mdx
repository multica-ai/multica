Partez de ce que vous attendez d’un agent : lui confier une tâche, lui demander une aide ponctuelle ou organiser un travail récurrent.

<TriggerChooserDemo />

| Votre besoin | Fonction à utiliser |
|---|---|
| Confier une tâche à un agent | [Assignez-la](/assigning-issues) à un agent ou un squad. |
| Demander de l’aide sans changer le responsable | [@mentionnez l’agent](/mentioning-agents) dans un commentaire ou répondez à son commentaire. |
| Envoyer souvent le même type de demande | Enregistrez une [action rapide](/quick-actions), comme une revue de code. |
| Transmettre le travail selon des étapes répétées | Choisissez un [workflow](/workflows) de projet avec un responsable par étape. |
| Poser une question sans créer de tâche | Démarrez une [discussion](/chat) avec l’agent. |
| Commencer un travail récurrent selon une date ou un événement extérieur | Créez une [automatisation](/autopilots). |
| Faire revenir un agent sur une tâche plus tard | Ajoutez à la tâche un [réveil](/issue-wakeups) avec l’heure ou l’événement à attendre. |

Vous ne pouvez appeler que les agents que vous avez le droit d’exécuter. Avant d’envoyer un commentaire, vérifiez l’aperçu sous le champ ; utilisez `/note` pour laisser un message sans réveiller d’agent. Une tâche en `backlog` attend que vous soyez prêt à la commencer.

## Suivre l’avancement

Suivez les réponses dans la tâche ou la discussion où vous avez demandé le travail. Le [journal d’exécution](/tasks) permet de voir l’avancement, d’arrêter ou de réessayer. Si rien n’a commencé, vérifiez que l’ordinateur de l’agent est en ligne ; le [dépannage](/troubleshooting) indique la suite.
