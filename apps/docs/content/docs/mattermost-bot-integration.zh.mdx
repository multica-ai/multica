Multica 连接的是你在自有 Mattermost 服务器中创建的机器人账号。一个机器人对应一个 Multica 智能体。需要独立 Mattermost 身份的每个智能体，都要单独创建机器人。

Mattermost 支持属于[社区维护](/community-maintained)：它随每个版本发布，但不提供官方支持 SLA。问题请提交到 [GitHub issues](https://github.com/multica-ai/multica/issues)。

## 开始之前

- 需要由 Multica 工作区所有者或管理员来连接机器人。
- Multica API 服务器必须能通过 HTTP 或 HTTPS 访问你的 Mattermost 服务器。由于 Mattermost 是自部署的，这通常是内网地址而非公网地址。
- 需要在 Mattermost 中启用机器人账号（**系统控制台 → 集成 → 机器人账号**）。
- 需要机器人的访问令牌，请像对待密码一样保管它。

## 1. 创建机器人账号

1. 在 Mattermost 中打开**系统控制台 → 集成 → 机器人账号**，确认允许创建机器人账号。
2. 从团队主菜单打开**集成 → 机器人账号**，点击**添加机器人账号**。
3. 填写用户名（成员将用它来 @ 提及）、显示名称和头像。
4. 点击**创建机器人账号**并复制显示的令牌。Mattermost 只会显示一次。
5. 把机器人加入它需要工作的频道。机器人只能收到自己所在频道的消息。

<Callout type="warning">
切勿把令牌粘贴到任务、聊天消息、日志或代码仓库中。一旦泄露，请在**集成 → 机器人账号**中吊销，并用新令牌重新连接。
</Callout>

<Callout type="info">
请使用**机器人账号**，不要使用个人访问令牌。Multica 会拒绝个人令牌：那样机器人自己发出的消息会作为入站消息回流，导致自问自答。
</Callout>

## 2. 连接到智能体

1. 在 Multica 中打开**智能体**，选择一个智能体，进入**集成**。
2. 点击**连接 Mattermost**。
3. 粘贴 Mattermost 服务器地址（例如 `https://mattermost.example.com`）和机器人访问令牌，然后点击**连接**。

Multica 会调用你的服务器校验令牌、确认该账号是机器人、加密保存令牌，并建立一条受监管的 WebSocket 连接。若该机器人已连接到其他智能体或工作区，需先在那里断开。

服务器地址会随安装记录一并保存，因此同一个 Multica 工作区中的两个智能体可以分别连接到两台不同 Mattermost 部署上的机器人。

## 首次使用与账号绑定

成员第一次给机器人发消息时，机器人会发送一个一次性的 Multica 账号绑定链接。打开链接、登录同一个 Multica 工作区，然后回到 Mattermost 重新发送消息。链接 15 分钟后过期；重新给机器人发消息即可获取新链接。

在频道中，机器人绝不会公开发布该链接，而是提示发送者先开启私聊。

只有当前工作区成员可以使用机器人，并且每条消息都会重新校验成员身份。

## 使用机器人

### 私聊

与机器人开启私聊并直接发送文本，无需 @ 提及。

### 频道与群组消息

把机器人加入频道后 @ 提及它。被接受的消息会延续该话题串对应的 Multica 会话；未指向机器人的频道闲聊不会被采集。

如果话题串的根消息本身由机器人发出，那么串内不带 @ 的回复同样会送达机器人——机器人发起的对话可以直接继续，无需反复提及它。若话题串由真人发起，则每次都需要 @ 提及。

每个话题串都是独立的 Multica 会话。同一频道中的两个 @ 提及话题串是两段互不干扰的对话；私聊则是一段连续对话。

### 命令

- `/issue <标题>` 创建 Multica 任务，后续行作为可选描述。只输入 `/issue` 会返回用法提示。
- `/new` 创建一个新的空 Multica Chat，并把该话题串后续消息路由进去。`/new <消息>` 会把该消息作为首轮内容。
- `/clear` 保留当前 Multica Chat，并为下一条非空消息应用全新的智能体可见上下文。

<Callout type="info">
这些是 Multica 的消息命令，按普通消息文本输入即可。它们不是 Mattermost 斜杠命令，无需在系统控制台注册。
</Callout>

### 回复与支持的内容

机器人会在请求所在的话题串中回复，原生渲染智能体输出的 Markdown，并按服务器的最大消息长度自动分段。回复在智能体完成后一次性发出，不是流式的。

当前版本仅支持文本。同时包含文本和附件的消息按文本处理；只有文件、图片或其他非文本内容的消息，会在私聊中以及明确指向机器人时收到明确的不支持提示，未指向机器人的频道媒体消息则保持静默。

没有"正在输入"提示：Mattermost 仅通过 WebSocket 暴露该能力，对于正在处理中的消息，Multica 没有可调用的服务端等价接口。

## 管理连接

打开**设置 → 集成 → Mattermost** 查看已连接的机器人及其所属服务器。所有者和管理员可以断开连接。断开会关闭连接并停止外发回复，但会保留 Multica 中的会话与审计记录。

## 自部署配置

启动 API 服务器前，设置一个稳定的 32 字节加密密钥：

```dotenv
MULTICA_MATTERMOST_SECRET_KEY=<base64 编码的 32 字节密钥>
```

可用 `openssl rand -base64 32` 生成。请长期保存：一旦丢失或轮换，已存储的机器人令牌将无法解密，需要重新连接每个机器人。

服务端不配置任何 Mattermost 地址：每个安装自带服务器地址，因此一套 Multica 部署可以服务多台 Mattermost 服务器上的机器人。

绑定链接使用 `MULTICA_APP_URL`，回退到 `FRONTEND_ORIGIN`。生成的地址必须能被成员访问。

<Callout type="warning">
Multica 访问你的 Mattermost 服务器时从不跟随 HTTP 重定向，因此错误配置的重定向不会把机器人令牌发往其他主机。如果你的部署存在重定向（例如 HTTP 跳转 HTTPS），请填写最终地址——也就是你在浏览器中实际使用的那个。
</Callout>

## 故障排查

- **无法验证机器人**：先检查服务器地址以及 API 服务器的网络或代理设置。只有当 Mattermost 明确拒绝当前令牌时才需要重新生成——错误提示会区分这两种情况。
- **提示"该令牌属于用户账号"**：你粘贴的是个人访问令牌。请创建机器人账号并使用它的令牌。
- **频道中没有回复**：确认机器人在该频道内，且消息 @ 提及了它，或是在机器人发起的话题串中回复。
- **`@channel` 不会触发机器人**：这是刻意设计。机器人只响应自己的名字，广播式提及不会惊动频道里的每个机器人。
- **绑定链接过期**：重新给机器人发一条私聊消息，使用最新的链接。
- **机器人不执行**：检查智能体是否已归档，以及其[运行时](/daemon-runtimes)是否在线。
