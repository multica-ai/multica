プロジェクトは、複数の[タスク](/issues)で完了する作業を整理するための単位です。プロダクトのリリース、移行、段階的に進める機能などが該当します。

1 件のタスクで説明できる作業にプロジェクトは不要です。プロジェクトが適しているのは、共通の目標を持ち、進捗をまとめて追跡したい、あるいはリポジトリや作業ディレクトリを共有したい一連の作業です。

## プロジェクトの構成

| 内容 | 役割 |
|---|---|
| **名前、アイコン、説明** | 目標、範囲、長期にわたって有効な要件。説明はプロジェクト内で作業するエージェントの実行コンテキストに入ります。 |
| **ステータス** | `planned`、`in_progress`、`paused`、`completed`、`cancelled`。 |
| **優先度** | `urgent`、`high`、`medium`、`low`、`none`。 |
| **リード（lead）** | メンバーまたはエージェント。プロジェクトの調整役を示します。 |
| **アクセス権** | ワークスペース全体、またはプロジェクトメンバーのみ。[プライベートプロジェクト](#private-projects)を参照してください。 |
| **開始日と目標日** | プロジェクトの計画期間。 |
| **タスクと進捗** | プロジェクト内の作業と、その完了割合。 |
| **リソース** | 紐づけた GitHub リポジトリ、または特定のコンピュータ上のローカルディレクトリ。 |
| **ワークフロー** | タスクが通るステップと、各ステップを引き継ぐ相手。 |

## プロジェクトを探す

**すべてのプロジェクト**を開き、表示メニューから**テーブル**か**ボード**を選びます。どちらも検索とステータス・優先度・リードによる絞り込みができ、同じ項目か[フォルダ](#folders)でグループ化できます。テーブルはグループ化なしにもできます。ボードで別の列にドラッグすると、その列に対応する項目が変更されます。

テーブルには開始日、期限、進捗、最終アクティビティを表示でき、それらの項目や名前、ステータス、優先度、作成日時で並べ替えられます。レイアウト、グループ化、並び順、表示列、フィルターはユーザー・ワークスペースごとに保存され、デバイス間で同期されます。検索文字列は保存されません。

## プロジェクトページ

プロジェクトを開くと、3 つのタブが表示されます。

- **概要** — プロジェクト名、アイコン、折りたたみ可能な説明（エージェントのコンテキストとして共有されます）、および紐づくリソース。
- **タスク** — 選択したリスト・ボード・テーブル・ガント・スイムレーンのレイアウトでのプロジェクト内タスク一覧。
- **アクティビティ** — プロジェクト内のタスク作成と、ステータス・担当者・優先度・日付・タイトル・重複マークの変更を新しい順に表示するフィード。

最後に開いたタブはこのデバイス上でプロジェクトごとに記憶されます。まだタスクがないプロジェクトは **概要** で開きます。

右サイドバーはどのタブでも共通で表示され、**プロパティ**、**進捗**（完了数と範囲内の件数、完了・進行中の分割バー、週次進捗グラフ、直近 4 週間のペースから十分な履歴がある場合に算出される完了見込み日）、**内訳**（**担当者** と **ラベル** を切り替えでき、行をクリックするとその条件で絞り込んだ **タスク** タブを開きます）、**最近のアクティビティ**（**すべて表示** から **アクティビティ** タブへ移動）が並びます。

## プロジェクトとタスクの関係

1 つのプロジェクトは任意の数のタスクを含むことができ、1 つのタスクは最大 1 つのプロジェクトに属します。タスクはプロジェクト内で直接作成することも、タスクのプロパティでプロジェクトを選択・変更することもできます。

プロジェクトの進捗は、紐づくタスクから自動的に計算されます。

```text
進捗 = done 分類のタスク数 ÷（プロジェクト内の全タスク数 − closed 分類のタスク数）
```

組み込みステータスでは、`done` が完了、`cancelled` が closed に当たります。closed のタスクはプロジェクトの範囲から外れたものとして、完了にも全体数にも数えられず、キャンセル済みの数は進捗の横に別に表示されます。カスタムステータスは所属する分類に従います。割合は切り捨てなので、100% は範囲内のタスクがすべて完了したことを意味します。範囲内にタスクがないプロジェクトは 0% と表示されます。

プロジェクトのステータスとタスクのステータスは連動しません。すべてのタスクが完了してもプロジェクトは自動では `completed` にならず、プロジェクトのステータスを変えても中のタスクは一括変更されません。

## プロジェクトの説明と実行コンテキスト

エージェントがプロジェクト内のタスクを実行するとき、プロジェクトの名前と説明がその実行のコンテキストに追加されます。目標、技術的な境界、成果物の取り決めなど、関連するすべての実行が知っておくべき情報は説明に書き、1 件のタスクにだけ関係する要件はそのタスクに書きます。

## リソースの追加

プロジェクトリソースは、どのコードとどの作業ディレクトリを使うかをエージェントに伝えます。

- **GitHub リポジトリ**: ランタイムが checkout できるリポジトリと、任意の ref を指定します。
- **ローカルディレクトリ**: 特定のコンピュータ上のランタイムに既存のディレクトリを使わせます。エージェントはディレクトリを直接変更するか、その独立した worktree で作業します。

選び方と安全上の境界は[プロジェクトリソース](/project-resources)を参照してください。

## ワークフローを選ぶ

プロジェクトの**ワークフロー**でボードの列と、各ステップの引き継ぎ先を決めます。たとえば開発とレビューを別々のエージェントに任せ、最後はメンバーが確認できます。ほかを選んでいなければ **Default** を使います。すべてのステータスを使え、自動の引き継ぎはありません。設定と既存プロジェクトの切り替えは[ワークフロー](/workflows)を参照してください。

## プロジェクトリード

リードはメンバーまたはエージェントで、メンバーであるリードはプロジェクトのワークフローも切り替えられます。リードに設定してもタスクは割り当てられず、作業も始まりません。あるステップをリードに渡したい場合は、ワークフローでそのステップの処理者を**プロジェクトリード**にします。

## プライベートプロジェクト [#private-projects]

プロジェクトの**アクセス権**は**ワークスペース全体**か**プロジェクトメンバーのみ**のどちらかです。プライベートプロジェクトとその中のタスク、コメント、添付ファイルは、メンバーリストに載っている人だけが見られます。それ以外の人には一覧や検索に表示されず、リンクを開いても見つからない扱いになります。

### プライベートプロジェクトを見られる人

- **メンバーリストに載っている人だけです**。ワークスペースのロールではアクセスできません。リストに載っていない `owner` や `admin` もプロジェクトを見られません。ほかの人と同じようにリストに追加され、外されることもあります。
- **エージェント**は、代わりに作業する人に従います。エージェントの実行がプライベートプロジェクトを見られるのは、実行をトリガーした人とエージェントの所有者が両方ともリストに載っている場合だけです。プライベートプロジェクトのタスクは、所有者がリストに載っているエージェントにしか割り当てられません。
- ワークスペースを離れたメンバーは、その中のすべてのプライベートプロジェクトからも外れます。

<Callout type="info">
`owner` や `admin` なのにプライベートプロジェクトが表示されなくなった場合は、そのメンバーリストに載っていません。アクセスを管理しているメンバーに追加を依頼してください。ワークスペースのオーナーは設定から参加することもできます（[ワークスペースオーナーによる復旧](#workspace-owner-recovery)を参照）。
</Callout>

### メンバーリストを管理できる人

アクセスの管理とは、メンバーの追加と削除、プロジェクトリードの変更、プロジェクトをワークスペース全体に戻すことを指します。次の人が行えます。

- リストに載っている `owner` と `admin`。
- プロジェクトがアクセス管理者として定める 1 人のメンバー。**アクセス権**ダイアログで**アクセスを管理**と表示されます。リードがリストに載っている人ならリード、そうでなければリストに載っている作成者、それもいなければリストに最も長く載っているメンバーです。

プライベートプロジェクトのリードも、ほかのプロジェクトと同じくメンバー、エージェント、または未設定にできます。アクセス管理者は保存されず、リード、作成者、リストから毎回決まるため、リードが変わったり誰かが離れたりすると移ります。人をリードにするとその人はリストに追加されます。現在のリードをリストから外すには、先にリードを変更します。ほかのメンバーはリストを見られますが、変更はできません。エージェントはどのプロジェクトのアクセス権も変更できません。

### プライベートプロジェクトを作成する、またはプロジェクトをプライベートにする

- **新しいプロジェクト**：作成ダイアログで**アクセス権**を開き、**プロジェクトメンバーのみ**を選んでメンバーを追加します。自分は常にリストに載り、リードに指定した人も載ります。
- **既存のプロジェクト**：プロジェクトのプロパティで**アクセス権**をクリックし、**プロジェクトメンバーのみ**を選びます。ワークスペース全体に公開されているプロジェクトをプライベートにできるのは `owner` か `admin` です。操作した人はリストに追加され、リードが人ならリードも追加されます。
- **CLI**：`project create` または `project update` に `--visibility private` を付け、`--member`（名前、メールアドレス、またはユーザー ID。繰り返し指定可）で最初のリストを指定します。その後は `project member list|add|remove` でリストを管理します。

```bash
multica project create --title "Pricing revamp" --visibility private --member alice@example.com --member Bob
multica project update <project-id> --visibility private --member alice@example.com
multica project member add <project-id> carol@example.com
```

プライベートプロジェクトを**ワークスペース全体**に戻すと、`owner`、`admin`、`member` がプロジェクトとその中のタスク、コメント、添付ファイルを見られるようになります。ゲストが閲覧できるのは、そのプロジェクトを共有されている場合だけです。アプリでは保存前に確認が表示されますが、`multica project update --visibility workspace` はすぐに反映されます。

### ワークスペースオーナーによる復旧 [#workspace-owner-recovery]

プライベートプロジェクトのリストに `owner` や `admin` が一人もいない、あるいはメンバーが誰も残っていないこともあります。ワークスペースの `owner` は**設定 → 一般 → プライベートプロジェクト**から対応できます。このセクションはオーナーにだけ表示され、`admin` には表示されません。すべてのプライベートプロジェクトの名前とメンバーだけが一覧され、タスク、コメント、添付ファイルは参加するまで見られません。

**参加**をクリックして確認すると、自分がメンバーリストに追加されます。ほかのメンバーと同じようにリストに表示され、既存のメンバーにはインボックスで通知が届きます。リストに載ったオーナーとして、そのプロジェクトのアクセスを管理できます。参加してもリードは変わりません。メンバーが全員離れたプロジェクトも同じ方法で復旧できます。参加してから、プロジェクトページで管理または削除してください。

## フォルダ [#folders]

フォルダは、ひとつのリリースやひとつのチームのプロジェクトなど、関連するプロジェクトをまとめて、サイドバーのプロジェクトセクションを短く保ちます。`owner`、`admin`、`member` には同じフォルダが表示され、フォルダの作成・名前の変更・削除や、プロジェクトの出し入れができます。プロジェクトが入れるフォルダは最大ひとつで、フォルダは入れ子にできません。フォルダは整理のためだけのもので、誰がプロジェクトを見られるかは変わりません。

- **フォルダを作成**：サイドバーのプロジェクトセクションの **+** から**新しいフォルダ**を選ぶか、プロジェクトのメニューで**フォルダに移動 → 新しいフォルダ…** を選ぶと、そのプロジェクトを入れた状態で作成されます。
- **プロジェクトを移動**：プロジェクトのメニューで**フォルダに移動**を選ぶか、サイドバーでフォルダの上にドラッグ、またはフォルダの外へドラッグします。プロジェクトの作成ダイアログでもフォルダを選べます。フォルダ行の **+** はそのフォルダにプロジェクトを作成します。
- **フォルダ名の変更・削除**：サイドバーでフォルダを右クリックします。フォルダを削除すると、中のプロジェクトは最上位に戻り、それ以外は変わりません。

サイドバーでどのフォルダを開いているかと、フォルダとプロジェクトの並び順は個人の設定で、他のメンバーには影響しません。プロジェクトセクションの絞り込みはフォルダの中にも適用され、プロジェクトがすべて絞り込まれたフォルダは非表示になります。空のフォルダは、プロジェクトを入れられるよう表示されたままです。**すべてのプロジェクト**で**フォルダ**でグループ化すると、フォルダごとにプロジェクトを確認できます。ボードで別の列にドラッグすると、そのフォルダに移動します。

## サイドバーへのピン留め

ピン留めすると、プロジェクトが自分のサイドバーに表示されます。ピン留めは個人の設定で、ほかのメンバーには影響しません。

プロジェクトセクションの設定で**デフォルトのアイコンのみ**を有効にすると、そのセクションのカスタムアイコンが標準のプロジェクトアイコンで表示されます。初期状態ではオフで、プロジェクト自体のアイコンは変わりません。

## アーカイブと復元

プロジェクトのメニューで**プロジェクトをアーカイブ**、または一覧で**アーカイブ**を選びます。プロジェクトを編集できる人はアーカイブ・復元もできます。アーカイブすると通常の一覧や選択肢から非表示になり、新しいタスクの作成や移動先に指定できなくなります。既存のタスク、履歴、設定は残り、タスクは引き続き閲覧・編集できます。プロジェクトのステータスも変わりません。

そのプロジェクトにタスクを作る有効な自動化は一時停止します。復元するには、一覧のタイトルメニューを**アーカイブ済みのプロジェクト**に切り替えて**復元**を選ぶか、プロジェクトのページで**プロジェクトを復元**を選びます。復元しても自動化は再開しません。必要なときに個別に有効にしてください。

## 作成、編集、削除

`owner`、`admin`、`member` はプロジェクトの作成と編集ができます。メンバーは自分、または現在自分が所有するエージェントが作成したプロジェクトを削除できます。エージェントは自分が作成したものだけを削除できます。人間の `owner` と `admin` は、作成者不明の既存プロジェクトを含むすべてのプロジェクトを削除できます。プライベートプロジェクトを編集・削除できるのはメンバーリストに載っている人だけなので、`owner` や `admin` も先にリストに載る必要があります。

<Callout type="warning">
プロジェクトを削除しても中のタスクは削除されません。タスクは紐づけが解除され、ワークスペースにそのまま残ります。プロジェクトの説明、ステータス、リソースは完全に削除されます。
</Callout>
