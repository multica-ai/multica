Multica は、普段使っている AI コーディングツールの代わりになるものではありません。ランタイムがコンピューターにインストール済みでログイン済みのツールを呼び出し、実行の進捗と結果をタスクに書き戻します。

すでにいずれかのツールを使っている場合は、通常そのまま使い続けられます。ツールを選ぶときは、次の 4 点を確認してください。

- コンピューターにすでにインストールされているか
- アカウントでどのモデルを利用できるか
- Multica から MCP を設定する必要があるか
- チームでどのスキルを再利用したいか

インストール方法は [AI コーディングツールをインストールする](/install-agent-runtime)を参照してください。

「Multica による MCP 管理」とは、エージェント設定に MCP server を入力し、Multica が実行前にその設定を対応ツールへ渡せることを意味します。そのツールにほかの MCP 設定方法がない、という意味ではありません。

## モデルの取得元

エージェントを作成するとき、モデル一覧は対応するランタイムから取得されます。固定されたモデル名を提供するツールもあれば、ローカル設定、ログイン中のアカウント、サブスクリプションに応じて利用可能なモデルを返すツールもあります。

モデルを選択しない場合、Multica はそのツールのデフォルト設定を使用します。一覧が空の場合は、ランタイムがオンラインでツールにログイン済みであることを確認してから、モデル一覧を更新してください。

QwenPaw と MiniMax Code は例外です。Multica 側で選んだモデルを受け付けないため、選択欄は操作できず「ランタイムで管理」と表示されます。モデルは各ツール側の設定で選んでください。モデル一覧が空なのは正常であり、ランタイムがオフラインであることを示すものではありません。

DeepSeek Harness のモデルカタログはランタイム自身が提供します（`dsh --profile multica --list-models`）。モデル ID は `provider/model` 形式（例: `deepseek-official/deepseek-chat`）なので、一覧から完全な ID を選択してください。

<Callout type="info">
ツールによってモデル名が異なることがあります。AI コーディングツールを変更すると、以前のモデル値は新しいツールで使えないため、選び直す必要があります。
</Callout>

## セッション再開

表で ✓ が付いたツールは、後続の実行で既存のセッションを続行できます。ただし、元のセッションが残っており、そのセッションへアクセスできるランタイムが実行を処理する必要があります。MiniMax Code 0.1.2 は ACP でセッション読み込み機能を通知しないため、後続の実行では新しい MCode セッションを開始します。

Multica はツールから返されたセッション識別子を保存します。次に同じタスクで作業を続けるとき、ランタイムはそのセッションの再開を試みます。再開できない場合は、新しいセッションを作成して実行を続けます。Pi はローカルのセッションファイルパスを保存するため、元のコンピューターとファイルへの依存度が高くなります。

再試行とセッション再開のルールは、[実行](/tasks#手動リトライ)を参照してください。

## MCP 設定

Antigravity、GitHub Copilot CLI、DevEco Code は、現時点ではエージェントの MCP 設定を読み取りません。そのため、これらのツールを選んだ場合、エージェント作成画面にこの項目は表示されません。

### Pi の MCP 管理

デーモンが有効かつ互換性のある `pi-mcp-adapter` を検出すると、Pi で Multica による MCP 管理を利用できます。対応するアダプターのバージョンは **2.37.0** と **3.1.0** です。ほかのバージョンは互換性があるとみなしません。ランタイムのコンピューターで対応バージョンをインストールし、デーモンを再起動して検出結果を更新してください。

```bash
pi install npm:pi-mcp-adapter@2.37.0
```

ローカル MCP の一覧は、他のランタイムと同じ非機密フィールド（名前、通信方式、提供元、有効状態）を報告します。共有ユーザー MCP ファイルと互換アダプターのユーザー設定を読み取り、`PI_CODING_AGENT_DIR` と `PI_MCP_CONFIG_MODE=exclusive` に従います。プロジェクトファイル、互換インポート、パッケージ由来のサーバーは対象外です。一覧への表示によって管理対象の実行にサーバーが追加されることはありません。

MCP タブは、この機能を通知する Pi ランタイムでのみ利用できます。古いデーモン、アダプターの未導入、または非対応バージョンでは利用できませんが、MCP 管理を使わない通常の Pi 実行は引き続き可能です。Multica がアダプターを自動でインストールしたり有効にしたりすることはありません。

管理対象の実行では、`createMcpAdapter({ config })` を通じて、エージェントの解決済み MCP 設定だけを渡します。コンピューターのグローバル設定やプロジェクトの MCP 設定は統合しません。設定とアダプターの状態は非公開の一時ディレクトリに保存し、実行終了、起動失敗、キャンセル時に削除します。グローバルの Pi 設定と MCP ファイルは変更しません。

- MCP 設定が未設定（`null`）なら、Pi の従来の起動動作を維持します。
- 明示的な空の設定（`{}` または `{"mcpServers": {}}`）では、MCP server のない分離された管理対象の実行を開始します。
- 管理対象の実行では拡張機能の自動検出を無効にし、Multica の MCP ブリッジだけを読み込みます。ほかの拡張機能と、それらが提供するモデルプロバイダーは利用できません。Pi 標準とプロジェクトのスキル、設定済みのスキルパス、インストール済み npm パッケージやローカルパッケージのスキルは維持されます。

Pi パッケージは、インストール済みの npm パッケージか、絶対パスで指定するローカルパッケージディレクトリである必要があります。Git ソースや相対パスでは管理対象の実行準備が失敗します。Multica はリソースを維持するためにパッケージをダウンロードしません。モデル設定と認証情報は実行ごとにコピーされますが、更新された認証情報は元のファイルに書き戻しません。リフレッシュトークンがローテーションされた場合、再認証が必要になることがあります。MCP 認証には明示的に設定したヘッダーと環境変数を使い、アダプターのグローバル OAuth 認証情報は取り込みません。

#### ランタイムのコンピューターで検証する

テスト用 MCP server と利用許可のあるモデルアカウントを使ってください。実際の実行ではモデルのクレジットを消費する場合があります。

1. 対応バージョンのアダプターを有効にしてデーモンを再起動し、Pi エージェントに MCP タブが表示されることを確認します。互換性のあるアダプターがない場合は、タブが利用できず、通常の実行は動作することを確認します。
2. 2 つのエージェントに別々のテスト用 MCP server を割り当て、同時に実行して利用可能な MCP ツールを列挙させます。それぞれが自分に割り当てられた server だけを参照できることを確認します。明示的な空の設定では MCP ツールがないことを確認します。
3. スキルを紐づけ、認証済みのモデルを選び、管理対象の実行を完了します。同じタスクを続行してセッション再開を確認し、キャンセルと MCP 起動失敗も検証します。
4. 実行前後のグローバル Pi 設定と MCP ファイルのチェックサムを比較します。完了、失敗、キャンセルした各実行の一時ディレクトリが削除されることを確認します。ログやスクリーンショットに認証情報を含めないでください。

<Callout type="warning">
MCP server のコマンド、引数、環境変数は、エージェント設定の一部としてサーバーに保存されます。共有する必要がないローカルの認証情報を設定へ直接入力しないでください。
</Callout>

## スキルの注入方法

実行を開始する前に、Multica はエージェントに紐づいたスキルを上表の場所へ書き込み、各ツールが標準の仕組みで検出できるようにします。

リポジトリにすでにあるスキルは上書きしません。同名のスキルがある場合、Multica は注入するコピーに別のディレクトリ名を使い、実行後には自分で作成したファイルだけを削除します。

Codex、Hermes、OpenClaw の動作は少し異なります。

- Codex は実行ごとに専用の `CODEX_HOME` を使い、システム全体の Codex ディレクトリにはスキルを書き込みません。
- Hermes は実行ごとに専用の `HERMES_HOME` を使います。既存のローカル設定は読み取れますが、紐づけたスキルとセッションデータは実行ごとに分離されます。この分離はエージェントにスキルが紐づいている場合だけ有効になり、スキルがない実行では既存の Hermes ホームディレクトリを使います。
- OpenClaw は現在の実行の作業ディレクトリにある `skills/` を使い、実行専用の設定でそのディレクトリをワークスペースとして指定します。

スキルの作成と紐づけについては、[スキル](/skills)を参照してください。
