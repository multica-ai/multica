加入[工作區](/workspaces)的人都是成員，每位成員有一個角色：`owner`、`admin` 或 `member`。角色只控制工作區設定和團隊管理；建立任務、發表評論等日常協作對所有成員開放。工作區還可以有[訪客](#訪客)，訪客只能看到分享給自己的專案。

## 三種角色

| 操作 | owner | admin | member |
|---|:---:|:---:|:---:|
| 檢視工作區並參與日常協作 | ✓ | ✓ | ✓ |
| 修改工作區設定 | ✓ | ✓ | — |
| 邀請 `admin` 或 `member` | ✓ | ✓ | — |
| 調整或移除 `admin`、`member` | ✓ | ✓ | — |
| 授予、收回或移除 `owner` | ✓ | — | — |
| 刪除工作區 | ✓ | — | — |

工作區必須始終保留至少一名 `owner`：最後一名 `owner` 不能被降級、移除或離開。

<RolesDemo />

<Callout type="info">
角色不決定誰能執行 AI 代理。每個 AI 代理有獨立的訪問範圍（Access），`owner` 和 `admin` 也不能繞過它執行未授權的 AI 代理。詳見[AI 代理](/agents#權限與-access)。
</Callout>

<Callout type="info">
角色同樣不會開放私有專案。`owner` 或 `admin` 只有在成員名單裡時才能看到私有專案。詳見[私有專案](/projects#private-projects)。
</Callout>

## 邀請成員

`owner` 和 `admin` 在**設定 → 成員**中點選**邀請成員**，填寫信箱、選擇角色後傳送。邀請可以授予 `admin`、`member` 或[訪客](#訪客)身分；`owner` 需要先加入工作區，再由現有 `owner` 提升。

![成員管理：邀請表單與帶角色的成員名冊](/images/docs/members-roster.webp)

受邀者用該信箱登入即可接受，無需提前註冊。邀請有效期 7 天，過期後重新傳送。在限制註冊的自部署例項中，待接受且未過期的邀請允許該信箱建立帳號，無需另外加入白名單，見[登入與註冊](/auth-setup#邀請與註冊限制)。

邀請連結只出現在郵件裡，產品介面中沒有檢視或複製它的入口。郵件傳送失敗時邀請記錄仍然存在，可以撤銷後重新傳送。

需要一條能直接轉發的連結時，在**設定 → 成員**的**分享連結**中選擇角色和有效期後生成。拿到連結的人都可以以所選角色加入，直到連結過期或被撤銷；前提是工作區還有空餘的成員名額（見下文）。

### 成員上限

在 Multica Cloud 上，Free 套餐的工作區最多 5 位成員。成員和待接受的邀請各佔一個名額，訪客不佔。上限生效時，超出上限的新邀請、接受邀請和透過分享連結加入都會被拒絕，直到空出名額（撤回邀請或移除成員）或工作區升級。既有成員不會被移除。工作區滿員時，管理員會在邀請視窗裡看到**升級並邀請**：付款完成後，在**設定 → 帳單與套餐**裡可以發出這份邀請。Pro 和 Business 每位成員佔一個付費席位。自行部署的工作區沒有成員上限。

## 訪客

訪客只能看到分享給自己的專案。在這些專案裡，訪客可以查看任務、評論、加上表情回應和關注任務；不能建立或修改任務，不能執行或 @ agent，也不能開啟工作區設定，看不到其他專案、agent、autopilot 和 runtime。訪客免費，不佔付費席位，也不佔成員名額。

`owner` 和 `admin` 在邀請視窗裡選擇**訪客**並勾選可存取的專案，即可邀請訪客。在成員的操作選單裡，可以把成員設為訪客（釋出其席位，並收回其 agent、autopilot 和 runtime 權限），把訪客設為成員（佔用一個席位），或透過**管理可存取的專案**調整訪客能看到的專案。

在 Multica Cloud 上，Pro 和 Business 包含訪客。試用結束或工作區降到 Free 後，既有訪客保留存取權限，仍然可以移除、縮小範圍或設為成員，但不能再新增訪客。自行部署的工作區可以使用訪客。

## 調整角色

在成員列表中開啟某位成員右側的操作選單，選擇**更改角色**，角色立即生效。

`admin` 可以在 `admin` 和 `member` 之間調整角色，也可以移除這兩類成員。涉及 `owner` 的變更——提升、更改或移除——只有 `owner` 能執行。

## 移除成員

被移除的成員立即失去工作區訪問權限。該成員建立的任務、評論和其他協作記錄保留在工作區中。

<Callout type="warning">
移除成員會同時停用該成員擁有的執行時、歸檔繫結在其上的 AI 代理，並取消尚未結束的執行。該成員在 AI 代理訪問範圍（Access）中獲得的授權也會被清除，重新加入後不會自動恢復。
</Callout>
