Company as code は、会社の構造を一つの JSON ドキュメントとして記述します。フロア、憲章とルーティンを含むスクワッド、エージェントの役割と指示、パイプライン、ナレッジの種類、ポリシー、目標と予算が含まれます。構造のバックアップとして使うことも、同じ形の二つ目の会社を始めるために使うこともできます。

エクスポートとインポートができるのは、オーナーと管理者だけです。

## エクスポート

```bash
multica company export --file company.json
```

エクスポートには次のものが含まれます。

- フロアとスクワッドの座席。
- 憲章とルーティンを含むスクワッド。
- エージェントの役割、指示、テンプレートの参照。
- パイプラインとそのステージ。
- ナレッジの種類、フロアのチーフ、ガバナンスのセクション。

シークレット、ランタイム、ナレッジドキュメント、進捗、支出、履歴は含まれません。ファイルにもその旨が書かれています。シークレットとナレッジドキュメントは、別のバックアップとして保管してください。

## インポート

```bash
multica company import --file company.json --runtime <runtime-id> --dry-run
multica company import --file company.json --runtime <runtime-id>
```

まず `--dry-run` で実行してください。計画を表示するだけで、何も書き込みません。

- エンティティは名前で照合されます。同じファイルを二度インポートしても何も変わりません。
- エージェントは `--runtime` で指定したランタイム上に作成されます。指定がない場合、エージェントはブロックされたものとして報告されます。
- インポートされたルーティンは **一時停止** の状態で作成されます。自分で開始するか、スターター会社の開始オプションに従って開始してください。
- リクエストボディの上限は 8 MiB です。

## 引き継がれないもの

インポートでは次のものは再現されません。インポート後に確認してください。

- クローズ済みのイニシアチブ。履歴なのでエクスポートされません。クローズしていないイニシアチブは、その目標と予算とともに引き継がれます。
- 進捗と支出。

## 引き継ぎ方が異なるもの

- 有効なスクワッドの目標は**下書き**として引き継がれます。目標画面から有効化してください。インポートは承認しません。
- 取り消された常時承認ポリシーは**取り消し済み**のまま引き継がれ、何も承認しません。
- アーカイブされたスクワッドは**アーカイブ済み**として引き継がれます。メンバーとルーチンは再有効化されず、ルーチンは一時停止のままです。
- イニシアチブは、パイプラインの名前、ステージ、タイトルで照合されます。裏付けの課題は作成されますが、引き継ぎも起動もされません。

## 制限

- エクスポートとインポートのエンドポイントは、`GET /api/office/export` と `POST /api/office/import` です。

<Callout type="warning">
インポートは、指定したランタイム上で動作するエージェントを作成することがあります。ドライランの計画を確認し、そのランタイムが意図したマシンのものかを確かめてください。
</Callout>
