Multica bekerja dengan 31 alat pengkodean AI. Multica tidak menggantikan alat yang Anda gunakan: sebuah runtime menjalankan tool yang sudah terinstal dan sudah masuk di komputer tersebut, lalu menulis progres dan hasil kembali ke issue. Jika Anda sudah menggunakan salah satu tool ini, Anda biasanya dapat tetap memakainya, dan agent yang berbeda dalam satu workspace dapat menggunakan tool yang berbeda. Jika Anda belum memilih, pertimbangkan empat hal:

- apakah sudah terinstal di komputer tersebut;
- model mana yang dapat digunakan akun Anda;
- apakah Multica perlu mengonfigurasi MCP untuknya;
- skill mana yang ingin digunakan ulang oleh tim.

Langkah instalasi ada di [Instal alat pengkodean AI](/install-agent-runtime).

## Menghubungkan sebuah tool

Setiap tool pada tabel terhubung dengan cara yang sama: daemon Multica di sebuah komputer mencari command setiap tool di `PATH` dan mendaftarkan satu runtime untuk setiap tool yang ditemukan. Eksekusi berjalan di komputer itu, dengan login dan subscription milik tool itu sendiri; Multica tidak menyertakan tool tersebut maupun memproksi panggilan modelnya.

1. Instal tool dan masuk ke dalamnya, sesuai yang dijelaskan dokumentasinya sendiri.
2. Di komputer yang sama, buka [Multica Desktop](/desktop-app), yang menghubungkan komputer secara otomatis, atau instal CLI dan jalankan daemon:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.sh | bash
   multica setup
   ```

   Di Windows, gunakan `irm https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.ps1 | iex` untuk baris pertama. Instance hosting mandiri menggunakan command di [Panduan cepat hosting mandiri](/self-host-quickstart).
3. Pastikan tool tersebut muncul sebagai runtime di bawah komputer itu pada halaman **Runtimes**, atau dengan `multica runtime list`. Setelah menginstal tool lain, jalankan `multica daemon restart` atau buka ulang Desktop.
4. [Buat agent](/agents-create) pada runtime tersebut dan tugaskan sebuah issue kepadanya.

Jika tool terinstal di lokasi yang tidak dijangkau `PATH` daemon, arahkan `MULTICA_<PREFIX>_PATH` ke sana; lihat [Variabel lingkungan](/environment-variables#konfigurasi-daemon). Satu komputer dapat menjalankan beberapa tool, dan sebuah workspace dapat memadukan beberapa komputer, sehingga tim dapat menjalankan Claude Code di satu mesin dan Codex atau Kimi di mesin lain dari board yang sama.

## Sumber model

Saat Anda membuat sebuah agent, daftar model berasal dari runtime yang bersangkutan. Beberapa tool menampilkan sekumpulan nama model yang tetap; yang lain mengembalikan model yang tersedia berdasarkan konfigurasi lokal, akun yang masuk, dan hak subscription.

Jika Anda tidak memilih sebuah model, Multica menggunakan default milik tool itu sendiri. Jika daftarnya kosong, pastikan runtime-nya online dan tool-nya sudah masuk, lalu segarkan daftar model.

Untuk Kiro CLI, pemilih **Thinking** pada pembuatan agent dan pengaturan menampilkan level effort yang diiklankan untuk model yang dipilih. Pilihan ini berlaku untuk sesi baru dan sesi yang dilanjutkan. Biarkan tidak diatur untuk memakai pengaturan effort milik Kiro sendiri. Model atau versi CLI yang tidak mengembalikan opsi effort membuat pemilih tetap tersembunyi.

Pemilih Devin menampilkan pilihan model yang diiklankan oleh sesi ACP-nya. Pilih ID model kanonis, nama model sesi yang tidak ambigu atau slug/alias family katalog (seperti `opus`), atau biarkan model kosong untuk default CLI. Alias family yang membutuhkan `devin models list` masih bisa memerlukan login CLI yang tersimpan; jika resolusi alias gagal, pilih ID model dari pemilih. Multica mengonfirmasi model sesi yang sebenarnya sebelum mengirim prompt; fallback ke family lain ditolak. Nama yang ambigu, nama parsial sembarang, atau varian yang tidak tersedia memerlukan ID kanonis, bukan tebakan. Penggunaan diatribusikan ke model yang dilaporkan, bukan ke flag peluncuran. Penggunaan Adaptive tetap berada di bawah ID Adaptive routing yang dilaporkan, bukan model dasar hasil inferensi.

Devin membaca `WINDSURF_API_KEY` bila diatur, jika tidak maka login yang disimpan oleh `devin auth login`; metode auth ACP yang tidak dikenal tidak memblokir login tersimpan tersebut. Penemuan model menggunakan kredensial pengguna daemon: key yang hanya diatur di environment kustom agent tidak tersedia bagi pemilih model runtime. Daftar model sesi yang kosong akan meminta Anda memeriksa kredensial tersebut dan allowlist model tim Anda. Multica mempertahankan mode sesi Devin yang dikonfigurasi alih-alih menaikkan izin. Jika defaultnya `plan`, beralihlah ke mode pengeditan di Devin sebelum mengirim pekerjaan yang harus mengubah file.

QwenPaw, MiniMax Code, dan ZeroClaw adalah pengecualian: ketiganya tidak menerima model yang dipilih dari Multica, sehingga pemilihnya tidak aktif dan menampilkan "Managed by runtime". Pilih model di konfigurasi tool itu sendiri. Daftar model yang kosong untuk tool ini memang wajar dan bukan tanda bahwa runtime-nya offline.

Untuk Antigravity, gunakan pemilih model untuk memilih varian reasoning persis yang ditampilkan oleh `agy models`, termasuk sufiks apa pun. Multica tidak memiliki pengaturan **Thinking** terpisah untuk Antigravity. Jika Anda meneruskan `--effort` di argumen kustom, Antigravity memeriksa apakah itu dapat dikombinasikan dengan model yang dipilih.

DeepSeek Harness menampilkan katalog modelnya dari runtime itu sendiri (`dsh --profile multica --list-models`). ID model-nya menggunakan bentuk `provider/model` (misalnya `deepseek-official/deepseek-chat`), jadi pilih id lengkapnya dari daftar tersebut.

<Callout type="info">
Nama model tidak dibagikan antar-tool. Setelah beralih alat pengkodean AI, nilai model sebelumnya tidak valid di tool yang baru dan perlu dipilih ulang.
</Callout>

## Resumpsi sesi

Tool yang ditandai ✓ dapat melanjutkan sesi yang sudah ada pada eksekusi selanjutnya, dengan syarat sesi aslinya masih ada dan eksekusi tersebut dijalankan oleh sebuah runtime yang dapat menjangkaunya. MiniMax Code 0.1.2 tidak mengiklankan kemampuan memuat sesi lewat ACP, sehingga Multica memulai sesi MCode baru untuk eksekusi selanjutnya.

Multica menyimpan identifier sesi yang dikembalikan tool tersebut. Saat pekerjaan berikutnya berlanjut pada issue yang sama, runtime mencoba melanjutkan sesi itu; jika tidak dapat, runtime membuat sesi baru dan melanjutkan. Pi menyimpan path file sesi lokal, sehingga lebih bergantung pada komputer dan file aslinya.

Aturan percobaan ulang dan resumpsi sesi ada di [Eksekusi](/tasks#percobaan-ulang-manual).

## Konfigurasi MCP

Amp, Factory Droid, Antigravity, GitHub Copilot CLI, DevEco Code, Muse Code, dan ZeroClaw belum membaca konfigurasi MCP pada sebuah agent, sehingga field tersebut tidak ditampilkan saat membuat agent untuk tool-tool itu.

Pengiriman MCP terkelola untuk Pi membutuhkan Pi 0.99.0 atau lebih baru. Versi Pi yang lebih lama tetap menjalankan agent yang tidak memiliki konfigurasi MCP.

<Callout type="warning">
Perintah, argumen, dan environment variable server MCP disimpan di server bersama konfigurasi agent. Jangan menuliskan kredensial lokal yang tidak perlu Anda bagikan ke dalam konfigurasi tersebut.
</Callout>

Server yang sudah dikonfigurasi di mesin runtime digabungkan dengan konfigurasi agent di mesin tersebut; lihat [Konfigurasi MCP lokal](/daemon-runtimes#local-mcp).

## Injeksi skill

Sebelum sebuah eksekusi dimulai, Multica menulis skill yang terikat pada agent tersebut ke jalur-jalur pada tabel di atas, sehingga setiap tool menemukannya lewat mekanisme bawaannya sendiri.

Skill yang sudah ada di repositori tidak pernah ditimpa. Pada tabrakan nama, Multica menggunakan nama direktori berbeda untuk salinan yang diinjeksikan; setelah eksekusi selesai, Multica hanya membersihkan file yang dibuatnya sendiri.

Codex, Hermes, dan OpenClaw ditangani sedikit berbeda:

- Codex menggunakan `CODEX_HOME` per-eksekusi, sehingga skill tidak pernah ditulis ke direktori Codex tingkat sistem.
- Hermes menggunakan `HERMES_HOME` per-eksekusi. Konfigurasi lokal yang sudah ada masih dapat dibaca, tetapi skill yang terikat dan data sesi diisolasi per eksekusi. Isolasi ini hanya berlaku saat agent memiliki skill yang terikat; eksekusi tanpa skill yang terikat menggunakan home Hermes asli komputer tersebut.
- OpenClaw menggunakan `skills/` di bawah direktori kerja eksekusi saat ini, dan konfigurasi per-eksekusinya menetapkan direktori tersebut sebagai workspace.

Untuk membuat dan mengikat skill, lihat [Skills](/skills).

## ZCode

ZCode menggunakan protokol `app-server` NDJSON native miliknya untuk pembuatan sesi, resumpsi, pembatalan, penemuan model, level thinking, dan MCP. Task berjalan dalam mode yolo tanpa persetujuan tool interaktif. Pilihan reasoning berasal dari katalog model runtime; membuat agent mempertahankan level default model yang dipilih.

Di macOS, daemon juga menemukan CLI bawaan ZCode Desktop; Node.js harus terinstal. Di Linux, daemon menemukan ZCode Desktop dan menjalankan CLI bawaannya tanpa membuka jendela desktop; tidak diperlukan instalasi Node.js terpisah maupun konfigurasi environment manual. Koneksi API-key/Coding Plan desktop yang diaktifkan diimpor ke konfigurasi provider sementara yang privat bagi proses, yang dihapus saat keluar tanpa mengubah file aslinya. Token identitas Start Plan bukan API key dan jalur autentikasi akun ini tidak didukung. Konfigurasikan koneksi API yang berfungsi di ZCode Desktop jika penemuan tidak mengembalikan model.
