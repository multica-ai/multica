<Callout type="info">
Before an agent can execute, the computer that runs it needs at least one [supported AI coding tool](/providers) installed and signed in — for example Claude Code, Codex, or Cursor. Multica does not ship these tools.
</Callout>

<Steps>
<Step>

## Sign in and open your workspace [#1-sign-in-and-open-your-workspace]

Sign in on the web ([multica.ai](https://multica.ai)) or with [Multica Desktop](https://multica.ai/download). Email verification codes and Google are both supported. If you sign in with Desktop, the next step can connect this computer automatically; on the web, you connect it from the command line.

</Step>
<Step>

## Connect a computer [#2-connect-a-computer]

Agents execute work on the computers you connect. Open **Runtimes** under **AI Team** in the sidebar:

- **With Desktop**: Desktop automatically registers this computer as a runtime and detects the installed AI coding tools. For a tool you just installed, click **Refresh** to detect it again.
- **With Web, or to add another computer**: click **Add** in the top right, choose **Other machine or server**, then run the two commands from the dialog in a terminal on the target computer:

<Tabs groupId="os" persist items={["macOS / Linux", "Windows"]}>
<Tab value="macOS / Linux">

```bash
curl -fsSL https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.sh | bash
multica setup
```

</Tab>
<Tab value="Windows">

```powershell
irm https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.ps1 | iex
multica setup
```

</Tab>
</Tabs>

`multica setup` opens a browser to complete sign-in, then leaves the daemon running in the background. Once the daemon is online, the dialog usually detects the computer within a minute.

**Success check**: an online computer appears in the runtime list.

![Add a computer dialog: two commands and the waiting-for-detection notice](/images/docs/quickstart-add-computer.webp)

<Callout type="info">
The connection commands differ slightly on self-hosted instances — see the [Self-host quickstart](/self-host-quickstart).
</Callout>

</Step>
<Step>

## Create an agent [#3-create-an-agent]

Open **Agents** under **AI Team** in the sidebar and click **New agent**. Choose an AI coding tool on the computer you just connected, enter a name, and click **Create agent**. The runtime and the name are the only required fields.

If you would rather not write the configuration yourself, click **Let AI write it** on the configuration page: the Agent Builder asks a few questions and fills it in. This needs the selected runtime to be online. Everything else can be refined later — see [Create and configure an agent](/agents-create).

**Success check**: your agent appears in the agent list and shows as online.

</Step>
<Step>

## Hand it your first issue [#4-hand-it-your-first-issue]

Click **New Issue** at the top of the sidebar (or press `C`). In the default agent mode:

1. Under **Created by**, select the agent you just created.
2. Describe the work in a sentence or two, for example "Explain how this workspace can be used."
3. Submit. Multica creates the issue, sets the agent as the assignee, and starts executing immediately.

![New issue dialog in agent mode: Created by set to Multica Assistant](/images/docs/quickstart-new-issue.webp)

</Step>
<Step>

## Watch progress and results [#5-watch-progress-and-results]

After submitting, open the issue: the execution log shows the run status, and the agent's progress and replies appear in the timeline.

**Success check**: the execution log status changes to Completed and the agent's reply appears in the timeline. To see the full transcript, click **View transcript**.

![The agent's reply in the issue and a completed execution log](/images/docs/quickstart-run-result.webp)

</Step>
</Steps>

## Common problems

| Symptom | Check first |
|---|---|
| No runtime found | Confirm the AI coding tool is installed and runs in a terminal. On Desktop, click **Refresh**; on the CLI path, rerun `multica setup`. |
| Runtime shows offline | Keep Desktop open; on the CLI path, run `multica daemon status`, and `multica daemon start` if it is not running. |
| Issue stays queued | Confirm the runtime the agent uses is online. When a runtime hits its concurrency limit, new runs keep queueing. |

For more cases, see [Troubleshooting](/troubleshooting).
