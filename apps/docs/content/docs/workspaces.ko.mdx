워크스페이스는 Multica의 최상위 경계입니다. 멤버, 태스크, 프로젝트, 에이전트, 스킬, 실행 기록은 모두 특정 워크스페이스에 속하며 서로 완전히 격리됩니다.

## 워크스페이스의 구성

| 범주 | 내용 |
|---|---|
| **작업** | 태스크, 프로젝트, 댓글, 첨부 파일, 실행 기록 |
| **팀** | 멤버, 역할, 초대 |
| **에이전트** | 에이전트 설정, 스킬, 런타임, 자동화 |
| **공유 설정** | 컨텍스트, 라벨, 사용자 지정 속성, 연동 |

**컨텍스트**는 워크스페이스의 모든 에이전트에게 제공됩니다. 팀 배경, 제품 규칙, 장기적으로 적용되는 요구 사항을 작성하기에 적합합니다. 일회성 작업 요구 사항은 해당 태스크에 작성하세요.

## 워크스페이스 만들기

만들 때 세 항목을 입력합니다.

- **이름**: 멤버에게 표시되며 나중에 변경할 수 있습니다.
- **워크스페이스 URL**: 주소에 들어가는 slug입니다. 예를 들어 `multica.ai/my-team`의 `my-team`입니다. 소문자, 숫자, 하이픈만 사용할 수 있고 기존 워크스페이스 또는 예약된 주소와 중복될 수 없으며 만든 뒤에는 변경할 수 없습니다.
- **태스크 접두사**: 워크스페이스 URL에서 자동으로 채워지며 만들기 전에 바꿀 수 있습니다. 접두사가 `MUL`이면 태스크 번호는 `MUL-1`, `MUL-2`처럼 표시되며 워크스페이스 안에서 독립적으로 증가합니다. 대문자와 숫자만, 최대 10자이며 나중에 설정에서도 바꿀 수 있습니다.

만든 사람은 자동으로 `owner`가 됩니다.

## 설정 변경

`owner`와 `admin`은 이름, 아이콘, 설명, 컨텍스트, 태스크 접두사를 변경할 수 있습니다. `member`는 보기만 할 수 있습니다.

![워크스페이스 설정: 이름, 컨텍스트, slug, 태스크 접두사, 위험 구역](/images/docs/workspace-settings.webp)

<Callout type="warning">
태스크 접두사를 변경하면 모든 태스크가 즉시 새 번호를 사용합니다(`MUL-5`가 `NEW-5`로 변경). 하지만 PR, 브랜치 이름, 채팅 기록의 이전 번호는 업데이트되지 않습니다.
</Callout>

## 전환 및 나가기

하나의 계정으로 여러 워크스페이스에 참여할 수 있습니다. 전환하면 현재 보는 범위만 바뀌며 데이터는 이동하지 않습니다.

워크스페이스를 나가면 다시 참여하려면 초대를 새로 수락해야 합니다. 나갈 때는 본인이 소유한 런타임도 비활성화되고, 해당 런타임에 연결된 에이전트는 보관 처리되며, 완료되지 않은 작업은 취소됩니다.

마지막 `owner`는 워크스페이스를 나갈 수 없습니다. 먼저 다른 멤버를 `owner`로 승격해야 합니다.

## 워크스페이스 삭제

워크스페이스는 `owner`만 삭제할 수 있습니다. 삭제하면 그 안의 모든 작업, 멤버, 에이전트 설정, 실행 기록이 영구적으로 제거되며 복구할 수 없습니다. 잠시 참여하지 않으려는 경우에는 삭제하지 말고 워크스페이스를 나가세요.
