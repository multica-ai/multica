收件箱彙總與你有關的工作動態，提醒你哪裡出現了需要關注的變化。它不是完整的活動日誌，前因後果仍在對應的任務裡。

## 收件箱的內容

常見通知包括：

- 任務分配給你，或從你名下移走；
- 你訂閱的任務出現新評論，或負責人、狀態、優先順序和日期發生變化；
- 有人在任務描述或評論中 @你；
- 你建立的任務或評論收到表情回應；
- 你訂閱的任務中，AI 代理執行失敗；
- [透過 AI 代理建立任務](/issues#透過 AI 代理建立)的操作完成或失敗；
- 你訂閱的自動化建立了新任務，或自動化因連續失敗被暫停。

自己的操作不會通知自己。同一任務的多條通知會合併成一項，開啟後可檢視這條任務最近的變化。

## 自動訂閱的來源

以下參與者會自動訂閱任務：

- 任務的建立者；
- 新的負責人；
- 發表評論的人；
- 在任務描述中被新增 @提及的人；
- 自動化中預先配置的訂閱成員。

負責人變更不會取消原有訂閱。可以在任務頁面隨時訂閱或取消；取消後普通更新不再進入收件箱，直接 @你仍會單獨通知。

<Callout type="info">
子任務的狀態發生變化時，也會通知父任務的訂閱者。子任務的評論、優先順序和日期變化不會向父任務冒泡。
</Callout>

## AI 代理不使用收件箱

收件箱只面向工作區成員。即使 AI 代理是負責人或訂閱者，它也不會讀取收件箱通知。

在評論中 @ AI 代理、把任務分配給 AI 代理或觸發自動化，都會直接建立一次執行，不會給 AI 代理留通知。`@all` 也只通知成員。

## 處理通知

選擇一條通知會把它標為已讀。處理完後可以歸檔，歸檔不會修改或刪除對應的任務。

<InboxDemo />

任務進入交回給人的狀態後，它的"執行失敗"通知會自動歸檔。這類狀態包括 `in_review`、`started` 分類下的自定義狀態，以及 `done`、`closed` 分類下的任一狀態。`blocked` 例外：它同樣交回給人，但工作還卡著，之前的失敗記錄還要看。

右鍵點選一條通知，可以使用**標為已讀** / **標為未讀**和**歸檔**（在"已歸檔"檢視中是**取消歸檔**）。標為未讀表達的是"我看過了，但還沒處理完"：該通知重新變為未讀，未讀數也會回升；即使它還開著也保持未讀，之後再開啟一次才會照常標為已讀。已歸檔的通知會保留已讀狀態，因此恢復時會原樣回來。

收件箱選單還可以：

- 全部標為已讀；
- 歸檔全部或全部已讀；
- 歸檔狀態為 `done` 或 `cancelled` 的任務通知；
- 開啟"已歸檔"並恢復某條通知。

從收件箱底部開啟**已歸檔**，向下捲動可繼續載入更早的通知。篩選覆蓋全部歸檔記錄，包括尚未載入的記錄。

## 調整通知型別

開啟**設定 → 通知**，可以分別開關：

- 分配；
- 狀態變更；
- 評論；
- 提及；
- 優先順序與日期；
- AI 代理活動。

關閉某一類後，相關變化仍然儲存在任務中，只是不再建立收件箱通知。表情回應、快速建立結果和自動化暫停等少數型別不受這六組控制，始終投遞。系統通知和瀏覽器通知控制的是桌面橫幅，不會改變收件箱本身。

### 將通知傳送到 Google Chat

在 **設定 → 通知 → 應用程式外通知** 中，可以新增 Google Chat 空間的傳入 Webhook。請按 **Google Chat 空間 → 應用程式和整合 → Webhook → 新增 Webhook → 複製 URL** 操作，然後將 URL 貼到 Multica。

Multica 會在儲存 Webhook 前傳送確認訊息。儲存的 URL 會在設定和 API 回應中隱藏敏感部分；新的收件箱條目會附上對應任務的連結。
