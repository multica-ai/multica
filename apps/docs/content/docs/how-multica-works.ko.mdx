이슈를 에이전트에게 할당하면 Multica가 실행 태스크를 만들고, 연결된 컴퓨터의 런타임이 이를 가져갑니다. 런타임은 로컬 AI 코딩 도구를 호출하고 진행 상황과 결과를 원래 이슈에 다시 기록합니다.

## 한 번의 실행이 이루어지는 전체 과정

![한 번의 실행 흐름도: 왼쪽 Multica 영역은 기록과 스케줄링을 담당하며 이슈가 태스크 생성을 트리거합니다. 오른쪽 '내 컴퓨터' 영역에서는 데몬이 태스크를 가져와 AI 코딩 도구를 시작하고 작업 디렉터리를 읽고 씁니다. 진행 메시지는 실행 로그로 실시간 전송되고, 최종 결과는 데몬이 이슈에 다시 기록합니다.](/images/docs/how-a-run-works.png)

1. **이슈가 컨텍스트를 제공합니다.** 이슈에는 작업 설명, 논의, 담당자가 저장됩니다. 에이전트에게 할당되면 시스템은 해당 에이전트의 지시문, 모델, 스킬, 런타임 설정을 사용합니다.
2. **Multica가 실행 태스크를 만듭니다.** 실행 태스크가 큐에 들어갑니다. 온라인 런타임이 없으면 큐에서 기다립니다.
3. **런타임이 태스크를 가져갑니다.** 연결된 컴퓨터의 온라인 런타임이 태스크를 가져와 에이전트에 설정된 AI 코딩 도구를 호출합니다.
4. **AI 코딩 도구가 로컬에서 실행됩니다.** 도구는 작업 디렉터리를 읽고 명령을 실행해 결과를 만듭니다.
5. **결과가 이슈에 기록됩니다.** 진행 상황, 댓글, 결과가 이슈 타임라인과 실행 로그에 표시됩니다.

이슈, 에이전트, 실행 태스크, 런타임의 전체 목록과 관계는 [핵심 개념](/concepts)을 참고하세요.

## 데이터와 실행의 경계

| Multica | 연결된 컴퓨터 |
|---|---|
| 워크스페이스, 이슈, 댓글, 상태 | AI 코딩 도구와 그 자격 증명 |
| 에이전트 설정과 스킬 | 코드 디렉터리와 로컬 파일 |
| 실행 태스크의 상태, 실행 기록, 결과 | 실제 파일 변경과 명령 실행 |

이 경계는 Multica Cloud와 자체 호스팅 환경에서 동일합니다.

<Callout type="warning">
한 가지 예외가 있습니다. 에이전트의 `custom_env`에 저장한 내용은 Multica 서버에 보관되며 실행할 때 런타임으로 전달됩니다. 컴퓨터 밖으로 나가면 안 되는 secret은 `custom_env`에 넣지 마세요.
</Callout>

## 에이전트를 트리거하는 방법

에이전트는 스스로 작업을 시작하지 않습니다. 모든 실행은 이슈 할당, 댓글에서 에이전트 @멘션, 직접 대화, 자동화 중 하나의 명시적인 동작으로 트리거됩니다. 네 가지 방법의 선택 기준과 공통 규칙은 [에이전트가 작업을 시작하게 하기](/triggering-agents)를 참고하세요.

## 실행 종료와 이슈 완료

실행 로그에 "완료됨"이 표시되는 것은 이번 실행이 끝났다는 뜻일 뿐입니다. 이슈에서는 계속 논의하거나 요구 사항을 추가하고 에이전트를 다시 트리거할 수 있습니다. 이슈의 완료 여부는 실제 작업 진행 상황과 이슈 상태를 기준으로 판단합니다.
