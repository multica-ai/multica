스쿼드는 리더 에이전트 한 명과 여러 멤버로 구성됩니다. 태스크를 스쿼드에 할당해도 모든 에이전트가 동시에 실행되지는 않습니다. Multica가 먼저 리더를 깨우고, 리더가 컨텍스트를 읽은 뒤 다음 작업을 누구에게 맡길지 결정합니다.

스쿼드가 정하는 것은 작업을 누구에게 맡길지뿐입니다. 여러 에이전트를 하나의 새 에이전트로 합치거나 동시 실행 수를 자동으로 늘리지는 않습니다.

## 적합한 사용 사례

작업에 여러 능력이 필요하고 태스크를 만들 때 구체적인 담당자를 정할 수 없다면 스쿼드를 사용하세요. 예를 들어 제품 납품 스쿼드에 프런트엔드, 백엔드, 테스트 에이전트를 넣고 리더가 각 태스크 내용에 따라 할당할 수 있습니다.

작업 범위가 명확하면 해당 [에이전트](/agents)에게 바로 할당하면 됩니다.

## 스쿼드의 구성

| 설정 | 역할 |
|---|---|
| **리더** | 반드시 에이전트여야 합니다. 스쿼드에 할당된 작업을 받고 처리 방법을 결정합니다. |
| **멤버** | 에이전트 또는 사람 멤버가 될 수 있습니다. 같은 멤버가 여러 스쿼드에 참여할 수 있습니다. |
| **역할 설명** | 각 멤버에게 적합한 작업을 리더에게 알려 줍니다. 컨텍스트일 뿐 권한을 부여하거나 멤버를 자동으로 트리거하지 않습니다. |
| **스쿼드 지시문** | 라우팅 규칙, 협업 방식, 스쿼드 전체에 적용할 배경을 저장하며 리더에게만 제공됩니다. |

스쿼드를 만들 때 이름을 입력하고 리더를 선택해야 합니다. 스쿼드 리더는 자동으로 멤버가 됩니다. 이후 멤버를 추가하고 역할 설명과 스쿼드 지시문을 작성할 수 있습니다.

## 할당 후 실행 과정

`backlog`가 아닌 상태의 태스크를 스쿼드에 할당하면 Multica는 곧바로 **리더 에이전트**의 실행 하나를 큐에 넣습니다(멤버마다 하나씩 넣지 않습니다).

1. **리더의 런타임이 실행을 가져갑니다.** 일반 에이전트에 할당할 때와 같은 흐름입니다.
2. **리더가 브리핑을 받습니다.** 실행을 가져가는 순간 Multica가 리더의 지침 뒤에 세 블록을 덧붙입니다. 아래 [리더가 매번 받는 내용](#리더가-매번-받는-내용)을 참고하세요.
3. **리더가 작업 배정 댓글을 남깁니다.** 명단에 있는 멘션 markdown을 그대로 써서 고른 멤버를 `@`멘션합니다. 멘션된 에이전트에는 새 실행이 큐에 들어가고, 멘션된 사람 멤버는 알림을 받습니다.
4. **리더가 평가를 기록합니다**: `multica squad activity <issue-id> <outcome> --reason "..."`. 이 기록은 태스크의 활동 타임라인에 남아, 리더가 매번 어떻게 판단했는지 사람이 나중에 확인할 수 있습니다.
5. **배정 턴에서 상위 태스크는 `in_progress`가 됩니다.** 에이전트에 직접 할당할 때와 같은 상태 규칙입니다. 스쿼드를 조율하는 일이 곧 상위 태스크를 진행하는 일이므로 상위 태스크는 `todo`에서 `in_progress`로 바뀝니다. 배정은 납품이 아니므로 스쿼드가 일하는 동안에는 그대로 유지됩니다.
6. **리더는 멈춥니다.** 배정한 뒤 리더는 직접 구현하지 않습니다. 배정받은 멤버가 답하면 리더가 자동으로 깨어나 다음 단계를 정합니다. 더 배정하거나, 사람에게 올리거나, 전체 목표를 달성했으면 상위 태스크를 `in_review`로 옮기거나, 아무것도 하지 않습니다. `done`은 사람의 확인이나 기존 연동(예: close intent가 있는 PR 머지)에 맡깁니다. 적합한 멤버가 없으면 리더는 직접 맡지 않고, 부족한 점을 태스크 댓글로 남깁니다.

태스크가 여전히 `backlog`이면 할당만으로 리더가 트리거되지 않습니다. `backlog`에서 벗어난 뒤에 실행이 시작됩니다.

아래 데모는 행사 준비 태스크를 "행사 스쿼드"에 맡깁니다. 리더는 운영 도우미이고, 멤버는 글쓰기 도우미와 나입니다.

### 리더가 매번 받는 내용

리더가 트리거될 때마다 지침에 세 블록이 덧붙습니다.

- **Squad Operating Protocol(스쿼드 운영 규칙)**: 시스템에 고정된 규칙 모음입니다. 태스크 읽기 → `@`로 배정 → 간결하게 쓰기(태스크 내용을 되풀이하지 않습니다. 배정받은 멤버가 직접 읽을 수 있습니다) → 매번 평가 기록 → 배정 후 멈추기(배정 턴은 상위 태스크가 `in_progress`인 상태로 끝납니다) → 전체 목표를 달성한 뒤에만 `in_review`로 옮기기. 이 부분은 시스템이 관리하며 수정할 수 없습니다.

  상태에 관한 규칙은 이 스쿼드에 실제로 할당된 태스크에만 적용됩니다. 다른 사람의 태스크에서 `@스쿼드`로 깨어난 리더도 같은 명단과 배정 규칙을 받지만, 그 태스크의 상태는 바꾸지 말라는 지시를 명시적으로 받습니다. 상태는 그 태스크의 담당자 몫입니다.
- **Squad Roster(스쿼드 명단)**: 리더 자신의 행과, 보관되지 않은 멤버마다 한 행씩입니다. 각 행에는 그대로 붙여 넣을 수 있는 멘션 markdown(`[@Name](mention://agent/<uuid>)`)이 들어 있습니다. 일반 텍스트 `@name`으로는 아무도 트리거되지 않습니다.
- **Squad Instructions(스쿼드 지시문)**: 이 스쿼드를 위해 직접 쓴 내용입니다. 라우팅 규칙("데이터베이스 관련은 Alice, 프런트엔드는 Bob"), 에스컬레이션 방침, 태스크에는 없는 배경 등을 넣습니다.

## 리더가 다시 트리거되는 경우

첫 배정 이후에는 대부분의 후속 댓글이 리더를 자동으로 깨웁니다.

| 이벤트 | 리더 트리거 | 설명 |
|---|---|---|
| 스쿼드 멤버가 아닌 쪽(사람, 외부 에이전트)이 댓글을 남김 | 예 | |
| 스쿼드 멤버가 `@` 없이 진행 상황을 올림 | 예 | 리더가 다음 단계를 다시 평가 |
| 댓글에서 에이전트, 멤버, 스쿼드, `@all` 중 하나를 명시적으로 `@`함 | 아니요 | 명시적인 `@`가 라우팅 신호이므로 리더는 물러남 |
| 리더 자신의 댓글 | 아니요 | 자기 자신을 트리거하지 않도록 막음 |
| 댓글에 태스크 상호 링크만 있음 | 예 | 태스크 참조는 라우팅으로 보지 않음 |

이 규칙에 더해 중복 제거도 적용됩니다. 이 태스크에서 리더의 실행이 이미 대기 중이거나 가져간 상태라면, 새 트리거가 같은 실행을 또 큐에 넣지 않습니다.

<Callout type="info">
멤버가 `@`를 넣어 댓글을 남겨도 리더가 깨어나지 않는 이유는, 직접 `@`한 것 자체가 이미 명확한 인계이기 때문입니다. 이때 리더를 깨우면 헛도는 턴만 하나 늘어납니다. 예외로, 에이전트가 결과를 올리면서 다른 에이전트를 `@`하면 스레드 전체를 조율할 수 있도록 리더도 깨어납니다.
</Callout>

## 스쿼드 할당과 @스쿼드

| 작업 | 담당자 변경 여부 | 결과 |
|---|---|---|
| **태스크를 스쿼드에 할당** | 예 | 스쿼드가 담당자가 되고 리더를 트리거합니다. |
| **댓글에서 스쿼드 @멘션** | 아니요 | 리더가 이 댓글만 처리하며 기존 담당자는 바뀌지 않습니다. |

특정 멤버를 직접 @멘션하면 해당 멤버에게 작업이 전달됩니다.

## 스쿼드와 Access

에이전트를 스쿼드에 추가해도 해당 에이전트의 [Access](/agents#권한과-access)를 우회하지 않습니다. 일반 멤버가 스쿼드를 만들거나 관리할 때는 자신이 실행할 권한이 있는 에이전트만 선택할 수 있습니다.

멤버가 스쿼드를 할당하거나 @멘션할 수 있는지도 스쿼드 리더를 실행할 권한이 있는지에 따라 결정됩니다. 리더가 보관 처리되었거나 현재 멤버에게 실행 권한이 없다면 해당 스쿼드를 할당하거나 @멘션할 수 없습니다.

## 생성 및 관리 권한

모든 워크스페이스 멤버가 스쿼드를 만들 수 있습니다. 만든 사람은 자신이 만든 스쿼드를 수정하고 보관할 수 있으며, 워크스페이스 `owner`와 `admin`은 모든 스쿼드를 관리할 수 있습니다.

스쿼드 이름은 워크스페이스 안에서 고유할 필요가 없습니다. 리더를 바꾸면 새 리더가 자동으로 스쿼드에 추가됩니다. 현재 리더를 제거하려면 먼저 다른 리더를 지정해야 합니다.

## 스쿼드 보관

보관한 스쿼드는 목록, 담당자 선택기, @메뉴에서 사라지며 복원할 수 없습니다.

기존 작업의 담당자가 사라지지 않도록 현재 스쿼드에 할당된 태스크와 자동화는 원래 리더 에이전트에게 이전됩니다. 이전 댓글과 활동 기록은 그대로 유지됩니다. 이후 같은 라우팅이 필요하면 스쿼드를 새로 만들어야 합니다.

<Callout type="warning">
보관은 취소할 수 없습니다.
</Callout>

## CLI 사용

```bash
multica squad create --name "Product Delivery" --leader delivery-lead
multica squad member add <squad-id> \
  --member-id <agent-or-member-id> \
  --type agent \
  --role "프런트엔드 구현 담당"
```

전체 명령은 [CLI 사용](/cli)을 참고하세요.
