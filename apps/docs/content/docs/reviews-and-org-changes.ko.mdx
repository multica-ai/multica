리뷰와 조직 변경은 루프를 닫습니다. **스코어카드**는 에이전트나 스쿼드의 성과를 측정합니다. **리뷰**는 스코어카드를 읽고 변경을 권고합니다. **조직 변경**은 당신이 승인한 권고를 적용합니다. 그 변경은 **시험 기간**에 들어가며, 플랫폼은 변경이 도움이 되었는지 기록합니다.

## 스코어카드

야간 작업이 각 에이전트, 각 스쿼드, 회사 전체에 대해 스코어카드를 계산합니다. 대상은 마지막으로 완료된 주 또는 월입니다. 해당 기간의 실행 수가 너무 적은 스코어카드는 `insufficient`(부족)로 표시되며, 절대 리뷰되지 않습니다.

지표는 다음과 같습니다.

- 실행 수와 성공률. 실패는 원인별로 나뉩니다. 런타임이 오프라인이었던 실패는 에이전트의 감점이 되지 않습니다.
- 완료된 이슈 수, 첫 시도 성공률(다시 열리지 않고 완료된 비율), 사이클 타임, 완료 이슈당 비용.
- 사람의 개입률. 에이전트가 완료로 표시한 뒤의 사람 댓글이나 편집.
- 제안 채택률, 루틴 준수율, 지식 기여.
- 비서에 대해서는 브리프의 유용성.

일부 수치는 대리 지표입니다. 완료 시각은 이슈가 마지막으로 완료 상태에 들어간 시각입니다. 첫 시도 성공률과 개입률은 완료된 실행 수와 멤버 댓글을 씁니다. 비용은 제공자가 보고한 것만 셉니다. 재오픈 횟수는 이 릴리스부터 기록되는 이슈의 완료 이력에서 셉니다. 그 이전의 재오픈은 알 수 없습니다.

소유자, 관리자, 대상의 리더는 스코어카드를 볼 수 있습니다.

```bash
multica review scorecards --subject-type squad --subject-id <squad-id> --period month
```

## 리뷰

**Governance** 층에 있는 **People & Performance**(인사와 성과) 스쿼드는 리뷰어 에이전트를 가지고 있습니다. 매달 데이터가 충분한 모든 스쿼드와, 스코어카드나 샘플링으로 `below`(미달)로 표시된 모든 에이전트를 리뷰합니다. 각 리뷰에는 평가(`exceeds`(초과), `meets`(충족), `below`(미달), `at_risk`(위험)), 서술, 권고가 있습니다. 리뷰는 자신이 근거로 삼는 스코어카드 수치와 그 증거(이슈, 실행, 문서)를 인용해야 합니다.

리뷰는 도구이지 순위표가 아닙니다. 소유자, 관리자, 대상 스쿼드의 리더가 볼 수 있습니다. 각 지표는 무엇을 측정하는지 드러냅니다.

리뷰어는 JSON 파일로 공개합니다.

```bash
multica review publish --file review.json
multica review list
```

리뷰를 공개하면 권고된 변경 각각이 `org_change` 제안으로 올라옵니다. 근거를 옆에 두고 결정할 수 있습니다. **Governance**의 Reviews 탭은 리뷰를 나열하며, 링크 대신 제안 ID를 보여 줍니다. 브리프의 **People** 섹션은 새 리뷰와 그 권고를 나열합니다.

## 조직 변경

`org_change` 제안에는 여덟 가지 종류가 있습니다.

| 종류 | 바꾸는 대상 | 적용 방식 |
| --- | --- | --- |
| `instruction_change` | 에이전트의 지시문 | 이전 텍스트의 리비전을 먼저 기록한 뒤 에이전트를 갱신 |
| `skill_change` | 에이전트의 스킬 | 스킬을 추가하고 제거 |
| `charter_change` | 스쿼드의 헌장 | 헌장을 갱신하고 리비전을 생성 |
| `autonomy_change` | 스쿼드의 자율성 수준 | 수준을 설정 |
| `hire` | 스쿼드에 에이전트 추가 | 템플릿으로 에이전트를 만들고, 그 스쿼드를 소속 스쿼드로 지정 |
| `retire` | 에이전트 또는 스쿼드 제거 | 보관합니다. 대기 중인 작업은 취소되고, 실행 중인 작업은 끝까지 가며, 지식은 남습니다. |
| `move` | 에이전트의 스쿼드 | 멤버십과 소속 스쿼드를 변경 |
| `merge_squads` | 두 스쿼드 | 멤버와 루틴을 옮기고, 원본 스쿼드를 보관합니다. 헌장 본문은 대화상자에서 당신이 합칩니다. |

조직 변경은 리뷰어, 비서, 해당 변경의 대상 스쿼드 리더, 또는 사람이 제출합니다. 자동 승인되지 않으며, 상시 승인의 대상이 되지도 않습니다. 결정 대화상자는 지시문이나 헌장 변경을 차이로 보여 줍니다.

## 지시문 리비전과 되돌리기

에이전트의 지시문을 갱신할 때마다, 경로와 무관하게 리비전이 기록됩니다. 경로란 앱, CLI, 템플릿, 가져오기, 적용된 조직 변경 중 하나입니다. 리비전에는 텍스트, 출처(`human`, `proposal`, `rollback`), 관련 제안(있는 경우)이 기록됩니다.

에이전트 페이지의 이력에는 리비전이 나열됩니다. 어떤 리비전을 복원하면, 이전 텍스트를 담은 새 리비전이 기록되므로 아무것도 잃지 않습니다.

```bash
curl -H "Authorization: Bearer $MULTICA_TOKEN" -H "X-Workspace-ID: $WORKSPACE_ID" \
  "$MULTICA_API/api/agents/<agent-id>/instruction-revisions"
curl -X POST -H "Authorization: Bearer $MULTICA_TOKEN" -H "X-Workspace-ID: $WORKSPACE_ID" \
  "$MULTICA_API/api/agents/<agent-id>/instruction-revisions/<revision>/restore"
```

리비전 이력은 처음 기록된 변경부터 시작합니다. 그 이전의 변경은 포함되지 않습니다. 빌더 캐리어 에이전트는 추적되지 않습니다.

## 시험 기간

적용된 변경은 **14일의 시험 기간**에 들어갑니다. 기간이 끝나면 리뷰어가 변경 전후의 스코어카드를 비교하고, 다음 결과 중 하나를 기록합니다.

| 결과 | 의미 |
| --- | --- |
| `improved`(개선) | 지표가 바람직한 방향으로 움직였음 |
| `neutral`(중립) | 뚜렷한 변화가 없음 |
| `worse`(악화) | 지표가 바람직하지 않은 방향으로 움직였음. 되돌리기 제안이 올라감. |
| `insufficient`(부족) | 데이터가 부족함. 결과는 보류됨. |

시험 기간은 여덟 종류 모두에 적용됩니다. 되돌리기는 취소할 수 있는 변경에만 가능합니다. `hire`, `retire`, `merge_squads`는 취소할 수 없으므로, 이들에 대해 악화 결과가 나와도 되돌리기 제안은 올라가지 않습니다. 스쿼드의 첫 헌장을 만드는 헌장 변경도 취소할 수 없습니다. 승인하기 전에 이 제약을 고려하세요.

<Callout type="info">
조직 변경 제안은 주의 한도에 포함됩니다. 적용된 각 변경과 각 결과는 [거버넌스 로그](/controls-and-log)에 기록됩니다.
</Callout>
