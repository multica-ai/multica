Resource [proyek](/projects) memberi tahu agent kode apa yang digunakan oleh pekerjaan ini dan di mana harus berjalan. Resource tetap tertaut pada proyek, sehingga tidak perlu menempelkan ulang URL repositori atau path lokal ke setiap tugas.

Saat ini ada dua jenis resource yang didukung:

| Resource | Paling cocok untuk | Tempat eksekusi berjalan |
|---|---|---|
| **Repositori GitHub** | Kode yang dibagikan oleh tim, dengan checkout yang dikelola oleh runtime | Direktori kerja yang dikelola runtime |
| **Direktori lokal** | Checkout yang sudah ada, repositori yang sangat besar, atau saat Anda ingin memeriksa perubahan lokal secara langsung | Folder asli atau worktree terisolasi pada komputer tertentu |

## Bagaimana resource masuk ke sebuah eksekusi

Saat seorang agent mengerjakan tugas di dalam proyek, Multica menambahkan nama proyek, deskripsi proyek, dan daftar resource ke konteks eksekusi tersebut, serta menulis `.multica/project/resources.json` ke dalam direktori kerja.

Daftar repositori yang tertaut pada ruang kerja selalu disertakan dalam konteks eksekusi. Repositori yang tertaut pada proyek secara tambahan menentukan kode dan ref default yang digunakan oleh pekerjaan ini.

Direktori lokal hanya berlaku untuk daemon tempat ia diikat. Saat daemon yang mengeksekusi sebuah eksekusi memiliki direktori lokal yang cocok, agent menggunakannya dalam mode `in_place` atau menggunakan worktree terisolasi darinya dalam mode `worktree`; komputer lain tetap menggunakan repositori GitHub milik proyek atau repositori ruang kerja.

## Menambahkan repositori GitHub

Buka proyek dan klik **Add repository** di **Resources → Repositories**. Cari repositori yang sudah tertaut pada ruang kerja, atau tempelkan URL Git. Repositori ruang kerja dikelola di **Settings → Code**; setelah GitHub terhubung, halaman yang sama menawarkan **Pick from GitHub** untuk mengimpor repositori yang diotorisasi untuk App tersebut.

Menempelkan URL branch GitHub (`https://github.com/owner/repo/tree/branch`) mengisi URL repositori dan branch awal secara terpisah. Nama branch yang di-encode URL akan di-decode; parameter query dan anchor halaman tidak disertakan. Periksa branch awal sebelum menambahkan repositori. Mengubah URL repositori menghapus branch awal sebelumnya kecuali URL baru menentukannya.

Repositori tidak terbatas pada GitHub: URL Git apa pun yang dapat dijangkau oleh runtime berfungsi sebagai resource repositori. Multica yang di-hosting sendiri juga dapat terhubung ke Forgejo, Gitea, atau GitLab yang di-hosting sendiri di bawah **Settings → Code**; lihat [Hosting Git mandiri](/vcs-integration).

Saat membuat proyek, Anda juga dapat memilih repositori langsung di bawah **Repos**. Satu proyek dapat menautkan beberapa repositori GitHub.

`ref` pada sebuah resource mengatur branch, tag, atau commit yang digunakan secara default oleh checkout berikutnya. `default_branch_hint` hanya memberi agent petunjuk branch default dan tidak memaksa perpindahan branch.

Untuk repositori yang dikelola, agent dimulai di direktori kerja task. `multica repo checkout` biasanya membuat subdirektori untuk repositori tersebut dan mencetak path-nya. Jalankan perintah yang memerlukan root repositori dari path itu. Jika proses agent sendiri harus dimulai di root dan Anda mengendalikan komputer runtime, tautkan checkout yang sudah ada sebagai direktori lokal. Baik `in_place` maupun `worktree` memulai agent di root repositori; utamakan `worktree` untuk repositori git agar eksekusi tetap terisolasi dan paralel. Lihat [Bagaimana eksekusi membagikan direktori](#how-runs-share-the-directory).

Jika subdirektori target repositori sudah berisi repositori lain atau sisa file dan checkout melaporkan konflik path, jalankan `multica repo checkout` dari direktori lain di dalam direktori kerja task yang sama. Pertahankan direktori asli sampai Anda memeriksa apakah ada pekerjaan yang masih Anda perlukan di dalamnya.

## Menambahkan direktori lokal

UI untuk menambahkan direktori lokal hanya tersedia di Desktop, karena browser tidak dapat memilih folder di komputer Anda.

<Callout type="warning">
**Ini untuk kasus khusus; jangan memilihnya hanya karena praktis.** `local_directory` ada untuk orang-orang yang tidak memiliki pilihan lain — contoh baku-nya adalah proyek game dengan checkout berukuran puluhan gigabyte, di mana melakukan clone ulang untuk setiap eksekusi sama sekali tidak praktis.

Jika direktori Anda adalah repo git biasa yang dapat Anda clone, gunakan `github_repo` sebagai gantinya: secara default ia menggunakan mode worktree, sehingga eksekusi dalam jumlah berapa pun pada repo yang sama dapat berjalan sekaligus. `local_directory` memproses satu eksekusi dalam satu waktu secara default; jika direktorinya adalah repo git, Anda dapat memilih mode worktree untuk mendapatkan kembali konkurensi (lihat [Bagaimana eksekusi membagikan direktori](#how-runs-share-the-directory)). Jika ragu, bandingkan kedua jenis resource di bagian atas halaman ini.
</Callout>

Pemilihan otomatis ini hanya berlaku untuk direktori yang sedang Anda tautkan sekarang. Direktori yang ditautkan sebelumnya tetap menggunakan mode yang tersimpan saat itu, sehingga pengaturan yang sudah ada tidak akan pernah berubah tanpa sepengetahuan Anda.

Direktori tersebut harus berupa path absolut, harus sudah ada, dan harus dapat dibaca serta ditulis oleh daemon saat ini. Path berikut ini akan ditolak: root sistem dan root drive (`/`, `C:\`), direktori home itu sendiri dan induk dari direktori home (seperti `/Users`, `/home`, `/root`), serta direktori sistem seperti `/etc`, `/var`, `/tmp`, `/usr`, dan `/opt`. Jika path yang dipilih adalah symlink, path tersebut akan diselesaikan ke path aslinya terlebih dahulu dan divalidasi ulang dengan aturan yang sama; kunci serial juga berlaku pada path asli tersebut.

Setiap proyek paling banyak dapat menautkan satu direktori lokal per daemon. Komputer-komputer berbeda dalam satu tim masing-masing dapat menautkan direktorinya sendiri untuk proyek yang sama.

<Callout type="warning">
Dalam mode default `in_place`, direktori lokal bukan environment yang terisolasi: agent secara langsung melihat dan mengubah branch Anda saat ini beserta file yang belum di-commit, dan Multica tidak secara otomatis beralih branch, stash, commit, push, atau membuka PR. Mode worktree berbeda — lihat [Bagaimana eksekusi membagikan direktori](#how-runs-share-the-directory) di bawah.
</Callout>

## Bagaimana eksekusi membagikan direktori [#how-runs-share-the-directory]

Direktori lokal memiliki dua mode eksekusi, yang diatur per resource dengan `execution_mode`. Desktop menampilkannya sebagai **Edit directly** dan **Run in parallel** saat Anda menambahkan folder, dan sebagai **Direct** dan **Parallel** pada label mode folder; API, CLI, dan sisa halaman ini menggunakan pengenal (identifier) tersebut.

<LocalDirModeDemo />

<Tabs items={["in_place (Direct, default)", "worktree (Parallel)"]}>
<Tab value="in_place (Direct, default)" id="in-place">

Agent bekerja langsung di direktori Anda, dan eksekusi berjalan satu per satu. Saat dua eksekusi menggunakan direktori asli yang sama, eksekusi yang lebih baru masuk ke `waiting_local_directory` dan berlanjut setelah eksekusi sebelumnya melepaskan direktori tersebut. Dua path yang mengarah ke direktori yang sama melalui symlink berbeda akan diserialkan dengan cara yang sama.

Jika path yang tertaut hilang saat eksekusi yang menunggu hendak dimulai, eksekusi tersebut melaporkan bahwa folder proyek tidak lagi ada. Pulihkan folder atau perbarui path resource sebelum mencoba lagi.

Menunggu tidak mengubah direktori dan tidak memakai slot eksekusi daemon. Eksekusi yang menunggu dapat dibatalkan; jika tidak, eksekusi tersebut melanjutkan startup setelah direktori dan kapasitas eksekusi sama-sama tersedia.

Direktori biasa yang bukan git hanya dapat menggunakan mode ini: mode worktree mencakup repositori git.

</Tab>
<Tab value="worktree (Parallel)" id="worktree">

Setiap eksekusi mendapatkan [git worktree](https://git-scm.com/docs/git-worktree) tersendiri dari repo Anda, yang dibuat di dalam direktori workspace milik runtime itu sendiri. Eksekusi pada direktori yang sama berjalan secara konkuren tanpa menunggu, dan tidak satu pun yang menulis ke working copy Anda.

Direktori harus berupa repositori git dengan setidaknya satu commit; jika bukan, eksekusi akan gagal dengan error yang jelas, bukan diam-diam kembali ke eksekusi serial.

Runtime pada mesin tersebut juga harus mengimplementasikan mode ini. Runtime mendeklarasikan hal ini saat terhubung, dan Multica melakukan gating berdasarkan deklarasi tersebut, bukan berdasarkan nomor versi: sebuah development build bisa membawa string versi yang terlihat cukup baru padahal belum memiliki implementasinya sama sekali. Deklarasi ini diperiksa dua kali. Penyimpanan resource ditolak, dengan petunjuk untuk memperbarui aplikasi pada mesin tersebut, selama runtime-nya belum mendeklarasikan kapabilitas ini; dan setiap eksekusi diperiksa ulang terhadap runtime yang benar-benar mengklaimnya, sehingga mesin yang di-downgrade setelah resource disimpan akan memiliki eksekusinya dibatalkan dengan sebuah alasan, bukan diam-diam dijalankan secara in place. Meminta `worktree` berarti meminta isolasi; Multica tidak pernah kembali ke pengeditan working copy Anda.

Apa yang dilihat agent, dan apa yang Anda dapatkan kembali:

<Accordions type="multiple">
<Accordion title="Agent mulai dari apa yang Anda lihat, bukan dari HEAD" id="starts-from-your-working-state">

Edit yang belum di-commit dan file yang belum dilacak (untracked) milik Anda akan diputar ulang (replay) ke dalam worktree, sehingga agent tidak meninjau kode yang sudah tidak Anda miliki lagi. Working copy, index, dan daftar stash Anda sendiri tidak pernah tersentuh.

Jika state tersebut tidak dapat direproduksi secara akurat, termasuk saat ada konten untracked lebih banyak daripada yang dapat ditangani oleh replay (2000 file / 200 MiB), eksekusi akan gagal daripada dimulai dari sebuah tree yang tidak Anda kenali. Perbaikan yang umum dilakukan adalah menambahkan gitignore atau membersihkan output build yang belum diabaikan.

</Accordion>
<Accordion title="Hasilnya adalah sebuah branch di repo Anda" id="result-is-a-branch">

Ada satu branch per tugas, bukan satu per eksekusi: `agent/<agent>/<issue>` (sebuah chat mendapatkan `agent/<agent>/chat-<session>`). Panel **Detail eksekusi** menampilkan nama branch tersebut (dan memungkinkan Anda menyalinnya); Anda juga dapat menemukannya dengan `git branch`. Tinjau dengan `git log` / `git diff`, dan gabungkan atau cherry-pick sendiri. Multica tidak pernah menggabungkannya untuk Anda.

`<agent>` berasal dari nama agent: diubah ke huruf kecil, dengan semua karakter selain a–z dan 0–9 diubah menjadi `-`, hingga 30 karakter. Nama tanpa huruf Latin atau angka menjadi `agent`. Jadi Ops helper yang mengerjakan OPS-21 mendapatkan `agent/ops-helper/ops-21`, sedangkan agent bernama 运营助手 mendapatkan `agent/agent/ops-21`. `<issue>` adalah pengenal issue dalam huruf kecil.

Eksekusi yang gagal di tengah jalan tetap melaporkan branch-nya: commit milik agent ada di dalamnya, dan apa yang ditinggalkan tanpa di-commit disimpan seperti dijelaskan di [Tidak ada apa pun yang diam-diam hilang](#nothing-is-silently-lost).

</Accordion>
<Accordion title="Lanjutan akan melanjutkan dari titik eksekusi terakhir berhenti" id="follow-ups-continue-the-branch">

Komentar berikutnya pada tugas yang sama akan melakukan checkout branch tersebut lagi, sehingga agent berdiri di atas pekerjaan yang baru saja diserahkannya, bukan mulai dari `HEAD` dengan perubahannya sendiri terdampar di branch lain. Hanya apa yang Anda ubah di direktori Anda sendiri sejak eksekusi terakhir yang diputar ulang di atasnya; branch tersebut sudah membawa sisanya. Gabungkan branch tersebut dan eksekusi berikutnya akan mulai dari `HEAD` Anda lagi.

Jika dua eksekusi pada satu tugas tumpang tindih, eksekusi kedua akan bercabang dari hasil kerja eksekusi pertama menjadi `agent/<agent>/<issue>-<task>`, karena git hanya mengizinkan satu worktree per branch.

</Accordion>
<Accordion title="Commit ke HEAD lokal Anda terpisah dari edit yang belum di-commit" id="committed-head-changes-stay-separate">

Pull atau commit lokal di antara giliran tidak diputar ulang ke branch tugas; gabungkan commit tersebut ke dalamnya secara eksplisit bila diperlukan. Jika eksekusi sebelumnya menangkap pekerjaan yang belum di-commit, membandingkannya pada `HEAD` yang baru memerlukan Git 2.40 atau lebih baru.

Jika edit lama tersebut berkonflik dengan baseline ter-commit yang baru, runtime mencatat peringatan di log dan menggunakan `HEAD` saat ini hanya untuk path yang terdampak; draf lain tetap memakai perbandingan inkremental. Dengan begitu, menyelesaikan dan meng-commit satu draf tidak menghalangi eksekusi berikutnya atau mengajukan ulang draf Anda yang tidak berubah terhadap pekerjaan agent. Konflik apa pun antara edit Anda saat ini dan pekerjaan agent tetap ditawarkan kepada agent untuk diselesaikan.

</Accordion>
<Accordion title="Jika perubahan Anda berkonflik dengan perubahan agent, agent-lah yang menyelesaikannya" id="conflicts-are-resolved-by-the-agent">

Saat Anda menulis ulang baris yang sama dengan yang ditulis ulang oleh agent, git tidak dapat memutuskan versi mana yang menang, sehingga eksekusi dimulai pada worktree yang berkonflik dan diberi tahu untuk menyelesaikan merge tersebut sebelum melakukan apa pun yang lain (`git status` pada worktree itu menampilkan path yang belum di-merge).

Eksekusi yang meninggalkan file yang belum di-merge tidak menghasilkan apa pun: eksekusi tersebut gagal, mempertahankan worktree-nya, dan eksekusi berikutnya akan menawarkan edit yang sama lagi, sehingga perubahan Anda tidak pernah diam-diam hilang.

</Accordion>
<Accordion title="Hanya branch milik Multica yang dilanjutkan" id="only-multica-branches-resume">

Melanjutkan sebuah branch ditentukan oleh catatan kepemilikan, bukan oleh namanya: catatan tersebut menyebutkan percakapannya, dan menyebutkan commit tempat branch itu ditinggalkan. Branch yang Anda buat sendiri yang kebetulan bernama `agent/<agent>/<issue>` tidak akan pernah di-checkout, ditambahkan, atau dibaca sebagai eksekusi sebelumnya, demikian pula branch yang tidak lagi mengandung commit yang tercatat. Jadi menghapus branch milik Multica dan membuat branch Anda sendiri dengan nama yang sama, atau memindahkannya secara paksa ke histori lain, aman untuk dilakukan; eksekusi akan menggunakan `agent/<agent>/<issue>-<id>` sebagai gantinya. Melakukan commit di atas branch yang sudah diserahkan adalah hal yang normal dan membuatnya tetap berlanjut: commit Anda akan muncul begitu saja pada eksekusi berikutnya.

Setiap branch juga dimulai dengan sebuah commit baseline miliknya sendiri, yang menandai tree tempat eksekusi pertama dimulai. Commit tersebut yang mengidentifikasi branch itu nantinya, dan `git diff <baseline>..<branch>` adalah tepat pekerjaan agent tersebut.

Eksekusi yang tidak dapat mencatat branch-nya — gagal sebelum selesai, catatannya tidak dapat ditulis, atau mereset worktree-nya melewati commit yang membawa perubahan Anda ke dalam branch tersebut — melaporkan kegagalan dan mempertahankan worktree-nya, dan eksekusi berikutnya memulai branch baru daripada melanjutkan branch yang tidak dapat dibuktikan sebagai miliknya.

</Accordion>
<Accordion title="Tidak ada apa pun yang diam-diam hilang" id="nothing-is-silently-lost">

Selama eksekusi worktree, file instruksi runtime yang dilacak seperti `CLAUDE.md` atau `AGENTS.md` ditandai `skip-worktree` di index privat task. Ini menjaga brief yang disuntikkan tetap di luar commit agent tanpa mengubah checkout Anda. Edit yang disengaja pada file itu tetap belum di-commit sampai pembersihan memulihkan pelacakan normal: edit tersebut mengikuti aturan penyerahan di bawah. File runtime yang tidak dilacak dan direktori skill tetap perlu dikecualikan dari commit agent.

Apa pun yang ditinggalkan agent tanpa di-commit tidak dihapus bersama worktree, termasuk saat eksekusi gagal di tengah jalan. Ke mana hasilnya pergi bergantung pada apakah agent melakukan commit selama eksekusi:

- **Agent tidak melakukan commit:** semua yang ditinggalkannya dan tidak di-gitignore di-commit ke branch. Hook commit repositori Anda tidak berjalan untuk commit ini.
- **Agent melakukan commit sendiri:** hanya commit tersebut yang diserahkan. Apa pun yang ditinggalkannya tanpa di-commit (output hasil generate, file scratch, edit yang tidak di-commit) disimpan di bawah hidden ref, `refs/multica/leftovers/<branch>/<task>`, dan tidak sampai ke branch. Agent diberi tahu aturan ini di awal setiap eksekusi, sehingga agent yang melakukan commit menentukan apa yang diserahkan.

Satu pengecualian: eksekusi yang dimulai dengan menyelesaikan merge bersama edit lokal Anda (lihat [konflik](#conflicts-are-resolved-by-the-agent)) meng-commit semua yang ditinggalkannya, karena perubahan yang belum di-commit itu mencakup edit Anda.

Untuk melihat apa yang disimpan sebuah eksekusi, daftarkan ref dengan `git for-each-ref refs/multica/leftovers` dan periksa salah satunya dengan `git show --stat <ref>`. `git restore --source=<ref> -- <path>` mengembalikan sebuah file ke checkout Anda.

Dalam kasus jarang di mana commit atau penyimpanan itu sendiri tidak dapat dilakukan — misalnya repo dengan `commit.gpgSign` dan tidak ada signing key yang tersedia untuk runtime — worktree tersebut sengaja dipertahankan, eksekusi dilaporkan sebagai gagal, dan `git worktree list` di repo Anda akan menunjuk ke direktori yang menyimpan pekerjaan tersebut.

</Accordion>
<Accordion title="Eksekusi yang tidak mengubah apa pun tidak meninggalkan apa pun" id="no-changes-leave-nothing">

Branch-nya akan dihapus, bukan ditinggalkan sebagai entri kosong di `git branch`, kecuali itu adalah branch tugas yang membawa pekerjaan dari eksekusi sebelumnya, yang selalu tetap ada.

</Accordion>
<Accordion title="Branch dan hidden ref yang tersisa di repo Anda" id="what-stays-in-your-repo">

Worktree berada di dalam direktori workspace milik runtime dan dibersihkan sesuai [jadwal pembersihan normal](/daemon-runtimes#cleanup). Yang tetap ada di repo Anda adalah branch tersebut; satu hidden ref per branch di bawah `refs/multica/local-state/` yang mencatat siapa pemiliknya dan seperti apa direktori Anda saat terakhir kali dilanjutkan; dan satu hidden ref di bawah `refs/multica/leftovers/` untuk setiap eksekusi yang meninggalkan perubahan yang belum di-commit setelah melakukan commit sendiri.

Hidden ref tersebut tidak pernah muncul di `git branch`; daftarkan dengan `git for-each-ref refs/multica`. Multica menghapus setiap hidden ref beserta branch-nya, dan membuang hidden ref mana pun yang branch-nya Anda hapus sendiri pada saat eksekusi berikutnya dimulai pada repo tersebut. Anda juga dapat menghapusnya sekaligus dengan `git for-each-ref --format='%(refname)' refs/multica | xargs -n1 git update-ref -d`.

</Accordion>
</Accordions>

<Callout type="warn">
**Operator self-hosted:** isolasi untuk mode ini ditegakkan oleh server (saat penyimpanan dan sekali lagi saat sebuah runtime mengklaim setiap eksekusi), sehingga runtime yang di-downgrade kapan pun akan tertangkap. Kombinasi yang *tidak* tertangkap adalah mengembalikan server ke build yang lebih lama dari fitur ini sementara runtime yang belum mengimplementasikan mode ini masih terhubung: server lama tidak memiliki gate, dan runtime semacam itu mengabaikan `execution_mode` serta akan mengeksekusi eksekusi tersebut secara in place. Jangan mengembalikan server ke versi sebelum rilis ini selama resource `worktree` masih ada, kecuali setiap runtime pada mesin-mesin tersebut sudah diperbarui.
</Callout>

## Apa yang ditulis selama sebuah eksekusi

Selain perubahan kode yang dibuat agent, runtime juga dapat menulis ke direktori tersebut file instruksi yang dibutuhkan oleh AI coding tool yang sedang digunakan, beserta `.multica/project/resources.json`. Tambahkan file-file tersebut ke `.gitignore` jika Anda tidak ingin menyertakannya dalam version control.

Multica tidak pernah menghapus direktori lokal yang tertaut saat membersihkan environment eksekusi. Perubahan agent pada direktori tersebut adalah jenis perubahan yang sama seperti saat Anda sendiri menjalankan AI coding tool di terminal, dan membutuhkan tinjauan yang sama.

## Mengelola resource dengan CLI

```bash
# Link a repository when creating a project
multica project create \
  --title "Agent UX" \
  --repo https://github.com/multica-ai/multica

# List and add resources
multica project resource list <project-id>
multica project resource add <project-id> \
  --type github_repo \
  --url https://github.com/multica-ai/multica \
  --ref main

# Link a local directory on a specific daemon
multica project resource add <project-id> \
  --type local_directory \
  --local-path /absolute/path/to/repo \
  --daemon-id <daemon-id>

# Link a local git repo and let runs execute concurrently in their own worktrees
multica project resource add <project-id> \
  --type local_directory \
  --local-path /absolute/path/to/repo \
  --daemon-id <daemon-id> \
  --execution-mode worktree

# Switch an existing local directory between modes
multica project resource update <project-id> <resource-id> --execution-mode worktree
multica project resource update <project-id> <resource-id> --execution-mode in_place

# Remove a resource
multica project resource remove <project-id> <resource-id>
```

Perubahan resource memengaruhi eksekusi yang dibuat setelahnya; perubahan tersebut tidak menulis ulang catatan eksekusi yang sudah berakhir.
