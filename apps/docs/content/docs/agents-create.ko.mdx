에이전트를 만들기 전에 사용할 수 있는 [런타임](/daemon-runtimes)이 있어야 합니다. 런타임은 이 에이전트가 사용할 컴퓨터와 AI 코딩 도구를 결정하며, 에이전트에는 장기적으로 사용할 정체성, 지시문, 기능이 저장됩니다.

워크스페이스의 **에이전트** 페이지에서 **새 에이전트**를 클릭합니다.

## 시작 방법 선택

생성 페이지에서는 두 가지 방법을 제공합니다.

| 방법 | 적합한 경우 |
|---|---|
| **빈 상태에서 시작** | 에이전트의 역할을 이미 알고 있고 각 설정을 직접 입력하려는 경우 |
| **AI로 만들기** | 먼저 목표를 설명하고 Agent Builder가 핵심 정보를 추가로 질문해 초안을 만들게 하려는 경우 |

AI로 만들려면 Builder 대화를 진행할 온라인 런타임이 필요합니다. 어느 방법을 선택하든 만들기 전에 최종 설정을 확인하고 수정할 수 있습니다.

![에이전트 생성 시작 방법 선택: Start blank와 Build with AI](/images/docs/quickstart-new-agent.webp)

## 필수 항목

에이전트를 만들 때 필요한 항목은 두 가지뿐입니다.

- **이름**: 현재 워크스페이스에서 고유해야 합니다.
- **런타임**: 에이전트 실행을 처리할 환경을 선택합니다.

다른 필드는 기본값으로 두고 만든 뒤 조정할 수 있습니다. 새 에이전트는 기본적으로 생성자만 실행할 수 있습니다.

## 설명과 지시문

**설명**은 팀을 위한 짧은 소개로 에이전트 목록과 상세 화면에만 표시되며 AI 코딩 도구의 프롬프트에는 포함되지 않습니다.

**지시문**은 모든 실행에서 에이전트에게 제공되며 일반적으로 다음 내용을 포함합니다.

- 담당하는 일과 담당하지 않는 일
- 작업을 받으면 먼저 확인할 사항
- 수정해도 되는 내용
- 결과 제출 방식
- 멤버에게 확인해야 하는 시점

예시:

```text
프런트엔드 Pull Request 검토를 담당합니다.

먼저 변경 사항과 관련 테스트를 읽고 다음 항목만 확인합니다.
- React와 TypeScript의 정확성
- 접근성
- 기존 컴포넌트 패턴과의 일관성

코드를 직접 수정하지 마세요. 문제를 심각도별로 태스크 댓글에 작성하고,
차단 문제가 없다면 병합해도 된다고 명확히 설명하세요.
```

## 스킬 추가

만들 때 워크스페이스에서 하나 이상의 [스킬](/skills)을 선택할 수 있습니다.

스킬은 여러 에이전트가 재사용할 수 있는 방법과 자료를 저장하기에 적합합니다. 이 에이전트에만 적용되는 장기 요구 사항은 지시문에 작성하세요.

## 대화 시작 예시

첫 채팅 메시지를 보내기 전에 이 에이전트가 잘하는 일을 보여 주는 **대화 시작 예시**를 최대 3개 추가할 수 있습니다. 새 채팅을 열면 입력창 위에 표시됩니다. 각 예시에는 짧은 라벨과 전체 프롬프트가 있습니다. 선택하면 전송하지 않고 입력창에 채워져 사용자가 먼저 확인하거나 수정할 수 있습니다.

편집기 바로 아래에서 새 채팅에 표시될 실제 모습을 미리 볼 수 있습니다. 에이전트를 편집할 수 있는 사람에게는 그 빈 화면에 **시작 예시 편집** 링크가 표시되어 이 설정으로 바로 이동합니다.

목록을 비워 두면 채팅에 현지화된 범용 기본값이 표시됩니다. 에이전트의 역할과 경계에 맞춘 예시가 보통 더 유용합니다.

## 런타임, 모델, 사고 강도 선택

런타임은 이미 특정 AI 코딩 도구에 대응합니다. 런타임을 선택한 뒤 해당 도구가 지원하는 모델과 사고 강도를 선택할 수 있습니다. Codex 같은 일부 도구에서는 속도 단계도 선택할 수 있습니다.

- 비워 두면 런타임 또는 로컬 CLI의 기본 설정을 사용합니다.
- 모델을 설정하면 이후 이 에이전트가 가져가는 실행에 해당 값이 적용됩니다.
- 일부 런타임은 모델을 자체 관리하므로 모델 선택이 표시되지 않습니다.

도구별 모델, 세션 복원, 스킬, MCP 기능은 [AI 코딩 도구 비교](/providers)를 참고하세요.

## Access 설정

Access는 어떤 멤버가 이 에이전트를 실행할 수 있는지 결정합니다. 실행에는 할당, @멘션, 대화가 포함됩니다.

| Access | 의미 |
|---|---|
| **나만**(Only me) | 나만 실행할 수 있습니다. 기본값입니다. |
| **전체 워크스페이스**(Entire workspace) | 모든 워크스페이스 멤버가 실행할 수 있습니다. |
| **지정한 멤버**(Specific people) | 나와 선택한 멤버만 실행할 수 있습니다. |

![Access 설정: 나만, 전체 워크스페이스, 지정한 멤버의 세 단계](/images/docs/agent-access-settings.webp)

에이전트 owner만 Access를 수정할 수 있으며 워크스페이스 관리자도 수정할 수 없습니다. 워크스페이스 `owner`와 `admin`은 다른 설정을 관리할 수 있지만 관리자 권한으로 허가받지 않은 에이전트를 실행할 수는 없습니다.

## 생성 후 설정 항목

에이전트 상세 페이지를 열면 다음 항목을 계속 조정할 수 있습니다.

| 설정 | 역할 |
|---|---|
| **동시 실행 상한** | 같은 에이전트가 동시에 실행할 수 있는 실행 수입니다. 기본값은 6이며 상한에 도달하면 계속 큐에서 기다립니다. |
| **환경 변수** | AI 코딩 도구를 시작할 때 변수를 주입합니다. |
| **사용자 지정 인수** | AI 코딩 도구의 CLI 인수에 항목별로 추가합니다. |
| **MCP** | 지원되는 AI 코딩 도구에 MCP server 설정을 제공합니다. |
| **연동** | 이 에이전트가 사용할 수 있는 외부 서비스를 연결합니다. |

런타임이 속한 데몬에도 전체 동시 실행 상한(기본 20)이 있으며 실제 동시 실행 수에는 둘 중 더 작은 값이 적용됩니다.

설정을 수정해도 이미 진행 중인 실행은 바뀌지 않습니다. 이후 실행이 런타임에 의해 수령될 때 당시 저장된 에이전트 설정을 사용합니다.

## 환경 변수와 자격 증명

환경 변수에는 이 에이전트 실행에 필요한 제한된 권한의 자격 증명을 넣는 것이 적합합니다. 예를 들면 읽기 전용 API key나 단일 scope token입니다.

<Callout type="warning">
**`custom_env` 값은 Multica 서버 데이터베이스에 평문으로 저장되며** "로컬에만 남는" 데이터가 아닙니다. 에이전트 목록 및 상세 API는 env 값을 전혀 반환하지 않고 키 개수만 반환합니다. 워크스페이스 `owner`와 `admin`만 잠금을 해제하고 수정할 수 있으며 모든 읽기와 수정이 감사 기록에 남습니다. 실행 중인 에이전트는 관리 API로 다른 에이전트의 변수를 읽을 수 없습니다.
</Callout>

프로덕션 데이터베이스의 관리자 비밀번호나 가치가 높은 장기 자격 증명을 사용하지 마세요.

`PATH`, `HOME`, `MULTICA_*` 같은 핵심 실행 환경 변수는 여기서 덮어쓸 수 없습니다.

## 사용자 지정 인수와 MCP

사용자 지정 인수는 배열의 각 항목으로 AI 코딩 도구에 전달되며 shell 확장을 거치지 않습니다. 인수 이름의 유효성은 해당 도구가 결정합니다. 별도 필드가 있는 모델 설정을 여기서 다시 입력할 필요는 없습니다.

<Callout type="warning">
자격 증명이나 다른 secret을 사용자 지정 인수에 넣지 마세요. 값은 자식 프로세스의 argv에 남아 같은 머신의 다른 프로세스에서 `ps` 또는 `/proc`를 통해 보일 수 있습니다. 대신 환경 변수(`custom_env`)를 사용하세요. 데몬 로그는 인수 값을 가리지만 운영 체제의 프로세스 목록까지 보호하지는 못합니다.
</Callout>

MCP 설정에는 token이 포함될 수 있으며 저장 및 표시 규칙은 환경 변수와 같습니다. 관리형 MCP 설정을 지원하는 런타임에서만 이 항목이 표시됩니다. 지원하지 않는 도구는 설정을 저장해도 MCP 기능을 자동으로 얻지 않습니다.

## 에이전트 복사

복사하면 이름을 제외한 대부분의 작업 설정이 포함됩니다. 지시문, 대화 시작 예시, 스킬, 사용자 지정 인수, 아바타, 동시 실행 상한, Access 설정이 복사됩니다. 모델, 사고 강도, 속도 단계도 함께 복사되지만 원래 런타임을 사용할 수 없어 다른 런타임으로 바꿔야 하면 이 세 항목이 비워지므로 다시 선택해야 합니다.

환경 변수 값과 MCP 설정은 어떤 경우에도 복사되지 않으며 새 에이전트에서 다시 설정해야 합니다. 복사본은 원래 에이전트의 런타임 연결과 Access 설정을 유지합니다.

## CLI로 만들기

```bash
multica agent create \
  --name "Frontend Reviewer" \
  --runtime-id <runtime-id> \
  --description "프런트엔드 Pull Request 검토" \
  --instructions "먼저 변경 사항과 테스트를 읽고 태스크 댓글에만 검토 결론을 제출하세요."
```

명령줄 인수의 평문은 shell 기록에 남습니다. stdin과 권한이 제한된 파일은 기록에 남지 않습니다.

비슷한 설정의 에이전트가 이미 있다면 바로 복사할 수 있습니다.

```bash
multica agent copy <agent-id>
```

기본적으로 같은 런타임으로 복사됩니다. 다른 런타임으로 바꾸려면 `--runtime-id`를 추가하고 `--model`도 함께 지정해야 합니다. 환경 변수, MCP 설정, `runtime_config`는 절대 복사되지 않지만 런타임 연결 자체는 유지됩니다. 전체 인수는 [CLI 사용](/cli)을 참고하세요.
