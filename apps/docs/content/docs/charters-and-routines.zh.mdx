有章程的小队有一项长期职责。章程写明使命、需要交付的产出、不能做什么，以及何时上报给你。例行任务是按计划产生这些产出的运行。没有章程的小队只有在有人分配工作时才运行。

## 章程

打开小队面板，选择 **Charter** 标签页。成员可以查看章程。所有者、管理员和小队的创建者可以编辑。

| 字段 | 用途 |
| --- | --- |
| Mission（使命） | 小队为什么存在，最多 2,000 个字符 |
| Responsibilities（职责） | 小队负责的领域，每项附一段简短文字 |
| Outputs（产出） | 小队产出什么，包括类型和周期，例如每周一份市场报告 |
| Boundaries（边界） | 小队不能做什么，例如花钱或调整组织结构 |
| Escalation（上报） | 何时必须向你请示 |
| Intake（接收） | 其他小队可以向它提出什么请求 |
| Response hours（响应时限） | 小队回复请求需要的时间，1 到 720，默认 48 |

每次保存都会让章程的版本号加一。如果你打开表单后有人保存了更新的版本，保存会被拒绝并提示冲突，让你先看到对方的修改再覆盖。

小队的负责人会收到系统管理的 **Your charter**（你的章程）内容，由上述字段生成。其后是通用规则：开始前先搜索公司知识；涉及资金、外部影响或组织变更的事项先提交提案；没有实际行动时记录 `no action` 并说明原因，而不是凑数；并遵守注意力上限。

<Callout type="info">
章程取代了小队原有的描述作为此用途。描述仍是一行标签，指令仍是负责人的路由规则。
</Callout>

## 例行任务

例行任务是关联到小队的普通 [自动化](/autopilots)，并附带目的和预期产出。它不会新增第二个调度器：调度、运行历史和 **Run now**（立即运行）都属于自动化本身。

在小队面板的 **Routines**（例行任务）列表中添加。

- **关联现有自动化**，或按周期**新建**：`daily`（每天）、`weekdays`（工作日）、`weekly`（每周）、`biweekly`（每两周）、`monthly`（每月），或一个 cron 表达式。
- 目的最多 200 个字符，例如"每周竞品扫描"。
- 选择预期产出：无、议题、提案、知识文档或报告。

在列表中可以立即运行、暂停或移除例行任务。移除只是取消关联，同时你可以暂停其自动化。

列表显示每个例行任务的状态，以及上次和下次运行时间。状态包括：

| 状态 | 含义 |
| --- | --- |
| `on_time` | 上次运行已完成并产出预期结果，或记录了附原因的 `no action` |
| `no_output` | 上次运行已完成，但没有产出，也没有记录 `no action` |
| `late` | 下次运行超过宽限期（默认 24 小时）仍未开始 |
| `failed` | 最近一次运行失败 |
| `paused` | 自动化已暂停 |
| `held` | 公司控制措施正在暂停该运行，例如[暂停](/controls-and-log)或[预算](/budgets)上限 |
| `never_ran` | 已创建，但第一次计划时间尚未到达 |

这些状态由平台根据运行历史和小队创建的记录得出，小队不自行报告。

## 运营评审

首次保存章程时，平台会为小队创建一个名为 **Operating review**（运营评审）的每周例行任务。其说明要求小队：

1. 对比上周的产出与章程，列出逾期或缺失的内容；
2. 在公司知识中搜索该领域的既往决定和过期文档；
3. 指出至多一件没人要求、但值得做的事，并附证据；
4. 在注意力上限内作为提案提交，或记录附原因的 `no action`；
5. 为过期的知识文档起草更新，仅限草稿。

运营评审是普通的例行任务，它的合规情况同样被统计，你可以在例行任务列表中暂停它。

## 限制

- 章程和例行任务在应用中管理。`multica` CLI 没有章程或例行任务命令。API 为 `GET` 和 `PUT /api/squads/{id}/charter`、`GET` 和 `POST /api/squads/{id}/routines`，以及 `DELETE /api/squads/{id}/routines/{routine_id}`。
- 公司暂停或安静时段保留的例行任务显示为 `held`，而不是 `failed`。参见[控制与日志](/controls-and-log)。
