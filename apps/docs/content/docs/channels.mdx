Existing chat integrations let a team ask an agent questions, @-mention it in a group, or create issues without opening Multica.

<Callout type="info">
  New Agent-scoped Bot connection and reassignment are retired. Existing
  installations, identity callbacks, and message execution remain supported.
</Callout>

## Retained platform behavior

| | Feishu / Lark | Slack | DingTalk | WeCom |
|---|---|---|---|---|
| Direct messages | Supported | Supported | Supported | Supported |
| Groups or channels | Triggered by @-mention | Triggered by @-mention | Triggered by @-mention | Triggered by @-mention |
| Create issues | `/issue` message command | `/issue` slash command | `/issue` message command | `/issue` message command |
| Connection | Platform long connection | Socket Mode | Stream mode | Platform long connection |

Each retained Bot keeps its existing Agent binding. DingTalk discovered-group routes also remain available to execution but are read-only in the browser. DingTalk and WeCom are community-maintained and carry no official support SLA.

## How a message is processed

1. Multica resolves the retained Bot to its workspace and agent.
2. Group and channel messages continue only when they explicitly @-mention the Bot; DMs need no mention.
3. Multica verifies the sender's account binding and workspace membership.
4. The message joins an [agent chat](/chat) session and creates a task.
5. The reply returns to the original DM or thread.

`/issue` is a command rather than a chat turn. Slack's native slash command keeps its separate asynchronous issue-creation flow.

## Session isolation

- Feishu/Lark separates sessions by chat.
- Slack separates DMs by channel and channel conversations by thread.
- DingTalk separates sessions by conversation.
- WeCom separates sessions by chat.

## Account binding

The first message from a member may return a single-use identity link. After sign-in, the external account is linked to that membership. These callback and broker contracts remain independent of new Agent connection and continue to re-check workspace membership on every message.

## Manage retained connections

Workspace owners and admins can inspect or disconnect retained Bots in **Settings → Integrations**. Regular members can view connected integrations and use agents they may invoke. Disconnecting stops new messages while preserving existing conversations and audit records.

## Self-hosting

Stored Bot credentials still require the platform's 32-byte encryption key:

```dotenv
MULTICA_LARK_SECRET_KEY=<base64-encoded 32-byte key>
MULTICA_SLACK_SECRET_KEY=<base64-encoded 32-byte key>
MULTICA_DINGTALK_SECRET_KEY=<base64-encoded 32-byte key>
MULTICA_WECOM_SECRET_KEY=<base64-encoded 32-byte key>
```

Keep these keys stable so retained credentials remain decryptable. WeCom additionally requires a single backend replica until cross-replica outbound routing is available.
