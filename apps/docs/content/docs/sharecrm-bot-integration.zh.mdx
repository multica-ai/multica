把任意[智能体](/agents)接入一个纷享销客 Bot，团队就能在纷享销客里直接使用它——私聊 Bot、在群里 @ 它，或者输入 `/issue` 直接创建一个 [Multica issue](/issues)，不用打开应用。

纷享销客集成由社区维护：每个版本都会随包发布，但不附带官方支持 SLA。遇到问题请提到 [GitHub issues](https://github.com/multica-ai/multica/issues)。

纷享销客走的是**自带应用（bring-your-own-app，BYO）**模式：workspace 管理员在纷享销客开放平台创建机器人凭证，再把它的凭证粘贴进 Multica。每个智能体都有**它自己的**纷享销客机器人——所以多个智能体可以在同一个组织里各自拥有一个独立、可单独 @ 的 Bot。（这一点和 [Lark](/lark-bot-integration) 不同，Lark 的绑定是扫码安装流程。）

整个设置流程在下面，大约五分钟。最后你会得到两个凭证粘贴进 Multica：

- 一个 **App ID** —— 机器人应用的 client id
- 一个 **App Secret** —— 机器人应用的 client secret

私有化部署可选填 **API 地址**（默认 `https://open.fxiaoke.com`）。

## 设置你的纷享销客机器人

### 1. 在纷享销客开放平台创建机器人凭证

1. 用管理员账号打开[纷享销客开放平台](https://open.fxiaoke.com)（或你的私有化控制台）。
2. 创建（或打开）Multica 将连接的那个机器人应用。
3. 复制该应用的 **App ID** 和 **App Secret**。
4. 确认机器人可以**接收消息**（私聊与群 @）并**发送回复**。Multica 通过 SSE 长连接**主动向外**连接——你**不需要**为聊天配置任何公网 webhook URL。

这就是 Multica 在平台层所需的一切：

| 配置项 | 为什么需要它 |
|---|---|
| **机器人应用** | 签发 Multica 鉴权用的 App ID / App Secret。 |
| **接收消息** | 让机器人能收到单聊消息，以及群里 @ 了它的消息（群消息在到达 Multica 前已由纷享销客侧过滤）。 |
| **发送消息** | 让机器人能把智能体回复和提示发回同一会话。 |
| **SSE 长连接** | Multica 主动拨出并保持推送连接——**无需任何公网 webhook / URL** 接收聊天消息。 |

这里**既没有 Multica 侧的 webhook URL，也没有 OAuth 重定向 URL**，因为机器人跑在 SSE 长连接上，而 BYO 不使用 OAuth。

<Callout type="info">
纷享销客没有原生的「正在输入」指示器，所以——和钉钉一样——Bot 会在开始处理时先回一条简短的「正在处理」提示，完整回复在智能体处理完后送达。短时间内连发的多条消息会合并为一条提示。
</Callout>

### 2. 在 Multica 里连接它

1. 在 **Agents → _你的智能体_** 打开该智能体 → **Integrations** tab（或左侧栏的 **Integrations** 区块）。
2. 点击 **连接纷享销客**。
3. 粘贴 **App ID** 和 **App Secret**。公有云请把 **API 地址** 留空；私有化部署则填你的 API 主机。
4. 点击 **连接**。Multica 会用该 API 地址校验凭证（换取 token）。
5. 智能体显示 **已连接到纷享销客**。Bot 现在通过它自己的 SSE 连接在监听了。

<Callout type="warning">
这两个凭证必须来自**同一个**纷享销客机器人应用，而那个应用恰好对应**一个**智能体。连接一个已经连到别的智能体或 workspace 的 App ID 会被拒绝。要把一个机器人挪到另一个智能体，先断开它；用一个**新的** App ID 重新连接某个智能体，会就地更新那个智能体的 Bot。
</Callout>

<Callout type="info">
要给**多个智能体**做这套设置？每个智能体都把整套流程走一遍——每个智能体都有自己的一对 App ID / App Secret，它们会显示成各自独立的 Bot。
</Callout>

## 这个集成能做什么

| 入口 | 行为 |
|---|---|
| **智能体 → Integrations** | 所有者和管理员能看到 **连接纷享销客**；连接后它会变成一个 **已连接到纷享销客** 徽标，并带一个 **断开连接** 操作。 |
| **私聊 Bot** | 工作区成员在单聊里直接给 Bot 发消息。这段对话会成为该智能体的一个 Multica [chat](/chat) 会话；每一条消息都会被读取。 |
| **群里 @ 它** | 把 Bot 加进群再 @ 它。只有纷享销客投递给 Bot 的消息会被读取——Bot 不会监听整个群。 |
| **仅文字** | 目前只处理文字消息。图片、文件和语音不会交给智能体。 |
| **`/issue` 命令** | 以 `/issue <标题>` 开头，会按输入直接、同步地以你的身份创建 Multica 任务，并在原对话中返回任务编号和标题；后续行会作为描述。这条命令不会出现在 Multica Chat；新建任务是 Multica 中记录的处理结果。 |
| **`/new` 命令** | 以 `/new <你的消息>` 开头，会让这条消息在不带旧上下文的情况下运行。单独发送 `/new` 会把同样的 fresh 意图留给下一条非空消息，不会创建空 turn；已有对话记录保持不变。 |
| **回复** | 智能体的答复会被以纯文本发回同一个单聊或群里（交付时会去掉 Markdown）。 |

## 使用 Bot（成员）

### 第一条消息：绑定你的账号

第一次 @ 或私聊 Bot 时，它会回一条 **绑定你的账号** 提示，指向产品内的 **/sharecrm/bind** 页面。点开链接、登录 Multica，你的纷享销客身份就会绑定到你的 Multica 成员身份——正是这一步让智能体能以你的身份行事（比如 `/issue` 会把 issue 记在你名下）。这个链接是一次性的，大约 15 分钟后过期；再给 Bot 发条消息就能拿到一个新的。

<Callout type="warning">
只有**工作区成员**才能使用 Bot。如果你不是成员，或者跳过了身份绑定，Bot 不会运行——你的消息会被丢弃（仅出于审计目的记录，不保存消息内容）。
</Callout>

### 对话与命令

- **在群里** —— 把 Bot 加进群，然后 `@your-bot <你的消息>`。每次追问都要重新 @ 它一下（Bot 只接收纷享销客路由给它的消息）。
- **在单聊里** —— 打开 Bot 并直接给它发消息；不用 @，每一条消息都会被读取。
- **创建 issue** —— 发送 `/issue Safari 上登录跳转坏了`，需要时可在后续行补充描述。Multica 会同步创建 issue，并在聊天中返回编号和标题。
- **重新开始** —— 发送 `/new <你的消息>`，让这条消息不带旧上下文运行；也可以单独发送 `/new`，把 fresh 意图应用到下一条非空消息。两种方式都不会删除已有对话记录。

## 管理与断开

工作区级别的管理在 **Settings → Integrations**：

- **Connected bots** 列出工作区里每个 Bot 以及它各自绑定的智能体（所有成员都能看到）。
- **Disconnect** 仅限 **所有者 / 管理员**。它会让 Bot 停止接收纷享销客消息并拆掉它的连接；安装记录会保留以便审计，之后你可以重新连接。

## 权限

- **连接 / 断开** 需要工作区**所有者**或**管理员**。
- **和 Bot 对话** 需要你是工作区成员且已绑定纷享销客身份。其余的人一律被丢弃。
- 对于被丢弃的消息，绝不保存消息内容——只记录一个丢弃原因，用于审计。

## 自部署配置

在 Multica Cloud 上这个集成已经可用——可跳过本节。

自部署时，**在你设置好静态加密密钥之前，纷享销客是关闭的**。这个密钥会在每个机器人的 App Secret 落库前对其加密；App ID 作为非敏感的安装路由标识明文保存。BYO 在部署层面**不需要** OAuth client id/secret——每个安装用的都是管理员粘贴进来的那对凭证。

1. 生成一个 32 字节的密钥并设置到 API 服务器：

   ```dotenv
   MULTICA_SHARECRM_SECRET_KEY=<base64-encoded 32-byte key>
   ```

   例如：`openssl rand -base64 32`。

2. 重启 API。在密钥设置好之前，**Settings → Integrations** 会显示一条「纷享销客集成未启用」提示，**连接纷享销客** 入口也会保持隐藏。

<Callout type="info">
这个密钥必须正好解码出 32 字节——`openssl rand -base64 32` 就能做到。把它当成一个长期有效的密钥：轮换或丢失它会让已存储的凭证无法解密，迫使每个 Bot 重新连接。「绑定你的账号」链接是用你的 Web 应用地址（`MULTICA_APP_URL`，未设置时回退到 `FRONTEND_ORIGIN`）拼出来的——正常部署里这个值本来就有，聊天侧无需额外配置。成员在浏览器里打开绑定链接时，需要能访问该 URL。
</Callout>

同一个 App ID 同一时间只允许**一条**活跃的 SSE 连接。Multica 的 channel supervisor 会为每个安装分配租约，由单个后端副本持有连接；多副本部署时，只有持有租约的副本保持流。
