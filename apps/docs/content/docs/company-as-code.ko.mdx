Company as code는 회사의 구조를 하나의 JSON 문서로 기술합니다. 층, 헌장과 루틴이 포함된 스쿼드, 에이전트의 역할과 지시문, 파이프라인, 지식 종류, 정책, 목표와 예산이 들어갑니다. 구조의 백업으로 쓰거나, 같은 형태의 두 번째 회사를 시작하는 데 쓸 수 있습니다.

내보내기와 가져오기는 오너와 관리자만 할 수 있습니다.

## 내보내기

```bash
multica company export --file company.json
```

내보내기 파일에는 다음이 들어 있습니다.

- 층과 스쿼드 좌석.
- 헌장과 루틴이 포함된 스쿼드.
- 에이전트의 역할, 지시문, 템플릿 참조.
- 파이프라인과 그 단계.
- 지식 종류, 층 책임 에이전트, 거버넌스 섹션.

시크릿, 런타임, 지식 문서, 진행 상황, 지출, 이력은 포함되지 않습니다. 파일에도 그렇게 적혀 있습니다. 시크릿과 지식 문서는 별도 백업으로 보관하세요.

## 가져오기

```bash
multica company import --file company.json --runtime <runtime-id> --dry-run
multica company import --file company.json --runtime <runtime-id>
```

먼저 `--dry-run`으로 실행하세요. 계획만 출력하고 아무것도 쓰지 않습니다.

- 항목은 이름으로 대조됩니다. 같은 파일을 두 번 가져와도 아무것도 바뀌지 않습니다.
- 에이전트는 `--runtime`으로 지정한 런타임에서 만들어집니다. 지정하지 않으면 에이전트는 차단된 것으로 보고됩니다.
- 가져온 루틴은 **일시 정지** 상태로 만들어집니다. 직접 시작하거나, 스타터 회사의 시작 옵션에 따라 시작하세요.
- 요청 본문은 8 MiB로 제한됩니다.

## 함께 옮겨지지 않는 것

가져오기는 다음을 다시 만들지 않습니다. 가져온 뒤에 직접 확인하세요.

- 닫힌 이니셔티브. 기록이므로 내보내지 않습니다. 닫히지 않은 이니셔티브는 목표와 예산과 함께 옮겨집니다.
- 진행 상황과 지출.

## 다르게 옮겨지는 것

- 활성 상태였던 스쿼드 목표는 **초안**으로 옮겨집니다. 목표 화면에서 활성화하세요. 가져오기는 승인하지 않습니다.
- 철회된 상시 승인 정책은 **철회된 상태**로 옮겨지며, 아무것도 승인하지 않습니다.
- 보관된 스쿼드는 **보관된 상태**로 옮겨집니다. 구성원과 루틴은 다시 활성화되지 않으며, 루틴은 일시 중지 상태로 남습니다.
- 이니셔티브는 파이프라인 이름, 단계, 제목으로 대조됩니다. 연결된 이슈는 만들어지지만, 인계나 깨우기는 없습니다.

## 제한 사항

- 내보내기와 가져오기 엔드포인트는 `GET /api/company/export`와 `POST /api/company/import`입니다.

<Callout type="warning">
가져오기는 당신이 지정한 런타임에서 동작하는 에이전트를 만들 수 있습니다. 드라이런 계획을 확인하고, 그 런타임이 의도한 머신의 것인지 확인하세요.
</Callout>
