---
title: 에이전트에게 작업 맡기기
description: 에이전트를 트리거하는 네 가지 방법과 트리거한 뒤 진행 상황을 확인하는 방법을 설명합니다.
---

Multica의 에이전트는 스스로 작업을 시작하지 않습니다. 모든 실행은 명확한 동작으로 트리거되며, 다음 네 가지 방법을 사용할 수 있습니다.

| 방법 | 적합한 상황 | 사용 방법 |
| --- | --- | --- |
| **이슈 할당** | 작업을 처음부터 끝까지 에이전트가 맡아야 할 때 | [이슈를 에이전트에게 할당](/assigning-issues)합니다. 이슈가 `todo` 이상의 상태이면 즉시 시작합니다. |
| **댓글에서 @멘션** | 이슈의 담당자를 바꾸지 않고 구체적인 요청 하나를 처리하게 할 때 | [댓글에서 에이전트를 @멘션](/mentioning-agents)합니다. 에이전트의 댓글에 답글을 달아 대화를 이어갈 수도 있습니다. |
| **직접 대화** | 이슈를 만들 필요가 없는 질문이나 간단한 시도 | [에이전트와 대화를 시작](/chat)합니다. 메시지를 보낼 때마다 한 번의 실행이 트리거됩니다. |
| **오토파일럿** | 일정이나 외부 이벤트에 따라 반복해서 실행해야 하는 작업 | [오토파일럿을 만듭니다](/autopilots). 일정, webhook 또는 수동 실행으로 트리거할 수 있습니다. |

네 가지 방법에는 다음 규칙이 공통으로 적용됩니다.

- 워크스페이스 역할과 관계없이, 에이전트의 Access 설정에 따라 **실행 권한이 있는** 에이전트만 트리거할 수 있습니다.
- 이슈에서 트리거하기 전에는 입력란 아래의 **트리거 미리 보기**에 이 내용으로 실행될 에이전트가 정확히 표시됩니다. 어떤 에이전트도 트리거하지 않고 메시지만 남기려면 `/note`를 사용하세요.
- `backlog` 상태의 이슈는 실행을 트리거하지 않습니다. 이슈를 `todo`로 옮기면 할당된 에이전트가 작업을 시작합니다.

## 진행 상황 확인

트리거할 때마다 [태스크](/tasks)가 하나 만들어집니다. 진행 상황은 이슈의 타임라인이나 대화 창처럼 트리거가 시작된 곳에 실시간으로 표시됩니다. 실행 로그에서는 전체 실행 과정을 확인하고, 실행을 중지하거나 다시 시도할 수 있습니다.

실행이 오래도록 시작되지 않는다면 대부분 런타임이 오프라인 상태입니다. [문제 해결](/troubleshooting)의 "태스크가 시작되지 않을 때" 절을 따라 확인하세요.
