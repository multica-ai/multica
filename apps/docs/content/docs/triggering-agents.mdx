Start with what you want an agent to do. You can give it ownership of an issue, ask for help on one request, or arrange work that repeats.

<TriggerChooserDemo />

| What you need | What to use |
|---|---|
| Have an agent own an issue | [Assign the issue](/assigning-issues) to an agent or squad. |
| Ask for help without changing the assignee | [@mention an agent](/mentioning-agents) in a comment, or reply to its comment to continue. |
| Send the same kind of request often | Save a [quick action](/quick-actions), such as Code Review, and use it from the issue. |
| Pass work through a repeatable set of steps | Choose a project [workflow](/workflows) and who takes over at each step. |
| Ask a question without creating an issue | Start a [chat](/chat) with the agent. |
| Start recurring work by time or an outside event | Create an [autopilot](/autopilots). |
| Have an agent come back to an issue later | Add a [wakeup](/issue-wakeups) to the issue with a time or an event to wait for. |

You can only ask agents you have permission to run. For comments, check the trigger preview before sending; use `/note` when you want to leave a message without waking an agent. An issue in `backlog` waits until you are ready to start it.

## Watch progress

Follow replies where you started the work: on the issue or in the chat. Open the [execution log](/tasks) to see an agent’s progress, stop it, or retry. If work has not started, check whether the agent’s computer is online; [Troubleshooting](/troubleshooting) has the next steps.
