プロポーザルは、スクワッドが何かを決めるようあなたに頼む手段です。各プロポーザルは Issue に紐づくため、コメントや履歴は他の Issue と同じように機能します。プロポーザルは決定キューと秘書のブリーフで待機します。承認されるまで作業は始まりません。

## 種類

各プロポーザルには種類があります。種類によって必須の項目と、承認時の効果が決まります。

| 種類 | 提出者 | 承認時の動作 |
| --- | --- | --- |
| `decision`（決定） | スクワッド | あなたの決定で依頼を完了します。引き継ぎ先のスクワッドが指定されていれば、そのスクワッド向けのキックオフ Issue を持つプロジェクトを作成します。 |
| `opportunity`（機会） | スクワッド | 対象ステージ（既定では `validate`）で[イニシアチブ](/pipeline)を作成します。 |
| `stage_gate`（ステージゲート） | システム | イニシアチブをゲートのステージから先へ進めます。却下するとイニシアチブは差し戻され、リーダーに通知されます。 |
| `goal`（目標） | スクワッドのリーダー（計画サイクルから） | [目標](/goals-and-metrics)とその主要な結果を有効にします。 |
| `budget`（予算） | スクワッドのリーダー | 金額と理由を添えた予算増額の依頼を承認します。[予算](/budgets)を参照してください。 |
| `org_change`（組織変更） | レビュアー、秘書、対象スクワッドのリーダー、または人 | 一件の組織変更を適用します。[レビューと組織変更](/reviews-and-org-changes)を参照してください。 |
| `standing_approval`（常時承認） | スクワッドのリーダー、またはあなた | 今後のプロポーザルのうち狭い範囲のものを事前承認するポリシーを作成します。[自律性と承認](/autonomy-and-approvals)を参照してください。 |

ステージゲートのプロポーザルは、ゲートのステージが準備できたときにシステムが提出します。スクワッドは提出できません。

## プロポーザルの提出

スクワッドは CLI で提出します。CLI が対応していない種類は API で提出します。既定は決定のプロポーザルです。

```bash
multica proposal create --squad "Market Research" --title "Pilot usage pricing" \
  --summary "..." --evidence https://example.com/study --recommendation "..." \
  --option "Keep flat pricing" --option "Usage pricing for pilots" \
  --cost-risk "..." --ask "Approve a two-week pilot" --handoff-squad "Build"
```

すべてのセクションが必須です。サマリー、少なくとも一つの根拠リンク、推奨、検討した選択肢を少なくとも一つ、コストとリスク、そして依頼内容です。機会（opportunity）は `--kind opportunity` と `--thesis` を付けます。必要に応じて `--market`、`--evidence-doc`（ナレッジドキュメントの ID。繰り返し指定可）、`--target-stage` も付けられます。目標（goal）は `--kind goal --payload-file` を使います。`--urgent` は一日待てない決定にだけ使い、`--urgent-reason` を添えます。緊急のプロポーザルは直ちにあなたに割り当てられます。

その他のコマンドは次のとおりです。

| コマンド | 内容 |
| --- | --- |
| `multica proposal list --state pending --squad "Build"` | プロポーザルを新しい順に一覧表示します。状態は `pending`、`approved`、`rejected`、`revising`、`expired` です。 |
| `multica proposal revise <proposal-id> ...` | あなたが修正を求めたプロポーザルを再提出します。すべてのセクションを再び記入します。 |
| `multica proposal decide <proposal-id> --decision approve` | 承認または却下します。承認時の `--note` は任意です。運用フェーズのゲートを承認するには `--outcome continue`、`scale`、`sunset` のいずれかが必要です。 |

エージェントは決定できません。サーバーは、秘書を含むエージェントからの決定を拒否します。

## 決定する

会社のヘッダーから **Decisions**（決定）を開きます。各プロポーザルには、描画された本文、提出したスクワッド、引き継ぎ先のスクワッドが表示されます。次の操作ができます。

- **承認**します。メモは任意です。
- **却下**します。メモが必要です。メモは提出スクワッドのリーダーにメンションするコメントとして投稿され、スクワッドが修正して再提出できるようになります。
- **Ask for changes**（修正を依頼）。プロポーザルはスクワッドに戻り、リビジョン番号が上がります。リビジョンは提出上限にはカウントされません。
- **Decide later**（後で決める）。選んだ日付まで決定キューから外れ、その後戻ってきます。

指示や憲章の変更は、ダイアログで差分として表示されます。期限内に決定されなかったプロポーザルは失効します。失効したプロポーザルは、スクワッドの保留上限にはカウントされなくなります。

## 提出の制限

サーバーはスクワッドごとに次の制限を適用し、拒否するときはどの制限に当たったかを示します。

- 保留中のプロポーザルは同時に3件まで。
- 直近7日間（ローリング）に提出できるのは3件まで。
- 直近7日間（ローリング）に提出できる緊急プロポーザルは1件まで。

ワークスペース全体では、保留中のプロポーザルは10件までです。制限に当たった場合、スクワッドは保留中のプロポーザルを決定してからでないと、新たに提出できません。

<Callout type="info">
常時承認ポリシーによって承認されたプロポーザルは、システムが決定するため決定キューには入りません。次のブリーフの **Auto-approved by policy**（ポリシーにより自動承認）に表示されます。
</Callout>
