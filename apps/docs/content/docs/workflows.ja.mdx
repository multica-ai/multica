ワークフローは、プロジェクトのタスクが通るステップ、各ステップの担当者、そこで行うことを決めます。

たとえば、開発の流れを次のように組めます。

| ステップ | 担当 | 行うこと |
|---|---|---|
| 開発 | 開発エージェント | 変更を実装し、レビューの準備をする。 |
| レビュー | レビューエージェント | 結果を確認し、QA へ渡すか修正のために戻す。 |
| QA | チームのメンバー | 実際に試して、完了にしてよいか判断する。 |

タスクをレビューに移すと、レビューエージェントに引き継がれます。説明、議論、それまでの成果は同じタスクに残るので、次の担当者は続きから取り組めます。

**開発デリバリー**テンプレートはこの構成です。ワークフローを選んでいないプロジェクトは **Default** を使います。すべてのステータスを使え、自動の引き継ぎもなく、これまでどおりです。

## ワークフローを作る

ワークスペースの `owner` または `admin` が、Web またはデスクトップアプリで作成できます。

<Steps>
<Step>

**設定 → ワークフロー**で**新規ワークフロー**を選びます。空白から始めるか、**開発デリバリー**、**コンテンツ制作**、**コミュニティ運営**のテンプレートを使えます。

</Step>
<Step>

名前を付けて、必要なステータスの列を選びます。中央の列はドラッグで並べ替えられます。

</Step>
<Step>

列を選び、タスクが入ったときの動作を**引き継がない**、**エージェントに渡す**、**メンバーに渡す**から選びます。メンバーの一覧からは**プロジェクトリード**も選べます。

</Step>
<Step>

エージェントに渡す場合は、このステップで行うことを書き、**完了したら移動**する先（未設定なら次の列）と**差し戻す先**（受け取った作業が不十分でやり直しが必要なときに使います）を選びます。外部の理由で進められないときは、差し戻しではなく **Blocked** を使います。

</Step>
<Step>

エージェントが受け取る説明をプレビューして、保存します。

</Step>
</Steps>

新しいステータスを追加した場合は、一度保存してからそのステータスの引き継ぎを設定します。

引き継がない場合、担当者は変わりません。メンバーへの引き継ぎでは担当者だけが変わり、エージェントは起動しません。エージェントに渡す場合はそのステップの作業を依頼します。呼び出す権限が必要で、実行にはそのコンピューターがオンラインである必要があります。

## プロジェクトで使う

プロジェクトを開き、**ワークフロー**のプロパティで選びます。ワークスペースの `owner`、`admin`、およびメンバーであるプロジェクトのリードが切り替えられます。

確認画面には、今のステータスを保つタスクが表示されます。新しいワークフローにないステータスを使っているタスクは、移動先を選びます。ワークフローを切り替えるだけでは、担当者の引き継ぎやエージェントの起動は行われません。

プロジェクトのボードはワークフローの列に沿って表示されます。タスクで選べるステータスもそのステップに限られ、引き継ぐ相手が表示されます。別のワークフローを選んでいないプロジェクトは **Default** を使います。あとで Default に戻すこともできます。

## 次のステップへ渡す

タスクのステータスを変えるか、カードを別の列へドラッグします。引き継ぎのあるステップでは、相手を確認します。エージェントの場合は、受け取る説明も確認できます。

<WorkflowDemo />

プロジェクトで担当者を選ばずにタスクを作成し、そのステータスに引き継ぎがある場合、タスクはそのステップの担当者に直接渡ります。エージェントならすぐに作業を始めます。作成画面には「作成後に…に引き継ぎます」と引き継ぎ先が表示されます。まだ何も始めたくない場合は Backlog に作成します。

前の担当者がエージェントで、まだ実行中または開始待ちの場合は、確認画面にそれを停止またはキャンセルする選択肢が加わり、最初から選択されています。2 つのエージェントに同時に作業させたい場合以外はそのままで構いません。そのエージェントが投稿したコメントと保存済みの作業は残ります。

「完了したら移動」と「差し戻す先」は、次にタスクをどこへ移すかをエージェントに伝えます。実行が終わっただけではタスクは次に進まず、そのステップを担当するメンバーやエージェントがステータスを更新します。エージェントがタスクを次のステップに移した場合も、そのステップの引き継ぎが同じように行われます。

引き継ぎとその説明はタスクのタイムラインに残ります。プロジェクトのボードにあるワークフローメニューから、流れ全体を確認できます。

## ワークフローを調整する

複数のプロジェクトで同じワークフローを使えます。**設定 → ワークフロー**で保存した変更は、それを使うすべてのプロジェクトに反映されます。1 つのプロジェクトだけ変えたいときは複製し、そのプロジェクトでコピーを選びます。

管理者はプロジェクトのボードからも引き継ぎを設定できます。列の見出しにカーソルを合わせて**引き継ぐ…**をクリックするか、表示されている担当者をクリックします。ほかのプロジェクトと共有しているワークフローでは、**この変更をどこに適用しますか？**と確認されます。現在のプロジェクトだけを選ぶと、そのプロジェクト用にワークフローが複製され、ほかのプロジェクトは変わりません。

列を削除する際、そこにタスクが残っている場合は移動先を選びます。それ以外のタスクは変わらず、この移動でエージェントは起動しません。ワークフロー一覧の下にあるステータスライブラリでは名前や色を変更でき、同じステータスを使う場所すべてに反映されます。

ワークフローを削除するには、先に使用中のプロジェクトを別のワークフローに切り替えます。タスクは今のステータスのまま残ります。

**設定**に**ワークフロー**がない場合、このワークスペースではまだ利用できません。ステータスは引き続き**設定 → タスクステータス**で管理します。
