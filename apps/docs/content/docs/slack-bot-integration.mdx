Existing Slack Bot installations continue to connect a Slack app to one [agent](/agents). Team members can DM the Bot, @-mention it in channels, send files, and use `/issue` without opening Multica.

<Callout type="info">
  New Agent-scoped Slack connections are retired. Existing installations keep
  running and remain visible in **Settings → Integrations**.
</Callout>

## Use an existing Bot

- **Direct messages** become Multica [chat](/chat) sessions with the installation's assigned agent.
- **Channel and group messages** run only when the Bot is @-mentioned.
- **Files** sent with an eligible message are copied into Multica storage for the agent.
- **`/issue <title>`** creates a Multica issue attributed to the linked workspace member.
- **`/new <message>`** runs the message without earlier conversation context while preserving history.

The first message from a Slack user may return a one-time account-linking URL. Open it and sign in with the Multica account that belongs to the workspace. This identity callback remains an independent contract and is not a new Agent connection.

## Manage retained installations

Open **Settings → Integrations** to inspect retained Slack Bots and their assigned agents. Workspace owners and admins can disconnect an installation; disconnecting stops new Slack messages but preserves existing conversations and audit records.

## Self-hosting

Existing encrypted Slack credentials require `MULTICA_SLACK_SECRET_KEY`. Keep the key stable: rotating or losing it makes stored credentials unreadable. Slack Socket Mode connects outbound, so retained installations do not require a public request URL.

## Troubleshooting

- **No new connection action**: this is expected; Agent-scoped browser connection is retired.
- **Bot does not respond**: confirm the retained installation is active, its assigned agent is not archived, and its [runtime](/daemon-runtimes) is online.
- **Account-link prompt repeats**: open the newest single-use link while signed in to the correct workspace.
