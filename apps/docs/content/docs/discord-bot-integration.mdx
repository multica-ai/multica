Multica uses a Bot you create in the [Discord Developer Portal](https://discord.com/developers/applications). One Bot maps to one Multica agent. Create a separate Bot for each agent that needs its own Discord identity.

Discord support is [community-maintained](/community-maintained): it ships in every release, but it carries no official support SLA. Report problems in [GitHub issues](https://github.com/multica-ai/multica/issues).

## Before you start

- A Multica workspace owner or admin must connect the Bot.
- The API server must be able to reach `https://discord.com` and `wss://gateway.discord.gg`.
- You need the Bot token from the Discord Developer Portal. Treat it as a password.

## 1. Create the Bot

1. Open the [Discord Developer Portal](https://discord.com/developers/applications) and create a new application.
2. Open **Bot**, then **Reset Token** and copy the token.
3. Under **Privileged Gateway Intents**, enable **Message Content Intent**. Multica reads message bodies through this intent; without it, server messages arrive with empty content.
4. Under **OAuth2 → URL Generator**, select the `bot` scope and the permissions **View Channels**, **Send Messages**, and **Read Message History**. Open the generated URL to invite the Bot to a server.

<Callout type="warning">
Never paste the token into an issue, chat message, log, or source repository. If it is exposed, reset it in the Discord Developer Portal, then reconnect the Bot with the replacement token.
</Callout>

## 2. Connect it to an agent

1. In Multica, open **Agents**, select an agent, and open **Integrations**.
2. Click **Connect Discord**.
3. Paste the Bot token and click **Connect**.

Multica calls Discord to verify the Bot, encrypts the token, and starts one supervised Gateway connection. A Bot already connected to another agent or workspace must be disconnected there first.

## First use and account binding

The first time a member messages the Bot, it sends a single-use Multica account-binding link. Open it, sign in to the same Multica workspace, then return to Discord and send the message again. The link expires after 15 minutes; message the Bot again to get a new link.

In a server channel, the Bot never posts the bearer link publicly. It asks the sender to start a direct message first.

Only current workspace members can use the Bot. Membership is checked again for every message.

## Use the Bot

### Direct messages

Open a direct message with the Bot and send text directly. No @-mention is required.

### Server channels

Add the Bot to a server channel, then @-mention it. A channel message that does not mention the Bot never starts a conversation or a turn. Each channel is one continuous Multica chat.

### Commands

- `/new` creates a new empty Multica Chat and routes later messages in the Discord conversation to it. `/new <message>` creates the Chat with that message as its first turn.
- `/clear` keeps the current Multica Chat and applies a fresh agent-visible context to the next non-empty message. `/clear <message>` uses that message as the first turn after the context boundary.
- `/issue <title>` creates a Multica issue; following lines are used as its optional description. `/issue` without a title returns usage guidance.

Discord does not register `/issue`, `/new`, or `/clear` as native slash commands. Send them as plain message text. In a server channel, include the @-mention: `@YourBot /issue Fix the build`.

### Replies and supported content

The Bot posts the agent's reply when the run finishes, quoting the triggering message. Long replies are split under Discord's 2000-character message limit. There is no live streaming or message editing.

Files attached to a message reach the agent as a text marker such as `[File: report.pdf]`; the file itself is not downloaded. The agent cannot send files back into Discord yet.

## Manage connections

Open **Settings → Messaging → Discord** to view connected Bots. Owners and admins can disconnect one. Disconnecting closes the Gateway connection and stops outbound replies, but preserves Multica conversations and audit records.

## Self-hosting setup

Set a stable 32-byte encryption key before starting the API server:

```dotenv
MULTICA_DISCORD_SECRET_KEY=<base64-encoded 32-byte key>
```

Generate one with `openssl rand -base64 32`. Keep it long-term: losing or rotating it makes existing Bot tokens unreadable and requires reconnecting each Bot.

Binding links use `MULTICA_APP_URL`, falling back to `FRONTEND_ORIGIN`. The resulting address must be reachable by members. The server's network or proxy must allow HTTPS access to `discord.com` and WebSocket access to `gateway.discord.gg`; Go honors standard `HTTPS_PROXY` and `NO_PROXY` environment variables.

## Troubleshooting

- **Bot cannot be verified**: first check server connectivity and proxy settings. Reset the token only when Discord itself rejects the current one.
- **Server messages arrive empty**: enable **Message Content Intent** for the application in the Discord Developer Portal, then reconnect.
- **No channel reply**: confirm the Bot can view the channel and that the message @-mentions it.
- **Binding link expired**: send the Bot another direct message and use the newest link.
- **Bot does not run**: check whether the agent is archived and whether its [runtime](/daemon-runtimes) is online.
