秘書は、ワークスペース全体に対して一人だけ置かれるエージェントです。スクワッドが行った作業を読み取り、毎日一つのブリーフをあなたのために書きます。ブリーフには、あなたの判断が必要な事項、進行中の事項、行き詰まっている事項が書かれます。スクワッドごとに報告が届くことはありません。

スクワッドは、これまでどおりタスク、プロジェクト、[提案](/office)の中で作業します。あなたに状況報告を書くことはありません。秘書が必要な事実を自分で取得するため、スクワッドは状況報告のために実行回数を使いません。

<Callout type="warning">
オフィスには、まだセットアップのボタン、ブリーフのカード、**問い合わせ** の操作がありません。それらが提供されるまでは、受信トレイの **ブリーフが届きました** という通知と、下の `multica brief` コマンドでブリーフを読みます。秘書のセットアップについては、[SELF_HOSTING.md](https://github.com/multica-ai/multica/blob/main/SELF_HOSTING.md) のアップグレードノートに記載しています。
</Callout>

## 前提条件

- 選んだマシンでオンラインになっている Hermes ランタイム。[エージェントランタイムをインストールする](/install-agent-runtime)の手順でインストールし、Hermes 自体でモデルを設定してください。
- 秘書はそのランタイム一つで動きます。その記憶はそのマシンに保存されるため、ワークスペースを移動しても記憶は移動しません。

## セットアップで作成されるもの

セットアップは次のものを作成します。複数回実行しても重複は作られません。

- **Secretary** という名前のエージェント。非公開に設定され、選んだランタイム上の Hermes を使い、一度に一つの実行だけを行います。
- **Executive** フロアと、その上の **Executive Office** スクワッド。秘書がこのスクワッドのリーダーになり、あなたはメンバーになります。
- 秘書を指定するワークスペース設定。
- 有効な **Daily brief** オートパイロットと、一時停止された **Weekly review** オートパイロット。

## 毎日のブリーフと週次レビュー

どちらも秘書を実行する[オートパイロット](/autopilots)です。

| オートパイロット | 実行時刻 | セットアップ後の状態 |
| --- | --- | --- |
| **Daily brief** | 毎日 08:00、セットアップ時に選んだタイムゾーン | 有効 |
| **Weekly review** | 金曜 17:00 | 一時停止。オートパイロットのページで有効にします。 |

08:00 にマシンがスリープしていた場合、そのオートパイロットの実行は、ほかのオートパイロットと同じく飛ばされます。すぐにブリーフを受け取りたい場合は、オートパイロットの **今すぐ実行** を押してください。

ブリーフが公開されると、ワークスペースのオーナーには受信トレイの通知 **ブリーフが届きました** が一件届きます。秘書から届く定期的な通知はこれだけです。

## ブリーフの内容

ブリーフは、次の六つのセクションを順に持つ Markdown です。

1. **見出し**：三行以内。何も起きていない日は、そのことを書いて短くまとめます。
2. **あなたの判断が必要な事項**：まず判断待ちの提案を並べ、その後にあなたにしか解消できない障害を並べます。各項目には、状況、選択肢、秘書の推奨、リンクを書きます。表示は最大五件までで、残りは件数だけ示します。
3. **進捗**：フロアごとに、動きのあったスクワッドだけを載せます。変化のないスクワッドは一行にまとめます。
4. **障害とリスク**：それぞれに、考えられる解決策を添えます。
5. **注目**：前回のブリーフ以降の、リサーチフロアにおける市場と製品に関するメモ。
6. **その他**：コスト、ランタイム、失敗の異常。

ブリーフは二分で読める長さを目指します。セクションが欠けたブリーフはサーバーが拒否し、どのセクションが足りないかを秘書に伝えます。秘書は修正して再度公開できます。ブリーフ本文は 20,000 文字までです。

## ダイジェスト

ダイジェストは、秘書がブリーフを書くための事実の集まりです。サーバーがデータベースから計算するため、サイズが制限され、モデルに依存しません。

- **スクワッドごと**。最も注意が必要なものから順に並びます。完了、進行中、ブロックされたタスク。72 時間活動のない進行中のタスク。失敗した実行。リーダーが何もしなかった回数。判断待ちの提案。最近完了したタスクへのリンク。
- **動きのないスクワッド**は、一つの一覧にまとめます。
- **ワークスペース全体**。期間内の実行回数とコスト、オフラインのランタイム。

ダイジェストは、最大 20 のスクワッドを詳しく扱います。それ以外は順位付けされて件数だけ示されます。さかのぼれるのは最大 35 日です。

## チャットで秘書に質問する

秘書もエージェントなので、ほかのエージェントと同じようにチャットできます。会社の状況について尋ねると、まずダイジェストを読み、その内容に基づいて答えます。記憶に頼ることはありません。会社が何を知っているか、何を決めたかを尋ねると、まず[ナレッジベース](/knowledge-base)を検索し、見つけた内容を引用します。

秘書があなたの代わりに提案を承認することはありません。回答では、ブリーフやオフィスの **判断** を案内します。

## できること、できないこと

| 秘書ができること | 秘書ができないこと |
| --- | --- |
| `multica` CLI でワークスペースを読む | 提案を判断する。エージェントによる判断はサーバーが拒否します。 |
| ブリーフを公開する | 別のエージェントとしてブリーフを公開する。公開できるのは秘書か管理者メンバーだけです。 |
| スクワッドのリーダーに問い合わせるため、タスクにコメントする（ブリーフあたり最大三回） | スクワッドの作業を実行する。指示により、報告と質問に限られています。 |
| ナレッジベースに下書きを保存する | ナレッジを公開する。下書きは人が公開します。 |

## CLI

秘書はランタイム上でこれらのコマンドを実行します。`publish` は秘書か管理者メンバーである必要があります。

```bash
multica brief digest --since 24h --json
multica brief publish --kind daily --title "Daily brief" --file brief.md --proposal <proposal-id>
multica brief list --kind daily --limit 10
multica brief show <brief-id>
```

| コマンド | 役割 |
| --- | --- |
| `digest` | `--since` で指定した期間のダイジェストを表示します。期間は `30m`、`24h`、`7d` のような長さ、または RFC 3339 のタイムスタンプで指定します。既定は 24 時間です。 |
| `publish` | Markdown ファイルを公開します。`--kind`（`daily`、`weekly`、`ad_hoc`）、`--title`、`--file` が必要です。`--file` には `-` を指定すると標準入力から読みます。ブリーフが取り上げる提案ごとに `--proposal` を繰り返すと、アプリでリンク表示されます。 |
| `list` | 新しい順にブリーフを一覧します。`--kind` で絞り込み、`--limit` で件数を制限します（最大 50）。 |
| `show` | ID を指定して一つのブリーフを表示します。 |

どのコマンドにも `--json` または `--output json` を付けると、機械が読める出力になります。

## 記憶とプライバシー

秘書は、あなたの好みと常設の指示を Hermes の記憶に保存します。会社に関する事実はすべて、実行時点のダイジェストと、そこから参照されるタスクから得ます。記憶は、ランタイムが回収されたり移動されたりすると失われることがあります。そのため、ワークスペースの何もかもが記憶に依存することはありません。

秘書はワークスペース全体を読めるため、セットアップでは非公開のエージェントとして作成されます。誰が実行できるかは、[非公開エージェントのアクセスルール](/agents#permissions-and-access)によって決まります。
