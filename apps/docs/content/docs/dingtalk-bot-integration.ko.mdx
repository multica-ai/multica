기존 DingTalk 연결은 DM과 @멘션을 할당된 [에이전트](/agents)로 계속 보냅니다. `/issue`, `/new`, 이미지, 신원 연결, 발견 그룹 실행도 유지됩니다.

<Callout type="info">
  새 에이전트별 DingTalk 연결과 그룹 재할당은 폐기되었습니다. 기존 연결과 경로 매핑은 실행 호환성을 위해 유지됩니다.
</Callout>

## 기존 Bot 사용

- DM은 할당된 에이전트와의 Multica [Chat](/chat)이 됩니다.
- 그룹에서는 Bot을 @멘션한 메시지만 유지된 그룹 경로로 실행됩니다.
- 대상 메시지의 이미지는 Multica 스토리지로 복사됩니다.
- **`/issue <제목>`**은 연결된 멤버 이름으로 이슈를 만듭니다.
- **`/new <메시지>`**는 기록을 보존하면서 이전 맥락 없이 실행합니다.

첫 대상 메시지에서 일회용 `/dingtalk/bind` URL이 돌아올 수 있습니다. 올바른 워크스페이스로 로그인해 여세요. 이 신원 콜백은 독립 계약입니다.

## 유지된 연결 관리

**Settings → Integrations**에서 기존 Bot과 할당된 에이전트를 확인합니다. 발견된 그룹 경로는 읽기 전용이며 새 재할당은 폐기되었습니다. 워크스페이스 owner와 admin은 연결을 해제할 수 있습니다. 대화와 감사 기록은 유지됩니다.

할당된 에이전트를 보관하면 복원될 때까지 해당 경로의 처리가 중지됩니다.

## 셀프 호스팅

기존 암호화 자격 증명에는 `MULTICA_DINGTALK_SECRET_KEY`가 필요합니다. 저장된 자격 증명을 읽을 수 없게 만들지 않도록 키를 안정적으로 유지하세요. Stream mode는 외부로 연결하므로 공개 webhook URL은 필요하지 않습니다.

## 문제 해결

- **새 연결 또는 경로 선택이 없음**: 에이전트별 writer는 폐기되었습니다.
- **Bot이 응답하지 않음**: 연결, 할당된 에이전트, [Runtime](/daemon-runtimes)을 확인하세요.
