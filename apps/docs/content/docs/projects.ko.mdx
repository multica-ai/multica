프로젝트는 제품 출시, 마이그레이션, 단계적으로 진행하는 기능처럼 여러 [태스크](/issues)를 함께 완료해야 하는 작업을 구성할 때 사용합니다.

하나의 태스크로 충분히 설명할 수 있는 작업에는 프로젝트가 필요하지 않습니다. 프로젝트는 공동 목표가 있고 진행 상황을 한곳에서 추적해야 하거나 저장소와 작업 디렉터리를 공유해야 하는 작업 묶음에 적합합니다.

## 프로젝트의 구성

| 내용 | 용도 |
|---|---|
| **이름, 아이콘, 설명** | 목표, 범위, 장기적으로 적용되는 요구 사항입니다. 설명은 프로젝트 안에서 실행되는 에이전트의 컨텍스트에 포함됩니다. |
| **상태** | `planned`, `in_progress`, `paused`, `completed`, `cancelled` 중 하나입니다. |
| **우선순위** | `urgent`, `high`, `medium`, `low`, `none` 중 하나입니다. |
| **담당자(lead)** | 프로젝트 조율 책임자를 나타내는 멤버 또는 에이전트입니다. |
| **접근 권한** | 전체 워크스페이스 또는 프로젝트 멤버만입니다. [비공개 프로젝트](#private-projects)를 참고하세요. |
| **시작일과 마감일** | 프로젝트의 계획 기간입니다. |
| **태스크와 진행률** | 프로젝트에 속한 작업과 완료 비율입니다. |
| **리소스** | 연결된 GitHub 저장소 또는 지정한 컴퓨터의 로컬 디렉터리입니다. |
| **워크플로** | 태스크가 거칠 단계와 각 단계를 이어받을 담당자. |

## 프로젝트 탐색

**전체 프로젝트**를 열고 표시 메뉴에서 **테이블** 또는 **보드**를 선택합니다. 두 레이아웃 모두 검색과 상태·우선순위·담당자 필터를 지원하며, 같은 항목으로 그룹화할 수 있습니다. 테이블은 그룹화하지 않을 수도 있습니다. 보드에서 프로젝트를 다른 열로 끌어 놓으면 해당 필드가 바뀝니다.

테이블에는 시작일, 마감일, 진행률, 최근 활동을 표시할 수 있으며, 이 필드나 이름, 상태, 우선순위, 생성 시간으로 정렬할 수 있습니다. 레이아웃, 그룹화, 정렬, 표시 열, 필터는 사용자와 워크스페이스별로 저장되어 기기 간에 동기화됩니다. 검색어는 저장되지 않습니다.

## 프로젝트와 태스크의 관계

하나의 프로젝트에는 여러 태스크가 포함될 수 있고, 하나의 태스크는 최대 하나의 프로젝트에만 속할 수 있습니다. 프로젝트에서 바로 태스크를 만들거나 태스크 속성에서 프로젝트를 선택하거나 변경할 수 있습니다.

프로젝트 진행률은 연결된 태스크를 기준으로 자동 계산됩니다.

```text
진행률 = 상태가 done 또는 closed 분류에 속하는 태스크 수 ÷ 프로젝트의 전체 태스크 수
```

기본 상태로는 `done`과 `cancelled`가 여기에 해당하며, 이 두 분류에 속하는 사용자 지정 상태도 똑같이 포함됩니다. `cancelled`는 해당 작업이 프로젝트 범위에서 종료되었다는 뜻이므로 진행률에 포함됩니다.

프로젝트 상태와 태스크 상태는 따로 움직입니다. 모든 태스크가 완료되어도 프로젝트가 자동으로 `completed`가 되지 않고, 프로젝트 상태를 바꿔도 그 안의 태스크가 일괄 변경되지 않습니다.

## 프로젝트 설명과 실행 컨텍스트

에이전트가 프로젝트 안의 태스크를 실행할 때 프로젝트 이름과 설명이 해당 실행의 컨텍스트에 포함됩니다. 목표, 기술적 경계, 납품 규칙처럼 관련된 모든 실행이 알아야 할 정보는 설명에 적고, 하나의 태스크에만 관련된 요구 사항은 그 태스크에 적습니다.

## 리소스 추가

프로젝트 리소스는 에이전트가 사용할 코드와 작업 디렉터리를 지정합니다.

- **GitHub 저장소**: checkout할 수 있는 저장소와 선택적 ref를 제공합니다.
- **로컬 디렉터리**: 지정한 컴퓨터의 런타임이 기존 디렉터리를 사용하게 합니다. 에이전트는 디렉터리를 직접 수정하거나 해당 디렉터리의 독립된 worktree에서 작업합니다.

선택 방법과 안전 경계는 [프로젝트 리소스](/project-resources)를 참고하세요.

## 워크플로 선택하기

프로젝트의 **워크플로**는 보드의 열과 각 단계의 인계 대상을 정합니다. 예를 들어 개발과 리뷰를 각각 다른 에이전트에게 맡기고 마지막 확인은 멤버에게 맡길 수 있습니다. 다른 선택이 없으면 **Default**를 사용합니다. 모든 상태를 쓸 수 있고 자동 인계는 없습니다. 설정과 기존 프로젝트 전환은 [워크플로](/workflows)를 참고하세요.

## 프로젝트 담당자

프로젝트 리드는 멤버 또는 에이전트이며, 리드인 멤버는 프로젝트 워크플로를 바꿀 수도 있습니다. 리드로 지정해도 태스크가 할당되거나 작업이 시작되지는 않습니다. 특정 단계를 리드에게 넘기려면 워크플로에서 그 단계의 처리자를 **프로젝트 리드**로 설정하세요.

## 비공개 프로젝트 [#private-projects]

프로젝트의 **접근 권한**은 **전체 워크스페이스**와 **프로젝트 멤버만** 중 하나입니다. 비공개 프로젝트와 그 안의 태스크, 댓글, 첨부 파일은 멤버 목록에 있는 사람만 볼 수 있습니다. 그 밖의 사람에게는 목록과 검색에 나타나지 않으며, 링크를 열어도 찾을 수 없다고 표시됩니다.

### 비공개 프로젝트를 볼 수 있는 사람

- **멤버 목록에 있는 사람만** 볼 수 있습니다. 워크스페이스 역할로는 접근할 수 없습니다. 목록에 없는 `owner`나 `admin`도 프로젝트를 볼 수 없습니다. 다른 사람과 똑같이 목록에 추가되고, 목록에서 제거될 수도 있습니다.
- **에이전트**는 자신이 대신 일하는 사람을 따릅니다. 실행을 트리거한 사람과 에이전트 소유자가 모두 목록에 있을 때만 그 실행이 비공개 프로젝트를 볼 수 있습니다. 비공개 프로젝트의 태스크는 소유자가 목록에 있는 에이전트에게만 할당할 수 있습니다.
- 워크스페이스를 떠난 멤버는 그 안의 모든 비공개 프로젝트에서도 빠집니다.

<Callout type="info">
`owner`나 `admin`인데 비공개 프로젝트가 더 이상 보이지 않는다면 그 프로젝트의 멤버 목록에 없는 것입니다. 접근 권한을 관리하는 멤버에게 추가를 요청하세요. 워크스페이스 소유자는 설정에서 직접 참여할 수도 있습니다([워크스페이스 소유자 복구](#workspace-owner-recovery) 참고).
</Callout>

### 멤버 목록을 관리할 수 있는 사람

접근 관리란 멤버 추가와 제거, 프로젝트 리드 변경, 프로젝트를 전체 워크스페이스로 되돌리는 일을 말합니다. 다음 사람이 할 수 있습니다.

- 목록에 있는 `owner`와 `admin`.
- 프로젝트가 접근 관리자로 정하는 멤버 한 명. **접근 권한** 대화상자에 **액세스 관리**로 표시됩니다. 리드가 목록에 있는 사람이면 리드, 그렇지 않으면 목록에 있는 생성자, 그것도 아니면 목록에 가장 오래 있었던 멤버입니다.

비공개 프로젝트의 리드도 다른 프로젝트처럼 멤버, 에이전트이거나 비워 둘 수 있습니다. 접근 관리자는 저장되지 않고 매번 리드, 생성자, 목록으로 정해지므로 리드가 바뀌거나 누군가 떠나면 함께 바뀝니다. 사람을 리드로 지정하면 그 사람이 목록에 추가됩니다. 현재 리드를 목록에서 제거하려면 먼저 리드를 바꾸세요. 다른 멤버는 목록을 볼 수 있지만 바꿀 수는 없습니다. 에이전트는 어떤 프로젝트의 접근 권한도 바꿀 수 없습니다.

### 비공개 프로젝트 만들기, 프로젝트를 비공개로 전환하기

- **새 프로젝트**: 생성 대화상자에서 **접근 권한**을 열고 **프로젝트 멤버만**을 선택한 뒤 멤버를 추가합니다. 나는 항상 목록에 포함되며, 리드로 지정한 사람도 포함됩니다.
- **기존 프로젝트**: 프로젝트 속성에서 **접근 권한**을 클릭하고 **프로젝트 멤버만**을 선택합니다. 전체 워크스페이스에 공개된 프로젝트를 비공개로 바꾸려면 `owner`나 `admin`이어야 합니다. 바꾼 사람이 목록에 추가되고, 리드가 사람이면 리드도 함께 추가됩니다.
- **CLI**: `project create`나 `project update`에 `--visibility private`를 붙이고, `--member`(이름, 이메일 또는 사용자 ID, 여러 번 지정 가능)로 처음 목록을 정합니다. 이후에는 `project member list|add|remove`로 목록을 관리합니다.

```bash
multica project create --title "Pricing revamp" --visibility private --member alice@example.com --member Bob
multica project update <project-id> --visibility private --member alice@example.com
multica project member add <project-id> carol@example.com
```

비공개 프로젝트를 **전체 워크스페이스**로 되돌리면 모든 워크스페이스 멤버가 프로젝트와 그 안의 태스크, 댓글, 첨부 파일을 볼 수 있습니다. 앱에서는 저장 전에 확인을 거치지만, `multica project update --visibility workspace`는 바로 적용됩니다.

### 워크스페이스 소유자 복구 [#workspace-owner-recovery]

비공개 프로젝트의 목록에 `owner`나 `admin`이 없거나, 멤버가 한 명도 남지 않을 수 있습니다. 워크스페이스 `owner`는 **설정 → 일반 → 비공개 프로젝트**에서 개입할 수 있습니다. 이 섹션은 소유자에게만 보이며 `admin`에게는 보이지 않습니다. 모든 비공개 프로젝트의 이름과 멤버만 나열되고, 태스크, 댓글, 첨부 파일은 참여하기 전까지 볼 수 없습니다.

**참여**를 클릭하고 확인하면 내가 멤버 목록에 추가됩니다. 다른 멤버처럼 목록에 표시되고, 기존 멤버는 인박스로 알림을 받습니다. 목록에 있는 소유자로서 그 프로젝트의 접근 권한을 관리할 수 있습니다. 참여해도 리드는 바뀌지 않습니다. 멤버가 모두 떠난 프로젝트도 같은 방법으로 복구합니다. 먼저 참여한 다음 프로젝트 페이지에서 관리하거나 삭제하세요.

## 사이드바에 고정

고정한 프로젝트는 내 사이드바에 표시됩니다. 고정은 개인 설정이며 다른 멤버에게 영향을 주지 않습니다.

프로젝트 섹션 설정의 **기본 아이콘만 표시**를 켜면 해당 섹션에서 사용자 지정 프로젝트 아이콘 대신 기본 폴더 아이콘이 표시됩니다. 기본값은 꺼짐이며 프로젝트 자체의 아이콘은 바뀌지 않습니다.

## 보관과 복원

프로젝트 메뉴에서 **프로젝트 보관**을 선택하거나 프로젝트 목록에서 **보관**을 선택합니다. 프로젝트를 편집할 수 있는 사람은 보관하거나 복원할 수도 있습니다. 보관된 프로젝트는 일반 목록과 선택기에서 숨겨지며, 새 태스크를 만들거나 기존 태스크를 옮겨 넣을 수 없습니다. 기존 태스크, 기록, 설정은 유지되고 태스크는 계속 읽고 편집할 수 있습니다. 프로젝트 상태도 바뀌지 않습니다.

해당 프로젝트에 태스크를 만드는 활성 자동화는 일시 중지됩니다. 목록 제목 메뉴에서 **보관된 프로젝트**로 전환해 **복원**을 선택하거나 프로젝트 페이지에서 **프로젝트 복원**을 선택하세요. 프로젝트를 복원해도 자동화는 재개되지 않습니다. 필요할 때 각각 활성화하세요.

## 생성, 수정, 삭제

모든 워크스페이스 멤버가 프로젝트를 만들고 수정할 수 있습니다. 멤버는 자신이나 현재 자신이 소유한 에이전트가 만든 프로젝트를 삭제할 수 있고, 에이전트는 자신이 만든 프로젝트만 삭제할 수 있습니다. 사람인 `owner`와 `admin`은 생성자를 알 수 없는 기존 프로젝트를 포함해 모든 프로젝트를 삭제할 수 있습니다. 비공개 프로젝트는 멤버 목록에 있는 사람만 수정하거나 삭제할 수 있으므로, `owner`나 `admin`도 먼저 목록에 있어야 합니다.

<Callout type="warning">
프로젝트를 삭제해도 그 안의 태스크는 삭제되지 않습니다. 태스크는 프로젝트와 연결이 해제된 뒤 워크스페이스에 계속 남습니다. 프로젝트의 설명, 상태, 리소스는 영구적으로 삭제됩니다.
</Callout>
