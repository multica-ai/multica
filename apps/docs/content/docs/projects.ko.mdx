프로젝트는 제품 출시, 마이그레이션, 단계적으로 진행하는 기능처럼 여러 [이슈](/issues)를 함께 완료해야 하는 작업을 구성할 때 사용합니다.

하나의 이슈로 충분히 설명할 수 있는 작업에는 프로젝트가 필요하지 않습니다. 프로젝트는 공동 목표가 있고 진행 상황을 한곳에서 추적해야 하거나 저장소와 작업 디렉터리를 공유해야 하는 작업 묶음에 적합합니다.

## 프로젝트의 구성

| 내용 | 용도 |
|---|---|
| **이름, 아이콘, 설명** | 목표, 범위, 장기적으로 적용되는 요구 사항입니다. 설명은 프로젝트 안에서 실행되는 에이전트의 컨텍스트에 포함됩니다. |
| **상태** | `planned`, `in_progress`, `paused`, `completed`, `cancelled` 중 하나입니다. |
| **우선순위** | `urgent`, `high`, `medium`, `low`, `none` 중 하나입니다. |
| **담당자(lead)** | 프로젝트 조율 책임자를 나타내는 멤버 또는 에이전트입니다. |
| **시작일과 마감일** | 프로젝트의 계획 기간입니다. |
| **이슈와 진행률** | 프로젝트에 속한 작업과 완료 비율입니다. |
| **리소스** | 연결된 GitHub 저장소 또는 지정한 컴퓨터의 로컬 디렉터리입니다. |

![프로젝트 상세: 상태별로 나뉜 이슈, 진행률, 프로젝트 설명](/images/docs/project-detail.png)

## 프로젝트와 이슈의 관계

하나의 프로젝트에는 여러 이슈가 포함될 수 있고, 하나의 이슈는 최대 하나의 프로젝트에만 속할 수 있습니다. 프로젝트에서 바로 이슈를 만들거나 이슈 속성에서 프로젝트를 선택하거나 변경할 수 있습니다.

프로젝트 진행률은 연결된 이슈를 기준으로 자동 계산됩니다.

```text
진행률 = 상태가 done 또는 cancelled인 이슈 수 ÷ 프로젝트의 전체 이슈 수
```

`cancelled`는 해당 작업이 프로젝트 범위에서 종료되었다는 뜻이므로 진행률에 포함됩니다. 프로젝트 상태와 이슈 상태는 서로 독립적입니다. 모든 이슈가 완료되어도 프로젝트가 자동으로 `completed`가 되지 않으며, 프로젝트 상태를 바꿔도 그 안의 이슈 상태가 일괄 변경되지 않습니다.

## 프로젝트 설명과 실행 컨텍스트

에이전트가 프로젝트 안의 이슈를 실행할 때 프로젝트 이름과 설명이 해당 실행의 컨텍스트에 포함됩니다. 모든 관련 태스크에 필요한 목표, 기술적 경계, 납품 규칙을 설명에 저장하세요. 하나의 이슈에만 관련된 요구 사항은 해당 이슈에 작성합니다.

## 리소스 추가

프로젝트 리소스는 에이전트가 사용할 코드와 작업 디렉터리를 지정합니다.

- **GitHub 저장소**: checkout할 수 있는 저장소와 선택적 ref를 제공합니다.
- **로컬 디렉터리**: 지정한 컴퓨터의 런타임이 기존 디렉터리에서 작업하게 하며, 에이전트가 디렉터리 내용을 직접 수정합니다.

선택 방법과 안전 경계는 [프로젝트 리소스](/project-resources)를 참고하세요.

## 프로젝트 담당자

Lead는 프로젝트 조율 책임자를 나타내는 멤버 또는 에이전트입니다. 권한 설정이 아니며 프로젝트의 이슈를 자동으로 할당하지 않습니다. 에이전트를 lead로 지정해도 자동 실행되지 않습니다. 실행을 시작하려면 여전히 이슈 할당, @멘션, 자동화 트리거 중 하나가 필요합니다.

## 사이드바에 고정

고정한 프로젝트는 내 사이드바에 표시됩니다. 고정은 개인 설정이며 다른 멤버에게 영향을 주지 않습니다.

## 생성, 수정, 삭제

모든 워크스페이스 멤버가 프로젝트를 만들고 수정할 수 있습니다. 삭제는 `owner`와 `admin`만 할 수 있습니다.

<Callout type="warning">
프로젝트를 삭제해도 그 안의 이슈는 삭제되지 않습니다. 이슈는 프로젝트와 연결이 해제된 뒤 워크스페이스에 계속 남습니다. 프로젝트의 설명, 상태, 리소스는 영구적으로 삭제됩니다.
</Callout>
