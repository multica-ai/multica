Existing DingTalk installations continue to route DMs and @-mentions to their assigned [agent](/agents). They also keep `/issue`, `/new`, images, identity linking, and discovered-group execution working.

<Callout type="info">
  New Agent-scoped DingTalk connection and group reassignment are retired.
  Existing installations and route mappings remain available to execution.
</Callout>

## Use an existing Bot

- **Direct messages** become Multica [chat](/chat) sessions with the installation's assigned agent.
- **Group messages** run only when the Bot is @-mentioned and continue to use the retained discovered-group route.
- **Images** sent with an eligible message are copied into Multica storage for the agent.
- **`/issue <title>`** creates an issue attributed to the linked workspace member.
- **`/new <message>`** runs without earlier conversation context while preserving history.

The first eligible message may return a single-use `/dingtalk/bind` account-linking URL. Open it while signed in to the correct Multica workspace. This identity callback remains an independent contract and is not a new Agent connection.

## Manage retained installations

Open **Settings → Integrations** to inspect retained Bots and their assigned agents. Discovered group routes are visible read-only; new Agent reassignment is retired. Workspace owners and admins can disconnect an installation. Existing conversations and audit records are preserved.

If an assigned agent is archived, its retained route stops processing until that agent is restored.

## Self-hosting

Existing encrypted DingTalk credentials require `MULTICA_DINGTALK_SECRET_KEY`. Keep the key stable: rotating or losing it makes stored credentials unreadable. Stream mode connects outbound, so retained installations do not require a public webhook URL.

## Troubleshooting

- **No new connection or route selector**: this is expected; those Agent-scoped writers are retired.
- **Bot does not respond**: confirm the retained installation is active, its assigned agent is not archived, and its [runtime](/daemon-runtimes) is online.
- **Account-link prompt repeats**: open the newest single-use link while signed in to the correct workspace.
