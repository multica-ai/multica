title: 成员与权限
description: 邀请成员，并用 owner、admin 和 member 三种角色管理工作区权限。
---

加入[工作区](/workspaces)的人都是成员，每位成员有一个角色：`owner`、`admin` 或 `member`。角色只控制工作区设置和团队管理；创建 issue、发表评论等日常协作对所有成员开放。

## 三种角色

| 操作 | owner | admin | member |
|---|:---:|:---:|:---:|
| 查看工作区并参与日常协作 | ✓ | ✓ | ✓ |
| 修改工作区设置 | ✓ | ✓ | — |
| 邀请 `admin` 或 `member` | ✓ | ✓ | — |
| 调整或移除 `admin`、`member` | ✓ | ✓ | — |
| 授予、收回或移除 `owner` | ✓ | — | — |
| 删除工作区 | ✓ | — | — |

工作区必须始终保留至少一名 `owner`：最后一名 `owner` 不能被降级、移除或离开。

<Callout type="info">
角色不决定谁能运行智能体。每个智能体有独立的访问范围（Access），`owner` 和 `admin` 也不能绕过它运行未授权的智能体。详见[智能体](/agents#权限与-access)。
</Callout>

## 邀请成员

`owner` 和 `admin` 在设置 → 成员中输入邮箱、选择角色后发送邀请。邀请只能授予 `admin` 或 `member`；`owner` 需要先加入工作区，再由现有 `owner` 提升。

![成员管理：邀请表单与带角色的成员名册](/images/docs/members-roster.webp)

受邀者用该邮箱登录即可接受，无需提前注册。邀请有效期 7 天，过期后重新发送。在限制注册的自部署实例中，还没有账号的受邀者注册时仍受注册规则约束，见[登录与注册](/auth-setup#邀请与注册限制)。

邀请链接只出现在邮件里，产品界面中没有查看或复制它的入口。邮件发送失败时邀请记录仍然存在，可以撤销后重新发送。

## 调整角色

`admin` 可以在 `admin` 和 `member` 之间调整角色，也可以移除这两类成员。涉及 `owner` 的变更——提升、更改或移除——只有 `owner` 能执行。

角色变化立即生效。

## 移除成员

被移除的成员立即失去工作区访问权限。该成员创建的 issue、评论和其他协作记录保留在工作区中。

<Callout type="warning">
移除成员会同时停用该成员拥有的运行时、归档绑定在其上的智能体，并取消尚未结束的执行任务。该成员在智能体访问范围（Access）中获得的授权也会被清除，重新加入后不会自动恢复。
</Callout>
