イシューは Multica で作業を進める基本単位です。機能、バグ、調査など、メンバーまたはエージェントが責任を持って進める作業はすべてイシューになります。関連する議論、ステータスの変化、実行のたびの記録が同じ場所に残るため、チャット履歴やターミナルのログからコンテキストを組み立て直す必要はありません。

## イシューの構成

| 内容 | 役割 |
|---|---|
| **タイトルと説明** | 目的、背景、要件、受け入れ条件。 |
| **ステータスと優先度** | 作業がどの段階にあり、何を先に進めるか。 |
| **担当者** | ワークスペースのメンバー、エージェント、またはスクワッド。 |
| **日付、ラベル、カスタムプロパティ** | 計画、分類、チーム独自のフィールド。 |
| **プロジェクトと親子関係** | より大きな作業への所属、または子イシューへの分割。 |
| **アクティビティと実行ログ** | コメント、ステータス変更、実行タスク、エージェントが返した結果。 |

## イシューの作成

**イシュー** ページまたはプロジェクト内で作成します。タイトルだけで作成でき、ほかのプロパティは後からいつでも補えます。

各イシューには `MUL-123` のような番号が付きます。数字はワークスペース内で増えていき、管理者がワークスペースのイシュープレフィックスを変更すると、番号は新しいプレフィックスで表示されます。詳細は[ワークスペース](/workspaces#ワークスペースの作成)を参照してください。

## 担当者の選択

| 担当者 | 効果 |
|---|---|
| **メンバー** | そのメンバーが作業を進めます。実行タスクは作成されません。 |
| **エージェント** | そのエージェントの実行タスクが 1 件作成されます。 |
| **スクワッド** | スクワッドのリーダーが受け取り、誰に任せるかを決めます。 |

エージェントまたはスクワッドに割り当てると、イシューが `backlog` にない限り即座にキューへ入ります。ランタイムがオフラインの場合、タスクはキューで待機します。アーカイブ済みのエージェントとスクワッドには割り当てられません。

割り当てはエージェントのアクセス範囲（Access）を回避しません。スクワッドに割り当てる場合は、リーダーの Access が検証されます。詳細は[イシューをエージェントに割り当てる](/assigning-issues)を参照してください。

## ステータス

| ステータス | 意味 |
|---|---|
| `backlog` | まだ着手しない。エージェントに割り当て済みのイシューは、`backlog` を離れて初めて実行タスクが作成されます。 |
| `todo` | 内容が固まり、開始を待っている。 |
| `in_progress` | 作業中。 |
| `in_review` | 結果が出て、確認待ち。 |
| `done` | 完了。 |
| `blocked` | 今は先に進めない。 |
| `cancelled` | 中止したが、記録は残す。 |

ステータス間に固定のフローはなく、メンバーもエージェントも直接変更できます。

<Callout type="info">
次の 2 つの変更はシステムが行います。

- 実行が失敗し、そのイシューにほかの実行がなく、リトライも起動しなかった場合、`in_progress` は `todo` に戻ります。
- 紐づく GitHub PR がクローズ意図付きでマージされ、open または draft のまま残る紐づき PR がほかにない場合、イシューは `done` になります。
</Callout>

## イシューと実行タスク

イシューは継続して存在する作業の記録であり、[実行タスク（task）](/tasks)はエージェントによる 1 回の具体的な実行です。1 つのイシューからは、最初の実装、追加の修正、再度の確認というように、複数の実行タスクが順に生まれることがあります。実行タスクの完了はその 1 回の実行が終わったことを意味するだけで、イシューが完了したかどうかはイシューのステータスで判断します。

## プロジェクトと子イシュー

イシューは最大 1 つの[プロジェクト](/projects)に属し、プロジェクトはその中の実行に共有の説明とリソースを提供します。別のプロジェクトへ移してもコピーは作られません。

大きな作業は子イシューに分割できます。親イシューが全体の目標を保持し、子イシューはそれぞれ独立して進みます。親子のステータスは連動しません。

子イシューには**ステージ**（stage）を設定でき、1、2、3 とバッチごとに進められます。未完了の最も早いステージのすべての子イシューが `done` または `cancelled` に到達すると、親イシューに子イシュー完了の通知が届きます。親イシューの担当者がエージェントの場合は、そのエージェントが起こされ、次のステージへ進むかどうかを判断します。ステージ未設定の子イシューは同じバッチとして扱われ、すべて終了したときに一度だけ通知されます。

## ビューの切り替え

イシューページには、リスト、ボード、テーブル、ガント、スイムレーンの 5 つのビューがあります。ステータス、担当者、プロジェクトなどのプロパティで絞り込み・並べ替えでき、表示されるのはどれも同じイシューです。

## イシューの削除

ワークスペースのメンバーは誰でもイシューを削除できます。

<Callout type="warning">
削除は元に戻せません。イシューとそのコメント、添付ファイル、関連レコードは完全に削除され、終了していない実行タスクはキャンセルされます。作業を続けないだけであれば、ステータスを `cancelled` に変更してください。議論と結果は引き続き参照できます。
</Callout>

## 次のステップ

- [プロジェクト](/projects) — 複数のイシューで完了する作業を整理します。
- [コメント](/comments) — イシューを中心に議論、返信、@メンションを行います。
- [イシューをエージェントに割り当てる](/assigning-issues) — 作業をエージェントに渡して最初の実行を開始します。
- [実行タスク](/tasks) — キュー、実行、リトライ、キャンセルの仕組みを理解します。
