채팅 연동을 사용하면 팀이 Multica를 열지 않고도 에이전트에게 바로 질문하고, 그룹 채팅에서 @멘션하거나, 채팅 창에서 이슈를 만들 수 있습니다.

현재 Feishu/Lark와 Slack을 지원합니다. 두 연동은 같은 대화, 신원, 실행 메커니즘을 사용하지만 설치 방법은 다릅니다.

## 플랫폼 선택

| | Feishu / Lark | Slack |
|---|---|---|
| 설치 방법 | Multica에서 QR 코드를 만든 뒤 Feishu로 스캔해 승인 | Slack에서 app을 만든 뒤 두 token을 Multica에 입력 |
| 에이전트와 DM | 지원 | 지원 |
| 그룹 채팅 또는 채널 | Bot을 @멘션하면 트리거 | Bot을 @멘션하면 트리거 |
| 이슈 만들기 | `/issue` 메시지 명령으로 입력 내용을 바로 생성 | `/issue` slash 명령으로 에이전트가 설명을 정리한 뒤 생성 |
| 연결 방식 | 플랫폼 장기 연결 | Socket Mode |

새 연결은 현재 중국 본토 버전 Feishu에서만 만들 수 있습니다. 기존 국제 버전 Lark 연결은 계속 사용하고 관리할 수 있습니다.

Bot 하나는 Multica 에이전트 하나에 연결됩니다. 같은 채팅 플랫폼에서 여러 에이전트를 사용하려면 각각 별도의 Bot을 연결해야 합니다.

자세한 단계는 다음 문서를 참고하세요.

- [Feishu / Lark Bot 연결](/lark-bot-integration)
- [Slack Bot 연결](/slack-bot-integration)

## 메시지 실행 과정

1. Multica가 Bot을 기준으로 해당 워크스페이스와 에이전트를 찾습니다.
2. 그룹 채팅이나 채널에서는 Bot을 명시적으로 @멘션한 메시지만 처리됩니다. DM에서는 @멘션이 필요 없습니다.
3. Multica가 보낸 사람의 계정 연결과 워크스페이스 멤버 자격을 확인합니다.
4. 메시지가 [에이전트 대화](/chat)에 들어가고 실행 태스크가 하나 생성됩니다.
5. 에이전트의 답변이 원래 DM 또는 스레드로 돌아옵니다.

Bot을 @멘션하지 않은 채널 메시지는 에이전트를 트리거하지 않으며 대화 컨텍스트에도 추가되지 않습니다.

## 대화 격리

- Feishu/Lark는 채팅별로 대화를 구분하며 같은 채팅의 후속 메시지는 기존 대화를 이어갑니다.
- Slack DM은 채널별로 구분하고, 채널 안에서는 각 thread가 별도 대화를 저장합니다.

채널에서 후속 질문을 할 때도 Bot을 다시 @멘션해야 합니다. 에이전트는 자신에게 보낸 메시지만 받으며 전체 채널 기록을 자동으로 읽지 않습니다.

## 계정 연결

멤버가 Bot에 처음 메시지를 보내면 계정 연결 링크를 받습니다. Multica에 로그인하면 플랫폼 계정이 현재 워크스페이스 멤버와 연결됩니다.

연결을 마친 뒤에만 Multica가 에이전트를 실행합니다. 메시지마다 계정 연결과 워크스페이스 멤버 자격을 다시 확인하므로 워크스페이스를 떠난 뒤에는 Bot으로 해당 에이전트를 계속 사용할 수 없습니다.

<Callout type="info">
계정 연결은 보낸 사람의 신원을 확인하는 데만 사용됩니다. 채팅 플랫폼의 다른 멤버가 자동으로 Multica 워크스페이스에 참여하지는 않습니다.
</Callout>

## 연결 관리

워크스페이스 owner와 admin은 Bot을 연결하거나 연결 해제할 수 있습니다. Feishu/Lark Bot은 에이전트 owner도 연결하고 연결 해제할 수 있습니다. 일반 멤버는 이미 연결된 연동을 확인하고 자신에게 호출 권한이 있는 에이전트를 사용할 수 있습니다.

연결을 해제하면 Bot이 새 메시지를 받지 않습니다. 기존 Multica 대화와 실행 기록은 그대로 유지됩니다.

## 자체 호스팅

자체 호스팅 환경에서는 해당 플랫폼에 32바이트 암호화 키를 먼저 설정해야 Multica에 연결 메뉴가 열립니다.

```dotenv
MULTICA_LARK_SECRET_KEY=<base64로 인코딩한 32바이트 키>
MULTICA_SLACK_SECRET_KEY=<base64로 인코딩한 32바이트 키>
```

이 키는 Bot 자격 증명을 암호화해 저장하는 데 사용됩니다. 생성, 보관, 교체 방법은 [환경 변수](/environment-variables)를 참고하세요. Multica Cloud에는 이미 설정되어 있습니다.
