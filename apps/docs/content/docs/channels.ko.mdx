기존 채팅 연동에서는 Multica를 열지 않고 에이전트에게 질문하고 그룹에서 @멘션하며 이슈를 만들 수 있습니다.

<Callout type="info">
  새 에이전트별 Bot 연결과 재할당은 폐기되었습니다. 기존 연결, 신원 콜백, 메시지 실행은 유지됩니다.
</Callout>

## 유지되는 동작

| | Feishu / Lark | Slack | DingTalk | WeCom |
|---|---|---|---|---|
| DM | 지원 | 지원 | 지원 | 지원 |
| 그룹 / 채널 | @멘션으로 실행 | @멘션으로 실행 | @멘션으로 실행 | @멘션으로 실행 |
| 이슈 생성 | `/issue` | `/issue` slash command | `/issue` | `/issue` |
| 연결 방식 | 장기 연결 | Socket Mode | Stream mode | 장기 연결 |

각 Bot은 기존 에이전트 매핑을 유지합니다. DingTalk 발견 그룹 경로도 실행을 위해 유지되지만 브라우저에서는 읽기 전용입니다.

## 메시지 처리

1. Multica가 Bot에서 워크스페이스와 에이전트를 확인합니다.
2. 그룹에서는 명시적인 @멘션만 처리합니다.
3. 신원 연결과 워크스페이스 멤버십을 확인합니다.
4. [Chat](/chat)에 합류하고 태스크를 만듭니다.
5. 원래 DM 또는 thread로 응답합니다.

## 계정 연결

첫 메시지에서 일회용 신원 링크가 돌아올 수 있습니다. 이 callback / broker 계약은 새 에이전트 연결과 독립적으로 유지되며 매 메시지마다 멤버십을 확인합니다.

## 유지된 연결 관리

워크스페이스 owner와 admin은 **Settings → Integrations**에서 기존 Bot을 확인하고 연결을 해제할 수 있습니다. 대화와 감사 기록은 유지됩니다.

## 셀프 호스팅

저장된 Bot 자격 증명에는 플랫폼별 32바이트 암호화 키가 필요합니다:

```dotenv
MULTICA_LARK_SECRET_KEY=<base64-encoded 32-byte key>
MULTICA_SLACK_SECRET_KEY=<base64-encoded 32-byte key>
MULTICA_DINGTALK_SECRET_KEY=<base64-encoded 32-byte key>
MULTICA_WECOM_SECRET_KEY=<base64-encoded 32-byte key>
```

유지된 자격 증명을 복호화할 수 있도록 키를 안정적으로 보관하세요.
