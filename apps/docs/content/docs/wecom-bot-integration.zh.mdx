把一个 Multica 智能体连接成企业微信智能机器人后，团队成员可以私聊它、在群里 @ 它，也可以用 `/issue` 创建 issue。对话和执行记录仍会保存到 Multica 工作区。

每个智能机器人只对应一个智能体。需要在企业微信中使用多个智能体时，分别为它们连接机器人。

## 连接机器人

智能体的所有者、工作区 owner 和 admin 可以发起连接：

1. 打开 **智能体**，选择要接入企业微信的智能体。
2. 进入 **集成**，点击 **绑定到企业微信**。
3. 用企业微信扫描二维码并授权创建新的智能机器人。
4. 回到 Multica。页面显示 **已连接到企业微信** 后即可使用。

二维码有效期为 5 分钟；过期后点击 **重新扫码** 即可重新生成。

<Callout type="info">
每次扫码都会在企业微信里创建一个全新的智能机器人，而不是给已有机器人重新授权。断开一个智能体后再重新连接，会得到一个身份完全不同的新机器人，旧机器人不会被复用或恢复。
</Callout>

已经连接的智能体不会再次显示扫码入口。Multica 不提供机器人改名或权限管理功能，这些操作请在企业微信管理后台完成。

## 第一次使用

成员第一次在私聊中给机器人发消息时，会收到一个账号绑定链接：

1. 打开链接并登录 Multica。
2. 确认要关联的工作区账号。
3. 回到企业微信，再发送一次消息。

绑定后，Multica 才能确认消息来自哪位工作区成员。非成员无法使用机器人。这个流程对所有人都适用，包括扫码创建机器人的人 —— 安装机器人和绑定自己的企业微信账号是两个独立的步骤。

绑定链接只能在与机器人的私聊中获取。群聊中未绑定的成员会被引导先私聊机器人。

## 在企业微信中交代工作

### 私聊

直接给机器人发消息即可。连续消息保留在同一段 Multica 对话中，智能体的回复也发回当前对话。

### 群聊

先把机器人加入群聊，再 `@` 它并写下要求。机器人只会响应明确 @ 它的消息；执行时会结合当前会话中可读取的近期上下文。

### 创建 issue

发送：

```text
/issue 修复登录后的跳转问题
Safari 登录成功后仍然停留在登录页。
```

第一行成为标题，后面的内容成为描述。只发送 `/issue` 时，Multica 会尝试使用上一条消息作为标题。

## 管理连接

打开 **设置 → 集成** 可以查看工作区内已连接的机器人。工作区 owner 和 admin 可以在这里断开连接；智能体所有者也可以回到该智能体的 **集成** 页面管理自己的机器人。

断开后，机器人不再接收新消息，已有的对话和审计记录不会随之删除。

<Callout type="warning">
断开连接只是解除机器人与 Multica 的关联，并不会删除企业微信里的智能机器人。如果需要彻底删除，请自行到企业微信管理后台操作。
</Callout>

## 自托管配置

Multica Cloud 无需额外配置。自托管部署需要先设置一个用于加密机器人凭据的密钥：

```dotenv
MULTICA_WECOM_SECRET_KEY=<base64 编码的 32 字节密钥>
```

可以这样生成：

```bash
openssl rand -base64 32
```

重启 API 服务后，再从智能体的 **集成** 页面连接机器人。该密钥需要长期保存：更换或丢失后，已有凭据无法解密，需要重新连接。

Multica Cloud 和自托管部署默认共用同一个内置的企业微信"调用来源"（source）id 来创建智能机器人，这是既定设计，不构成安全边界，自托管用户无需自行申请。`MULTICA_WECOM_SOURCE_ID` 仅用于调试或未来更换来源时覆盖该默认值，正常情况下不需要设置。

## 常见问题

- **没有绑定按钮**：确认当前账号是智能体所有者、工作区 owner 或 admin，并检查自托管密钥是否已配置。
- **二维码失效**：有效期只有 5 分钟，关闭弹窗后重新发起连接即可。
- **机器人要求绑定账号**：打开绑定链接并使用该工作区的 Multica 账号登录。即使你是安装该机器人的人，也需要完成这一步。
- **短暂断连后很晚才收到回复**：Multica 会自动重发连接中断期间未能送达的回复，但只回溯最近 24 小时；更早的消息不会补发。
- **机器人不执行**：检查智能体是否已归档，以及它使用的[运行时](/daemon-runtimes)是否在线。
- **重新连接后旧机器人还在企业微信里**：这是预期行为 —— Multica 断开连接不会删除企业微信里的智能机器人。如果不再需要，请到企业微信管理后台手动删除。
