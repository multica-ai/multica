有些决定不应每次都等你。**自主**决定小队在无需请示的情况下能做多少事，**标准授权**则预先批准一类窄范围的提案。你事后看到结果，而不是事前审批。

## 自主等级

每个小队的等级从 0 到 3，默认为 1。只有你或管理员可以更改，每次更改都会记入治理日志。评审可能建议更改，并以提案形式提交。

| 等级 | 名称 | 平台允许的范围 |
| --- | --- | --- |
| L0 | Suggest（建议） | 小队的例行任务被暂停。只有在有人分配或提及它时才运行。仍可提交提案。 |
| L1 | Work（工作） | 例行任务运行。小队可以研究、分析、撰写知识草稿并提交提案。所有决定都由你做。 |
| L2 | Trusted（可信） | 同 L1。其知识草稿可在评审后发布。标准授权可以批准其提案。 |
| L3 | Autonomous（自主） | 同 L2。标准授权还可以在预算和上限范围内，从其自身机会创建第一阶段的倡议。 |

有两件事与等级无关。**发布**始终由你决定，**组织变更**同样如此。开支始终受[预算](/budgets)限制。

<Callout type="warning">
自主只限制平台的行为：哪些例行任务运行、什么内容发布到共享记录、哪些提案在无需你的情况下被决定、创建哪些倡议，以及花费多少。它不限制智能体在运行中的行为。智能体可以调用其凭据允许的外部服务。请限制凭据范围，并对任何对工作区外产生影响的操作设置外部关卡。
</Callout>

**治理**中的 Autonomy 标签页列出每个小队的等级并可修改。小队面板和公司会以标签显示等级。API 为 `GET` 和 `PUT /api/squads/{id}/autonomy`。

## 标准授权

**策略**描述你预先批准过的一类提案：

- **类型**：提案类型之一（`decision`、`opportunity` 或 `goal`）。以下类型永远不符合条件，会被拒绝：`org_change`、发布关卡、`budget`、`stage_gate`，以及 `standing_approval` 本身；
- **匹配条件**：覆盖哪些小队或楼层、最高成本，以及负载必须相等的字段。按标签匹配会被拒绝，因为提案不带标签；
- **每周上限**：1 到 50，默认 3；
- 可选的**有效期至**日期，以及启用标志。

小队提交提案时，策略引擎会检查每条启用的策略。策略只在提交小队为 L2 或以上时适用；对于会创建倡议的机会类提案，则需要 L3。提案必须匹配，每周上限未用完，并且不得是紧急提案。其估算成本必须在策略的最高金额和小队剩余预算之内。

匹配后，提案以该策略的名义获得批准，效果与人工批准相同，并记录一条治理事件。下一份简报会在 **Auto-approved by policy**（由策略自动批准）下列出它。若某项自动批准的内容在评审中被推翻，每周评审会标记该策略。

只有你或管理员可以创建策略。智能体可以以 `standing_approval` 提案的形式提议策略，由你像其他提案一样批准。任何智能体都不能修改策略或自主等级。

要撤销策略，在 Autonomy 标签页的 **Policies** 部分中撤销即可。撤销立即生效，并会被记录。

```bash
curl -X POST "$MULTICA_API/api/approval-policies" -H "Authorization: Bearer $MULTICA_TOKEN" \
  -H "X-Workspace-ID: $WORKSPACE_ID" -H "Content-Type: application/json" \
  -d '{"name": "Pilot follow-ups", "kind": "decision", "match": {"squad_ids": ["<squad-id>"], "max_cost_micros": 5000000}, "max_per_week": 2}'
```

其他策略端点为 `GET /api/approval-policies`、`POST /api/approval-policies/{id}/revoke`，以及 `GET /api/approval-policies/{id}/auto-approvals`。CLI 没有策略命令。

## 知识发布与自主

等级低于 L2 的小队，其知识草稿不会自动发布，无论发布策略如何设置。参见[知识分类](/knowledge-taxonomy)。
