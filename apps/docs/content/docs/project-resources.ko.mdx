[프로젝트](/projects) 리소스는 이 작업 묶음에 어떤 코드가 필요하며 어디에서 실행할지 에이전트에게 알려 줍니다. 리소스는 프로젝트에 계속 연결되어 있으므로 각 이슈에 저장소 주소나 로컬 경로를 반복해서 붙여 넣을 필요가 없습니다.

현재 두 가지 리소스를 지원합니다.

| 리소스 | 적합한 경우 | 실행 위치 |
|---|---|---|
| **GitHub 저장소** | 팀이 공유하는 코드베이스이며 런타임이 checkout을 관리해야 할 때 | 런타임이 관리하는 작업 디렉터리 |
| **로컬 디렉터리** | 이미 존재하는 checkout, 매우 큰 저장소, 로컬 변경 내용을 직접 확인해야 할 때 | 지정한 컴퓨터의 원본 디렉터리 |

## 리소스가 실행에 들어가는 방식

에이전트가 프로젝트 안의 이슈를 처리하면 Multica가 프로젝트 이름, 프로젝트 설명, 리소스 목록을 실행 컨텍스트에 추가하고 작업 디렉터리에 `.multica/project/resources.json`을 기록합니다.

워크스페이스에 연결된 저장소 목록은 항상 실행 컨텍스트에 포함됩니다. 프로젝트에 연결된 저장소는 그중 이 작업 묶음에서 사용할 코드와 기본 ref를 지정합니다.

로컬 디렉터리는 연결된 데몬에서만 유효합니다. 이번 실행을 담당한 데몬에 일치하는 로컬 디렉터리가 있으면 에이전트가 해당 디렉터리로 바로 들어가 작업합니다. 다른 컴퓨터에서는 프로젝트의 GitHub 저장소 또는 워크스페이스 저장소를 계속 사용합니다.

## GitHub 저장소 추가

프로젝트를 열고 **리소스**에서 "리소스 추가"를 선택합니다. 워크스페이스에 이미 연결된 저장소를 고르거나 Git URL을 붙여 넣을 수 있습니다. 워크스페이스 저장소는 **설정 → 코드 저장소**에서 관리합니다. GitHub를 연결한 뒤 같은 페이지에서 **GitHub에서 선택**을 통해 App에 승인된 저장소를 가져올 수 있습니다.

저장소는 GitHub로 제한되지 않습니다. 런타임이 접근할 수 있는 Git URL이라면 모두 저장소 리소스로 사용할 수 있습니다. 자체 배포한 Multica에서는 **설정 → 연동 → Git 코드 호스팅**에서 자체 호스팅 Forgejo, Gitea, GitLab을 연결할 수도 있습니다. [자체 호스팅 Git 코드 호스팅](/vcs-integration)을 참고하세요.

프로젝트를 만들 때 **Repos**에서 바로 저장소를 선택할 수도 있습니다. 하나의 프로젝트에 여러 GitHub 저장소를 연결할 수 있습니다.

리소스의 `ref`에는 이후 checkout에서 기본으로 사용할 브랜치, tag, commit을 지정할 수 있습니다. `default_branch_hint`는 에이전트에게 기본 브랜치 힌트만 제공하며 강제로 브랜치를 전환하지 않습니다.

## 로컬 디렉터리 추가

브라우저는 컴퓨터의 폴더를 선택할 수 없으므로 로컬 디렉터리 추가 화면은 Desktop에서만 제공됩니다.

<Callout type="warning">
**이것은 비상구이지, 더 편리한 기본값이 아닙니다.** `local_directory`는 다른 선택지가 없는 사람들을 위해 존재합니다 — 대표적인 사례는 체크아웃 하나가 수십 기가바이트인 게임 프로젝트로, 작업마다 다시 클론하는 것이 현실적으로 불가능한 경우입니다.

대상 디렉터리가 평범하게 클론할 수 있는 일반 git 저장소라면 **대신 `github_repo`를 사용하세요**: 기본적으로 워크트리 모드로 동작하므로 같은 저장소에 대한 작업을 무제한으로 동시에 실행할 수 있습니다. `local_directory`를 선택한다는 것은 그 폴더의 작업이 이후로 **항상 한 번에 하나씩 직렬로** 실행된다는 뜻입니다. 결정하기 전에 위의 리소스 비교를 확인하세요.
</Callout>


1. Desktop의 로컬 데몬이 온라인인지 확인합니다.
2. 프로젝트의 **리소스**를 엽니다.
3. "로컬 디렉터리 추가"를 선택한 뒤 사용할 폴더를 고릅니다.

디렉터리는 절대 경로여야 하고 이미 존재해야 하며 현재 데몬이 읽고 쓸 수 있어야 합니다. 시스템 루트와 드라이브 루트(`/`, `C:\`), 사용자 홈 디렉터리 자체 및 각 홈 디렉터리의 상위 경로(`/Users`, `/home`, `/root`), 그리고 `/etc`, `/var`, `/tmp`, `/usr`, `/opt` 같은 시스템 디렉터리는 거부됩니다. 선택한 경로가 심볼릭 링크이면 실제 경로를 먼저 해석한 뒤 같은 규칙으로 다시 확인하며 직렬 잠금도 실제 경로를 기준으로 적용됩니다.

프로젝트 하나에는 같은 데몬에서 로컬 디렉터리를 최대 하나만 연결할 수 있습니다. 팀의 서로 다른 컴퓨터에서는 같은 프로젝트에 각자의 디렉터리를 연결할 수 있습니다.

<Callout type="warning">
로컬 디렉터리는 격리된 환경이 아닙니다. 에이전트가 현재 브랜치와 커밋하지 않은 파일을 직접 보고 수정합니다. Multica는 브랜치 전환, stash, commit, push, PR 생성을 자동으로 수행하지 않습니다.
</Callout>

## 로컬 디렉터리 직렬 실행

두 실행 태스크가 같은 실제 디렉터리를 사용하면 나중에 도착한 태스크가 `waiting_local_directory` 상태로 들어가 앞선 태스크가 디렉터리를 해제할 때까지 기다립니다. 서로 다른 심볼릭 링크 경로가 같은 디렉터리를 가리켜도 직렬로 실행됩니다.

기다리는 동안 디렉터리는 변경되지 않습니다. 대기 중인 태스크는 취소할 수 있으며 취소하지 않으면 디렉터리를 사용할 수 있을 때까지 계속 기다립니다.

여러 변경 작업을 동시에 처리해야 한다면 GitHub 저장소 리소스를 사용하세요. 런타임이 작업마다 별도 작업 디렉터리를 준비합니다.

## 실행 중 기록되는 내용

에이전트가 만든 코드 변경 외에도 런타임이 현재 AI 코딩 도구에 필요한 지시 파일과 `.multica/project/resources.json`을 디렉터리에 기록할 수 있습니다. 버전 관리에 포함하고 싶지 않다면 `.gitignore`에 추가하세요.

Multica가 실행 환경을 정리할 때 연결된 로컬 디렉터리는 삭제하지 않습니다. 에이전트가 이 디렉터리에 만든 변경은 터미널에서 AI 코딩 도구를 직접 실행해 만든 변경과 성격이 같으므로 동일하게 검토해야 합니다.

## CLI로 리소스 관리

```bash
# 프로젝트를 만들면서 저장소 연결
multica project create \
  --title "Agent UX" \
  --repo https://github.com/multica-ai/multica

# 리소스 확인 및 추가
multica project resource list <project-id>
multica project resource add <project-id> \
  --type github_repo \
  --url https://github.com/multica-ai/multica \
  --ref main

# 지정한 데몬의 로컬 디렉터리 연결
multica project resource add <project-id> \
  --type local_directory \
  --local-path /absolute/path/to/repo \
  --daemon-id <daemon-id>

# 리소스 제거
multica project resource remove <project-id> <resource-id>
```

리소스 변경은 이후 생성되는 실행 태스크에 적용되며 이미 끝난 실행 기록은 바꾸지 않습니다.
