工作区是 Multica 的最上层边界。成员、issue、项目、智能体、skill 和执行记录都属于某一个工作区，彼此完全隔离。

## 工作区的组成

| 类别 | 内容 |
|---|---|
| **工作** | Issue、项目、评论、附件、执行记录 |
| **团队** | 成员、角色、邀请 |
| **智能体** | 智能体配置、skill、运行时、自动化 |
| **共享设置** | 上下文、标签、自定义属性、集成 |

**上下文**会提供给工作区中的每个智能体，适合写团队背景、产品约定和长期有效的要求。一次性的任务要求写在对应的 issue 里。

## 创建工作区

创建时填两项：

- **名称**：展示给成员，之后可以修改。
- **工作区 URL**：地址中的 slug，例如 `multica.ai/my-team` 里的 `my-team`。只能用小写字母、数字和连字符，不能与已有工作区或保留地址重复，创建后不可修改。

创建者自动成为 `owner`。issue 前缀由工作区名称自动生成，例如前缀为 `MUL` 时，issue 编号显示为 `MUL-1`、`MUL-2`，在工作区内独立递增。

## 修改设置

`owner` 和 `admin` 可以修改名称、图标、描述、上下文和 issue 前缀；`member` 只能查看。

![工作区设置：名称、上下文、slug、issue 前缀与危险区](/images/docs/workspace-settings.png)

<Callout type="warning">
修改 issue 前缀后，所有 issue 立即换用新编号（`MUL-5` 变为 `NEW-5`），但 PR、分支名和聊天记录里的旧编号不会更新。
</Callout>

## 切换和离开

一个账号可以加入多个工作区。切换只改变当前查看的范围，不移动任何数据。

离开工作区后，需要重新接受邀请才能回来。离开会同时停用你拥有的运行时、归档绑定在其上的智能体，并取消它们未结束的执行任务。

最后一名 `owner` 不能离开，需要先把另一位成员提升为 `owner`。

## 删除工作区

只有 `owner` 可以删除工作区。删除会永久移除其中的全部工作、成员、智能体配置和执行记录，无法恢复。暂时不参与时选择离开，而不是删除。
