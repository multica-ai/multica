CLI Multica menghubungkan runtime lokal sekaligus mengelola ruang kerja, tugas, agent, dan otomatisasi dari terminal. Halaman ini membahas alur yang umum digunakan; flag yang didukung oleh versi yang Anda instal selalu ditentukan oleh `--help` masing-masing command.

## Instalasi

<Tabs groupId="os" persist items={["macOS / Linux", "Windows"]}>
<Tab value="macOS / Linux">

```bash
curl -fsSL https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.sh | bash
```

Jika Homebrew sudah terinstal, Anda juga bisa menjalankan:

```bash
brew install multica-ai/tap/multica
```

</Tab>
<Tab value="Windows">

Jalankan di PowerShell:

```powershell
irm https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.ps1 | iex
```

</Tab>
</Tabs>

Konfirmasi instalasi:

```bash
multica version
```

## Koneksi pertama

Pilih layanan yang ingin Anda hubungkan:

<Tabs items={["Multica Cloud", "Instance self-hosted"]}>
<Tab value="Multica Cloud">

```bash
multica setup
```

</Tab>
<Tab value="Instance self-hosted">

```bash
multica setup self-host \
  --server-url https://api.example.com \
  --app-url https://app.example.com
```

</Tab>
</Tabs>

`setup` menyimpan alamat server, membuka browser untuk menyelesaikan proses masuk, dan menjalankan daemon. Setelah selesai, periksa:

```bash
multica auth status
multica daemon status
```

Jika Anda hanya perlu masuk kembali tanpa menimpa konfigurasi lain, jalankan `multica login`. Pada komputer tanpa browser, buat token akses pribadi di pengaturan web terlebih dahulu, lalu masukkan dengan:

```bash
multica login --token
```

Command ini meminta Anda menempelkan token di terminal, sehingga nilai lengkapnya tidak masuk ke histori shell.

## Memilih ruang kerja

Lihat daftar ruang kerja dan ganti ruang kerja default:

```bash
multica workspace list
multica workspace switch <slug>
```

Command berikutnya menggunakan ruang kerja ini. Satu command tertentu dapat menimpanya dengan `--workspace-id`, atau Anda bisa mengatur `MULTICA_WORKSPACE_ID`.

Undang anggota:

```bash
multica workspace member invite teammate@example.com
multica workspace member invite admin@example.com --role admin
```

## Operasi tugas yang umum

```bash
# Lihat dan cari
multica issue list
multica issue get MUL-123
multica issue search "kegagalan login"

# Buat dan perbarui
multica issue create --title "Perbaiki kegagalan login"
multica issue status MUL-123 in_progress
multica issue assign MUL-123 --to "Backend Agent"

# Komentar dan eksekusi
multica issue comment list MUL-123
multica issue comment add MUL-123 --content "Periksa dulu tes regresi"
multica issue comment update <comment-id> --expected-revision 2 --content "Periksa tes regresi dan catatan rilis"
multica issue runs MUL-123
```

Baca deskripsi atau komentar yang panjang dari stdin agar tidak perlu menangani baris baru dan tanda kutip:

```bash
multica issue create --title "Catatan pembaruan" --description-stdin < notes.md
multica issue comment add MUL-123 --content-stdin < review.md
multica issue comment update <comment-id> --expected-revision 2 --content-file revised-review.md
```

Periksa, hentikan, atau ulangi satu eksekusi:

```bash
multica issue run-messages <task-id> --issue MUL-123
multica issue cancel-task <task-id> --issue MUL-123
multica issue rerun-task <run-id> --issue MUL-123
multica issue rerun-task <run-id> --issue MUL-123 --fresh
```

Tambahkan komentar ke eksekusi yang masih berjalan, alih-alih mengantrekan eksekusi lanjutan (hanya untuk eksekusi yang menerima pesan tambahan; Anda bisa mengarahkan agent tepat ketika komentar Anda memang dapat memulainya):

```bash
multica issue comment add MUL-123 --content-file note.md --steer <task-id>
multica issue comment add MUL-123 --content-file note.md --steer-active
```

Jika `issue comment add` timeout atau koneksinya terputus, komentar mungkin sudah tersimpan. Di dalam eksekusi agent, menjalankan ulang command yang sama aman: CLI mengirim idempotency key yang diturunkan dari eksekusi, tugas, parent, konten, dan attachment, dan server mengembalikan komentar yang sudah tersimpan alih-alih memostingnya lagi. Di tempat lain, berikan `--idempotency-key <key>` yang sama pada setiap percobaan untuk mendapatkan perlindungan yang sama. Server lama mengabaikan key ini.

Jika tugas terbuka dengan judul yang sama (tidak peka huruf besar/kecil, spasi berlebih diabaikan) sudah ada di bawah proyek dan parent yang sama, `issue create` menolak dan menunjuk ke tugas tersebut. Untuk tetap membuat tugas lain, tambahkan `--allow-duplicate`. Untuk menandai tugas sebagai duplikat dari tugas lain, jalankan `multica issue status MUL-124 cancelled --duplicate-of MUL-123`.

Untuk pengiriman PR secara berurutan, gunakan `issue create --title "..." --pr-auto-complete off` atau `issue update <id> --pr-auto-complete off` agar status tugas tersebut tetap ketika PR di-merge. Gunakan `--pr-auto-complete on` untuk mengembalikan aturan ruang kerja; ini berlaku pada event PR berikutnya. `issue pull-requests <id>` menampilkan override tugas, pengaturan ruang kerja, status target, dan status keputusan, bahkan tanpa PR yang terhubung. Server yang didukung menyimpan override saat pembuatan secara atomik; server lama menerima PUT lanjutan. Jika itu gagal, CLI melaporkan ID tugas yang dibuat dan command update untuk dicoba ulang, jadi jangan ulangi create.

### Update massal

Terapkan perubahan yang sama ke beberapa tugas, atau berikan satu key atau UUID tugas per baris dengan `--ids-stdin`:

```bash
multica issue batch update MUL-123 MUL-124 --priority high --add-label QA --dry-run
multica issue batch update MUL-123 MUL-124 --priority high --add-label QA
multica issue batch update MUL-123 MUL-124 --property "Severity=High" --unset-property Reviewer
```

`--add-label` dan `--remove-label` tidak mengubah label lain; `--clear-labels` menghapus label sebelum penambahan apa pun. `--property` mengatur nilai dan `--unset-property` menghapusnya; properti multi-nilai diganti secara keseluruhan. Status, assignee, proyek, tanggal, parent, dan stage juga didukung. Tambahkan `--no-start` untuk menerapkan perubahan tanpa memulai eksekusi agent.

Setiap tugas mendapat hasilnya sendiri: `updated`, `unchanged`, atau `skipped` beserta alasannya. Jika ada tugas yang di-skip, command mencetak hasilnya dan keluar dengan kode bukan nol; perubahan yang berhasil tetap berlaku. Perbaiki dan coba ulang hanya tugas yang di-skip. `--dry-run` menampilkan pratinjau pemeriksaan dan perubahan yang dimaksud tanpa menulis.

### Menghapus tugas

Hapus satu tugas, atau berikan beberapa key tugas atau UUID lengkap untuk menghapusnya sekaligus:

```bash
multica issue delete MUL-123
multica issue delete MUL-123 MUL-124 --yes --output json
```

Penghapusan bersifat permanen: komentar dan attachment dihapus, eksekusi yang sedang berjalan dibatalkan, eksekusi autopilot yang terkait digagalkan, tanda duplikat yang menunjuk ke tugas yang dihapus dibersihkan, dan sub-tugas dilepas tanpa dihapus. Setiap ID di-resolve sebelum konfirmasi; tugas yang tidak dikenal atau tidak dapat diakses membatalkan command sebelum penghapusan.

Command ini meminta konfirmasi. `--yes` melewati prompt; tanpa itu, eksekusi non-interaktif yang tidak bisa menjawab akan gagal tanpa menghapus apa pun.

`--dry-run` memeriksa apa yang akan dihapus, termasuk izin penghapusan, tanpa menulis atau meminta konfirmasi:

```bash
multica issue delete MUL-123 MUL-124 --dry-run --output json
```

### Timeline

`issue get` menampilkan tugas sebagaimana kondisinya sekarang. `issue timeline` mencantumkan secara berurutan perubahan status, prioritas, assignee, judul, dan tanggal serta hasil eksekusi, bercampur dengan komentar, sehingga menjawab pertanyaan seperti "kapan pindah ke in_review" atau "sudah berapa lama tertahan di status ini":

```bash
multica issue timeline MUL-123 --action status_changed
multica issue timeline MUL-123 --activity-only --output json
multica issue timeline MUL-123 --since 2026-08-19T00:00:00Z
```

`--activity-only` membuang komentar dan mempertahankan setiap catatan aktivitas; `--action` hanya mengembalikan action yang diberikan, dapat diulang, dan otomatis mengaktifkan `--activity-only`. Server membatasi seberapa jauh ke belakang pembacaan; ketika hasilnya terpotong, peringatan dikirim ke stderr, dan durasi sebaiknya tidak disimpulkan darinya.

### Membaca thread komentar yang panjang

Pada tugas dengan banyak komentar, membacanya satu per satu menghabiskan banyak token bagi agent. Pindai thread terlebih dahulu, lalu buka yang Anda butuhkan:

```bash
multica issue comment list MUL-123 --roots-only --summary --output json --compact
multica issue comment list MUL-123 --thread <comment-id> --tail 5 --output json --compact
```

- `--roots-only` hanya mengembalikan komentar tingkat atas, masing-masing dengan jumlah balasan dan waktu aktivitas terakhir.
- `--summary` memotong setiap komentar menjadi pratinjau singkat.
- `--compact` berlaku untuk output JSON dan membuang field yang tidak membawa informasi (seperti `issue_id` yang digemakan dan array kosong).
- `--recent N` mengembalikan N thread dengan aktivitas terbaru beserta semua balasannya, yang bisa panjang.
- Thread yang sudah resolved dilipat menjadi root dan kesimpulannya secara default; tambahkan `--full` untuk teks lengkap.

Daftar juga bisa dipangkas ke field yang Anda butuhkan: `multica issue list --output json --fields id,identifier,title,status`. Pemfilteran dilakukan di CLI, jadi ini mengecilkan output dan konteks, bukan request.

Untuk mendaftar tugas berdasarkan waktu pembaruan terakhir, berikan `--updated-since` dan `--updated-until` sebagai timestamp RFC3339. Server mengembalikan tugas yang `updated_at`-nya saat ini sama dengan atau setelah `since` dan sebelum `until`: `[since, until)`. Flag ini bekerja bersama filter, pengurutan, dan paginasi yang ada. Pertahankan batas yang sama di semua halaman; pembaruan bersamaan dapat mengubah kumpulan hasil karena paginasi tidak menyediakan snapshot.

```bash
multica issue list --updated-since 2026-11-05T10:00:00Z \
  --updated-until 2026-11-05T10:01:00Z \
  --sort created_at --direction asc --limit 100 --offset 0 \
  --output json --fields id,workspace_id,project_id,title
```

### Wakeup

Wakeup memulai eksekusi biasa untuk agent ketika suatu event terjadi, suatu kondisi menjadi benar, atau waktu tertentu tiba. Aturan lengkapnya ada di [Wakeup tugas](/issue-wakeups).

```bash
multica issue wakeup events
multica issue wakeup create MUL-123 --agent-id <agent-id> \
  --event comment.created --filter-actor-type member --filter-actor-id <user-id> \
  --instruction "When they reply, update the quote from their answer"
multica issue wakeup create MUL-123 --agent-id <agent-id> \
  --kind every --every 1h --expires-in 72h \
  --instruction "Check whether the supplier has replied"
multica issue wakeup list MUL-123
multica issue wakeup runs MUL-123 <wakeup-id>
```

Membuatnya dari terminal sebagai member memerlukan `--agent-id`; agent yang membuatnya di dalam eksekusinya sendiri membangunkan dirinya sendiri secara default.

## Wakeup chat [#chat-wakeups]

Hanya agent di dalam eksekusi chat yang dapat menggunakan `chat wakeup`; percakapan saat ini bersifat implisit. Command ini tidak menerima ID sesi dan tidak dapat digunakan dari terminal member biasa atau eksekusi tugas. Lihat [Tindak lanjut nanti](/chat#follow-up-later) untuk kontrol sisi pengguna.

```bash
multica chat wakeup create --title "Review ready" \
  --until-issue MUL-123 --state in_review --expires-in 48h \
  --instruction "Summarize the result in this conversation"
multica chat wakeup create --title "Check back in two hours" \
  --after 2h --instruction "Remind the user to review the result"
multica chat wakeup list
```

Gunakan tepat satu kondisi `--until-*`, `--at` / `--after`, atau `--every`. Pembuatan dan update memerlukan `--title` dan `--instruction` (atau `--instruction-file`). `update` mengganti konfigurasi dan memulai ulang tenggat relatif; command ini tidak dapat mengubah wakeup antara kondisi, pengingat, dan pemeriksaan. Kondisi dan pemeriksaan default ke 24 jam dan mengizinkan maksimal 7 hari melalui `--expires-in` atau `--expires-at`; pengingat mengizinkan maksimal 30 hari dan tidak menerima flag kedaluwarsa. Pemeriksaan berjalan dengan jarak minimal 10 menit, dan tenggat boleh mengizinkan maksimal 100 pemeriksaan: `--every 10m` dengan default 24 jam akan menjadi 144 pemeriksaan dan ditolak, jadi gunakan interval yang lebih panjang atau tenggat yang lebih awal seperti `--expires-in 16h`.

Kondisi mendukung `--until-issue` dengan `--state` atau `--status`, `--until-children-done` dengan `--stage` opsional, `--until-pr`, `--until-run`, dan `--until-reply` dengan `--from <user-id>` opsional. Kondisi PR menggunakan PR GitHub yang dimirror di ruang kerja ini: `owner/repo#N[:merged|closed|checks]`. `checks` menunggu check selesai pada head saat ini, baik lulus maupun gagal. Kondisi `checks` hanya dapat dibuat ketika server membaca status CI dari GitHub; server self-hosted memerlukan `GITHUB_APP_ID` dan `GITHUB_APP_PRIVATE_KEY` (lihat [Integrasi GitHub](/github-integration)). Hasil check yang sudah selesai saat pembuatan dicatat sebagai baseline dan tidak langsung membangunkan agent.

Gunakan `list`, `get <id>`, atau `cancel <id>` untuk memeriksa atau membatalkan wakeup. Selama pemeriksaan berkala, `checkin <id> --note "..."` mencatat pembaruan senyap tanpa mengirim balasan; `finish <id>` mengakhiri pemeriksaan ketika tujuannya tercapai. Giliran tenggat akhir harus melapor kembali dan tidak dapat check-in secara senyap.

## Agent dan skill

```bash
multica agent list
multica agent get <agent-id>
multica agent create --help
multica agent update <agent-id> --help

multica skill list
multica skill get <skill-id>
multica skill import --url <skill-url>
multica agent skills add <agent-id> --skill-ids <skill-id>
```

Ketika proses import menemukan skill dengan nama yang sama, perilaku default adalah berhenti tanpa mengubah konten yang sudah ada. Pilih sesuai maksud Anda:

```bash
multica skill import --url <skill-url> --on-conflict overwrite
multica skill import --url <skill-url> --on-conflict rename
multica skill import --url <skill-url> --on-conflict skip
```

`overwrite` hanya diizinkan untuk pembuat skill tersebut dan tetap mempertahankan ID asli serta binding ke agent.

Environment variable dan konfigurasi MCP sering membawa token. Nilai yang diketik di command line tersimpan di histori shell dan output `ps`, jadi berikan melalui bentuk `-file` atau `-stdin`:

```bash
multica agent create --name "Ops helper" --runtime-id <runtime-id> \
  --custom-env-file ./agent-env.json \
  --mcp-config-file ./mcp.json \
  --custom-args '["--max-turns", "40"]'

multica agent env set <agent-id> --custom-env-stdin < agent-env.json
multica agent update <agent-id> --mcp-config-file ./mcp.json
```

- Flag `--custom-env` hanya ada pada `agent create`. Ubah variabel nanti dengan `agent env set`, yang mengganti seluruh set; key yang nilainya `****` mempertahankan nilai yang ada.
- `agent update --mcp-config null` menghapus konfigurasi MCP.
- `--custom-args` adalah array JSON yang ditempatkan di akhir argumen peluncuran. Pilih model dengan `--model`; beberapa tool menolak `--model` di dalam argumen kustom.
- `--permission-mode` mengontrol siapa yang dapat memanggil agent: `private` hanya untuk owner, atau `public_to` dengan `--public-to-workspace` atau `--public-to-member <user-id>`. `--visibility private|workspace` adalah bentuk lama dan dipetakan ke `--permission-mode`; ketika keduanya diberikan, `--permission-mode` yang dipakai.

### Riwayat eksekusi agent

`multica agent tasks <agent-id> --limit 200` mengembalikan halaman terbaru dari eksekusi.
Ukuran halaman default dan maksimum adalah 200. Jika masih ada eksekusi lain, stderr menampilkan
cursor; teruskan tanpa diubah sebagai `--before '<cursor>'` untuk membaca halaman berikutnya.
`--output json` mempertahankan output array dan menyertakan usage hanya untuk halaman tersebut.

Endpoint `GET /api/agents/{id}/tasks` yang terkait menerima `limit` dan
`before`, dan tetap mengembalikan response array JSON. Header response `X-Agent-Tasks-Next-Cursor`
menyediakan cursor berikutnya; jika tidak ada, berarti ini halaman terakhir.
Cursor mempertahankan urutan `(created_at, id)`, termasuk presisi timestamp.
Limit atau cursor yang tidak valid mengembalikan HTTP 400; limit di atas 200 akan dibatasi.
Klien yang tidak mengikuti cursor hanya menerima 200 eksekusi terbaru.


## Daemon dan runtime

```bash
multica daemon start
multica daemon stop
multica daemon restart
multica daemon status --output json
multica daemon logs --follow

multica runtime list
multica runtime rename <runtime-id> "Office Mac"
multica runtime usage <runtime-id>
multica runtime activity <runtime-id>
```

```bash
multica daemon autostart enable
multica runtime usage <runtime-id> --days 30
multica runtime update <runtime-id> --target-version <version> --wait
multica runtime profile create --display-name "Internal Claude wrapper" \
  --command-name ccms --runtime-type claude
```

`daemon autostart` mendaftarkan profil saat ini agar berjalan saat login; lihat [Jalankan saat login](/daemon-runtimes#autostart) untuk detail per platform. `runtime usage` mencakup 90 hari secara default, dan `--days` hingga 365. `runtime update` meminta daemon di komputer tersebut untuk memperbarui CLI-nya ke versi yang diberikan. Berbeda dengan mengeklik **Update** di halaman **Runtimes** (yang [mengantre saat sibuk](/daemon-runtimes#updating-cli)), permintaan ini tidak diantrekan: jika mesin sedang menjalankan task, update gagal alih-alih menunggu. `--wait` menunggu hingga selesai dan keluar dengan kode bukan nol jika update gagal atau timeout, atau jika penantiannya sendiri timeout. `runtime profile create` menerima tool yang kompatibel melalui `--runtime-type` (`--protocol-family` yang lama tetap berfungsi); argumen tetap saat ini hanya dapat diatur di aplikasi web. `runtime profile create` mengikat profil ke mesin ini secara default; gunakan `--daemon-id <id>` untuk memilih mesin lokal terdaftar lainnya. Ikat profil lama yang tidak memiliki scope dengan `multica runtime profile update <profile-id> --daemon-id <id>`.

Menghapus runtime yang masih memiliki agent aktif yang terikat padanya akan ditolak secara default. `multica runtime delete <id> --cascade` melepas ikatan agent tersebut, mempertahankan konfigurasi dan riwayatnya, serta membatalkan eksekusi aktifnya.

Lihat [Daemon dan runtime](/daemon-runtimes) untuk cara kerjanya dan profil khusus.

## Environments [#environments]

```bash
multica env start web
multica env start web --wait=false
multica env list
multica env stop web
```

`multica env` (bentuk panjang `multica environment`) memulai environment yang dideklarasikan repository di `.multica/environments.toml`. Daemon mengawasinya, sehingga tetap berjalan setelah eksekusi berakhir, tampil di sidebar tugas, dan berhenti pada TTL-nya. `start` menunggu hingga environment merespons dan mencetak URL-nya. Command ini memakai kredensial task yang sedang berjalan, jadi hanya berfungsi di dalam eksekusi agent; dari komputer Anda sendiri, gunakan sidebar tugas. Lihat [Environments](/environments) untuk format file dan contohnya.

## Proyek, ruang kerja, dan autopilot

```bash
multica project create --title "Summer campaign" --lead "Lei Li" \
  --repo https://github.com/acme/campaign-site
multica project resource add <project-id> --type github_repo \
  --url https://github.com/acme/brand-assets --default-branch-hint main

multica workspace create --name "Operations" --slug ops --issue-prefix OPS
multica workspace update --context-stdin < team-context.md

multica autopilot create --title "Weekly sales report" --agent "Ops helper" \
  --mode create_issue --issue-title-template "Sales report {{date}}"
multica autopilot trigger-add <autopilot-id> --cron "0 9 * * 1" --timezone Europe/London
```

- `--lead` menerima nama member atau agent. `--default-branch-hint` hanya memberi tahu agent branch default repository; ini tidak berpindah branch.
- `--context` ruang kerja diberikan ke setiap agent di ruang kerja tersebut. `--slug` tidak dapat diubah setelah pembuatan. `--issue-prefix` diubah menjadi huruf besar; mengubahnya menomori ulang setiap tugas yang ada, dan identifier lama di referensi eksternal tidak lagi ter-resolve.
- `--issue-title-template` hanya menginterpolasi `{{date}}` (UTC, `YYYY-MM-DD`) dan menolak token `{{...}}` lainnya. `--timezone` pada trigger schedule default ke UTC.

### Filter event webhook [#webhook-event-filters]

Gunakan `--event-filters-file` pada `autopilot trigger-add` atau `trigger-update` untuk mengonfigurasi filter event dan action pada trigger webhook. Simpan array JSON yang tidak kosong sebagai `filters.json`:

```json
[
  {"event": "pull_request_review", "actions": ["submitted"]},
  {"event": "push"}
]
```

Setiap baris juga boleh menyertakan `conditions`, dengan aturan field payload yang sama seperti di aplikasi. Misalnya, baris ini hanya menerima pull request non-draft yang menargetkan `main`:

```json
{
  "event": "pull_request",
  "conditions": [
    { "path": "pull_request.draft", "op": "equals", "value": false },
    { "path": "pull_request.base.ref", "op": "equals", "value": "main" }
  ]
}
```

Setiap aturan mendukung hingga 20 kondisi. Path field dapat berisi maksimal 256 karakter, dan daftar `in` dapat berisi maksimal 100 nilai. Membuat atau memperbarui trigger dengan kondisi yang terlalu besar mengembalikan HTTP 400.

Ini menerima pengiriman review PR dan semua event push. Menghilangkan `actions` atau memakai array actions kosong menerima setiap action untuk event tersebut.

```bash
multica autopilot trigger-add <autopilot-id> --kind webhook --event-filters-file filters.json
multica autopilot trigger-list <autopilot-id> --full-id
multica autopilot trigger-update <autopilot-id> <trigger-id> --event-filters-file filters.json
multica autopilot get <autopilot-id> --output json
```

File tersebut menggantikan seluruh daftar filter saat update. Menghilangkan kedua opsi filter mempertahankan filter yang tersimpan, termasuk ketika memperbarui label atau mengaktifkan/menonaktifkan trigger. `autopilot get` mengembalikan filter di array `triggers` tingkat atas.

Untuk menghapus semua filter dan menerima setiap event, gunakan flag khusus update:

```bash
multica autopilot trigger-update <autopilot-id> <trigger-id> --clear-event-filters
```

`--clear-event-filters` dan `--event-filters-file` tidak dapat digabungkan. `null` tingkat atas atau array kosong, field yang tidak dikenal, JSON yang rusak, dan nama event/action yang kosong ditolak. Opsi ini hanya berlaku untuk trigger webhook; membuat trigger tanpa file filter menerima semua event. Lihat [Autopilot](/autopilots#event-filters) untuk cara event masuk dicocokkan.

## Ringkasan command

| Command | Fungsi |
| --- | --- |

## ID dan format output

Tugas menggunakan key seperti `MUL-123` atau UUID lengkap; prefix UUID yang dipersingkat tidak diterima.

Command `list` untuk resource lain biasanya menampilkan ID singkat yang dapat disalin dan mendukung `--full-id` untuk UUID lengkap. Ketika ID singkat ambigu, CLI akan meminta karakter tambahan atau UUID lengkap. ID eksekusi (task) yang singkat juga memerlukan `--issue` untuk mengidentifikasi tugas pemiliknya.

Banyak command mendukung output terstruktur:

```bash
multica issue list --output json
multica agent list --output json
```

Script sebaiknya menggunakan output JSON daripada mem-parsing tabel yang ditujukan untuk terminal. Format output dan flag paginasi yang didukung masing-masing command ditentukan oleh `multica <command> --help`.

## Profil dan konfigurasi

Konfigurasi default berada di `~/.multica/config.json`. Gunakan `--profile <name>` untuk mengisolasi kumpulan alamat server, token, ruang kerja default, dan status daemon secara terpisah:

```bash
multica setup self-host --profile staging \
  --server-url https://api.staging.example.com \
  --app-url https://app.staging.example.com

multica issue list --profile staging
```

Profil bernama berada di `~/.multica/profiles/<name>/config.json`. Periksa nilai saat ini:

```bash
multica config show
multica config show --profile staging
```

Jangan mengatur `MULTICA_DAEMON_PORT` di shell host, Compose service, atau container entrypoint yang menjalankan daemon. Daemon host biasanya menentukan health port-nya dari `--profile`; jika port tersebut tidak dapat di-bind, daemon memakai port loopback yang tersedia dan menyuntikkan port sebenarnya ke dalam task agent sendiri. Hapus variabel ini sepenuhnya dari environment startup lama: jika tidak, versi 0.4.22 dan 0.4.23 akan salah mengira shell tersebut sebagai task yang dikelola dan menolak login. Versi yang lebih baru memungkinkan login manusia yang dijaga (guarded) dan `daemon status` untuk tetap berfungsi ketika port menjadi satu-satunya sinyal task, tetapi command API biasa dan command yang me-resolve profil tetap secara sengaja fail-closed hingga variabel tersebut dihapus.

Saat CLI berjalan di dalam task agent yang dikelola daemon, CLI tidak memuat atau mengubah file profil milik manusia ini. Command API Multica melakukan autentikasi dengan kredensial yang dibatasi pada task (task-scoped) yang disuntikkan oleh daemon. `config show` dan `config set` menggunakan state privat yang bersifat lokal pada task; command manusia/lokal seperti `login`, `logout`, `setup`, `workspace switch`, perubahan path profil runtime lokal, `daemon start` / `stop` / `restart`, `daemon logs`, dan `daemon probe-runtimes` tidak tersedia. `auth status` tidak menampilkan materi token dalam konteks ini.

`daemon status` dan `daemon disk-usage` tetap tersedia sehingga agent dapat memeriksa runtime yang menghostingnya, dibatasi pada runtime tersebut: `status` memeriksa health port yang disuntikkan daemon, dan `disk-usage` memindai root workspace yang disuntikkan daemon. Keduanya tidak menerima `--profile`; `disk-usage` juga menolak `--all-profiles` dan `--workspaces-root`, dan kolom STATUS-nya kosong karena me-resolve-nya akan memerlukan token tersimpan milik manusia. Gunakan `du` dan `df` untuk hal lain di luar lingkup ini.

Ini melindungi resolusi profil CLI Multica yang bersifat implisit, sambil tetap mempertahankan variabel `HOME` dan XDG normal yang digunakan oleh tool penyedia lain. Ini bukan batas filesystem di level OS: proses yang berjalan sebagai pengguna sistem yang sama tetap dapat membuka path yang sudah diketahui secara eksplisit. Gunakan pengguna khusus, container, VM, atau isolasi setara jika jaminan yang lebih kuat tersebut diperlukan.

<Callout type="warning">
File konfigurasi CLI berisi token yang dapat mengakses Multica sebagai Anda. Jangan commit file ini ke repository, unggah ke log, atau bagikan ke orang lain.
</Callout>

## Referensi command

Tabel berikut mencakup semua command tingkat atas (top-level) saat ini, dikelompokkan sama seperti pengelompokan di CLI itu sendiri. Semua command menerima flag global `--server-url`, `--workspace-id`, `--profile`, dan `--debug`. `--output` didaftarkan per command, dan format default-nya berbeda-beda: command `list` secara default menampilkan tabel, sedangkan command `get` dan `create` sebagian besar default ke JSON. Flag lengkap ditentukan oleh `multica <command> --help`.

### Attachment tugas

Untuk `issue create`, `issue update`, dan `issue comment add`, setiap `--attachment` menerima satu path file literal, termasuk koma atau tanda kutip ganda dalam nama file. Ulangi flag untuk beberapa file: `--attachment 'report,final.csv' --attachment notes.txt`. Tanpa flag ini tidak ada file yang dilampirkan; path kosong yang eksplisit adalah error. Semua path lokal diperiksa sebelum file apa pun diunggah.

Migrasi dari parsing CSV: ganti `--attachment a,b` dengan `--attachment a --attachment b` untuk melampirkan dua file. Bentuk yang lama kini memilih satu file bernama `a,b`. Hapus tanda kutip CSV tambahan dari workaround lama `--attachment '"report,final.csv"'`; gunakan `--attachment 'report,final.csv'` kecuali nama filenya sendiri memang mengandung tanda kutip ganda tersebut.

## Mengoperasikan Multica dari agent coding lain

Jika sebagian besar pekerjaan Anda sudah berlangsung di Codex, Claude Code, atau Cursor, Anda
dapat mengoperasikan Multica dari sana tanpa perlu beralih ke terminal. [Skill Multica CLI](https://github.com/multica-ai/multica-cli)
mengajarkan agent tersebut untuk menjalankan command di halaman ini secara aman: membaca tugas dan thread
komentar tanpa menghabiskan token secara berlebihan, menulis komentar melalui file, dan menangani
efek samping yang dibawa oleh mention, perubahan status, dan penugasan.

Skill ini berjalan sepenuhnya melalui CLI Anda yang sudah terautentikasi dan tidak memberikan akses sendiri —
izin tetap berasal dari login, profil yang dipilih, dan ruang kerja Anda. Dibutuhkan CLI v0.4.26 atau
yang lebih baru. README repository menjelaskan instalasi untuk Claude Code plugin marketplace, installer
skill Codex, Cursor, dan tool lain apa pun yang memuat instruksi Markdown.
