任务是 Multica 中安排工作的基本单位：一项功能、一个 bug、一次调研，只要需要成员或智能体负责推进，都可以建成任务。围绕它的讨论、状态变化和每次执行都记在这条任务里，不用再去聊天记录或终端日志里翻找。

## 任务的组成

| 内容 | 用途 |
|---|---|
| **标题和描述** | 目标、背景、要求和验收条件。 |
| **状态和优先级** | 工作处于哪个阶段，先处理什么。 |
| **负责人** | 工作区成员、智能体或小队。 |
| **日期、标签和自定义属性** | 计划、分类和团队自己的字段。 |
| **项目和父子关系** | 归入更大的工作范围，或拆成子任务。 |
| **动态和执行日志** | 评论、状态变化、运行和智能体返回的结果。 |
| **产物** | 评论中上传的文件，同名文件按版本归在一起。 |

## 创建任务

在**任务**页面或项目中新建。点侧栏的**新建任务**或按 `C`，创建对话框会用你上次用的方式打开：**手动创建**由你填写标题和属性，填了标题就能创建，其余属性随时补充；**通过智能体创建**只需要写一段需求。两种方式可以在对话框底部切换，切换不会丢掉已经填写的内容。

每个任务有一个编号，例如 `MUL-123`。数字在工作区内递增；管理员修改工作区的任务前缀后，编号会用新前缀显示。详见[工作区](/workspaces#创建工作区)。

### 通过智能体创建

写下要做的事，选一个智能体或小队作为**创建者**，点击**创建**。对话框随即关闭，智能体在后台把需求整理成标题和描述，建好任务，成功或失败都会通知到你的收件箱。失败的通知里有**在完整表单中编辑**，点开后原来写的需求会填进手动创建的表单。

<IssueDraftDemo />

- 智能体按原意复述需求，不会替你补上没提过的要求或验收条件。
- 需求里点名了负责人（例如"交给李雷"），就按点名分配；没点名时，负责人是创建者本身，选的是小队时是这个小队。新任务的状态是 `todo`，所以负责人是智能体时，任务建好后它会接着开始处理。
- 对话框里选的项目、优先级和截止日期会原样使用，智能体不会从文字里另行推断。项目默认显示，优先级和截止日期在 **⋯** 菜单里；常驻显示哪些字段，在**设置 → 偏好设置 → 创建任务时显示的字段**中调整。
- 打开**继续创建**后，提交完对话框不会关闭，可以接着写下一条。
- 创建者列表只包含你有权分配的智能体和小队。智能体所在运行时的 multica CLI 版本过低时，对话框会提示升级守护进程，或改用手动创建。

## 选择负责人

| 负责人 | 效果 |
|---|---|
| **成员** | 由这位成员负责跟进，不创建运行。 |
| **智能体** | 为该智能体创建一次运行。 |
| **小队** | 由小队 leader 接收，再决定交给谁处理。 |

分配给智能体或小队时，任务不在 `backlog` 就会立即入队；运行时离线时，运行留在队列中等待。已归档的智能体和小队不能被分配。

分配不会绕过智能体的访问范围（Access）；分配给小队时，校验的是 leader 的 Access。详见[分配任务给智能体](/assigning-issues)。

## 状态

每个工作区都自带 7 个内置状态，归入 4 个生命周期分类。

<Tabs items={["按分类", "按状态"]}>
<Tab value="按分类" id="status-categories">

| 分类 | 内置状态 | 含义 |
|---|---|---|
| `unstarted` | `backlog`、`todo` | 还没开始的工作，不论是已规划还是暂时搁置。 |
| `started` | `in_progress`、`in_review`、`blocked` | 已经开始、等待检查，或暂时无法继续。 |
| `done` | `done` | 顺利完成，终态。 |
| `closed` | `cancelled` | 不再继续，终态，但不算顺利完成。 |

分类只用来判断任务处在生命周期的哪一段。看板、列表、筛选和排序都按具体状态工作，智能体和自动化依赖的特殊行为也挂在具体状态上。

</Tab>
<Tab value="按状态" id="built-in-statuses">

| 状态 | 含义 |
|---|---|
| `backlog` | 暂不启动。已分配给智能体的任务需离开 `backlog` 后才会创建运行。 |
| `todo` | 已明确，等待开始。 |
| `in_progress` | 正在处理。 |
| `in_review` | 已有结果，等待检查。 |
| `done` | 已完成。 |
| `blocked` | 暂时无法继续。 |
| `cancelled` | 不再继续，保留记录。 |

</Tab>
</Tabs>

成员和智能体可以直接修改状态。项目使用[工作流](/workflows)时，只能选择这个工作流中的步骤。进入设有交接的步骤，还会更换负责人，并可能请智能体开始工作。

智能体会随工作进展更新任务状态：默认开始工作时改为 `in_progress`，交付后改为 `in_review`；项目使用工作流时，按其中的步骤和交接说明推进。

<Callout type="info">
两个变化由系统执行：

- 执行失败，且该任务没有其他执行、也没有触发重试时，`in_progress` 回到 `todo`。
- 任务的所有关联 PR 都合并时，任务改为工作区选定的状态（默认 `done`），除非工作区设置为不改变，或该任务设置了合并后不改状态。详见 [GitHub 集成](/github-integration)。
</Callout>

### 自定义状态

工作区的 `owner` 或 `admin` 可以添加自己的状态，比如**代码审查**、**QA**、**返工**。设置中有**工作流**时，在它下方的状态库中管理；没有时，在**设置 → 任务状态**中管理。

创建时要为它选一个分类：未开始、已开始、已完成或已关闭，之后不能更改。自定义状态不会自动获得内置状态的特殊行为，例如取名"等待"并不会让智能体暂停。

- 内置状态的名称、颜色不能修改，也不能归档。
- 自定义状态始终显示你填写的名字。修改名称或颜色，会同步到所有使用它的地方。
- 归档前，需把使用这个状态的所有任务移到其他合适的状态，包括已完成或已取消的任务；也需从使用它的自定义工作流中移除。归档后，设置状态时不再提供这个选项。

状态库保存可用的状态；项目的工作流决定任务使用其中哪些状态，以及它们的顺序。

## 自定义属性

团队自己的字段，例如严重程度、客户、预算，用自定义属性添加。工作区的 `owner` 或 `admin` 在**设置 → 属性**中管理，一个工作区最多同时启用 20 个属性。

类型有文本、数字、单选、多选、日期、勾选、链接、成员、成员（多选）、文本列表和链接列表，创建后不能更改。属性可以用于筛选；看板还能按单选属性分组，数字和日期属性可以用来排序。

不再使用的属性可以归档：它从选择器和筛选中隐藏，任务上已有的值保留，之后可以恢复。

## 任务与运行

任务是持续存在的工作记录；[运行](/tasks)是智能体的一次具体执行。一个任务可以先后产生多次运行——第一次实现、补充修改、再次检查。运行"已完成"只表示这一次执行结束，智能体回答了一个问题也不代表任务本身的工作已经交付；任务是否完成，以任务的状态为准。

## 产物

成员和智能体在评论里上传的文件，会汇总到任务侧栏的**产物**区。这里直接列出最新的 3 张图片和 4 个其他文件，点**查看全部**可以按评论分组浏览全部产物，并按图片、文档、视频和其他筛选；在文件查看器里按 `G` 也能打开这个页面。任务描述里的附件算作输入材料，不计入产物。

同名、同类型的文件再次上传，算作同一份产物的新版本。产物区只列一份，标出版本号（例如 `v2`），评论里的文件卡片也标着各自是第几版。在查看器里点版本号可以切到旧版本，点**定位到评论**回到上传它的那条评论。

## 项目和子任务

一个任务最多属于一个[项目](/projects)，项目为其中的执行提供共享说明和资源；移到另一个项目不会产生副本。

较大的工作可以拆成子任务：父任务保留整体目标，子任务各自独立推进。父子状态互不联动。

子任务可以设置**阶段**（stage），按 1、2、3 分批推进。当前最早未完成阶段的全部子任务到达 `done` 或 `cancelled` 时，父任务会收到"子任务完成"通知；父任务的负责人是智能体时，它会被唤醒并决定是否推进下一阶段。未设置阶段的子任务视为同一批，全部结束时通知一次。这次唤醒由系统发起，规则和其他唤醒方式见[任务唤醒](/issue-wakeups)。

## 视图和显示设置 [#切换视图]

任务页面提供列表、看板、表格、甘特图和泳道五种布局，可按状态、负责人、项目和其他属性筛选，展示的都是同一批任务。

**显示**菜单调整当前布局：看板可以按状态、负责人、项目或单选属性分组，泳道按父级任务、项目或负责人分组；还可以设置排序、是否显示子任务、卡片上显示哪些属性，以及看板显示哪些列（有状态筛选时不能调整列）。

### 保存视图

常用的筛选和显示组合可以存成视图：点视图栏旁的**视图**按钮，选择**新增视图**，填写名称和可见性。

| 可见性 | 谁能看到 | 谁能编辑和删除 |
|---|---|---|
| **仅自己可见** | 只有你 | 你 |
| **工作区成员可见** | 工作区全体成员 | 你，以及工作区的 `owner` 和 `admin` |

视图里保存的显示设置是**默认显示**：成员第一次打开时按它显示，之后各自调整，互不影响。视图只在创建它的页面出现：在项目里建的只属于这个项目；在**我的任务**里建的视图始终仅自己可见。

视图栏中的视图可以拖动排序，**管理视图**里调整顺序和是否显示，只影响你自己。右键点击视图可以编辑、删除，或**固定到侧栏**。

### 悬浮预览

点击任务卡片或列表行，默认打开详情页。在**设置 → 偏好设置 → 打开任务**中改成**悬浮预览**后，任务会在页面右侧的浮层中打开，页头和工具栏仍可使用。不论选哪种，按住 Shift 点击都会用另一种方式打开。这项设置只作用于当前设备。

预览打开时，`J` / `K` 切换到下一条或上一条任务，看板中 `H` / `L` 在相邻列之间切换，`Esc` 关闭；点**打开完整页面**进入详情页。

## 批量修改

在列表、表格或子任务列表中勾选多条任务，页面底部会出现批量工具栏，可以一次修改状态、优先级、负责人，或删除。表格中按住 Shift 可以连续勾选一段。

- 选中的任务分属多个项目时，状态菜单只提供它们的工作流都允许的状态。个别任务不支持某项修改时，它保持原样，其余照常更新。
- 批量改状态直接生效。已分配给智能体的任务离开 `backlog` 后会开始运行。
- 批量分配给智能体或小队时，会先确认将要开始的运行；所选任务都在 `backlog` 时直接分配。

## 标记为重复

同一件事被建了两次，在多出来的那条任务上，从状态菜单或任务操作菜单的**关系**中选择**标记为重复**，再选出原始任务。选择列表会先给出标题相近的任务和你最近看过的任务。

确认后，这条任务改为 `cancelled`，并记下原始任务：

- 标题上方出现**重复于**横幅，链接到原始任务并显示它当前的状态；在列表、看板和表格中，任务旁显示指向原始任务编号的箭头。
- 原始任务的侧栏多出**重复项**，列出标成它重复的任务和各自的创建者。
- 标错了，点横幅上的**不是重复**，任务回到 `todo`。把状态改成 `cancelled` 以外的任何状态，标记同样会去掉。

重复关系只有一层：已经是重复的任务不能作为原始任务，已有重复项的任务也不能再标成别人的重复。项目的工作流里没有 `cancelled` 时，任务操作菜单不提供这一项。

## 删除任务

任何工作区成员都可以删除任务。

<Callout type="warning">
删除不可恢复：任务及其评论、附件和关联记录会被永久移除，尚未结束的运行会被取消。不再继续时把状态改为 `cancelled`，讨论和结果仍可查阅。
</Callout>
