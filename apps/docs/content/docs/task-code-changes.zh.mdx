---
title: 任务代码变更
description: 按执行运行浏览已提交的变更，无需连接 Git 服务商。
---

工作区所有者和管理员可以在**设置 → 代码**开启**任务代码变更**，默认关闭。它独立于 GitHub 集成；开启后从新的执行开始采集，关闭后停止采集与浏览，保留已保存的历史。

在任务详情侧栏打开**代码变更**，选择执行历史，浏览文件树和红绿行号差异。默认显示最近有变更且可读的一次执行，后续只读审核不会覆盖此前的实现或修正。此处展示所选执行的变更，不是整个任务的累计差异。

运行时比较仓库起始提交与交付提交，把有界快照保存到 Multica。分支合并和工作目录回收不会改变快照。有权读取该任务的工作区成员可以读取对应快照，因此开启此项会通过工作区共享已提交的源码变更；仓库的权限策略不适合时，请保持关闭。

## 支持的执行路径

- 配置的本地仓库，包括一次性本地 worktree。
- 执行中通过 `multica repo checkout` 按需检出的仓库。
- 多个已登记仓库，每个文件保留对应仓库的固定提交范围。

不会自动搜索通过其他方式克隆的仓库。未提交的编辑不包含在差异内，若仍有未提交内容会明确提示。二进制、空差异、采集失败和大小上限也有对应状态。主动取消会停止采集，原有取消回执仍保留分支与工作目录。

采集共用 15 秒预算，最多 100 个仓库、100 个文件、每文件 200 KiB、总差异 2 MiB，编码和解压后的 JSON 均限制为 8 MiB。达到上限会标记不完整。源码独立于任务摘要和普通任务事件保存，服务端不挂载运行时的仓库。

删除工作区时，既有清理事务会同步删除相关快照；来源运行被单独删除后，既有清理循环也会回收孤立记录。

终态报告会保留本地快照，直到服务端确认已保存摘要，或明确因开关关闭、任务取消而丢弃。服务端降级忽略新字段时，不会静默确认快照；重放不重新运行智能体，也不覆盖已有快照。dispatch 换代或重绑到其他非空运行时后，旧快照不再开放读取。已保存的终态快照在运行时删除后仍可读取，但已删除运行时不能补交此前未保存的快照。
