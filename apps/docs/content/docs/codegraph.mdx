---
title: CodeGraph
description: Give agents read-only access to indexed repository snapshots.
---

CodeGraph indexes source code and Markdown/YAML documents from a Git repository.
Agents can search symbols, inspect call relationships, and read source lines
without checking out the repository on their own computer.

## Add a repository

Git credentials can be managed before importing the first repository, from the
CodeGraph welcome page or beside the credential field in the registration form.
If the environment has no encryption key, credential management explains why
Token storage is unavailable; this is separate from having no saved credentials.

Open **Team → Resources → CodeGraph → Register repository**. Enter an HTTPS Git URL and branch.
Choose a saved Git credential for a private repository, or explicitly choose
anonymous access for a public one. Verify access, then register.

Owners and workspace administrators manage repositories and Git credentials.
Members can view repository details and query successful snapshots.
A repository's indexed content is shared within its workspace; the Git token
only controls fetching. Import only code you may share with that workspace.

Git credentials belong to the workspace. Their tokens are encrypted and never
returned after saving. Use a read-only token scoped to the required repositories.
Revoking a token prevents future fetches; it does not remove previously indexed
content. Delete the repository if that content should no longer be available.

## Build and query

Build progress distinguishes queue waiting, fetching, parsing, and publication.
Queue waiting does not consume the execution timeout. You can cancel a pending
or running build, or rebuild after a source change. A failed rebuild leaves the
last successful snapshot available.

For diagnostics, open **Details → Advanced → Query checks** to search symbols or documents, inspect callers,
callees and impact, or read source lines. Results identify the build and Git
commit. Pin the returned build ID when comparing several results; inspect the
source before treating a relationship as evidence. Missing results do not prove
that code or behavior is absent.

## Choose the usage scope

Open **Team → Resources → CodeGraph**, then open the repository details and
choose **Configure access**. The three scope sections show current selections
and counts. **Select agents** and **Select projects** open a selection list;
save to apply the changes. **Enable sharing** makes the graph available to all
workspace agents, including agents created later.

| Scope | When an agent can use the graph | Who can manage it |
| --- | --- | --- |
| Direct agent assignment | In any task or conversation for that agent | Agent owner, workspace owner or administrator |
| Project | Only in a task or conversation belonging to the selected project | Workspace owner or administrator |
| All workspace agents | For current and future agents in the workspace | Workspace owner or administrator |

New graphs have no agent access by default. Scopes are combined: removing one
assignment does not revoke access granted by another. Workspace members can
manually query all workspace graphs; these settings control agent tools, not
member visibility. Git credentials remain on the server and are never given to agents.

Project pages show project-assigned and workspace-shared graphs. Agent configuration
shows direct assignments and workspace sharing. An execution's transcript shows
the graphs currently available to that run and their authorization sources. This
is a current permission view, not an audit log of code previously read.

The server derives the project from the authenticated task's issue or project
conversation. Mentioning another project in a prompt does not grant access.
Moving an issue to another project changes project access on the next tool call.
Ordinary conversations without a project receive only direct and workspace access.

## Use the tools

Once a graph is assigned and built, ask an agent in a task or conversation to
find the relevant code, follow calls and check the source. You do not need to
enter symbol IDs or source line ranges in the management page.

Assignment does not install tools or bring an offline runtime online. A graph
also needs a successful build before it can be queried.
The daemon injects CodeGraph MCP tools into supported local providers.
Use a CLI/daemon build that includes this integration and restart older daemons
after upgrading; backend support alone does not inject tools into older CLIs.
Cloud providers that cannot receive local tools are not supported by this path.

Each tool call checks all current authorization sources. Removing every source
revokes future calls, including calls from an already running task. This does
not erase source content already included in a conversation.

## Query access

Graph queries require workspace membership or an authorized agent task token.
Importing a public Git repository anonymously does not make its graph public.
Anonymous graph queries and Skill export are not included.

Source-code indexing, symbol search and call relationships use
[CodeGraph by Colby Mchenry](https://github.com/colbymchenry/codegraph).
This integration pins
[revision 19813544766f](https://github.com/colbymchenry/codegraph/tree/19813544766f74a10f403c9e474306c0f7b61a18),

and authenticated agent tools around that library. This integration uses a
subset of its APIs; the original project's latest features are not implied.

## Self-hosting

CodeGraph needs the optional engine sidecar, shared snapshot storage and Git on
the API host. See the repository's
[`services/codegraph/README.md`](https://github.com/multica-ai/multica/blob/main/services/codegraph/README.md)
for setup, resource settings and encryption-key requirements.
