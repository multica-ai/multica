[워크스페이스](/workspaces)의 `owner`, `admin`, `member`는 모두 태스크를 만들고 댓글을 작성할 수 있습니다. 설정과 멤버를 관리할 권한은 역할마다 다릅니다. [게스트](#게스트)는 공유받은 프로젝트에서만 태스크를 읽고 댓글을 작성할 수 있습니다.

## 멤버 관리 권한 [#세-가지-역할]

| 작업 | owner | admin | member |
|---|:---:|:---:|:---:|
| 워크스페이스를 보고 일상적인 협업에 참여 | ✓ | ✓ | ✓ |
| 워크스페이스 설정 변경 | ✓ | ✓ | — |
| `admin` 또는 `member` 초대 | ✓ | ✓ | — |
| `admin`, `member`의 역할 변경 또는 제거 | ✓ | ✓ | — |
| `owner` 부여, 회수 또는 제거 | ✓ | — | — |
| 워크스페이스 삭제 | ✓ | — | — |

워크스페이스에는 항상 `owner`가 한 명 이상 있어야 합니다. 마지막 `owner`는 강등되거나 제거될 수 없으며 워크스페이스를 떠날 수도 없습니다.

<RolesDemo />

<Callout type="info">
게스트는 에이전트를 실행할 수 없습니다. 각 에이전트에는 별도의 접근 범위(Access)가 있으며, `owner`와 `admin`도 권한이 없는 에이전트를 우회해서 실행할 수 없습니다. 자세한 내용은 [에이전트](/agents#권한과-access)를 참고하세요.
</Callout>

<Callout type="info">
역할로 비공개 프로젝트를 볼 수 있게 되지도 않습니다. `owner`나 `admin`도 멤버 목록에 있을 때만 비공개 프로젝트를 볼 수 있습니다. 자세한 내용은 [비공개 프로젝트](/projects#private-projects)를 참고하세요.
</Callout>

## 멤버 초대

`owner`와 `admin`은 **설정 → 멤버**에서 **멤버 초대**를 누르고 이메일을 입력한 뒤 역할을 선택해 초대를 보냅니다. 초대 시 `admin`, `member` 또는 [게스트](#게스트)로 초대할 수 있습니다. `owner`로 지정하려면 먼저 워크스페이스에 참여한 다음 기존 `owner`가 역할을 올려야 합니다.

![멤버 관리: 초대 양식과 역할이 표시된 멤버 명단](/images/docs/members-roster.webp)

초대받은 사람은 해당 이메일로 로그인해 초대를 수락할 수 있으며 미리 가입할 필요는 없습니다. 초대는 7일 동안 유효하고, 만료되면 다시 보내야 합니다. 가입이 제한된 자체 배포 인스턴스에서는 대기 중이며 만료되지 않은 초대가 있으면 allowlist에 별도로 추가하지 않아도 해당 이메일로 계정을 만들 수 있습니다. [로그인과 가입](/auth-setup#초대와-가입-제한)을 참고하세요.

초대 링크는 이메일에만 표시되며 제품 화면에서 확인하거나 복사할 수 없습니다. 이메일 전송에 실패해도 초대 기록은 남으므로 취소한 뒤 다시 보낼 수 있습니다.

바로 전달할 수 있는 링크가 필요하면 **설정 → 멤버**의 **공유 링크**에서 역할과 유효 기간을 선택해 링크를 만드세요. 링크를 가진 사람은 링크가 만료되거나 취소될 때까지 선택한 역할로 참여할 수 있습니다. 단, 워크스페이스에 빈 멤버 자리가 있어야 합니다(아래 참고).

### 멤버 수 한도

Multica Cloud에서 Free 요금제 워크스페이스는 멤버를 최대 5명까지 둘 수 있습니다. 멤버와 대기 중인 초대가 각각 한 자리를 차지하며, 게스트는 자리를 차지하지 않습니다. 한도가 적용되는 동안에는 한도를 넘는 새 초대, 초대 수락, 공유 링크를 통한 참여가 거부됩니다. 자리가 생기거나(초대 취소 또는 멤버 제거) 워크스페이스를 업그레이드하면 다시 추가할 수 있습니다. 기존 멤버는 제거되지 않습니다. 워크스페이스가 가득 차면 관리자는 초대 대화 상자에서 **업그레이드하고 초대**를 볼 수 있습니다. 결제가 완료되면 **설정 → 결제 및 요금제**에서 보류해 둔 초대를 보낼 수 있습니다. Pro와 Business에서는 멤버마다 유료 좌석이 필요합니다. 셀프 호스팅 워크스페이스에는 멤버 수 한도가 없습니다.

## 게스트

게스트는 공유받은 프로젝트만 볼 수 있습니다. 그 프로젝트에서는 태스크를 보고, 댓글을 달고, 반응을 남기고, 팔로우할 수 있습니다. 태스크를 만들거나 수정할 수 없고, 에이전트를 실행하거나 멘션할 수 없으며, 워크스페이스 설정도 열 수 없습니다. 다른 프로젝트, 에이전트, 오토파일럿, 런타임도 보이지 않습니다. 게스트는 무료이며 유료 좌석이나 멤버 자리를 차지하지 않습니다.

`owner`와 `admin`은 초대 대화 상자에서 **게스트**를 선택하고 볼 수 있는 프로젝트를 골라 게스트를 초대합니다. 멤버의 작업 메뉴에서는 멤버를 게스트로 바꾸거나(좌석이 비고 에이전트, 오토파일럿, 런타임 접근 권한이 회수됩니다), 게스트를 멤버로 바꾸거나(좌석을 하나 사용합니다), **접근 가능한 프로젝트 관리**로 게스트의 프로젝트를 바꿀 수 있습니다.

Multica Cloud에서 게스트는 Pro와 Business에 포함됩니다. 체험이 끝나거나 워크스페이스가 Free로 바뀌어도 기존 게스트는 접근 권한을 유지하며 제거, 범위 축소, 멤버 전환은 계속할 수 있지만 새 게스트는 추가할 수 없습니다. 셀프 호스팅 워크스페이스에서는 게스트를 사용할 수 있습니다.

## 역할 변경

멤버 목록에서 해당 멤버 오른쪽의 작업 메뉴를 열고 **역할 변경**을 선택하면 즉시 적용됩니다.

`admin`은 `admin`과 `member` 사이에서 역할을 변경할 수 있고 두 역할의 멤버를 제거할 수도 있습니다. `owner` 승격, 역할 변경, 제거처럼 `owner`와 관련된 변경은 `owner`만 수행할 수 있습니다.

## 멤버 제거

제거된 멤버는 즉시 워크스페이스 접근 권한을 잃습니다. 해당 멤버가 만든 태스크, 댓글, 기타 협업 기록은 워크스페이스에 남습니다.

<Callout type="warning">
멤버를 제거하면 그 멤버가 소유한 런타임도 비활성화되고, 해당 런타임에 연결된 에이전트는 보관 처리되며, 끝나지 않은 실행은 취소됩니다. 에이전트 접근 범위(Access)를 통해 부여된 권한도 삭제되며, 다시 참여해도 자동으로 복구되지 않습니다.
</Callout>
