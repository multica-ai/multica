[워크스페이스](/workspaces)에 참여한 사람은 모두 멤버이며, 각 멤버는 `owner`, `admin`, `member` 중 하나의 역할을 가집니다. 역할은 워크스페이스 설정과 팀 관리 권한만 제어합니다. 이슈 생성, 댓글 작성 같은 일상적인 협업은 모든 멤버에게 열려 있습니다.

## 세 가지 역할

| 작업 | owner | admin | member |
|---|:---:|:---:|:---:|
| 워크스페이스를 보고 일상적인 협업에 참여 | ✓ | ✓ | ✓ |
| 워크스페이스 설정 변경 | ✓ | ✓ | — |
| `admin` 또는 `member` 초대 | ✓ | ✓ | — |
| `admin`, `member`의 역할 변경 또는 제거 | ✓ | ✓ | — |
| `owner` 부여, 회수 또는 제거 | ✓ | — | — |
| 워크스페이스 삭제 | ✓ | — | — |

워크스페이스에는 항상 `owner`가 한 명 이상 있어야 합니다. 마지막 `owner`는 강등되거나 제거될 수 없으며 워크스페이스를 떠날 수도 없습니다.

<Callout type="info">
역할은 에이전트를 실행할 수 있는 사람을 결정하지 않습니다. 각 에이전트에는 별도의 접근 범위(Access)가 있으며, `owner`와 `admin`도 권한이 없는 에이전트를 우회해서 실행할 수 없습니다. 자세한 내용은 [에이전트](/agents#권한과-access)를 참고하세요.
</Callout>

## 멤버 초대

`owner`와 `admin`은 설정 → 멤버에서 이메일을 입력하고 역할을 선택한 뒤 초대를 보낼 수 있습니다. 초대 시 부여할 수 있는 역할은 `admin`과 `member`뿐입니다. `owner`로 지정하려면 먼저 워크스페이스에 참여한 다음 기존 `owner`가 역할을 올려야 합니다.

![멤버 관리: 초대 양식과 역할이 표시된 멤버 명단](/images/docs/members-roster.webp)

초대받은 사람은 해당 이메일로 로그인해 초대를 수락할 수 있으며 미리 가입할 필요는 없습니다. 초대는 7일 동안 유효하고, 만료되면 다시 보내야 합니다. 가입이 제한된 자체 배포 인스턴스에서는 아직 계정이 없는 초대 대상도 가입 규칙의 적용을 받습니다. [로그인과 가입](/auth-setup#초대와-가입-제한)을 참고하세요.

초대 링크는 이메일에만 표시되며 제품 화면에서 확인하거나 복사할 수 없습니다. 이메일 전송에 실패해도 초대 기록은 남으므로 취소한 뒤 다시 보낼 수 있습니다.

## 역할 변경

`admin`은 `admin`과 `member` 사이에서 역할을 변경할 수 있고 두 역할의 멤버를 제거할 수도 있습니다. `owner` 승격, 역할 변경, 제거처럼 `owner`와 관련된 변경은 `owner`만 수행할 수 있습니다.

역할 변경은 즉시 적용됩니다.

## 멤버 제거

제거된 멤버는 즉시 워크스페이스 접근 권한을 잃습니다. 해당 멤버가 만든 이슈, 댓글, 기타 협업 기록은 워크스페이스에 남습니다.

<Callout type="warning">
멤버를 제거하면 그 멤버가 소유한 런타임도 비활성화되고, 해당 런타임에 연결된 에이전트는 보관 처리되며, 끝나지 않은 실행 태스크는 취소됩니다. 에이전트 접근 범위(Access)를 통해 부여된 권한도 삭제되며, 다시 참여해도 자동으로 복구되지 않습니다.
</Callout>
