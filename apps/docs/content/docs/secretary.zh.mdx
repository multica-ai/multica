秘书是整个工作区的一个智能体。它阅读各小队的工作情况，每天为你写一份简报，说明哪些事项需要你决定、哪些在推进、哪些卡住了。你不会收到每个小队各自的汇报。

小队照常在任务、项目和[提案](/office)中工作，从不为你撰写状态报告。秘书自己获取所需的事实，因此小队不必为状态信息消耗运行次数。

<Callout type="warning">
办公室目前还没有设置按钮、简报卡片或 **询问** 操作。在它们推出之前，你可以通过收件箱中的 **简报已生成** 通知，以及下面的 `multica brief` 命令阅读简报。设置秘书的方法记录在 [SELF_HOSTING.md](https://github.com/multica-ai/multica/blob/main/SELF_HOSTING.md) 的升级说明中。
</Callout>

## 前提条件

- 你选择的机器上有一个在线的 Hermes 运行时。请按[安装智能体运行时](/install-agent-runtime)的说明安装，并在 Hermes 本身中配置模型。
- 秘书运行在这一个运行时上。它的记忆保存在该机器上，因此不会随工作区移动。

## 设置会创建什么

设置会创建以下对象，并且可以重复运行而不会产生重复：

- 一个名为 **Secretary** 的智能体，设为私有，使用你选择的运行时上的 Hermes，一次只运行一个任务。
- 一个 **Executive** 楼层，以及其上的 **Executive Office** 小队。秘书担任该小队的队长，你是成员。
- 指定秘书身份的工作区设置。
- **Daily brief** 自动化，处于启用状态，以及 **Weekly review** 自动化，处于暂停状态。

## 每日简报与每周回顾

两者都是运行秘书的[自动化](/autopilots)。

| 自动化 | 时间 | 设置后的状态 |
| --- | --- | --- |
| **Daily brief** | 每天 08:00，使用设置时选择的时区 | 启用 |
| **Weekly review** | 周五 17:00 | 暂停。在自动化页面中启用。 |

如果 08:00 时机器处于睡眠状态，这次运行会被跳过，与任何自动化运行一样。在自动化页面点击 **立即运行**，即可立刻获得简报。

简报发布后，工作区所有者会收到一条收件箱通知 **简报已生成**。这是秘书发出的唯一常规通知。

## 简报的内容

简报是 Markdown 文档，包含六个按以下顺序排列的部分：

1. **标题**：最多三行。如果当天很平静，会注明，简报也会很短。
2. **需要你决定的事项**：优先列出待决定的提案，然后是只有你能清除的阻碍。每项说明情况、可选方案、秘书的建议和链接。最多列出五项，其余只计数。
3. **进展**：按楼层排列，只列出有新动态的小队。没有变化的小队只占一行。
4. **阻碍与风险**：每项附带建议的解决办法。
5. **关注**：自上次简报以来，研究楼层上的市场与产品动态。
6. **其他**：成本、运行时和失败的异常情况。

简报应能在两分钟内读完。缺少某个部分的简报会被服务器拒绝，并告诉秘书缺的是哪一部分，秘书修改后可以重新发布。简报正文最多 20,000 个字符。

## 摘要

摘要是秘书撰写简报所依据的事实集合。它由服务器从数据库中计算，因此有范围限制，也不依赖模型：

- **按小队**，按需要关注的程度排序：已完成、进行中和受阻的任务；进行中但 72 小时没有任何活动的任务；失败的运行；队长未采取行动的次数；待决定的提案；以及最近完成的任务链接。
- **没有变化的小队**汇总在一个列表中。
- **工作区**：该时段内的运行和成本，以及离线的运行时。

摘要最多完整列出 20 个小队，其余小队按排名计数。你最多可以回溯 35 天。

## 在聊天中询问秘书

秘书是一个智能体，因此你可以像与其他智能体聊天一样与它对话。问到公司状况时，它会先读取摘要，并依据摘要回答，而不是凭记忆。问到公司知道什么或决定了什么时，它会先搜索[知识库](/knowledge-base)，并引用找到的内容。

秘书不能替你批准提案。它的回答会引导你去看简报，或办公室中的 **决定**。

## 它能做什么，不能做什么

| 秘书可以 | 秘书不可以 |
| --- | --- |
| 通过 `multica` CLI 读取工作区 | 决定提案。服务器会拒绝智能体的决定。 |
| 发布简报 | 以其他智能体的身份发布简报。只有秘书或管理员成员可以发布。 |
| 在任务下评论以询问小队队长，每份简报最多三次 | 执行小队的工作。其指令将它限定为汇报和提问。 |
| 向知识库保存草稿 | 发布知识。草稿由人发布。 |

## 命令行

秘书在其运行时上运行这些命令。`publish` 需要秘书或管理员成员身份。

```bash
multica brief digest --since 24h --json
multica brief publish --kind daily --title "Daily brief" --file brief.md --proposal <proposal-id>
multica brief list --kind daily --limit 10
multica brief show <brief-id>
```

| 命令 | 作用 |
| --- | --- |
| `digest` | 打印 `--since` 时段内的摘要。时段可以是 `30m`、`24h`、`7d` 这样的时长，或 RFC 3339 时间戳。默认为 24 小时。 |
| `publish` | 发布 Markdown 文件。需要 `--kind`（`daily`、`weekly` 或 `ad_hoc`）、`--title` 和 `--file`，`--file` 可用 `-` 从标准输入读取。对简报提出的每个提案重复使用 `--proposal`，以便应用中显示链接。 |
| `list` | 按时间倒序列出简报。可用 `--kind` 筛选，用 `--limit` 限制数量（最多 50）。 |
| `show` | 按 ID 打印一份简报。 |

任何命令都可以加 `--json` 或 `--output json`，以获得机器可读的输出。

## 记忆与隐私

秘书把你的偏好和长期指令保存在 Hermes 记忆中。关于公司的每一项事实，都来自运行时刻的摘要以及摘要所指向的任务。记忆可能会丢失，例如运行时被回收或迁移，因此工作区中的任何内容都不依赖记忆。

由于秘书可以读取整个工作区，设置时会将它创建为私有智能体。谁可以运行它，由[私有智能体的访问规则](/agents#permissions-and-access)决定。
