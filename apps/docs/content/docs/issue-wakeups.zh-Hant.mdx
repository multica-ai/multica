有些工作做到一半只能等：等供應商回報價，等同事答覆，等子任務做完。這時可以在任務上加一條**喚醒**規則："當某件事發生時，喚醒某個 AI 代理，讓它做什麼"。條件滿足後，AI 代理在這條任務上開始一次普通執行，讀取任務的最新情況，結果照常以評論寫回任務。

規則儲存在任務上，等待期間沒有執行在跑。成員在任務側欄裡建立喚醒；AI 代理在執行中用 [CLI](#cli) 給自己安排下一次檢查，兩種方式建立的是同一種規則。

## 新建喚醒 [#create]

<Steps>
<Step>

開啟任務，點任務側欄**喚醒**區域右側的 **+**。

</Step>
<Step>

在**當**後面選擇條件，再補齊條件需要的引數，例如時間、要等的人或要等的狀態。

</Step>
<Step>

在**喚醒**後面選擇 AI 代理。任務負責人是 AI 代理時，這裡已經預選了它。只能選已繫結執行時、並且你有權限執行的 AI 代理，見[權限與 Access](/agents#權限與-access)。

</Step>
<Step>

在**喚醒後要做什麼**裡寫下指令，例如"看供應商是否都回了報價，回齊了就整理成對比表"。指令最多 12,000 位元組，之後可以修改，只影響以後的喚醒。

</Step>
<Step>

點**建立**。

</Step>
</Steps>

喚醒開始的執行代表建立者執行，開始前會再確認建立者仍有權限執行這個 AI 代理。

下面這條任務裡，運營助手已經發出詢價，正在等供應商回覆。給它加一條喚醒，再快進到喚醒時間。選"定期檢查"還能看到第一天沒有訊息時，AI 代理怎樣不發評論就結束。

## 可以等什麼 [#conditions]

| 分組 | 條件 | 什麼時候喚醒 |
|---|---|---|
| 時間 | 在某個時間 | 10 分鐘後、1 小時後、明天 09:00，或自定義時間。只喚醒一次。 |
| 時間 | 定期檢查 | 每小時、每天 09:00 或工作日 09:00，按你的時區計算。必須設截止日，截止日當天結束後停止。 |
| 協作 | 有人回覆 | 任務上出現新評論；可以限定為某位成員或某個 AI 代理。 |
| 協作 | 欄位變為某個值 | 任務的狀態、負責人、標籤或自定義屬性變成指定的值。 |
| 執行與子任務 | AI 代理的執行結束 | 這條任務上某個 AI 代理（或任意 AI 代理）的執行成功、失敗或被取消。 |
| 執行與子任務 | 子任務完成 | 全部子任務結束（`done` 或 `cancelled`），或某個階段及之前的階段全部結束。沒有子任務時不會觸發。 |
| 關聯 | 關聯 PR 的 CI 結束 | 也可以選 PR 合併、出現合併衝突。只看直接關聯到這條任務的 PR，有多個時任意一個滿足即可。CI 結束和合並衝突只支援 GitHub 上的 PR。 |
| 關聯 | 其他任務的狀態變化 | 另一條任務完成、完成或取消，或進入審查中。 |
| | 自定義事件 | 從 25 種原始事件裡勾選，例如表態、附件、評論被編輯或討論被解決。 |

欄位、子任務、PR 和其他任務這幾類條件由平臺自己去查：條件在建立時已經成立的，下一次檢查（約 30 秒內）就會喚醒；"CI 結束"例外，它只認建立之後才出結果的檢查。

時間以外的條件都是"等某件事發生"，還有三項設定：

- **觸發次數**：預設**僅觸發一次**；選**重複喚醒**時，再設**最多觸發**幾次（5、10、20 或 50 次，預設 20）。
- **最多等待**：1、3、7 或 30 天，預設 7 天。
- **超時後**：預設喚醒 AI 代理處理，它會知道要等的事沒有發生；也可以選直接結束。

任務負責人是 AI 代理時，成員發評論本來就會觸發它。給負責人再加一條"有人回覆"的喚醒，不會多跑一次，只會併入那次執行，所以只在想附加指令時才需要。

## 喚醒之後 [#after-wake]

- AI 代理在任務上開始一次普通執行，讀取任務、評論和喚醒指令，結束時發一條評論。評論帶有"由喚醒觸發"標籤和觸發條件，[執行日誌](/tasks)裡也能看到觸發來源。
- 定期檢查沒發現需要回復的事，AI 代理可以**靜默檢查**後結束：不發評論，只在任務時間線和這條喚醒的觸發記錄裡留一條說明。連續幾次靜默檢查在時間線裡合併成一條。
- AI 代理自己發的評論、自己對任務的修改，不會喚醒它自己。
- 同一個 AI 代理在這條任務上已經有一次執行在等待開始，新的喚醒會併入那次執行，不再另起一次。
- 有喚醒在等時，任務標題旁會顯示任務在等什麼，例如"運營助手 在等回覆"，點一下跳到喚醒區域。

## 檢視和管理 [#manage]

任務側欄的喚醒區域列出這條任務上的規則：條件、喚醒誰、下次什麼時候、還剩多久。點一條規則檢視詳情，包括來源、有效期、指令和**觸發記錄**（最近的執行，有沒有發評論，靜默檢查寫了什麼）。

| 操作 | 結果 |
|---|---|
| 關閉開關 | 停止後續喚醒，撤回還沒開始的執行。已經開始的執行繼續，需要時在執行日誌裡停止。 |
| **立即喚醒** | 現在就按這條規則喚醒一次，不等條件。 |
| 編輯指令 | 只影響以後的喚醒，正在執行的執行不變。 |
| **刪除** | 規則不再喚醒，還沒開始的執行被撤回，已經開始的繼續。 |
| **再次啟用** / **重新設定時間** | 單次規則觸發過後重新啟用；單次定時的規則需要選一個新時間。 |

結束的規則收進**歷史喚醒**。只有規則的建立者和工作區 owner、admin 可以管理它。AI 代理在執行中建立的喚醒，記在發起那次執行的成員名下，顯示為"運營助手 建立（代表 李雷）"。

要看整個工作區的喚醒，開啟**自動化**頁面，切到**任務喚醒**標籤。這裡可以按狀態（待喚醒或執行中、已暫停、已關閉、已結束）、觸發方式、來源和 AI 代理篩選，批次關閉，或者先選任務再新建喚醒。

## 自動結束和暫停 [#limits]

- 任務完成或取消時，上面的喚醒全部關閉，還沒開始的執行被撤回；任務重新開啟後不會自動恢復。已完成或已取消的任務不能新建喚醒。
- 等待類規則到了最多等待時間，按**超時後**的設定處理；定期檢查到截止日停止。
- 重複喚醒的規則達到最多觸發次數後自動暫停。等待類規則還有兩種保護：和其他喚醒規則互相觸發（觸發鏈第三次經過它，中間沒有人參與），或 1 小時內觸發超過 12 次，都會自動暫停。暫停的規則保持關閉，有人重新開啟後恢復，次數重新計算。
- 一條任務最多同時開啟 32 條喚醒，一個工作區最多 1000 條。

## 子任務結束時喚醒父任務 [#child-done]

任務有子任務時，喚醒區域會出現一條帶**系統**標記的規則，它不用手動建立：

- 某個階段的子任務全部結束、後面還有階段在等時，喚醒父任務的負責人；全部子任務結束時再喚醒一次。沒有分階段的子任務，全部結束時喚醒一次。
- 負責人是 AI 代理時喚醒它，是小隊時喚醒隊長，是成員時改發收件箱通知；沒有負責人就不喚醒。
- 父任務在 `backlog` 時暫不喚醒，移出 `backlog` 後補一次。
- 預設指令告訴 AI 代理哪個階段結束了、下一個是哪個：先檢查依賴，再把下一階段的子任務移出 `backlog`；全部結束時把結果彙總到父任務上。

父任務的負責人已經由這條規則喚醒，不需要再為同一件事加"子任務完成"條件。階段怎麼設定見[任務](/issues#專案和子任務)。

在單條任務上，工作區成員可以關閉這條規則，或者改寫它的指令（最多 4,000 位元組），AI 代理不能改。改過之後，這條任務不再跟隨工作區預設值。

工作區 owner 和 admin 在**設定 → 喚醒**裡設定預設值：是否預設開啟（預設開啟）和預設指令，預設指令留空時使用內建指令。頁面上會顯示有多少進行中的任務用了自己的設定。

## 讓 AI 代理自己安排喚醒 [#cli]

AI 代理在執行中用 `multica issue wakeup` 給這條任務安排下一次執行，然後結束當前執行。不寫 `--agent-id` 時，喚醒的就是執行命令的 AI 代理自己。你也可以在自己的終端裡用同一組命令，這時要用 `--agent-id` 指定 AI 代理。

```bash
# 明天上午 9 點（北京時間）再看一次
multica issue wakeup create OPS-56 --kind at --at 2026-10-21T09:00:00+08:00 \
  --instruction "看供應商是否都回了報價，回齊了就整理成對比表"

# 工作日每天 9 點檢查，一週後結束
multica issue wakeup create OPS-56 --kind cron --cron "0 9 * * 1-5" --timezone Asia/Shanghai \
  --expires-in 168h --instruction "檢視詢價郵件，有新報價就更新對比表"

# 等李雷回覆，最多等 3 天，超時也喚醒一次
multica issue wakeup create OPS-56 --event comment.created \
  --filter-actor-type member --filter-actor-id <李雷的使用者 ID> \
  --expires-in 72h --on-timeout wake --instruction "按李雷的答覆繼續"

# 等任務進入審查中
multica issue wakeup create OPS-56 --until-status in_review --instruction "檢查交付物並彙總"
```

- **時間**：`--kind at` 配 `--after 10m` 或 `--at <RFC3339 時間>`；`--kind every --every 1h` 按固定間隔，最短 1 分鐘；`--kind cron --cron "<5 段表示式>"` 配 `--timezone`，時區預設 UTC。
- **事件**：`--event` 後面寫事件名，多個用逗號分隔，`multica issue wakeup events` 列出全部事件和過濾引數。`--mode continuous` 改成重複喚醒。
- **條件**：`--until-status`、`--until-assignee`、`--until-label`、`--until-property`、`--until-children-done [--stage N]`、`--until-pr checks|merged|conflicts`、`--until-issue <任務> --until-issue-state done|ended|in_review|blocked`。一條喚醒只能用一個 `--until-*`，不能和 `--event` 同時用。
- **結束方式**：CLI 不會自動給等待加期限，用 `--expires-in 72h` 或 `--expires-at <RFC3339 時間>` 設結束時間；`--on-timeout wake` 讓事件規則在超時時再喚醒一次。`--max-fires N`（1–1000）限制重複規則最多執行幾次。
- **結果放在哪**：`--parent <評論 ID>` 讓喚醒後的回覆留在原來的評論串裡。

管理已有規則：

| 命令 | 作用 |
|---|---|
| `multica issue wakeup list <任務>` | 列出任務上的喚醒 |
| `multica issue wakeup get <任務> <喚醒 ID>` | 檢視一條喚醒的完整配置 |
| `multica issue wakeup runs <任務> <喚醒 ID>` | 最近的執行、觸發原因、靜默檢查說明，以及是否發了評論 |
| `multica issue wakeup update <任務> <喚醒 ID>` | 用和 `create` 相同的引數替換整份配置，並重新開啟 |
| `multica issue wakeup disable <任務> <喚醒 ID>` | 關閉，撤回還沒開始的執行 |
| `multica issue wakeup trigger <任務> <喚醒 ID>` | 立即喚醒一次 |
| `multica issue wakeup delete <任務> <喚醒 ID>` | 刪除規則，撤回還沒開始的執行 |
| `multica issue wakeup checkin <任務> <喚醒 ID> --note "..."` | 定期檢查沒發現需要回復的事時靜默結束，只能由這條規則開始的執行呼叫 |

`list`、`get` 和 `runs` 加 `--output table` 輸出表格。其他命令見[使用 CLI](/cli)。

## 和自動化的區別 [#vs-autopilots]

[自動化](/autopilots)按時間表或 Webhook 反覆開始新的工作，每次可以新建一條任務；喚醒掛在一條已有任務上，讓 AI 代理在約定的時間或事件之後回到這條任務接著做，任務結束時它也跟著結束。
