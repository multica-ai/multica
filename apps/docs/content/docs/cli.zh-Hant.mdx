Multica CLI 既負責連線本機執行時，也可以在終端中管理工作區、任務、AI 代理和自動化。這裡介紹常用路徑；當前版本支援的引數始終以命令自身的 `--help` 為準。

## 安裝

<Tabs groupId="os" persist items={["macOS / Linux", "Windows"]}>
<Tab value="macOS / Linux">

```bash
curl -fsSL https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.sh | bash
```

安裝了 Homebrew 時也可以執行：

```bash
brew install multica-ai/tap/multica
```

</Tab>
<Tab value="Windows">

在 PowerShell 中執行：

```powershell
irm https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.ps1 | iex
```

</Tab>
</Tabs>

確認安裝成功：

```bash
multica version
```

## 第一次連線

按連線的服務選擇：

<Tabs items={["Multica Cloud", "自託管例項"]}>
<Tab value="Multica Cloud">

```bash
multica setup
```

</Tab>
<Tab value="自託管例項">

```bash
multica setup self-host \
  --server-url https://api.example.com \
  --app-url https://app.example.com
```

</Tab>
</Tabs>

`setup` 會儲存服務地址、開啟瀏覽器完成登入，並啟動守護程序。完成後檢查：

```bash
multica auth status
multica daemon status
```

如果只需要重新登入，不想覆蓋其他配置，執行 `multica login`。沒有瀏覽器的環境可以先在 Web 設定中建立個人訪問令牌，再輸入：

```bash
multica login --token
```

命令會在終端中提示貼上令牌，避免把完整值留在 shell history 中。

## 選擇工作區

列出並切換預設工作區：

```bash
multica workspace list
multica workspace switch <slug>
```

之後的命令會使用這個工作區。單次命令可以透過 `--workspace-id` 臨時覆蓋，也可以設定 `MULTICA_WORKSPACE_ID`。

邀請成員：

```bash
multica workspace member invite teammate@example.com
multica workspace member invite admin@example.com --role admin
```

## 常用任務操作

```bash
# 檢視和搜尋
multica issue list
multica issue get MUL-123
multica issue search "登入失敗"

# 建立和修改
multica issue create --title "修復登入失敗"
multica issue status MUL-123 in_progress
multica issue assign MUL-123 --to "Backend Agent"

# 評論和執行記錄
multica issue comment list MUL-123
multica issue comment add MUL-123 --content "請先檢查迴歸測試"
multica issue comment update <comment-id> --expected-revision 2 --content "請檢查迴歸測試和釋出說明"
multica issue runs MUL-123
```

長描述或評論從 stdin 讀取，避免處理換行和引號：

```bash
multica issue create --title "升級說明" --description-stdin < notes.md
multica issue comment add MUL-123 --content-stdin < review.md
multica issue comment update <comment-id> --expected-revision 2 --content-file revised-review.md
```

檢視某次執行的訊息、停止執行或重試：

```bash
multica issue run-messages <task-id> --issue MUL-123
multica issue cancel-task <task-id> --issue MUL-123
multica issue rerun-task <run-id> --issue MUL-123
multica issue rerun-task <run-id> --issue MUL-123 --fresh
```

把評論插話到仍在進行中的執行，而不是排隊一個後續執行（僅限支援插話的執行；你的評論能啟動哪個 AI 代理，就能向它插話）：

```bash
multica issue comment add MUL-123 --content-file note.md --steer <task-id>
multica issue comment add MUL-123 --content-file note.md --steer-active
```

同一專案、同一父任務下已有標題相同（不區分大小寫，忽略多餘空格）且未關閉的任務時，`issue create` 會拒絕建立並給出那個任務。確實要再建一個，加 `--allow-duplicate`；要把一個任務標為另一個的重複，用 `multica issue status MUL-124 cancelled --duplicate-of MUL-123`。

一個任務要依次提交多個 PR 時，用 `issue create --title "..." --pr-auto-complete off` 或 `issue update <id> --pr-auto-complete off`，讓這個任務在 PR 合併後保持原狀態。用 `--pr-auto-complete on` 恢復工作區規則，從下一次 PR 事件起生效。`issue pull-requests <id>` 會顯示任務開關、工作區開關、目標狀態和判斷結果，沒有關聯 PR 時也會顯示。支援該欄位的伺服器會在建立交易內儲存開關；舊伺服器會補呼叫一次 PUT，失敗時 CLI 會提供已建立的任務 ID 和重試用的 update 命令，請勿重複建立。

### 時間線

`issue get` 給出任務現在的狀態；`issue timeline` 按時間順序列出狀態、優先順序、負責人、標題、日期的改動和執行結果，並混排評論，用來回答"什麼時候進入 in_review""卡在當前狀態多久了"：

```bash
multica issue timeline MUL-123 --action status_changed
multica issue timeline MUL-123 --activity-only --output json
multica issue timeline MUL-123 --since 2026-08-19T00:00:00Z
```

`--activity-only` 去掉評論，保留全部活動記錄；`--action` 只返回指定的動作，可重複，並隱含 `--activity-only`。伺服器讀取的歷史有上限，被截斷時 stderr 會列印警告，這時不要據此推算停留時長。

### 讀長評論執行緒

評論多的任務，AI 代理逐條讀取很費 token。先掃一遍執行緒，再展開需要的那一個：

```bash
multica issue comment list MUL-123 --roots-only --summary --output json --compact
multica issue comment list MUL-123 --thread <comment-id> --tail 5 --output json --compact
```

- `--roots-only` 只返回頂層評論，每條附帶回複數和最近活動時間。
- `--summary` 把每條內容截成預覽。
- `--compact` 只作用於 JSON 輸出，去掉不帶資訊的欄位（例如重複的 `issue_id`、空陣列）。
- `--recent N` 返回最近活躍的 N 個執行緒，每個執行緒帶上全部回覆，回覆多時輸出可能很長。
- 已解決的執行緒預設摺疊成首條評論和結論，需要原文時加 `--full`。

列表也可以只取需要的欄位：`multica issue list --output json --fields id,identifier,title,status`。篩選在 CLI 本地完成，減少的是輸出和上下文，不是請求量。

### 喚醒

喚醒讓 AI 代理在某個事件發生、某個條件成立或到點時開始一次普通執行。完整規則見[任務喚醒](/issue-wakeups)。

```bash
multica issue wakeup events
multica issue wakeup create MUL-123 --agent-id <agent-id> \
  --event comment.created --filter-actor-type member --filter-actor-id <user-id> \
  --instruction "對方回覆後，按回復內容更新報價單"
multica issue wakeup create MUL-123 --agent-id <agent-id> \
  --kind every --every 1h --expires-in 72h \
  --instruction "檢查供應商是否回信"
multica issue wakeup list MUL-123
multica issue wakeup runs MUL-123 <wakeup-id>
```

在終端裡以成員身份建立時需要 `--agent-id`；AI 代理在自己的執行中建立時預設喚醒它自己。

## AI 代理和 skill

```bash
multica agent list
multica agent get <agent-id>
multica agent create --help
multica agent update <agent-id> --help

multica skill list
multica skill get <skill-id>
multica skill import --url <skill-url>
multica agent skills add <agent-id> --skill-ids <skill-id>
```

匯入時遇到同名 skill，預設會停止且不修改現有內容。按意圖選擇：

```bash
multica skill import --url <skill-url> --on-conflict overwrite
multica skill import --url <skill-url> --on-conflict rename
multica skill import --url <skill-url> --on-conflict skip
```

`overwrite` 只允許 skill 的建立者使用，並保留原來的 ID 與 AI 代理繫結關係。

環境變數和 MCP 配置常帶有 token。命令列裡直接寫值會留在 shell 歷史和 `ps` 輸出中，用 `-file` 或 `-stdin` 形式傳入：

```bash
multica agent create --name "運營助手" --runtime-id <runtime-id> \
  --custom-env-file ./agent-env.json \
  --mcp-config-file ./mcp.json \
  --custom-args '["--max-turns", "40"]'

multica agent env set <agent-id> --custom-env-stdin < agent-env.json
multica agent update <agent-id> --mcp-config-file ./mcp.json
```

- `--custom-env` 系列只在 `agent create` 中可用。之後修改用 `agent env set`，它整體替換原有變數，值寫成 `****` 的鍵保留原值。
- `agent update --mcp-config null` 清除 MCP 配置。
- `--custom-args` 是 JSON 陣列，排在啟動引數的最後。選模型用 `--model`，部分工具會拒絕出現在自定義引數裡的 `--model`。
- 誰能呼叫 AI 代理用 `--permission-mode`：`private` 只有所有者，`public_to` 配合 `--public-to-workspace` 或 `--public-to-member <user-id>`。`--visibility private|workspace` 是舊寫法，會對映到 `--permission-mode`；兩者同時給出時以 `--permission-mode` 為準。

### AI 代理執行記錄

`multica agent tasks <agent-id> --limit 200` 返回最新一頁執行記錄。預設與最大分頁大小都是 200。還有更多執行記錄時，stderr 會印出一個 cursor；原樣帶入 `--before '<cursor>'` 即可讀取下一頁。`--output json` 維持陣列輸出，且只包含該頁的用量。

對應的 `GET /api/agents/{id}/tasks` 端點接受 `limit` 和 `before`，返回的仍是 JSON 陣列。響應頭 `X-Agent-Tasks-Next-Cursor` 提供下一個 cursor；沒有這個響應頭就表示已是最後一頁。cursor 保留 `(created_at, id)` 的順序，包含時間戳精度。無效的 limit 或 cursor 返回 HTTP 400；超過 200 的 limit 會被截到 200。不跟著 cursor 翻頁的客戶端只會拿到最新的 200 筆執行記錄。

## 守護程序和執行時

```bash
multica daemon start
multica daemon stop
multica daemon restart
multica daemon status --output json
multica daemon logs --follow

multica runtime list
multica runtime rename <runtime-id> "Office Mac"
multica runtime usage <runtime-id>
multica runtime activity <runtime-id>
```

```bash
multica daemon autostart enable
multica runtime usage <runtime-id> --days 30
multica runtime update <runtime-id> --target-version <version> --wait
multica runtime profile create --display-name "內部 Claude 封裝" \
  --command-name ccms --runtime-type claude
```

`daemon autostart` 為當前 profile 登記開機自啟，平臺差異見[開機自啟](/daemon-runtimes#autostart)。`runtime usage` 預設統計 90 天，`--days` 最多 365。`runtime update` 讓那臺電腦上的守護程序把 CLI 更新到指定版本，`--wait` 會一直等到更新結束。`runtime profile create` 用 `--runtime-type` 指定相容的工具（舊的 `--protocol-family` 仍可用）；固定引數目前只能在網頁端填寫。

刪除仍繫結活躍 AI 代理的執行時時，命令預設拒絕。`multica runtime delete <id> --cascade` 會解綁這些 AI 代理、保留其配置與歷史記錄，並取消它們的活動執行。

執行機制和自定義 profile 見[守護程序與執行時](/daemon-runtimes)。

## 專案、工作區和自動化

```bash
multica project create --title "618 活動" --lead "李雷" \
  --repo https://github.com/acme/campaign-site
multica project resource add <project-id> --type github_repo \
  --url https://github.com/acme/brand-assets --default-branch-hint main

multica workspace create --name "運營部" --slug ops --issue-prefix OPS
multica workspace update --context-stdin < team-context.md

multica autopilot create --title "每週銷售週報" --agent "運營助手" \
  --mode create_issue --issue-title-template "銷售週報 {{date}}"
multica autopilot trigger-add <autopilot-id> --cron "0 9 * * 1" --timezone Asia/Shanghai
```

- `--lead` 接受成員或 AI 代理的名稱。`--default-branch-hint` 只告訴 AI 代理倉庫的預設分支，不會切換分支。
- 工作區的 `--context` 會提供給工作區裡的每個 AI 代理。`--slug` 建立後不能修改；`--issue-prefix` 會轉成大寫，修改它會給所有現有任務重新編號，外部引用裡的舊編號隨之失效。
- `--issue-title-template` 只替換 `{{date}}`（UTC，`YYYY-MM-DD`），其他 `{{...}}` 會被拒絕。定時觸發器的 `--timezone` 預設 UTC。

## ID 和輸出格式

任務使用 `MUL-123` 這樣的 key 或完整 UUID，不接受 UUID 短字首。

其他資源的 `list` 命令通常顯示可複製的短 ID，並支援 `--full-id` 輸出完整 UUID。短 ID 不唯一時，CLI 會要求增加字元或改用完整 UUID。執行的短 ID 還需要透過 `--issue` 指明所屬任務。

許多命令支援結構化輸出：

```bash
multica issue list --output json
multica agent list --output json
```

指令碼使用 JSON 輸出，不解析面向終端的表格。各命令支援的輸出格式和分頁引數以 `multica <command> --help` 為準。

## Profile 與配置

預設配置儲存在 `~/.multica/config.json`。使用 `--profile <name>` 可以隔離另一套服務地址、令牌、預設工作區和守護程序狀態：

```bash
multica setup self-host --profile staging \
  --server-url https://api.staging.example.com \
  --app-url https://app.staging.example.com

multica issue list --profile staging
```

命名 profile 儲存在 `~/.multica/profiles/<name>/config.json`。檢視當前值：

```bash
multica config show
multica config show --profile staging
```

<Callout type="warning">
CLI 配置檔案包含可代表你訪問 Multica 的令牌。不要提交到倉庫、上傳到日誌或與他人共享。
</Callout>

## 命令參考

下表覆蓋當前全部頂層命令，按 CLI 自身的分組排列。所有命令都接受全域性 flag `--server-url`、`--workspace-id`、`--profile` 和 `--debug`。`--output` 是逐命令註冊的 flag，預設格式因命令而異：`list` 類預設表格，`get`、`create` 類多預設 JSON。完整引數以 `multica <command> --help` 為準。

### 任務附件

`issue create`、`issue update` 和 `issue comment add` 的每個 `--attachment` 接受一個完整檔案路徑，保留檔名中的逗號和雙引號。多個檔案須重複 flag，例如 `--attachment 'report,final.csv' --attachment notes.txt`。省略 flag 時不新增附件；顯式傳入空路徑會報錯。所有本地路徑都通過檢查後才開始上傳。

從舊 CSV 解析方式遷移：要新增兩個檔案，將 `--attachment a,b` 改為 `--attachment a --attachment b`。前一種寫法現在只選擇名為 `a,b` 的單個檔案。舊用法 `--attachment '"report,final.csv"'` 中額外的 CSV 雙引號也須移除，改用 `--attachment 'report,final.csv'`；只有檔名本身包含雙引號時才保留。

## 在其他編碼 AI 代理裡操作 Multica

如果你的工作大多發生在 Codex、Claude Code 或 Cursor 裡，可以直接在那裡操作 Multica，不必切回終端。[Multica CLI skill](https://github.com/multica-ai/multica-cli) 會教這些 AI 代理安全地使用本頁的命令：讀任務和評論執行緒時少耗 token、透過檔案寫評論，以及正確處理 mention、狀態變更和指派帶來的副作用。

它完全透過你已認證的 CLI 執行，本身不授予任何權限，權限仍然只來自你的登入、所選 profile 和工作區。要求 CLI 版本不低於 v0.4.26。該倉庫的 README 說明了 Claude Code 外掛市場、Codex skill 安裝器、Cursor 以及其他任何載入 Markdown 指令的工具的安裝方式。
