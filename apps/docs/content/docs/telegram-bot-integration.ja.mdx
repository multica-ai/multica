Multica は Telegram 公式の [@BotFather](https://t.me/BotFather) で作成した Bot を使用します。1 つの Bot は 1 つの Multica エージェントに対応します。Telegram 上で別々の Bot として振る舞わせたいエージェントには、それぞれ Bot を作成してください。

<Callout type="info">
Telegram 連携は[コミュニティメンテナンス](/community-maintained)です。毎リリースに同梱されますが、公式のサポート SLA は付きません。問題があれば [GitHub issues](https://github.com/multica-ai/multica/issues) に報告してください。
</Callout>

## 準備

- 接続できるのはワークスペースの owner または admin です。
- API サーバーから `https://api.telegram.org` に接続できる必要があります。
- @BotFather が発行した Bot token が必要です。パスワードと同様に扱ってください。

## Bot を接続する

<Steps>
<Step>

### Bot を作成する [#1-bot-を作成する]

1. [@BotFather](https://t.me/BotFather) を開き、`/newbot` を送信します。
2. 表示名と、`bot` で終わる username を設定します。
3. HTTP API token をコピーします。
4. 既定では **Group Privacy** を有効のままにします。これが可視範囲を最小にする構成で、Telegram はコマンド、明示的な @メンション、Bot への返信だけを Bot に配信します。無効にすると Bot は周囲のグループ会話をコンテキストとして扱えるようになりますが、その代わりグループの全メッセージを受信します。詳しくは[Group Privacy で Bot に届くメッセージが決まる](#group-privacy)を参照してください。

<Callout type="warning">
token をタスク、チャット、ログ、リポジトリに記録しないでください。漏えいした場合は @BotFather で失効させ、新しい token で再接続します。
</Callout>

</Step>
<Step>

### エージェントに接続する [#2-エージェントに接続する]

1. Multica の **エージェント**で対象エージェントを開き、**連携**を選びます。
2. **Telegram に接続**をクリックします。
3. Bot token を貼り付け、**接続**をクリックします。

Multica は Telegram で Bot を検証し、long polling と競合する webhook がないことを確認して token を暗号化保存し、監視された `getUpdates` 接続を開始します。他のエージェントやワークスペースに接続済みの Bot は、先に元の接続を解除してください。

</Step>
</Steps>

## 初回利用 [#初回利用とアカウント連携]

メンバーが初めて Bot にメッセージを送ると、1 回だけ使える Multica アカウント連携リンクが届きます。同じワークスペースの Multica アカウントでサインインし、Telegram に戻ってメッセージを再送してください。リンクは 15 分で期限切れになります。期限が切れたら、もう一度 Bot に DM を送ると新しいリンクが届きます。

グループには認証情報にあたる連携リンクを公開しません。Bot は送信者に、先に DM を開始するよう案内します。

利用できるのは現在のワークスペースメンバーだけです。メンバー資格はメッセージごとに再確認されます。

## Telegram から仕事を依頼する [#bot-を使う]

### DM

Bot を開き、そのままテキストを送信します。@メンションは不要です。

### グループと forum topic

Bot をグループに追加し、@メンションするか Bot のメッセージに直接返信します。受理されたメッセージは継続中の Multica 会話に残ります。通常のグループはそれぞれ 1 つの会話を継続し、forum topic は topic ごとに分離されます。

<Accordions type="multiple">
<Accordion title="Bot 宛てでないグループメッセージ" id="unaddressed-group-messages">

Bot 宛てでないグループメッセージは、それ自体で会話やターンを開始することはありません。ただし小さなメモリ上のバッファに保持されます。グループ（または forum topic）ごとに Bot が受信した直近 10 件で、サーバーの再起動で消えます。その後メンバーが @メンションまたは Bot のメッセージへの返信で Bot に指示すると、バッファ内のメッセージが読み取り専用のコンテキストとしてそのターンの前に添えられ、ターンと一緒に会話として保存されます。

バッファ内の画像やファイルは、コンテキストでは `[Image]` のようなマーカーと caption だけで示され、ファイル自体は取得されません。`/new` で始めた新しい会話にはこのコンテキストは付きません。

</Accordion>
<Accordion title="Group Privacy で Bot に届くメッセージが決まる" id="group-privacy">

バッファに入る内容は Telegram が何を配信するかで決まります。Group Privacy が有効ならコマンド、明示的な @メンション、Bot への返信だけなので、コンテキストには以前 Bot 宛てだったメッセージだけが入ります。

通常の会話も含めたい場合は @BotFather で Group Privacy を無効にし、Bot をグループから外して再追加してください。以後 Bot はグループの全メッセージを受信します。グループ管理者になっている Bot はプライバシー設定に関係なく全メッセージを受信するため、@BotFather を変更しなくても通常の会話がコンテキストに含まれます。

</Accordion>
<Accordion title="他のメンバーのメッセージに返信する" id="replying-to-members">

他のメンバーのメッセージへ返信する場合は、Bot も明示的に @メンションしてください。その場合に限り、引用元の送信者とテキスト（または caption）が新しい指示と一緒に渡されます。@メンションなしで人に返信しても Bot は起動しません。

Bot 宛ての返信が引用するメッセージに画像やファイルが含まれていれば、送信者が誰であれそのファイルも一緒に添付されます。

</Accordion>
</Accordions>

### コマンド

- `/new` は空の新しい Multica Chat を作成し、その Telegram 会話の後続メッセージを新しい Chat にルーティングします。`/new <メッセージ>` では、そのメッセージが新しい Chat の最初のターンになります。他のメンバーへの返信で Bot を明示的に @メンションした場合、選択した引用内容も最初のターンに含まれます。
- `/clear` は現在の Multica Chat を維持したまま、次の空でないメッセージに新しいエージェント可視コンテキストを適用します。`/clear <メッセージ>` では、そのメッセージが境界後の最初のターンになり、明示的に選択した返信の引用も保持されます。
- `/issue <タイトル>` は Multica のタスクを作成します。2 行目以降は任意の説明です。タイトルがない場合は使い方を返します。
- グループでは `/issue@your_bot` のような Telegram のコマンドサフィックスも利用できます。

### 返信と対応する内容

Bot は Telegram メッセージを送信・編集してテキストをストリーミング表示し、元メッセージを引用して forum topic を維持します。長い返信は Telegram の文字数制限に合わせて自動分割されます。

画像、ファイル、動画、ボイス、音声メッセージは、キャプションをメッセージ本文として、同じ会話の添付ファイルとしてエージェントに届きます。エージェントが生成したファイルは返信の後にチャットへ送り返されます。どちらの方向もサーバー側にオブジェクトストレージが必要です（後述のセルフホスト設定を参照）。

<Accordions type="multiple">
<Accordion title="最終返信の配信とキュー" id="reply-delivery">

最終返信はプロセス内で非同期に配信されます。通常、あるチャットのバックオフ待機は worker を占有しません。キャッシュが上限に達してバックオフ状態が圧縮されると、同じ Bot installation の他のチャットも安全側に遅延する場合があります。終端キューの容量は固定で、上限超過は明示的に拒否されてエラーとして記録されます。キューはサービス再起動後に復元されません。

</Accordion>
<Accordion title="画像、ファイル、その他のメディア" id="media">

画像、ファイル、動画、ボイス、音声を含むメッセージに返信すると（DM でも、グループで Bot に指示する場合でも、送信者が誰でも）、そのメッセージが引用として指示の前に添えられ、ファイルもエージェントに渡されます。以前の画像や動画を指し示したいときに使えます。

Telegram の Bot がダウンロードできるのは 20 MB までです。取得できなかった場合（大きすぎる、またはダウンロード失敗）は Bot がその旨を伝え、エージェントにはプレースホルダーだけが見えます。

エージェントが生成したファイルは別メッセージとして送り返されます。10 MB までの画像はインライン表示、それ以外は 50 MB までファイルとして届きます。送達を確認できなかった場合は Bot がその旨を伝え、ファイルは Multica の返信に添付されたまま残ります。

オブジェクトストレージが未設定の場合、Bot はメディアに非対応通知を返し、エージェントにはファイルを送れない旨が伝えられます。sticker、位置情報、投票などファイル以外のメッセージは、DM と、グループで Bot を明示的に @メンションした場合に同じ通知を返します。グループで Bot 宛てでないものには応答しません。

</Accordion>
</Accordions>

## 接続を管理する

**設定 → メッセージング → Telegram** で接続済み Bot を確認できます。owner と admin は接続を解除できます。解除すると long polling とその後の返信は止まりますが、Multica の会話と監査履歴は保持されます。

## セルフホスト設定 [#管理とセルフホスティング]

API サーバーを起動する前に、長期間変えない 32 バイトの暗号鍵を設定します。

```dotenv
MULTICA_TELEGRAM_SECRET_KEY=<base64-encoded 32-byte key>
```

`openssl rand -base64 32` で生成できます。この鍵を紛失またはローテーションすると既存の Bot token を復号できなくなり、Bot ごとに再接続が必要です。

連携リンクは `MULTICA_APP_URL`（未設定時は `FRONTEND_ORIGIN`）を使用します。生成されるアドレスはメンバーがアクセスできる必要があります。サーバーのネットワークまたは proxy は `api.telegram.org` への HTTPS 接続を許可している必要があり、Go は標準の `HTTPS_PROXY` / `NO_PROXY` 環境変数を読み取ります。

## よくある問題 [#トラブルシューティング]

- **Bot を検証できない**: まずサーバーのネットワークと proxy を確認します。Telegram が token を明示的に拒否した場合だけ再発行します。
- **webhook conflict**: 接続前にこの Bot の既存 webhook を削除します。Telegram では webhook と `getUpdates` を同時に使えません。
- **409 polling conflict**: 別の Multica インスタンスやプロセスが同じ Bot を polling しています。そちらを停止するか、環境ごとに Bot を分けます。
- **グループで返信しない**: Bot がグループに参加していて、メッセージが @メンションまたは Bot への返信になっていることを確認します。
- **連携リンクが期限切れ**: Bot に新しい DM を送り、最新リンクを使用します。
- **実行されない**: エージェントがアーカイブされていないか、使用している[ランタイム](/daemon-runtimes)がオンラインかを確認します。
