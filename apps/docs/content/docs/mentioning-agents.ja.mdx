新しい情報を確認してほしい、質問に答えてほしい、現在の担当者を手伝ってほしい — そんなときはコメントでエージェントを @メンションします。そのコメントが今回の実行の起点となり、タスクの担当者もステータスも変わりません。

## 割り当てと @メンションの使い分け

| | エージェントへの割り当て | コメントでの @メンション |
|---|---|---|
| 適した用途 | タスク全体をエージェントに任せる | 当該コメントをエージェントに処理させる |
| 担当者の変更 | あり | なし |
| ステータスの変更 | なし | なし |
| 一度に選べる対象 | 1 つのエージェントまたはスクワッド | 複数のエージェントやスクワッドを @メンション可能 |
| 実行のフォーカス | タスク全体 | トリガーしたコメントと、同じバッチに統合されたコメント |

明確な担当者が必要なときは[割り当て](/assigning-issues)を、一時的に議論へ参加してほしいだけのときは @メンションを使います。

## トリガープレビュー

コメントエディターでエージェントまたはスクワッドを選択すると、入力欄の下にトリガープレビューが表示されます。

- 送信後にどのエージェントが作業を開始するか
- 各対象が直接の @メンション、タスクの担当者、スクワッドのリーダーのどれに由来するか
- 対象が利用できない、またはあなたに実行権限がないかどうか

エージェントのチェックを外すと、今回のトリガーだけがスキップされます。コメントから名前を削除する必要はなく、エージェントの Access も変更されません。

<MentionDemo />

コメントが投稿されると、オンラインのランタイムは通常すぐに実行を受け取ります。ランタイムがオフラインの場合、実行はキューで待機します。

## 返信の自動ルーティング

@ をまったく含まない通常のコメントは、議論の文脈に沿ってルーティングされます。

1. エージェントのコメントへの返信は、そのエージェントに渡されます。
2. すでにエージェントが参加しているスレッドでの返信は、そのスレッドのエージェントを引き継ぎます。
3. どちらにも当てはまらない最上位のコメントは、現在の担当エージェントに渡されます。担当者がスクワッドのときはリーダーが処理します。メンバーのコメントへの通常の返信は担当者へフォールバックしません。エージェントやスクワッドに参加してほしい場合は、明示的に @メンションしてください。

コメントが他の対象（メンバーを含む）を明示的に @メンションしている場合、担当者へのフォールバックは適用されません。

返信が担当者以外のエージェントをトリガーした場合、Multica は担当者のために遅延フォールバック実行を予約します。対象のエージェントが約 5 分以内に返信すればフォールバックは自動的にキャンセルされ、返信がなければ担当者も実行を開始します。

## 実行中のエージェントに割り込む

エージェントが作業の途中で方向を誤っていても、止めて最初からやり直す必要はありません。コメント欄に修正を書いて送信すると、そのメッセージは現在の実行に加わります。エージェントは今のステップが終わったところで読み、新しい方向で元のタスクを続けます。

<SteerDemo />

送り先のエージェントが実行中のときは、コメント欄の下のラベルにメッセージの届け方が表示されます。クリックすると変更できます。

| 選択肢 | 動作 |
|---|---|
| 現在の実行に追加 | 現在のステップの後に読まれ、元のタスクがそのまま続きます。 |
| この実行の後に開始 | 現在の実行は止めず、終了後に新しい実行で扱います。 |
| 停止してやり直す | 現在の実行をすぐに停止し、このメッセージからやり直します。 |
| 今回は開始しません | コメントだけを投稿し、このエージェントはトリガーしません。 |

送信すると、コメントの下にまず「… が読むのを待っています」と表示され、読まれると「… が読みました」に変わります。実行ログのステップ一覧にも、どのステップで読んだかが示されます。届けられなかった場合は、再試行するか、新しい実行として送信できます。

- 実行中に追加できるのはテキストだけです。ファイル付きのメッセージは、この実行の後に処理されます。
- 割り込みには、エージェントが使う AI コーディングツールの対応が必要です。対応していない場合、「現在の実行に追加」は選択肢に表示されません。
- 既定の選択肢は **設定 → 環境設定** の **実行中のエージェントに返信するとき** で変えられます。メッセージごとに送信前に変更することもできます。
- チャットでキュー内のメッセージに使う**指示**は動きが違い、現在の返信を先に止めます。[チャット](/chat#返信中に続けてメッセージを送る)を参照してください。

## 連続コメントの統合

同じエージェントに同じタスク上で待機中の実行がある場合、新しいコメントはその実行に統合され、開始時にまとめて処理されます。すでに実行中の場合は、コメント欄で選んだ方法で処理されます（前のセクションを参照）。エージェントの返信を待たずに、続けて情報を補足できます。

1 つのコメントで複数の異なるエージェントを @メンションすると、エージェントごとに実行が作成されます。複数のメンションが同じエージェントに解決される場合は、1 回だけ残ります。

## エージェントをトリガーしないコメント

方法は 2 つあります。

- コメントを `/note` で始める: メンバー間のメモとして投稿され、どのエージェントもトリガーしません。
- `@all` を使う: すべてのワークスペースメンバーに通知し、このコメントによる担当者への自動トリガーを無効にします。

トリガープレビューにまだエージェントが残っている場合は、送信前にチェックを外してください。

<Callout type="info">
`@all` にエージェントは含まれません。エージェントにはインボックスがなく、働かせるには明示的に @メンションする、該当するスレッドで返信する、またはタスクを割り当てる必要があります。
</Callout>

## Access の制限

@メンションでエージェントの Access を回避することはできません。実行権限がない、対象がアーカイブ済み、利用可能なランタイムがない場合、トリガープレビューに開始されない旨が表示されます。コメント自体は通常どおり投稿されます。3 段階の Access の意味は[エージェント](/agents#権限と-access)を参照してください。

## エージェント同士のメンション

エージェントは自分の返信の中で他のエージェントを @メンションできます。A が B を、B が A をメンションし返す場合、同じタイミングの重複実行は統合されますが、この協働を終えるべきかどうかはシステムは判断しません。いつ止めるかはエージェントの指示に書いてください。
