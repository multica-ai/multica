任意の[エージェント](/agents)を ShareCRM Bot に接続すれば、チームは ShareCRM の中から直接それを使えます——Bot に DM したり、グループで @ メンションしたり、`/issue` と入力してアプリを開かずに [Multica イシュー](/issues)を起票したりできます。

ShareCRM 連携はコミュニティによってメンテナンスされています。毎リリースに同梱されますが、公式のサポート SLA は付きません。問題があれば [GitHub issues](https://github.com/multica-ai/multica/issues) に報告してください。

ShareCRM は**自分のアプリを持ち込む（BYO: bring-your-own-app）**モデルを採用しています。ワークスペースの admin が ShareCRM オープンプラットフォームでボット認証情報を作成し、それを Multica に貼り付けます。エージェントごとに**専用の** ShareCRM ボットを持つため、同じ組織内で複数のエージェントがそれぞれ別個に @ メンションできる異なる Bot を持てます。（これは紐づけがスキャンしてインストールするフローである [Lark](/lark-bot-integration) とは異なります。）

セットアップ全体は以下のとおりで、所要時間は約 5 分です。最終的に、Multica に貼り付ける 2 つの認証情報が得られます。

- **App ID** —— ボットアプリケーションの client id
- **App Secret** —— ボットアプリケーションの client secret

プライベートクラウドでは、任意で **API ベース URL** も設定できます（デフォルトは `https://open.fxiaoke.com`）。

## ShareCRM ボットをセットアップする

### 1. ShareCRM オープンプラットフォームでボット認証情報を作成する

1. 管理者アカウントで [ShareCRM オープンプラットフォーム](https://open.fxiaoke.com)（またはプライベートクラウドのコンソール）を開きます。
2. Multica が接続するボットアプリケーションを作成（または開きます）。
3. そのアプリケーションの **App ID** と **App Secret** をコピーします。
4. ボットがメッセージを受信（DM とグループ @ メンション）し、返信を送信できることを確認します。Multica は長時間維持される SSE セッションで**外向きに**接続するため、チャット用の公開 webhook URL は**不要**です。

これがプラットフォーム層で Multica が必要とするすべてです。

| 設定 | なぜそこにあるか |
|---|---|
| **ボットアプリケーション** | Multica が認証に使う App ID / App Secret を発行します。 |
| **メッセージ受信** | Bot が 1:1 メッセージと、自分を @ メンションしたグループメッセージを受け取れるようにします（グループ配信は Multica がイベントを見る前に ShareCRM 側でフィルタされます）。 |
| **メッセージ送信** | Bot がエージェントの返信や通知を同じチャットに投稿できるようにします。 |
| **SSE 長接続** | Multica が外向きにダイヤルし、push 接続を維持します——受信チャットに**公開 webhook／URL は不要**です。 |

**Multica 側の webhook URL も OAuth リダイレクト URL もありません**。ロボットは SSE 長接続で動作し、BYO は OAuth を使わないからです。

<Callout type="info">
ShareCRM にはネイティブの入力中インジケーターがないため——DingTalk と同様に——Bot は処理を始めると短い「処理中」の合図を先に返し、完全な返信はエージェントの処理が終わってから届きます。短時間に連投したメッセージは 1 つの合図にまとめられます。
</Callout>

### 2. Multica で接続する

1. **Agents → _あなたのエージェント_** でエージェントを開き、**Integrations** タブ（または左サイドバーの **Integrations** セクション）を開きます。
2. **Connect ShareCRM** をクリックします。
3. **App ID** と **App Secret** を貼り付けます。パブリッククラウドでは **API base URL** を空のままにし、プライベートクラウドではホストを指定します。
4. **Connect** をクリックします。Multica は API ベース URL に対してトークンを取得し、認証情報を検証します。
5. エージェントに **Connected to ShareCRM** と表示されます。Bot は専用の SSE 接続でリッスンしています。

<Callout type="warning">
2 つの認証情報は**同じ** ShareCRM ボットアプリケーションのものでなければならず、そのアプリケーションはちょうど**1 つ**のエージェントに対応します。別のエージェントやワークスペースにすでに接続されている App ID の接続は拒否されます。ボットを別のエージェントへ移すには、先に切断してください。エージェントを**新しい** App ID で再接続すると、そのエージェントの Bot がその場で更新されます。
</Callout>

<Callout type="info">
**複数のエージェント**でこれを設定しますか？ フロー全体をエージェントごとに 1 回ずつ繰り返してください——各エージェントが専用の App ID / App Secret を持ち、別々の Bot として表示されます。
</Callout>

## この連携でできること

| 画面 | 動作 |
|---|---|
| **エージェント → Integrations** | owner と admin には **Connect ShareCRM** が表示され、接続後は **Connected to ShareCRM** バッジと **Disconnect** 操作に切り替わります。 |
| **Bot に DM** | ワークスペースメンバーが 1:1 チャットで Bot にメッセージを送ります。会話はエージェントとの Multica [chat](/chat) セッションになり、すべてのメッセージが読み取られます。 |
| **グループで @ メンション** | Bot をグループに追加して @ メンションします。ShareCRM が Bot に配信するメッセージだけが読み取られ、Bot はグループ全体を監視しません。 |
| **テキストのみ** | 現在はテキストメッセージのみを扱います。画像・ファイル・音声はエージェントに渡されません。 |
| **`/issue` コマンド** | メッセージを `/issue <タイトル>` で始めると、入力内容からそのまま Multica イシューをあなた名義で作成し、同じ会話にイシュー ID とタイトルを返します。説明は続く行に書きます。コマンド自体は Multica Chat に現れず、作成されたイシューが Multica に記録される結果です。 |
| **`/new` コマンド** | メッセージを `/new <あなたのメッセージ>` で始めると、そのメッセージを以前の会話コンテキストなしで実行します。`/new` だけを送ると、同じ fresh 意図を次の非空メッセージに適用し、空の turn は作りません。会話履歴はそのまま残ります。 |
| **返信** | エージェントの回答は同じ 1:1 チャットまたはグループにプレーンテキストで投稿されます（配信時に Markdown は除去されます）。 |

## Bot を使う（メンバー）

### 最初のメッセージ: アカウントをリンクする

初めて Bot を @ メンションするか DM すると、製品内の **/sharecrm/bind** ページを指す **アカウントをリンク** プロンプトが返ります。リンクを開き Multica にサインインすると、ShareCRM のアイデンティティが Multica メンバーシップに紐づきます——これによりエージェントがあなたとして動作できます（例: `/issue` があなたの名義で起票されます）。リンクは使い捨てで約 15 分で期限切れになります。新しいリンクが必要なら、もう一度 Bot にメッセージしてください。

<Callout type="warning">
**ワークスペースのメンバー**だけが Bot を使えます。メンバーでない場合、またはアイデンティティリンクをスキップした場合、Bot は動作しません——メッセージは破棄されます（監査のために記録され、本文は保存されません）。
</Callout>

### チャットとコマンド

- **グループでは** —— Bot をグループに追加し、`@your-bot <あなたのメッセージ>` と送ります。フォローアップごとに再度 @ してください（Bot は ShareCRM がルーティングしたメッセージだけを受け取ります）。
- **1:1 チャットでは** —— Bot を開いて直接メッセージを送ります。@ は不要で、すべてのメッセージが読み取られます。
- **イシューを起票** —— `/issue Safari のログインリダイレクトが壊れている` と送り、必要なら続く行に説明を追加します。Multica は同期的にイシューを作成し、ID とタイトルをチャットに返します。
- **新しく始める** —— `/new <あなたのメッセージ>` で以前のコンテキストなしで実行するか、`/new` だけを送って次の非空メッセージに fresh 意図を適用します。どちらの形式も既存の会話履歴は削除しません。

## 管理と切断

ワークスペース全体の管理は **Settings → Integrations** にあります。

- **Connected bots** はワークスペース内のすべての Bot と、それぞれが紐づくエージェントを一覧表示します（全メンバーが閲覧可能）。
- **Disconnect** は **owner / admin のみ**です。Bot は ShareCRM メッセージの受信を止め、接続を解体します。インストール記録は監査用に残り、後から再接続できます。

## 権限

- **接続 / 切断** にはワークスペースの **owner** または **admin** が必要です。
- **Bot と話す** には、リンク済みの ShareCRM アイデンティティを持つワークスペースメンバーであることが必要です。それ以外は破棄されます。
- 破棄されたメッセージの本文は決して保存されません——監査用に破棄理由だけが記録されます。

## セルフホスト設定

Multica Cloud ではこの連携はすでに利用可能です——このセクションはスキップしてください。

セルフホストの場合、ShareCRM は**保存時の暗号化キーを設定するまでオフ**です。このキーは各ボットの App Secret をデータベース保存前に暗号化します。App ID は機密情報ではないインストールのルーティング識別子として平文で保存されます。BYO にはデプロイレベルの OAuth の client id/secret は**不要**です——各インストールは admin が貼り付けた認証情報を使います。

1. 32 バイトのキーを生成し、API サーバーに設定します。

   ```dotenv
   MULTICA_SHARECRM_SECRET_KEY=<base64-encoded 32-byte key>
   ```

   例: `openssl rand -base64 32`。

2. API を再起動します。キーが設定されるまで、**Settings → Integrations** には「ShareCRM integration not enabled」の通知が表示され、**Connect ShareCRM** の入口も非表示のままです。

<Callout type="info">
キーはちょうど 32 バイトにデコードされる必要があります——`openssl rand -base64 32` で可能です。長期有効なシークレットとして扱ってください。ローテーションや紛失は、保存済み認証情報を復号不能にし、すべての Bot の再接続が必要になります。「アカウントをリンク」リンクは Web アプリ URL（`MULTICA_APP_URL`、未設定時は `FRONTEND_ORIGIN`）から組み立てられます——通常のデプロイではすでに設定されているため、チャット側の追加設定はありません。メンバーがバインドリンクを開くとき、その URL にブラウザから到達できる必要があります。
</Callout>

同じ App ID は同時に**1 本**のアクティブな SSE 接続しか持てません。Multica の channel supervisor はインストールごとにリースし、単一のバックエンドレプリカが接続を所有します。複数レプリカでは、リースを持つレプリカだけがストリームを維持します。
