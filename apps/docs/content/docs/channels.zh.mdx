<Callout type="info">
  新的智能体级 Bot 连接与重新分配入口已退役。已有连接、身份回调和消息执行继续保留。
</Callout>

## 保留的平台行为

| | 飞书 / Lark | Slack | 钉钉 | 企业微信 |
|---|---|---|---|---|
| 私聊 | 支持 | 支持 | 支持 | 支持 |
| 群聊 / 频道 | @ 后运行 | @ 后运行 | @ 后运行 | @ 后运行 |
| 创建 issue | `/issue` | `/issue` slash command | `/issue` | `/issue` |
| 连接方式 | 平台长连接 | Socket Mode | Stream mode | 平台长连接 |

每个 Bot 继续保留已有的智能体映射。钉钉已发现群路由也继续用于执行，但在浏览器中只读展示。

## 消息如何处理

1. Multica 根据 Bot 确定工作区和智能体。
2. 群聊中只处理明确 @ Bot 的消息。
3. 验证身份绑定和工作区成员资格。
4. 消息进入 [Chat](/chat) 并创建任务。
5. 回复回到原私聊或 thread。

## 身份绑定

成员首次发消息时可能收到一次性的身份链接。这个 callback / broker 合同独立于新的智能体连接继续保留，并会在每条消息上检查成员资格。

## 管理保留连接

工作区所有者和管理员可在 **Settings → Integrations** 查看或断开已有 Bot。断开后仍保留会话与审计记录。

## 自部署

已保存的 Bot 凭证仍需要各平台的 32 字节加密密钥：

```dotenv
MULTICA_LARK_SECRET_KEY=<base64-encoded 32-byte key>
MULTICA_SLACK_SECRET_KEY=<base64-encoded 32-byte key>
MULTICA_DINGTALK_SECRET_KEY=<base64-encoded 32-byte key>
MULTICA_WECOM_SECRET_KEY=<base64-encoded 32-byte key>
```

请稳定保留密钥，确保已有凭证可以继续解密。
