把一個 Multica AI 代理連線成飛書 Bot 後，團隊成員可以在飛書裡私聊它、在群裡 @ 它，也可以用 `/issue` 建立任務。對話和執行記錄都儲存在 Multica 工作區。

每個 Bot 只對應一個 AI 代理。需要在飛書中使用多個 AI 代理時，分別為它們連線 Bot。

## 連線 Bot

AI 代理的所有者、工作區 owner 和 admin 可以發起連線：

<Steps>
<Step>
開啟 **AI 代理**，選擇要接入飛書的 AI 代理。
</Step>
<Step>
進入 **整合**，點選 **繫結到飛書**。
</Step>
<Step>
用飛書掃描二維碼並確認授權。二維碼只能用一次，過期後重新生成即可。
</Step>
<Step>
回到 Multica。繫結後頁面顯示 **已綁定，等待訊息驗證**。請在飛書/Lark 中向 Bot 傳送一則訊息。**訊息接收已驗證** 只表示這次繫結收到過有效訊息，不保證持續連線、AI 代理執行成功或回覆成功。升級期間，舊繫結可以依據這次繫結之後的有效對話記錄保留接收證明；沒有這類證據的繫結仍需等待新訊息。重新繫結會清空記錄。
</Step>
</Steps>

已經連線的 AI 代理不會再次顯示掃碼入口；需要改名或調整權限時，點選 **在飛書中管理**。

<Callout type="info">
目前只開放中國大陸版飛書的新連線入口。已有的國際版 Lark 連線仍可繼續使用和管理。
</Callout>

## 第一次使用

成員第一次給 Bot 發訊息時，會收到一個帳號繫結連結：

<Steps>
<Step>
開啟連結並登入 Multica。
</Step>
<Step>
確認要關聯的工作區帳號。
</Step>
<Step>
回到飛書，再傳送一次訊息。
</Step>
</Steps>

Multica 靠這次繫結確認訊息來自哪位工作區成員。非成員無法使用 Bot。

## 在飛書中交代工作

### 私聊

直接給 Bot 發訊息即可。連續訊息保留在同一段 Multica 對話中，AI 代理的回覆也發回當前對話。

### 群聊

先把 Bot 加入群聊，再 `@Bot` 並寫下要求。Bot 只響應明確 @ 它的訊息，執行時會帶上群裡最近的幾條訊息作為上下文。

### 建立任務

傳送：

```text
/issue 修復登入後的跳轉問題
Safari 登入成功後仍然停留在登入頁。
```

第一行作為標題，其餘內容作為描述。只傳送 `/issue` 不會建立任務；Bot 會回覆用法提示。

## 接收 AI 代理生成的圖片和檔案

部署啟用附件回傳後，AI 代理回覆中的文字與受支援圖片會在同一條飛書訊息中混排，圖片上傳完成後更新原訊息；檔案另發到同一會話。沒有正文的圖片回覆可直接傳送圖片訊息。圖片上限為 10 MB；不受支援、過大或被飛書明確拒絕的圖片會按檔案傳送，檔案上限為 30 MB。此功能需要服務端配置物件儲存，並授予飛書應用資源上傳權限。傳送失敗或無法確認送達時，附件仍保留在 Multica 的回覆中；請求重發前，請先檢查當前會話。

## 管理連線

開啟 **設定 → 訊息渠道 → 飛書** 可以檢視工作區內已連線的 Bot。工作區 owner 和 admin 可以在這裡斷開連線；AI 代理所有者也可以回到該 AI 代理的 **整合** 頁面管理自己的 Bot。

斷開後，Bot 不再接收新訊息，已有的對話和審計記錄不會隨之刪除。

## 自託管配置

Multica Cloud 無需額外配置。自託管部署需要先設定一個用於加密 Bot 憑據的金鑰：

```dotenv
MULTICA_LARK_SECRET_KEY=<base64 編碼的 32 位元組金鑰>
```

可以這樣生成：

```bash
openssl rand -base64 32
```

重啟 API 服務後，再從 AI 代理的 **整合** 頁面連線 Bot。該金鑰需要長期儲存：更換或丟失後，已有憑據無法解密，需要重新連線。

`MULTICA_LARK_HTTP_BASE_URL` 和 `MULTICA_LARK_CALLBACK_BASE_URL` 只用於代理、測試等特殊部署，正常情況下不需要設定。

## 常見問題

- **沒有繫結按鈕**：確認當前帳號是 AI 代理所有者、工作區 owner 或 admin，並檢查自託管金鑰是否已配置。
- **二維碼失效**：關閉彈窗後重新發起連線。
- **Bot 要求繫結帳號**：開啟繫結連結並使用該工作區的 Multica 帳號登入。
- **Bot 不執行**：檢查 AI 代理是否已歸檔，以及它使用的[執行時](/daemon-runtimes)是否線上。
- **Bot 完全不回覆**：應用必須透過長連線推送事件，Multica 沒有 webhook 接收地址。開啟飛書開發者後臺的 **事件與回撥 → 事件配置**，確認訂閱方式是使用長連線接收事件而不是請求地址，`im.message.receive_v1` 已訂閱，並且包含該配置的版本已釋出（企業需要審核時還要通過審核）。配成請求地址的應用照樣能繫結、照樣顯示"已連線"，但一條訊息都收不到。
