对话适合还没有形成明确任务的工作：梳理想法、查询工作区情况、讨论方案、问一个不属于任何任务的问题，或者先让智能体完成一个小任务。

对话（Chat）是你和[智能体](/agents)的一对一沟通，不在[任务](/issues)看板上。整段对话**完全私人**，[工作区](/workspaces)里的其他人，包括 admin，都看不到。

对话**不绑定任务**。智能体不盯着你的看板，不会自动收到任务的描述和评论，也不会自己把对话变成任务。它仍可以在权限范围内用 Multica CLI 查询工作区、项目、任务和 skill；你明确要求时，它会以你的工作区权限代你操作，例如建一个任务。

对话也可以携带背景。点击输入框左下角的 **+**，选择**项目上下文**，为对话挂上一个[项目](/projects)；智能体执行时会收到该项目的描述和仓库等资源。

## 开始对话

<Steps>
<Step>

打开侧边栏中的**聊天**。

</Step>
<Step>

点击新建，选择一个你有权运行的智能体。

</Step>
<Step>

输入消息，也可以附加图片或文件。

</Step>
<Step>

发送后，Multica 会为这条消息创建一次执行，回复回到当前对话。

</Step>
</Steps>

运行时离线时，消息会等待它重新上线。智能体被归档，或者你失去调用权限后，不能继续发送新消息。

第一条消息发送前，对话页会显示所选智能体配置的最多三个建议。选择一条只会把完整提示词填进输入框，不会发送，你可以先改再发。没有配置建议的智能体显示通用示例。

智能体回复后，下方有时会给出**后续提问**。后续提问点击后直接发送。

## 在任意页面打开悬浮聊天窗

不用离开当前页面也能聊天。工作区页面可以在悬浮聊天窗里打开对话。窗里的对话和**聊天**页是同一份，在哪边开始的对话，另一边都能接着聊。

窗口较宽时，快捷聊天在应用底部状态栏的右端：

- 点**问 Multica**开始新对话。
- 智能体正在处理、有未读回复，或者你在悬浮窗里打开过的对话，会在状态栏里显示成一个标签。标签上转圈表示智能体正在回复，彩色圆点表示有未读回复；悬停能看到对话标题和状态。点标签打开对应对话，再点一次收起悬浮窗。放不下的标签收进 **+N** 菜单。
- 悬停标签后点 **×** 可以关掉它。这段对话有新消息，或者你再次打开它时，标签会回来。
- 状态栏最右边的**对话历史**列出最近的对话，同样标出运行中和未读。点一条打开它，或者点**全部对话**进入**聊天**页。
- 悬浮窗打开在你点的按钮或标签上方。

窗口较窄时没有状态栏，改由右下角的圆形聊天按钮打开悬浮窗。智能体正在回复时，这个按钮会轻轻跳动；悬停提示会说明有对话正在运行或有未读回复。

- 按 `⌘J`（Windows / Linux 上是 `Ctrl+J`）打开或收起悬浮窗，打开后光标直接落在输入框里。光标在输入框里时也能用这个键收起。按键可以在**设置 → 快捷键**里改，见[搜索、快捷键与偏好设置](/shortcuts)。
- 按 `⇧⌘J`（Windows / Linux 上是 `Ctrl+Shift+J`）则直接开始新对话，和点**问 Multica**一样；`⌘J` 打开的是上次那段对话。停在新对话上再按一次会收起悬浮窗。
- 悬浮窗可以拖动边缘调整大小，也可以展开或最小化。
- **聊天**页本身的状态栏里没有快捷聊天，也不显示圆形按钮，`⌘J` 和 `⇧⌘J` 在这里也不起作用：整页显示的已经是同一段对话。

不需要悬浮窗时，在**设置 → 偏好设置 → 评论与聊天**里关闭**悬浮聊天窗**。之后状态栏里不再有快捷聊天，也不再显示圆形按钮，只能从侧边栏进入聊天。这个开关只对当前设备生效。

## 对话与任务的选择

| 需要 | 更适合 |
|---|---|
| 快速提问、探索方案或处理私人草稿 | **对话** |
| 明确负责人、状态、优先级和交付结果 | **任务** |
| 让团队成员查看背景并继续讨论 | **任务** |
| 临时查看工作区信息，不需要建立工作记录 | **对话** |

在 Multica 中创建的直接对话只有创建者能读取，其他成员和管理员都不能。需要团队一起看的结论，整理到任务、项目说明或 skill 中。

## 多轮上下文

同一段对话会尽量继续 AI 编程工具中的原会话，因此后续消息不需要重复前面的内容。Multica 会保存会话标识，并把后续执行路由到能够访问该会话的运行时。

如果本地会话已经不存在、上下文无法继续，或者上一次错误不适合复用，运行时会从新会话开始。对话中的历史消息仍然保留。

## 查看和停止执行

智能体运行时，界面会显示当前阶段和工具活动。展开**查看详情**可以检查更完整的执行过程。

需要中断时，点击输入框旁的停止按钮（输入框为空时显示）。已经返回到对话中的内容会保留。

如果智能体还没输出任何内容就被停下，你刚发的那条消息会从对话里撤回，连同附件放回输入框，改一改就能重发。停止有时要过一会儿才真正完成；这期间刷新页面或关掉窗口也不会丢，下次打开这段对话时，消息会回到输入框。输入框里已经有别的草稿时，会等你清空后再放回。

## 回复还没结束时继续发消息

智能体还在回复时，可以继续输入。运行时支持插话时，点**发送**会把不含 skill 链接的纯文本消息插入当前回复，不会停止运行；智能体在下一个安全时机读到消息，继续完成原任务。需要升级 daemon 才能启用。

在网页端和桌面端，输入时显示的**插话到当前运行**表示文字会加入当前回复；**本轮结束后开始**表示消息会排队，例如带有附件、skill 链接或当前运行不支持插话时。

带附件或 skill 链接的消息、回复尚未开始时发送的消息，以及不支持插话的运行，都会进入队列。如果插话在当前回复结束前没送达，会自动转成排队消息，无需重发。投递过程中点停止，会先等待投递结果，再将未送达的插话排队。如果回复自动重试，插话会保留在原请求中，一起处理；恢复同一会话时，已送达的插话不会再次发送。

排队消息显示在输入框上方，按顺序处理。可以删除，通过 **⋯ → 编辑排队消息** 放回输入框，或用 **⋯ → 全部清空** 撤回。**立即发送（停止当前回复）** 会把排队消息提到队首，并停止当前回复；需要当前回复已开始，且你有运行该智能体的权限。

插话适用于新版网页端、桌面端和移动端的普通 Chat。移动端的排队消息显示在对话末尾，删除或编辑请在网页端或桌面端操作。旧版客户端和 Slack、Lark 等渠道会话保持原有排队行为。

## 稍后跟进 [#follow-up-later]

可以让智能体在有结果时回来汇报，例如"任务可以评审时告诉我"或"两小时后提醒我"。它可以创建唤醒，在任务到达指定状态、子任务完成、GitHub PR 合并或关闭、其检查结束、运行结束或成员在任务下评论时，在原对话中启动新的运行；也可以按指定时间提醒或定期检查。

在网页和桌面端，回复下方的卡片会记录这次跟进。输入框上方的提示条显示正在等待的事项和截止时间。点击提示条或对话标题栏的时钟按钮，打开**唤醒**列表，也能查看过去 7 天内结束的记录。点击**取消唤醒**可停止等待；汇报运行失败或被取消时，可以点击**重试**。

条件等待和定期检查默认持续 24 小时，最长 7 天。到期仍未等到结果时，智能体会再运行一次，汇报当前进展。单次提醒最远可安排在 30 天后。每个对话最多有 10 个有效唤醒。归档对话会取消其有效唤醒；失去对智能体或所关注工作的访问权限，也可能让唤醒结束。

日报等长期计划使用[自动化](/autopilots)。智能体通过 [`chat wakeup`](/cli#chat-wakeups) 管理跟进。

## 整理对话列表

对话支持重命名、置顶、归档和删除：

- **置顶**把常用对话固定在列表前面；
- **归档**把对话移到"已归档"并设为只读；
- **取消归档**后可以继续发送消息；
- **删除**会永久移除对话及其中的消息。

如果对话绑定了外部渠道（如 Slack），归档时绑定会断开，取消归档不会恢复，需要重新绑定。

所有对话的未读回复数会以角标显示在应用侧栏的**聊天**上。在桌面端右键点击**聊天**可以**全部标为已读**。

<Callout type="warning">
删除对话无法撤销，并会停止其中尚未结束的执行。暂时不需要时用归档。
</Callout>
