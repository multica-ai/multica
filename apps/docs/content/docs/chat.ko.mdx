대화는 아직 명확한 태스크가 되지 않은 작업에 적합합니다. 아이디어를 정리하고, 워크스페이스 상황을 조회하고, 방안을 논의하고, 어떤 태스크에도 속하지 않는 질문을 하거나, 에이전트에게 작은 작업을 먼저 맡길 수 있습니다.

대화(Chat)는 나와 [에이전트](/agents) 사이의 일대일 소통이며, [태스크](/issues) 보드 밖에서 이루어집니다. 대화 전체는 **완전히 비공개**여서 [워크스페이스](/workspaces)의 다른 사람은 admin을 포함해 아무도 볼 수 없습니다.

대화는 **태스크에 연결되지 않습니다**. 에이전트는 내 보드를 보고 있지 않고, 태스크 설명과 댓글을 자동으로 받지 않으며, 대화를 스스로 태스크로 바꾸지도 않습니다. 그래도 권한 범위 안에서 Multica CLI로 워크스페이스, 프로젝트, 태스크, 스킬을 조회할 수 있고, 명시적으로 요청하면 내 워크스페이스 권한으로 대신 작업합니다. 예를 들어 태스크를 만들 수 있습니다.

대화에 배경을 추가할 수도 있습니다. 입력란 왼쪽 아래의 **+**를 클릭하고 **프로젝트 컨텍스트**를 선택해 대화에 [프로젝트](/projects)를 연결하세요. 에이전트는 실행할 때 해당 프로젝트의 설명과 저장소 같은 리소스를 받습니다.

## 대화 시작

<Steps>
<Step>

사이드바에서 **채팅**을 엽니다.

</Step>
<Step>

새 대화를 클릭하고 실행 권한이 있는 에이전트를 선택합니다.

</Step>
<Step>

메시지를 입력합니다. 이미지나 파일을 첨부할 수도 있습니다.

</Step>
<Step>

전송하면 Multica가 이 메시지에 대한 실행을 만들고 답변은 현재 대화로 돌아옵니다.

</Step>
</Steps>

런타임이 오프라인이면 다시 온라인이 될 때까지 메시지가 기다립니다. 에이전트가 보관 처리되거나 호출 권한을 잃으면 새 메시지를 보낼 수 없습니다.

첫 메시지를 보내기 전에 선택한 에이전트에 설정된 추천이 최대 3개 표시됩니다. 하나를 선택하면 전체 프롬프트가 입력창에 채워질 뿐 전송되지 않으므로 먼저 고칠 수 있습니다. 추천이 설정되지 않은 에이전트에는 범용 예시가 표시됩니다.

에이전트가 답변한 뒤 그 아래에 **후속 질문**이 나올 때가 있습니다. 클릭하면 바로 전송됩니다.

## 어느 페이지에서나 채팅하기

지금 보고 있는 페이지를 떠나지 않고도 채팅할 수 있습니다. 워크스페이스 페이지 오른쪽 아래에 둥근 채팅 버튼이 있고(툴팁은 'Multica에 묻기'), 클릭하면 플로팅 채팅 창이 열립니다. 이 창과 사이드바의 **채팅** 페이지는 같은 대화를 공유하므로, 어느 쪽에서 시작한 대화든 다른 쪽에서 이어서 할 수 있습니다.

- `⌘J`(Windows와 Linux에서는 `Ctrl+J`)로 플로팅 채팅 창을 열고 닫습니다. 창을 열면 커서가 메시지 입력란에 놓이고, 입력란에서 글을 쓰는 중에도 이 키로 닫을 수 있습니다. 키는 **설정 → 단축키**에서 바꿀 수 있습니다. [검색, 단축키, 환경설정](/shortcuts)을 참고하세요.
- 창 가장자리를 끌어 크기를 조절하거나, 창을 펼치거나 최소화할 수 있습니다. 에이전트가 답변하는 동안에는 닫힌 채팅 버튼이 살짝 맥박치듯 움직입니다.
- **채팅** 페이지에는 이 버튼이 표시되지 않고 `⌘J`도 동작하지 않습니다. 페이지 전체가 이미 같은 대화를 보여 주기 때문입니다.

플로팅 창이 필요 없다면 **설정 → 환경설정 → 댓글 및 채팅**에서 **플로팅 채팅 창**을 끄세요. 그 뒤에는 사이드바에서만 채팅에 들어갈 수 있습니다. 이 설정은 지금 쓰는 기기에만 적용됩니다.

## 대화와 태스크 선택

| 필요 | 더 적합한 방식 |
|---|---|
| 빠른 질문, 방안 탐색, 개인 초안 처리 | **대화** |
| 담당자, 상태, 우선순위, 결과물을 명확히 지정 | **태스크** |
| 팀 멤버가 배경을 확인하고 논의를 이어가게 하기 | **태스크** |
| 작업 기록을 만들 필요 없이 워크스페이스 정보를 임시로 확인 | **대화** |

Multica에서 만든 직접 대화는 만든 사람만 읽을 수 있고, 다른 멤버와 관리자는 읽을 수 없습니다. 팀이 함께 봐야 하는 결론은 태스크, 프로젝트 설명, 스킬에 정리하세요.

## 여러 대화 턴의 컨텍스트

같은 대화에서는 가능한 한 AI 코딩 도구의 기존 세션을 이어가므로 이후 메시지에서 앞선 내용을 반복할 필요가 없습니다. Multica는 세션 식별자를 저장하고, 이후 실행을 해당 세션에 접근할 수 있는 런타임으로 라우팅합니다.

로컬 세션이 더 이상 존재하지 않거나 컨텍스트를 이어갈 수 없거나 이전 오류가 재사용에 적합하지 않으면 런타임이 새 세션을 시작합니다. 대화의 이전 메시지는 그대로 남습니다.

## 실행 확인 및 중지

에이전트가 실행 중이면 화면에 현재 단계와 도구 활동이 표시됩니다. **상세 보기**를 펼치면 더 자세한 실행 과정을 확인할 수 있습니다.

중단하려면 입력란 옆의 중지 버튼(입력란이 비어 있을 때 표시)을 클릭하세요. 대화에 이미 반환된 내용은 유지됩니다.

에이전트가 아직 아무것도 출력하지 않았을 때 멈추면, 방금 보낸 메시지가 대화에서 빠지고 첨부 파일과 함께 입력란으로 돌아오므로 고쳐서 다시 보낼 수 있습니다. 중지가 끝나기까지 조금 걸릴 때가 있는데, 그사이 페이지를 새로 고치거나 창을 닫아도 메시지는 사라지지 않고 다음에 그 대화를 열 때 입력란으로 돌아옵니다. 입력란에 다른 초안이 있으면 그 초안을 비울 때까지 기다립니다.

## 답변 중에 메시지 이어서 보내기

에이전트가 답변하는 동안에도 다음 메시지를 입력할 수 있습니다. 입력란에 내용이 있으면 보내기 버튼이 **대기열에 추가**로 바뀝니다. 대기열에 들어간 메시지는 현재 답변을 끊지 않고 입력란 위의 대기열에서 기다리다가, 답변이 끝나면 순서대로 처리됩니다.

| 동작 | 결과 |
|---|---|
| **지시** | 이 메시지를 맨 앞으로 옮기고 현재 답변을 멈춥니다. 에이전트가 이미 쓴 내용은 대화에 남고, 이어서 이 메시지를 처리합니다. |
| 삭제(휴지통 아이콘) | 메시지를 대기열에서 뺍니다. 에이전트에게는 전달되지 않습니다. |
| **⋯ → 대기 중인 메시지 편집** | 메시지를 첨부 파일과 함께 입력란으로 되돌립니다. 고친 뒤 다시 보내면 됩니다. |
| **⋯ → 모두 지우기** | 대기 중인 메시지를 모두 취소합니다. 현재 답변은 그대로 이어집니다. |

현재 답변이 실제로 시작되기 전(예: 런타임이 가져가기를 기다리는 중)에는 **지시**를 쓸 수 없고, 에이전트를 실행할 권한을 잃은 뒤에도 쓸 수 없습니다.

<ChatQueueDemo />

<Callout>
여기서 **지시**는 현재 답변부터 멈춥니다. 태스크 댓글의 [현재 실행에 추가](/mentioning-agents#실행-중인-에이전트에게-끼어들기)는 다르게 동작합니다. 실행을 끊지 않고, 에이전트가 현재 단계를 마친 뒤 메시지를 읽고 원래 태스크를 이어 갑니다.
</Callout>

## 대화 목록 정리

대화는 이름 변경, 고정, 보관, 삭제할 수 있습니다.

- **고정**하면 자주 쓰는 대화가 목록 앞쪽에 유지됩니다.
- **보관**하면 대화가 "보관됨"으로 이동하고 읽기 전용이 됩니다.
- **보관 해제**하면 메시지를 다시 보낼 수 있습니다.
- **삭제**하면 대화와 그 안의 메시지가 영구적으로 제거됩니다.

대화가 Slack 같은 외부 채널에 연결되어 있다면 보관할 때 연결이 끊어집니다. 보관을 해제해도 연결은 복원되지 않으므로 다시 연결해야 합니다.

<Callout type="warning">
대화 삭제는 취소할 수 없으며 아직 끝나지 않은 실행도 중지합니다. 당분간 필요하지 않다면 보관하세요.
</Callout>
