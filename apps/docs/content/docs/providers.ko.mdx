Multica는 사용 중인 AI 코딩 도구를 대체하지 않습니다. 런타임이 컴퓨터에 이미 설치되어 로그인된 도구를 호출하고 실행 진행 상황과 결과를 태스크에 기록합니다. 이미 사용 중인 도구가 있다면 보통 그대로 쓰면 됩니다. 아직 정하지 않았다면 다음 네 가지를 보세요.

- 컴퓨터에 이미 설치되어 있는가
- 계정에서 어떤 모델을 사용할 수 있는가
- Multica가 MCP를 설정해야 하는가
- 팀에서 어떤 스킬을 재사용해야 하는가

설치 방법은 [AI 코딩 도구 설치](/install-agent-runtime)를 참고하세요.

"Multica의 MCP 관리"는 에이전트 설정에 MCP server를 입력하면 Multica가 실행 전에 해당 도구로 전달할 수 있다는 뜻입니다. 이 열은 Multica가 대신 설정할 수 있는지만 나타내며, 도구 자체에 다른 MCP 설정 방법이 있는지와는 관계없습니다.

"Multica에서 모델 선택"이 —인 도구는 도구 자체 설정에서 모델을 고릅니다. [모델 출처](#모델-출처)를 참고하세요.

## 모델 출처

Devin은 로컬 ACP로 실행되며 stdio MCP를 지원합니다. HTTP/SSE는 CLI가 지원을 선언한 경우에만 전달됩니다. skill 가져오기는 Devin/Cognition 디렉터리 다음에 `~/.codeium/<channel>/skills`(`windsurf`, `windsurf-next`, `windsurf-insiders` 순), 마지막으로 `~/.agents/skills`를 검색합니다.

Devin 모델 목록에는 계정에서 사용할 수 없는 모델도 포함될 수 있습니다. 전체 모델 ID, 명확한 세션 모델 이름 또는 카탈로그의 계열 slug/별칭(예: `opus`)을 선택하거나 비워 두어 CLI 기본 모델을 사용하세요. Multica는 전송 전에 실제 모델을 확인하고 다른 계열로의 대체를 거부합니다. 모호한 이름, 임의의 부분 이름, 사용할 수 없는 변형은 전체 ID로 지정하세요. 사용량은 반환된 모델에 귀속되며 Adaptive는 라우팅 ID로 기록합니다. 하위 모델은 추측하지 않습니다.

Devin은 `WINDSURF_API_KEY`가 있으면 사용하고, 없으면 `devin auth login`으로 저장한 인증 정보를 사용합니다. 알 수 없는 ACP 인증 방식도 저장된 로그인을 막지 않습니다. Multica는 권한을 높이지 않고 설정된 세션 모드를 유지합니다. 기본값이 `plan`이면 파일을 수정하는 태스크를 보내기 전에 Devin에서 편집 가능한 모드로 바꾸세요.

에이전트를 만들 때 모델 목록은 해당 런타임에서 가져옵니다. 일부 도구는 고정된 모델 이름을 제공하고, 일부는 로컬 설정, 로그인 계정, 구독 권한에 따라 사용 가능한 모델을 반환합니다.

모델을 선택하지 않으면 Multica가 해당 도구의 기본 설정을 사용합니다. 목록이 비어 있다면 런타임이 온라인이고 도구에 로그인되어 있는지 확인한 뒤 모델 목록을 새로 고치세요.

QwenPaw, MiniMax Code, ZeroClaw는 예외입니다. Multica에서 고른 모델을 받아들이지 않으므로 선택 상자가 비활성 상태로 "런타임에서 관리"라고 표시됩니다. 모델은 각 도구의 자체 설정에서 선택하세요. 이 도구들의 모델 목록이 비어 있는 것은 정상이며 런타임이 오프라인이라는 뜻이 아닙니다.

DeepSeek Harness의 모델 카탈로그는 런타임 자체가 제공합니다(`dsh --profile multica --list-models`). 모델 ID는 `provider/model` 형식(예: `deepseek-official/deepseek-chat`)이므로 목록에서 전체 ID를 선택하세요.

<Callout type="info">
모델 이름은 도구끼리 통용되지 않습니다. AI 코딩 도구를 바꾸면 기존 모델 값은 새 도구에서 유효하지 않으므로 다시 선택해야 합니다.
</Callout>

## 세션 복원

표에서 ✓로 표시된 도구는 원래 세션이 남아 있고 그 세션에 접근할 수 있는 런타임이 실행을 처리하면, 이후 실행에서 기존 세션을 이어갈 수 있습니다. MiniMax Code 0.1.2는 ACP에서 세션 로드 기능을 알리지 않으므로 이후 실행에서는 새 MCode 세션을 시작합니다.

Multica는 도구가 반환한 세션 식별자를 저장합니다. 다음에 같은 태스크에서 작업을 이어갈 때 런타임이 이 세션의 복원을 시도합니다. 복원할 수 없으면 새 세션을 만들어 계속 실행합니다. Pi는 로컬 세션 파일 경로를 저장하므로 원래 컴퓨터와 파일에 더 많이 의존합니다.

재시도와 세션 복원 규칙은 [실행](/tasks#수동-재시도)을 참고하세요.

## MCP 설정

Antigravity, GitHub Copilot CLI, DevEco Code, Muse Code, ZeroClaw는 현재 에이전트의 MCP 설정을 읽지 않으므로 에이전트를 만들 때 이 항목이 표시되지 않습니다.

Pi에 관리형 MCP 설정을 전달하려면 Pi 0.99.0 이상이 필요합니다. 이전 Pi 버전에서도 MCP 설정이 없는 에이전트는 계속 실행할 수 있습니다.

<Callout type="warning">
MCP server의 명령, 인수, 환경 변수는 에이전트 설정과 함께 서버에 저장됩니다. 공유할 필요가 없는 로컬 자격 증명을 설정에 직접 넣지 마세요.
</Callout>

런타임 컴퓨터에 이미 설정된 MCP server는 그 컴퓨터에서 에이전트 설정과 합쳐집니다. [로컬 MCP 설정](/daemon-runtimes#local-mcp)을 참고하세요.

## 스킬 주입 방식

실행을 시작하기 전에 Multica가 에이전트에 연결된 스킬을 위 표의 해당 위치에 기록해 도구가 자체 기본 메커니즘으로 발견할 수 있게 합니다.

저장소에 원래 있던 스킬은 덮어쓰지 않습니다. 이름이 충돌하면 Multica가 주입하는 복사본에 다른 디렉터리 이름을 사용하며 실행이 끝나면 자신이 만든 파일만 정리합니다.

Codex, Hermes, OpenClaw의 처리는 조금 다릅니다.

- Codex는 실행별 `CODEX_HOME`을 사용하며 시스템 수준 Codex 디렉터리에 스킬을 기록하지 않습니다.
- Hermes는 실행별 `HERMES_HOME`을 사용합니다. 기존 로컬 설정은 계속 읽을 수 있지만 연결된 스킬과 세션 데이터는 실행별로 격리됩니다. 이 격리는 에이전트에 스킬이 연결된 경우에만 사용되며, 연결된 스킬이 없는 실행은 컴퓨터의 기존 Hermes 홈 디렉터리를 사용합니다.
- OpenClaw는 현재 실행용 작업 디렉터리의 `skills/`를 사용하고 실행별 설정을 통해 이 디렉터리를 워크스페이스로 지정합니다.

스킬 생성 및 연결 방법은 [스킬](/skills)을 참고하세요.
