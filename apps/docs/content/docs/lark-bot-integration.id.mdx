Hubungkan agent Multica sebagai Bot Feishu, maka anggota tim dapat mengirim DM kepadanya di Feishu, @-mention di grup, atau menggunakan `/issue` untuk membuat tugas. Percakapan dan catatan eksekusi disimpan di ruang kerja Multica.

Setiap Bot dipetakan ke tepat satu agent. Untuk menggunakan beberapa agent di Feishu, hubungkan satu Bot untuk masing-masing.

## Hubungkan Bot

Pemilik agent serta pemilik dan admin ruang kerja dapat memulai koneksi:

<Steps>
<Step>
Buka **Agents** dan pilih agent yang akan dihubungkan ke Feishu.
</Step>
<Step>
Buka **Messaging**, klik **Add messaging channel**, lalu pilih **Feishu**.
</Step>
<Step>
Pindai kode QR dengan Feishu dan konfirmasi otorisasinya. Kode QR hanya berlaku sekali; jika kedaluwarsa, buat kode baru.
</Step>
<Step>
Kembali ke Multica. Setelah pengikatan, Multica menampilkan **Waiting for first message**. Kirim pesan ke bot di Feishu/Lark. **Connected** berarti sebuah pesan yang valid telah sampai ke pengikatan ini; ini tidak menjamin konektivitas berkelanjutan, eksekusi agent, atau balasan. Selama masa rollout, pengikatan lama yang memiliki riwayat percakapan yang memenuhi syarat dari pengikatan saat ini dapat mempertahankan bukti penerimaannya. Pengikatan tanpa bukti tersebut menunggu pesan baru. Mengikat ulang menghapus catatannya.
</Step>
</Steps>

Agent yang sudah terhubung tidak lagi menampilkan titik masuk pemindaian; untuk mengganti nama Bot atau menyesuaikan izinnya, buka menu pengelolaan Bot lalu klik **Manage in Feishu**.

<Callout type="info">
Koneksi baru saat ini hanya dibuka untuk Feishu Tiongkok daratan. Koneksi Lark internasional yang sudah ada tetap berfungsi dan masih dapat dikelola.
</Callout>

## Penggunaan pertama

Saat pertama kali anggota mengirim pesan ke Bot, mereka menerima tautan pengikatan akun:

<Steps>
<Step>
Buka tautan tersebut dan masuk ke Multica.
</Step>
<Step>
Konfirmasi akun ruang kerja yang akan ditautkan.
</Step>
<Step>
Kembali ke Feishu dan kirim ulang pesannya.
</Step>
</Steps>

Pengikatan ini adalah cara Multica mengetahui anggota ruang kerja mana yang mengirim suatu pesan. Non-anggota tidak dapat menggunakan Bot.

## Menyerahkan pekerjaan ke agent di Feishu

### Pesan langsung

Kirim pesan langsung ke Bot. Pesan beruntun tetap berada dalam percakapan Multica yang sama, dan balasan agent dikirim kembali ke percakapan itu.

### Obrolan grup

Tambahkan Bot ke grup terlebih dahulu, lalu `@Bot` dan jelaskan apa yang Anda perlukan. Bot hanya merespons pesan yang secara eksplisit @-mention dirinya, dan setiap eksekusi menyertakan pesan-pesan terbaru grup sebagai konteks.

Baik di pesan langsung maupun obrolan grup, prompt setiap eksekusi juga mencantumkan id Feishu dari pesan yang dijawabnya: `chat_id`, `chat_type`, `message_id`, `thread_id` topik jika pesan berada di sebuah topik, dan `sender_open_id` (`open_id` pengirim). Ini adalah id Feishu, bukan id Multica, sehingga agent dengan akses Feishu sendiri dapat mencari pesan atau percakapan aslinya. `open_id` bersifat spesifik untuk app Bot yang terhubung. Id yang tidak dicatat Multica dihilangkan.

Ketika beberapa pesan digabungkan menjadi satu eksekusi, `message_id` mengidentifikasi pesan terakhir dalam batch tersebut dan `sender_open_id` mengidentifikasi pengirim pesan itu. Eksekusi topik lama yang dipulihkan dapat menyertakan `thread_id` tanpa `message_id`.

### Buat tugas

Kirim:

```text
/issue Fix the redirect after login
Safari stays on the login page after a successful sign-in.
```

Baris pertama menjadi judul dan sisanya menjadi deskripsi. Mengirim `/issue` saja tidak membuat apa pun; Bot akan membalas dengan format yang diperlukan.

## Gambar dan file dari agent

Ketika pengiriman file diaktifkan, teks dan gambar yang didukung yang dilampirkan pada balasan agent muncul bersama dalam satu pesan Feishu. Gambar memperbarui pesan tersebut saat selesai diunggah; file tiba secara terpisah di percakapan yang sama. Balasan yang hanya berisi gambar dapat menggunakan pesan gambar. Gambar yang didukung dibatasi 10 MB; gambar yang tidak didukung, lebih besar, atau ditolak secara eksplisit dikirim sebagai file, hingga 30 MB. Ini memerlukan object storage dan izin unggah resource aplikasi. Jika pengiriman gagal atau tidak dapat dikonfirmasi, lampiran tetap tersedia pada balasan di Multica. Periksa percakapan sebelum meminta pengiriman ulang.

## Kelola koneksi

Buka **Settings → Messaging** untuk melihat agent yang terhubung, dikelompokkan per platform. Pilih sebuah agent untuk membuka bagian **Messaging**-nya. Pemilik agent serta pemilik/admin ruang kerja dapat memutuskan koneksi Bot dari menu pengelolaannya di sana.

Setelah diputuskan, Bot berhenti menerima pesan baru. Percakapan dan catatan audit yang sudah ada tidak dihapus.

## Pengaturan hosting mandiri

Multica Cloud tidak memerlukan konfigurasi tambahan. Deployment yang dihosting sendiri harus terlebih dahulu mengatur kunci yang digunakan untuk mengenkripsi kredensial Bot:

```dotenv
MULTICA_LARK_SECRET_KEY=<base64-encoded 32-byte key>
```

Buat kunci seperti ini:

```bash
openssl rand -base64 32
```

Restart API server, lalu hubungkan Bot dari bagian **Messaging** agent tersebut. Simpan kunci ini untuk jangka panjang: jika dirotasi atau hilang, kredensial yang ada tidak dapat lagi didekripsi dan Bot harus dihubungkan ulang.

`MULTICA_LARK_HTTP_BASE_URL` dan `MULTICA_LARK_CALLBACK_BASE_URL` hanya ada untuk deployment khusus seperti proxy dan pengujian; biarkan tidak diset dalam operasi normal.

## Pemecahan masalah

- **Tidak ada tombol bind**: pastikan akun saat ini adalah pemilik agent atau pemilik/admin ruang kerja, dan periksa apakah kunci self-hosting sudah dikonfigurasi.
- **Kode QR kedaluwarsa**: tutup dialognya dan mulai ulang koneksi.
- **Bot meminta pengikatan akun**: buka tautan pengikatan dan masuk dengan akun Multica untuk ruang kerja tersebut.
- **Bot tidak berjalan**: periksa apakah agent diarsipkan dan apakah [runtime](/daemon-runtimes) yang digunakannya online.
- **Bot sama sekali tidak pernah membalas**: app harus mendorong event melalui koneksi panjang; Multica tidak memiliki endpoint webhook. Di konsol developer Feishu/Lark, buka **Events & Callbacks → Event Configuration** dan pastikan metode subscription adalah koneksi panjang bukan request URL, bahwa `im.message.receive_v1` disubscribe, dan bahwa versi app yang membawa konfigurasi tersebut sudah dipublikasikan (dan disetujui, jika tenant mereview rilis). App yang diset ke request URL tetap bisa terhubung, menampilkan **Waiting for first message**, dan secara diam-diam tidak menerima apa pun.
