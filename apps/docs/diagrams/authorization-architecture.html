Multica authorization architecture

A request is admitted by composing identity, workspace membership, resource relationships, explicit grants, consent, and actor kind. No single role is a universal bypass.

2

Compose the policy planes

Each endpoint chooses the narrow set of gates its action needs.

01 Workspace role

owner, admin, or member; membership is the baseline tenant gate.

02 Resource relation

Owner, creator, author, or collaborator adds rights on one resource.

03 Explicit grant

Agent invocation targets and Autopilot collaborators narrow access.

04 Consent and visibility

Private runtimes, discoverability, and secret redaction use distinct rules.

05 Actor boundary

Sensitive endpoints apply explicit actor-source guards.

06 Resource scope

Workspace, user, task, and chat identifiers must match the resolved principal.

role+relationship+grant+action+scopedecision

General invocation: an explicit workspace grant can admit agent/system without a human originator. Private and member-target access remain denied.

Autopilot: manual runs use the clicker; automatic runs require the trigger's valid creator. Write access does not grant target-agent invocation.
