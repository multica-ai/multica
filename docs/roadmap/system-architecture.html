Nøgle-flows

Flow 1: App kalder CFO-agent via API
POST /api/v1/agents/cfo/chat
→ Auth (JWT/PAT) → Rate limit check
→ Governance: må caller kalde CFO?
→ Context: CFO's skills loaded
→ Memory: user + agent memory injected
→ MCP: Slack + Google MCP servers attached
→ Prompt built (CLAUDE.md + context)
→ Execute via daemon/cloud runtime
→ Eval: output quality check
→ SSE stream → caller
→ Event Bus: agent.responded published
Flow 2: Scheduled daily report
Cron trigger: 08:00 daily
→ Schedule entry loaded from DB
→ Same pipeline as Flow 1
→ Output routing: post til Slack #finance
→ Run logged in schedule history
→ Event Bus: schedule.completed

Ingen human i loopet.
Headless approval hvis governance kræver det.
Flow 3: Slack bot @mention
@multica-cfo hvad er MER i dag?
→ Slack webhook → Multica API
→ Route til CFO agent
→ Same pipeline as Flow 1
→ Response posted som Slack thread reply

Bruger fuld agent setup:
skills + memory + MCP tools + governance.
Flow 4: MCP client kalder agent
multica_agent_chat("cfo", "MER?")
→ MCP server modtager tool_use
→ Maps til Agent Chat API
→ Same pipeline as Flow 1
→ Response returneres som MCP result

Enhver MCP-klient (Claude Code, Cursor, etc.)
kan kalde Multica agenter som tools.
