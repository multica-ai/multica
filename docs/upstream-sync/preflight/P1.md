# P1 — TypeScript module augmentation

**Verdict:** PASS

**Hypothesis:** A future `packages/cerebro-types/` can extend upstream-defined types via `declare module`, with extended fields visible to consumers in `apps/web/`.

## What we did

1. Located upstream type definitions: `packages/core/types/project.ts:7-24` defines `Project` as `interface` (augmentable). Same for `Issue`, `Workspace`, `Member`, `Agent`, `Comment`, `Artifact`.
2. Verified tsconfig: `packages/tsconfig/base.json` sets `strict: true`, `module: ESNext`, `moduleResolution: bundler`, `isolatedModules: true` — all compatible with `declare module`.
3. Confirmed `@multica/core` exports `.ts` source (not pre-compiled `.d.ts`), so consumers see the original `interface` declarations.
4. Empirical proof in `/tmp/preflight-P1/`: scratch package, augmenting module, consumer. `tsc` exits 0 on positive case, fails with TS2339 on negative control. Augmentation is type-safe and discriminating.

## Result

Pattern works as planned. No working-tree changes; all artifacts in `/tmp/preflight-P1/`.

## Risks / gotchas

- **Augmentation must be in the type-graph to apply.** Bare `declare module` files need `include` listing OR a side-effect `import "@multica/cerebro-types/augment"` at app root.
- **`verbatimModuleSyntax: true`** (apps/web) requires `import type` for type-only imports — relevant on consumer side.
- **Server-shape mismatch:** declaring a non-nullable field cerebro backend may not populate → runtime `undefined`. Mitigation: use `string | null` even if the field appears non-nullable elsewhere.
- **Never re-declare a property with a different type than upstream** — TS silently keeps upstream's type and refuses the merge. Add only new fields.

## Phase 0 recommendations

- Place at `packages/cerebro-types/augment.ts`; re-export from `index.ts`. Package is private workspace member with `"exports": { ".": "./index.ts", "./augment": "./augment.ts" }`.
- `tsconfig.json` extends `@multica/tsconfig/react-library.json`.
- Mandatory side-effect import in one bootstrap per app: `apps/web/app/layout.tsx` and `apps/desktop/src/renderer/src/main.tsx`.
- Add a smoke test (`augment.test-d.ts`) using `expectTypeOf<Project>().toHaveProperty('cerebro_brand')` so future `pnpm typecheck` catches accidental loss of augmentation.
