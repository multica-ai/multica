# P8 — Feature flag pattern in both apps

**Verdict:** PASS

**Hypothesis:** Feature flag system with Settings-tab + persistence works in both Next.js + Electron via Zustand store + server-side override + `extraAccountTabs` extension API.

## What we found — all infrastructure exists

- **SettingsPage extension API exists.** `packages/views/settings/components/settings-page.tsx:30-39` defines `ExtraSettingsTab` interface + `extraAccountTabs?: ExtraSettingsTab[]` prop. Already used by desktop in `apps/desktop/src/renderer/src/routes.tsx:172-179` for the Daemon tab — same hook for "Cerebro Features".
- **Workspace-scoped Zustand persist pattern exists.** Model after `packages/core/issues/stores/comment-collapse-store.ts`: `persist` middleware + `createJSONStorage(() => createWorkspaceAwareStorage(defaultStorage))` + `registerForWorkspaceRehydration(...)`. Per-workspace namespacing automatic on `setCurrentWorkspace(slug, uuid)`.
- **Storage cleanup hook:** any new persist key must be added to `packages/core/platform/storage-cleanup.ts`.
- **API client pattern:** new methods on `ApiClient` in `packages/core/api/client.ts`. Existing fork-specific example: `updateMyPreferences()` at `client.ts:272`. Test mirror in `client.test.ts:129`.
- **Handler pattern for fork-specific endpoints:** `server/internal/handler/user_preferences.go` exists with header explicitly noting "Kept in a dedicated file so upstream-merges don't conflict on auth.go". Routes registered in `server/cmd/server/router.go:237` under `RequireUserScope` group.
- **Migration namespace already established:** cerebro 9xxx-series (`9005_user_preferences.sql`, `9008_member_enforcement_toggles.sql`, `9009_project_access.sql`) coexists with upstream 0xx in `server/migrations/`. Per P4, splitting to `server/migrations/cerebro/` is the work — not a precondition.

## Risks / gotchas

- **Workspace-scoping:** server table needs composite key `(workspace_id, user_id, flag_key)`. GET endpoint filters by both. **Server-side default-on:** return `enabled=true` when no row exists — avoids 404 churn. Use `LEFT JOIN` or fall back to defaults map, not `GetX returning ErrNoRows`.
- **Real-time:** WS event `feature_flag:changed` should invalidate TanStack Query cache (per CLAUDE.md "WS events invalidate queries — they never write to stores directly"). Real value for desktop multi-window; for web one-tab still keeps `extraAccountTabs` reactive without reload.
- **Default-on semantics:** registry holds defaults in TS. Server-side overrides opt-in only. Avoids migrations every time a new flag ships.
- **Router category (desktop):** flag-driven UI variants are session-route content (live inside `WorkspaceRouteLayout`), not transition flows (`WindowOverlay`).
