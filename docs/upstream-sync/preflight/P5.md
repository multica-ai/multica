# P5 — Playwright visual regression stability

**Verdict:** HOLD — feasible, but Phase 0.6 must invest in masks + deterministic data + Linux-CI-baselines.

**Hypothesis:** We can capture stable visual baselines for inbox / projects / settings with <0.1% pixel-diff variance across 5 consecutive runs.

## What we found

- Playwright `@playwright/test ^1.58.2`. Modern features available: `toHaveScreenshot` with `mask`, `maxDiffPixelRatio`, `animations: "disabled"`.
- Config at `playwright.config.ts`: chromium-only, headless, 30s timeout, no auto-server.
- 8 existing spec files (auth/comments/issues/navigation/notifications/projects-access/settings). Pattern: semantic E2E with `data-testid` + `waitForLoadState("networkidle")`. **Zero existing visual snapshots.**
- CI `.github/workflows/ci.yml`: Ubuntu runner, Node 22. Frontend job runs `turbo build typecheck test` — no Playwright step today. **Visual baselines captured on macOS dev will not match Ubuntu CI** — must generate in CI.

## Sources of pixel flake (located)

- **Dynamic timestamps:** `inbox-list-item.tsx`, `projects-page.tsx` use `formatRelativeDate` ("2m ago"/"just now") — drift between runs.
- **Animations:** `animate-ping` on inbox green dots; `transition-colors`/`transition-all` on hover; `transition-transform` chevrons in project-detail.
- **Loading skeletons:** `inbox-page.tsx` `<Skeleton>` rows during initial fetch — must wait past loading.
- **Avatar fallbacks:** `ActorAvatar` uses `bg-muted` + initials (no UUID-hashed colors) — **deterministic, low risk**. Image avatars only flake if external CDNs.
- **WS-driven invalidations:** inbox subscribes to `inbox:new`, `chatKeys.sessions`. Snapshot taken too early can race a refetch.

## Phase 0.6 recommendations

1. **Snapshot config:** `animations: "disabled"`, `caret: "hide"`, `maxDiffPixelRatio: 0.001`.
2. **Masks:**
   - `[data-testid="notification-row"] time` (relative timestamps)
   - `.animate-ping` parents (or CSS override)
   - `[data-slot="avatar"] img` (remote-loaded avatars)
3. **Wait conditions:** `waitForLoadState("networkidle")` + a stable testid that flips post-fetch (`getByTestId("inbox-loaded")`).  Avoid `networkidle` alone — WS holds connection open.
4. **Seed deterministic data:** use existing `TestApiClient` to insert fixed `created_at` + known users.
5. **CI baseline only:** generate baselines on Ubuntu in CI (`--update-snapshots`), never macOS dev. Add `playwright` job after `frontend` running `pnpm exec playwright test --grep @visual`.

## Fallback plan

If Phase 0.6 over-runs or flake exceeds 0.5% after masks: keep semantic E2E (already strong: 8 specs, testid-based) and **defer pixel snapshots to Phase 1**. The eval-baseline gate becomes "no semantic regression" rather than pixel-perfect. Recommend NOT doing this unless flake genuinely blocks progress.

## Mitigation for HOLD

Phase 0.6 explicitly budgets time for mask development + Linux-CI baseline generation. Document the masks list as part of the eval-baseline artifact.
