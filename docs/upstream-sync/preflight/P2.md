# P2 — Path-alias shadowing

**Verdict:** HOLD — pattern works, but plan's example specifier doesn't exist; use barrel-shadow instead.

**Hypothesis:** We can replace upstream's `@multica/views/issues/comment-card` module by configuring path aliases in Next.js + electron-vite, without modifying upstream consumers' import statements.

## What we found

The literal specifier `@multica/views/issues/comment-card` is **not** in `packages/views/package.json` `"exports"` and is **not** used by any consumer. The actual imports are:

- `packages/views/issues/components/issue-detail.tsx:73` — relative `./comment-card`
- `packages/views/issues/components/index.ts:6` — relative `./comment-card`, then re-exported via `./issues/components` subpath

## Bundler hooks

**Next.js (apps/web):** uses `transpilePackages: ["@multica/core","@multica/ui","@multica/views"]`. No webpack alias today. Override hook: add `webpack(config) { config.resolve.alias = { ...config.resolve.alias, ...overrides }; return config; }`.

**electron-vite (apps/desktop):** `renderer.resolve.alias = { "@": resolve("src/renderer/src") }`. Extend with the same overrides map.

**tsconfig:** must be kept in sync manually with `paths` since JSON cannot import `.ts` constants.

## Two override strategies

1. **Barrel-shadow (recommended):** override `@multica/views/issues/components` to point at `packages/cerebro-views-issues-components/index.ts` which re-exports upstream barrel + overrides `CommentCard`. Simple, works in both bundlers, no relative-path hackery.
2. **Absolute-path alias:** alias `path.resolve(repo, "packages/views/issues/components/comment-card.tsx")` → cerebro file. Works in vite + webpack but fragile (filename-coupled).

## Risks / gotchas

- **The plan's example specifier is fictional.** Don't claim `@multica/views/issues/comment-card` exists — pick barrel-shadow.
- **Type-only imports** follow tsconfig paths only; bundler aliases must mirror exactly or you get type-vs-runtime drift.
- **HMR survives aliasing** because `transpilePackages` already covers `@multica/views`.

## Phase 0 recommendations

- Centralize override list at `packages/cerebro-types/aliases.ts` exporting `cerebroAliases: Record<string, string>`.
- Both `apps/web/next.config.ts` and `apps/desktop/electron.vite.config.ts` import this same map.
- Re-frame plan's P2 phrasing to use barrel-shadow ("@multica/views/issues/components"), not the fictional specifier.
- Add P2.5 verification later: confirm barrel-shadow round-trips named exports + `import type` paths.

## Mitigation for HOLD

Update `03-decision.md` Phase 0.4 / Phase 3 sections to reference barrel-shadow as the canonical override mechanism, and remove all references to specific subpath specifiers that don't exist as exports.
