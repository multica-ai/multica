# Extension 受管小队

## 目标

Extension 导入创建的小队是受管小队。用户能在小队列表和详情中识别其来源，并在小队详情内查看内部 Agent 的只读详情；这些内部 Agent 不进入全局“智能体”工作流。

## 识别与接口

后端以 `platform_extension_release.squad_id` 为唯一事实来源。小队列表与详情响应携带受管标识及 Extension 身份（key、version、release ID）。前端不得通过小队名称或 Agent `system_key` 推断。

后端提供受管小队作用域内的内部 Agent 详情读取接口。它仅返回该小队成员中的 Extension 内部 Agent，并沿用工作区访问校验；响应只包含详情抽屉需要的非敏感字段。

## 行为

- 小队列表与详情显示 `Extension` 标识。
- 受管小队不显示创建智能体、添加成员、设为负责人、移除成员等会改变内部编排的操作。
- 小队成员中的内部 Agent 不跳转全局智能体详情；点击后在当前小队详情右侧打开只读抽屉。
- 抽屉展示名称、描述、角色、指令、绑定运行时与 Skills。
- 服务器拒绝对受管小队的成员与负责人变更，防止通过 API 绕过界面保护。
- 普通小队完全维持原有界面与接口行为。

## 测试

- 后端：受管标识、内部 Agent 详情授权、受管小队成员/负责人变更被拒绝。
- 前端：列表标识、受管小队无创建按钮、成员点击打开只读抽屉且没有智能体详情链接；普通小队仍可创建及跳转。
